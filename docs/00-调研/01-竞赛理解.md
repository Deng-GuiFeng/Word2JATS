> 本文档根据报名海报、官方介绍 PPT、补充说明、样例数据实地核对整理，所有结论都有出处。

## 1. 竞赛概况

- **名称**：学术期刊结构化技术创新大赛
- **主办方**：杭州电子科技大学计算机学院 × IMR Press（总部位于新加坡的国际学术出版商）
- **参赛对象**：杭电及各高校在读学生，不限专业和年级，每队 1–3 人

## 2. 我们的赛题：选题一（word2xml）

> 出处：PPT slide 15

- **任务名**：Word → JATS XML 的语义映射与自动化生成（word2xml）
- **任务描述**：把学术论文的 Word 排版格式自动转换成符合 JATS 标准的 XML 文档。眼下行业里靠人工转换这类没有结构的 Word 文档，既费时又费钱，这个任务就是要解决它。
- **功能要求**：完成以下模块的结构化识别与标记
  1. 标题层级
  2. 作者信息（姓名、单位、ORCID）
  3. 关键词
  4. 摘要
  5. 图片
  6. 列表
  7. 数学公式
  8. 参考文献
- **交付物**：
  1. 输入样例 Word 文档
  2. 自动转换生成的输出样例 JATS XML 文件
  3. 可运行的程序代码
  4. （必须）清晰完整的项目运行说明文档（出处：PPT slide 20）

## 4. 评审标准（决赛，权重）

> 出处：PPT slide 24–28

| 维度 | 权重 | 细则 |
|------|------|------|
| **落地性** | **40%** | 代码规范、工程结构、运行效率、资源消耗、稳定性 |
| 创新性 | 30% | 算法创新、模型设计、技术路线新颖度 |
| 业务适用性 | 20% | 问题解决完整性、对出版场景的适配能力 |
| 展示度 | 10% | 现场表现、PPT 质量、回答问题准确性 |

### 评分解读（关键判断）
- **落地性 40%（工程是否扎实好用），权重最高**，而且明确包含「运行效率 / 资源消耗 / 稳定性」。这意味着**纯 LLM 方案**（慢、贵、输出不稳定）在这一项上很容易丢分。
- **创新性 30%（技术路线是否新颖）** 明确鼓励前沿技术：PPT slide 18 原文点名「大模型做语义映射、Rust 原生库做高性能转换」。
- 这两项有矛盾 → **最好的做法很可能是两者结合**：用确定性的规则程序挑大梁（快、稳、省，拿工程分），大模型只用来处理规则搞不定的语义难点（判断哪段是作者、拆解参考文献、辨认章节角色）。而且设计成**可以配置、能一键关掉**——没有 API Key 也能跑出完整结果，保证稳定。
- 业务适用性 20%（功能是否解决实际问题）看「功能完整性 + 出版标准符合度」→ 必须照着 IMR Press 真实的 JATS 1.3 模板来（样例就是评判基准）。

## 5. 参赛纪律（约束）

> 出处：PPT slide 18–22

- **技术选型**：不限语言和框架，技术栈自由选择。
- **原创性**：可以借鉴成熟的开源方案，但**核心代码、核心算法必须原创**，禁止照搬抄袭。
- **运行说明**：提交物必须包含清晰完整的运行说明文档。
- **初赛要求**：不要求 100% 实现所有功能，但**作品必须能运行、能产生可验证的输出**；逾期不纳入评选。
- **决赛要求**：需要现场演示，按多个维度综合评分。

## 6. 补充说明（委员会群内通知）

> 出处：`补充说明.txt`

> 因为 XML 无法存储图片和附件，如果论文原始 Word 文件里有图片和附件，是需要转换成外部存储的；同样 XML 转成 PDF 也需要把图片和附件显示出来。
>
> 官方还给出 JATS 文档入口 <https://jats.nlm.nih.gov/publishing/tag-library/1.3/chapter/getting-started.html>，并随附 `JATSv1.3 完整手册.pdf`（9 页，按模块归类的元素清单）。我们据此核查并补齐了 ext-link / permissions / fn-group（Publisher's Note）/ history 等 IMR 标准元素（见 `../02-开发/03-迭代日志.md` R7）。

**解读**：图片和附件「外部化」是选题一明确要求的一环——程序要从 docx 里抽出内嵌的图片，转换格式后以外部文件形式保存，并在 XML 里用引用的方式（`<graphic xlink:href>`）指向它们。这一点已经在样例上实测确认（见 `02-数据与映射规格.md`）。
