# 数据与映射规格（Word → JATS XML）

> 本文档是整个项目的**技术地基**，内容综合了两部分：(1) 我对 5 个样例的亲自实测；(2) 7 个分析子代理对 5 个样例对、baseline 以及 JATS 标准的深入解析（原始报告见 `docs/参考资料/`）。所有结论都有样例为证。

## 0. 一句话总览

每个样例 = `初始文件.docx`（输入）+ `最终文件.xml`（IMR Press 已发表的金标准 JATS 1.3）+ `figures.zip`（图片包）。目标是写一个程序，把学术论文的 Word 文件转成**合规、完整、符合 IMR 出版规范**的 JATS XML，并把图片单独抽出来存成文件。

## 1. ⚠️ 最重要的一点：金标准不是 docx 算出来的结果

5 个样例**无一例外**地说明：金标准 XML 里有些内容，docx 中根本不存在，它们来自三个外部渠道：

| 来源 | 例证 |
|------|------|
| **出版系统注入的元数据** | DOI（`10.31083/RCM46777`）、ISSN、journal-meta、收稿/录用日期、版权/许可、`authenticated="true"` —— 用 grep 验证，这些在 docx 全文、页眉页脚、文档属性里**都找不到** |
| **人工编辑加工** | 样例5 标题改写（"How do…?"→"How…:"）；样例1 录用日期纠错（2025→2026）、摘要扩写、Author Contributions 全名改成缩写、伦理部分补审批号、**缺失的公式由编辑补写**；样例4 参考文献增删重排（docx 145 条→XML 144 条，`[10]Brodie`→`[10]Singh`） |
| **外部数据库补充信息** | 样例2/5 的参考文献逐条经 CrossRef/PubMed 补 DOI、把缩写刊名还原成全称、规范卷页 |

### 由此得出的几条结论（决定整个策略）
1. **不可能、也不该追求和某个金标准 XML 逐字节相同**——那些编辑改动从输入根本推不出来。
2. **评分项里没有"和金标准精确匹配"这一项**（评分=落地40%+创新30%+业务20%+展示10%，见 `01-竞赛理解.md`）。金标准是**目标格式和质量的参考样本**，用来学它的元素结构、id 命名方式、出版约定。
3. **真正该做的**：忠实转换 docx 里**真实存在**的内容（绝不臆造编辑改动）；已知的外部元数据通过配置文件或额外输入注入，没有的就留合理占位；输出要通过 JATS 1.3 DTD 校验 + 对齐 JATS4R 关键规则(我们以手写规则检查落地,见 `validate/checks.py`;完整 Schematron 列为未来项)。**尽量还原原文结构 + 符合标准 + 功能完整**，这才是得分点。

## 2. 金标准 XML 的统一骨架（IMR Press JATS 1.3）

5 个样例的文件头和骨架完全一样：

```xml
<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE article PUBLIC "-//NLM//DTD JATS (Z39.96) Journal Publishing DTD v1.3 20210610//EN"
  "https://jats.nlm.nih.gov/publishing/1.3/JATS-journalpublishing1-3.dtd">
<article xmlns:mml="http://www.w3.org/1998/Math/MathML"
         xmlns:xlink="http://www.w3.org/1999/xlink"
         dtd-version="1.3" xml:lang="en" article-type="...">
  <front> <journal-meta/> <article-meta/> </front>
  <body> ... </body>
  <back> <ack/> <ref-list/> <fn-group/> </back>
</article>
```

- `article-type` ∈ {`research-article`, `review-article`}，由 docx 首段「稿件类型」文本（"Original Research"/"Review"/"Article"）决定。
- **`journal-meta` 是按期刊查表得到的固定模板**（见 §9 期刊表）。

## 3. Front Matter 映射

### 3.1 article-categories
docx 首段稿件类型 → `<article-categories><subj-group subj-group-type="heading"><subject>Original Research</subject></subj-group></article-categories>`

### 3.2 作者 contrib-group（核心难点）
docx 里作者通常挤在**一个段落**，靠 run 级的上标来标角标（`w:vertAlign="superscript"`）：
```
Yinze Ji^1,2, M.D., Ph.D., Aimin Dang^1,*, ...
```
映射规则：
- 把姓名「Given Surname」**前后调换**成 `<surname>` / `<given-names>`（用末词当姓，是启发式判断）；去掉学位后缀 "M.D., Ph.D."。
- 上标数字 → `<xref ref-type="aff" rid="aff{n}"><sup>{n}</sup></xref>`。
- 上标 `*` → 通讯作者 `<xref ref-type="corresp" ...>`（或关联到 author-notes）。
- 上标 `†`/`#` → 共同贡献 `<xref ref-type="fn" rid="fn-1"><sup>†</sup></xref>`。
- **ORCID** 来自后面单独的段落（"ORCID: 0000-..."），按姓名**就近回填**；XML 里要补上 `https://orcid.org/` 前缀，加 `authenticated="true"`（这个属性 docx 没有，属于外部认证信息）。注意样例4 出现了没有连字符的 `0000000242784814`，需要格式化成 `0000-0002-4278-4814`。

```xml
<contrib contrib-type="author">
  <contrib-id contrib-id-type="orcid" authenticated="true">https://orcid.org/0009-0006-1026-1505</contrib-id>
  <name><surname>Ji</surname><given-names>Yinze</given-names></name>
  <xref ref-type="aff" rid="aff1"><sup>1</sup></xref>
  <xref ref-type="aff" rid="aff2"><sup>2</sup></xref>
</contrib>
```

### 3.3 单位 aff
docx 里 "Affiliations:" 标签后面，每条都带一个前导上标数字 →
```xml
<aff id="aff1"><sup>1</sup>Premium Care Center, Department of Cardiology, Fuwai Hospital, ... 100037 Beijing, China</aff>
```

### 3.4 学术编辑
docx 里的中文标签「学编：Salvatore De Rosa」→ 第二个 contrib-group：
```xml
<contrib contrib-type="editor"><name><surname>Rosa</surname><given-names>Salvatore De</given-names></name><role>Academic Editor</role></contrib>
```

### 3.5 author-notes / corresp
由通讯作者邮箱汇总而来：
```xml
<author-notes><corresp id="cor1"><sup>*</sup>Correspondence: <email>amdangfw@163.com</email> (Aimin Dang)</corresp>
  <fn id="fn-1"><p><sup>†</sup>These authors contributed equally.</p></fn>
</author-notes>
```

### 3.6 history / pub-date / permissions
- history（received/rev-recd/accepted）：docx 里是裸日期 "2025/9/21" → 拆成 `<day>/<month>/<year>`。**docx 没有或只是占位时，由出版系统补上**。
- permissions：固定模板（`Copyright: © {year} The Author(s). Published by IMR Press.` + CC BY 4.0），**docx 不提供**。

### 3.7 abstract（结构化）
docx 摘要段以粗体标签开头（Background:/Methods:/Results:/Conclusion:）→
```xml
<abstract><sec><title>Background:</title><p>...</p></sec>...</abstract>
```
（有些样例的 docx 摘要是一整段，金标准被编辑拆成了多个 sec——我们按 docx 实际结构转，是一段就转成一个 p。）

### 3.8 kwd-group
docx 关键词行（用 `;` 或 `,` 分隔）→ `<kwd-group kwd-group-type="author"><kwd>...</kwd></kwd-group>`

## 4. Body 映射

### 4.1 章节层级与 id
- docx 标题靠 heading 样式识别，**或者**靠文本规律来猜（编号正则 `^\d+\.`、句首大写、加粗短行、章节名词典）。
- 生成层级 id：`S1` / `S2.SS1` / `S2.SS3.SSS1`；段落 id：`S2.SS1.p1`。
- 补上节号（"2.1 …"）、把标题改成 Title-Case。
- **陷阱**：个别"伪标题"（如样例1 "Internal validation"）在金标准里被当成普通 `<p>`，没有单独建节——这里要小心。

```xml
<sec id="S2"><title>2. Materials and Methods</title>
  <sec id="S2.SS1"><title>2.1 Data Sources and Study Population</title>
    <p id="S2.SS1.p1">Data from 1035 hospitalizations ...</p>
  </sec>
</sec>
```

### 4.2 行内格式
run 级 `w:i`→`<italic>`、`w:b`→`<bold>`、`w:vertAlign=superscript`→`<sup>`、`subscript`→`<sub>`。
- **注意**（样例5）：docx 的斜体含义和 XML 的 `<italic>` 并不一致（docx 斜体用在 "Article"、表内小标题上；XML 的 italic 用在 "i.e."、统计符号 *p*/*t*、期刊名上）。**不能把 docx 的斜体照搬过来**，得看内容含义来判断。这是个进阶优化项。
- 特殊字符：`χ²` 在金标准里写成 `<styled-content style="color:#474747;">χ</styled-content><sup>2</sup>`（IMR 特定的灰色）；化学式 `Na⁺` → `Na<sup>+</sup>`。

### 4.3 交叉引用 xref（全靠纯文本解析）
docx **没有 REF 域、书签、超链接**，正文里 "Fig. 1"、"Table 1"、"[8-15]" 都是纯文本。要做的是：
- 识别出来并生成 `<xref ref-type="fig|table|bibr" rid="F001|T001|b8">`。
- 区间 `[8-15]` 展开成 8 个独立 xref；`[21,22]` 拆成 2 个。

### 4.4 列表
`<list list-type="...">` + `<list-item>`，需要读 `numbering.xml` + `w:numPr`。**列表很少见**（样例3 没有），而且样例2 把 bullet 列表改成了子节（不是 `<list>`）——按 docx 实际情况尽力处理。

## 5. 图片处理（必做，已实测确认）

**三处文件名互不相同，只能靠它们在文档里出现的先后顺序来对上**：
- docx 内嵌 `word/media/imageN.{tif,png,jpeg}`（高清，或者是低清的分面板图）。
- `figures.zip` 里是 `fig-0N.{jpg}`（有时是 docx 同一张图转成的 JPG，有时是作者另外提供的高清拼合图——样例1 docx 是 644×483 低清，figures.zip 是 9990×6000）。
- XML 里引用 `<graphic xlink:href="{article-id}/fig-0N.jpg">`，`{article-id}` 取自 DOI（`10.31083/JIN49347` → `JIN49347`）。

处理流程：
1. 按正文里出现的顺序把图编号（关联到 "Fig. N" 题注），排除页眉 logo、内联小装饰图、公式回退位图（wmf/MathType OLE）。
2. 图片来源优先用 `figures.zip`（如果提供了）；没有的话从 docx 里抽。统一转成 JPG，按图号重命名为 `fig-0N.jpg`，放进 `{article-id}/` 目录。
3. XML 生成 `<fig id="F001" position="float"><label>Fig. 1.</label><caption><p>...</p></caption><graphic xlink:href="{article-id}/fig-01.jpg"/></fig>`。

## 6. 公式处理（OMML → MathML3）

- docx 里的公式是 **OMML**：`<m:oMath>`（行内）/ `<m:oMathPara>`（独立段落，即块级）。python-docx **不暴露 OMML**，得用 lxml 直接读 `word/document.xml`。
- 转换路径：lxml 抽出 `m:oMath` 节点 → 用 `lxml.etree.XSLT` 加载**开源的 OMML2MML.xsl**（比如 plurimath/omml2mathml、meTypeset 自带的）→ 得到 Presentation MathML。
- 块级 → `<disp-formula id="E001"><label>(1)</label><mml:math ... display="block">...</mml:math></disp-formula>`；行内 → `<inline-formula><mml:math ...>...</mml:math></inline-formula>`。
- 金标准里的 `alttext="LaTeX"` 属性、用 `<mml:semantics>` 包裹，属于可选的增强（OMML→LaTeX）。
- 块级公式编号 "(N)" 是同一段里单独的一个 run，要把它和 `<label>` 配对起来。

## 7. 参考文献处理（mixed/element 混用）

- docx 里的参考文献是**没有结构的纯文本**（Vancouver/PubMed 风格，`[n] Author. Title. Source. Year; Vol: pages.`）。
- 金标准里每条是：`<ref id="b1"><label>[1]</label><CITATION>...</CITATION></ref>`，CITATION 是以下两种之一：
  - `<mixed-citation>`（把整段文本包起来，**主力做法，解析不出来时的兜底**）；或
  - `<element-citation>`（结构化：person-group/name + article-title + source + year + volume + fpage/lpage + pub-id[doi]）。
- **怎么判定用哪种**（金标准疑似的规则）：能通过 DOI/元数据反查到、解析把握大 → element；否则 → mixed。
- 我们的策略：用正则解析（不够时用 GROBID/anystyle 或 LLM 兜底）→ 把握大的转成 element-citation，把握小的转成 mixed-citation。**补 DOI（CrossRef）是可选的联网增强**。
- JATS4R 建议全篇统一、不要两种混用；但金标准实际上是混用的，我们的原则是"尽量结构化，把握不大的就保留原样"。

## 8. 表格处理

| docx 形态 | 出现样例 | 处理难度 |
|-----------|----------|----------|
| 真 `<w:tbl>`（gridSpan 跨列 / vMerge 跨行） | 样例1、3 | **能转得比较好** → `<table-wrap><table>`（colgroup/thead/tbody/tr/td/th，scope/style） |
| 整张**图片**表格 | 样例2（8 张全是图） | 极难（需 OCR）→ 尽力而为：作为图片嵌入，或注明做不到的地方 |
| 用**制表符**拼出来的表格（段落+`<w:tab/>`） | 样例5（14 张） | 很难（要聚类、切列、推断 colspan）→ 尽力而为 |

策略：真 `w:tbl` 尽量还原到位；图片表和制表符表尽力而为，并明确记下来是已知做不到的地方（初赛不要求 100%）。

## 10. back 区固定结构

声明类小节**标题文字固定、顺序固定**（IMR 模板）：
Availability of Data and Materials → Author Contributions → Ethics Approval and Consent to Participate → Acknowledgment(`<ack>`) → Funding → Conflicts of Interest，末尾的 `<fn-group>` 里含固定的 Publisher's Note。某项内容缺失时，用标准占位语（"Not applicable." / "This research received no external funding." / "The authors declare no conflicts of interest."）。

## 11. id 命名规范（金标准的约定，便于符合评委的预期）
sec=`S{n}` / `S{n}.SS{m}` / `…SSS{k}`；段落=`S{n}…p{m}`；aff=`aff{n}`；corresp=`cor{n}`；fn=`fn-{n}`；fig=`F00{n}`，其 graphic=`F00{n}.g1`；table=`T00{n}`，表脚注=`T00{n}-fn1`；公式=`E00{n}`（block）/`w{n}`（math id）；文献=`b{n}`。label：图 "Fig. N."、表 "Table N."、文献 "[n]"、公式 "(N)"。
