# 可得性边界:金标准里的内容,哪些做得到、哪些做不到

> 背景:这是真实出版社的真实问题。所以判断"能不能从输入得到"时,不能只看 docx 字面,
> 还要算上**领域知识、出版惯例、外部数据库**——这些在真实部署里本来就用得上。
> 据此把金标准里的每类内容分成三档,并写明我们怎么处理。结论来自 5 个样例的实地比对。

## A 档:docx 里直接就有,照抽即可

| 内容 | 怎么做 | 状态 |
|------|--------|------|
| 文章标题、作者姓名、单位、ORCID、邮箱 | 从前置区按内容特征识别 | 已做 |
| 关键词、摘要正文 | 标签/样式 + 文本切分 | 已做 |
| 正文各段、各级标题文字 | 按内容判断角色、建嵌套章节 | 已做 |
| 内嵌图片、OMML 公式、真正的表格(w:tbl) | 解析 OOXML | 已做 |
| 参考文献原文、收发/录用日期(部分样例有) | 切条 / 日期识别 | 已做 |

## B 档:docx 里没有,但结合领域知识/外部库/出版惯例**能得到、就该做**

这一档是这次最该想清楚的——以前我把不少 B 档当成 C 档(人工编辑)放过了,是偏差。

| 内容 | docx 里有吗 | 怎么得到 | 状态 |
|------|------------|----------|------|
| 期刊名/缩写/ISSN(journal-meta) | 没有 | 按期刊代号查表(IMR 各刊固定) | 已做(21 刊,见 `journals.yaml`) |
| 文章号(article-id) | 没有 | = DOI 去前缀;真实部署中 DOI 由出版方分配、是已知输入 | 已做(参数传入) |
| 参考文献的 DOI、刊名全称、规范卷页 | 没有 | 拿条目去 CrossRef 按标题反查 | 已做(`--crossref`,命中约 90–98%) |
| 版权年、版权声明 | 没有 | 录用年 + IMR 固定模板 | 已做 |
| 把源里已有的裸声明句拆成命名 back 小节(数据可得性/伦理/资助/利益冲突) | 有(常挤在一起) | `agent/declarations.py`:LLM 语义归类 + 重建 back 小节(**只搬运原文、不改写、不补造**) | 已做 |
| 图片外部化的命名与路径(fig-0N、article-id 目录) | 命名没有 | 出版惯例 + 文档顺序 | 已做 |
| 正文交叉引用链接("见图1""见文献[3]") | 只是文字 | 解析文字 + 关联目标 id | 已做 |
| 图片型表格 / 制表符表 | 是图/制表符 | 图片表**确定性外部化**为 `<table-wrap><graphic>`——不做 OCR 重建:图中文字不在 docx 文本流里,读图必造字(样例2 实测编造 617 词),R17 已删除该路径;制表符表**确定性切 Tab** 还原 HTML 表(`build/vision_tables.py`) | 已做(不丢表、不丢字;列数/表头合并系金标准人工判断,不强行精确复刻,见迭代日志 R17) |
| 章节自动编号("1."、"2.1")、标题规范成 Title Case | 多数没有 | 出版惯例 | 待评估(怕过拟合,见下) |
| 作者贡献段的姓名缩写(全名→缩写) | 有全名 | 按规则生成缩写 | 待做 |

## C 档:真正从输入得不到,**忠实保留原文,绝不臆造**

| 内容 | 例子 | 处理 |
|------|------|------|
| 编辑把标题/摘要彻底改写 | 样例5 标题 "How do…?" 改成 "How…:";样例1 摘要重写 | 保留 docx 原文 |
| 参考文献整条被替换或重排 | 样例4 第 10 条 docx 是 Brodie、金标准换成 Singh | 按 docx 原样 |
| 编辑手工补了原文缺失的内容 | 样例1 docx 缺了一个公式、金标准里补上了 | 标记缺失,不编造 |
| 把 docx 里的笔误改对 | 样例1 录用日期 docx 写错、金标准改对 | 除非有外部依据,保留 docx 值 |

## 原则

- **A、B 两档都要尽量做对、做全**——这是衡量我们做得好不好的真正标准。
- **C 档不猜**:保留原文。真实出版流程本来就有人工终校这一环,C 档交给人去定,机器不该乱改。
- **关于"待评估"的几项(章节编号、Title Case)**:这些是 IMR 这批样例的惯例,但未必所有期刊都这样。为了不过拟合,只在有把握泛化时才做,或做成可开关、并保留原文形态作为兜底。
