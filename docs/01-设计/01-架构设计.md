# 架构设计

> 本文说明 word2jats 转换系统的整体架构：唯一的处理流程、四个关键设计立场、模块地图、
> 各层之间的契约与关键机制。设计目标紧扣竞赛评分（见 `../00-调研/01-竞赛理解.md`）。
>
> 本文是 2026-07 那次架构重构后的权威说明。重构把系统从旧的"规则做理解 + LLM 打补丁"
> 倒置为"LLM 做理解 + 规则做保证"，方法唯一、没有可选分支。旧文档里的"确定性管线为主体 +
> LLM 增量层""`--agent` 视觉闭环"等描述已随重构作废，不再有效。
>
> 涉及的领域术语（JATS、DTD、OOXML、OMML、MathML、element/mixed-citation、ORCID 等）
> 本文在首次出现时会解释；更系统的领域背景见 `../00-调研/02-数据与映射规格.md`。
> 评测口径与成绩的完整方法见 `../03-评测/评测体系设计.md`。

## 0. 先读：这个系统在做什么，为什么这么设计

### 0.1 任务本身

竞赛要做的事，一句话讲：**把投稿用的 Word 论文稿（`.docx` 文件），自动转成学术期刊出版
通行的结构化全文 XML**。

这里有两个需要先交代的领域词：

- **docx / OOXML**：`.docx` 是微软 Word 的文档格式，本质是一个 zip 压缩包，里面装着一堆
  XML 文件（正文、样式、图片、公式等）。这套 XML 规范叫 **OOXML**（Office Open XML）。
  Word 关心的是"这段字长什么样"——字号、加粗、缩进、居中，而**不关心**"这段字扮演什么
  角色"——是标题、是作者名、还是参考文献。
- **JATS**：全称 Journal Article Tag Suite，是国际期刊界用来标记论文全文的 XML 标准。
  和 Word 相反，JATS 关心的正是**语义角色**：`<article-title>` 是标题、`<contrib>` 是
  作者、`<ref>` 是一条参考文献、`<sec>` 是一个章节。本竞赛的目标格式是 **JATS 1.3 的
  Journal Publishing DTD**（五个金标准样例都用这一版）。**DTD**（Document Type Definition，
  文档类型定义）是一份"语法规则书"，规定了哪些标签能嵌套在哪些标签里、哪些属性必填——
  产出的 XML 必须通过 DTD 校验才算合法，这是赛题的硬要求。

所以这个转换的实质是：**给已经存在于 docx 里的文字，判定并套上正确的 JATS 语义标签**。
它是一项"结构化"技术，不是"生成"技术——文字本来就在，我们要做的是识别结构、贴对标签。

### 0.2 贯穿全局的不变量：内容守恒

由上一节直接推出本系统最重要的约束——**内容守恒**：输出 XML 里的每一个内容词，都必须
来自输入 docx；**绝不用模型从图片里"读"字，绝不扩写、改写、编造**。

为什么这条如此关键？因为一旦模型开始"生成"文字，就会掺入 docx 里没有的内容——这在结构化
转换里是硬伤（评测会把它记为"编造词"）。特别是文档里那些"整张表其实是一张图片"的情况：
表格里的文字根本不在 docx 的文本流里，要拿到它只能**OCR**（光学字符识别，即让模型"看图
认字"）。而 OCR 读出来的字无法与源核对、必然出错、必然造字。所以本系统的立场是：图片就是
图片，永远不读它的内容，只把它作为一张图外部化保存。

### 0.3 旧架构的"拧巴"，以及这次重构解决了什么

理解新架构，最好的切入点是先看清旧架构错在哪。旧架构是"两层结构"：主体是一条**确定性
管线**（纯规则代码：解析→按规则分类→构建→校验），其上挂一个**LLM 增量层**打补丁。它有
两处结构性的别扭：

**拧巴一：用脆弱的先验规则去做本该靠理解才能做的判断。**
"这一行是标题还是正文？""这张表是图片还是网格？""这条参考文献的作者、标题、刊名边界在
哪？"——这类判断依赖对语义和上下文的理解。旧架构却用死规则去枚举：靠样式名、靠正则、靠
"在 DOI 前面找著录尾部"这样的锚点。但真实投稿千变万化——样式名经常缺失或乱标（很多稿子
通篇是 `Normal` 样式），锚点经常对不齐。规则枚举不完真实输入的花样，于是理解层天然脆弱、
边界情况层出不穷。**让规则去做理解，是把工具用反了。**

**拧巴二：又把 LLM 降格为被护栏捆住的补丁工。**
因为主线是规则、又提防模型编造，LLM 只能在规则失手的局部打零星补丁，而且处处被"内容守恒
护栏"捆着——生成的每个字段都要回头校验是不是原文子串，越界就整条拒绝。结果是：LLM 最强的
能力（读懂一篇文档的结构）发挥不出来，只能做零敲碎打的修补；护栏成了捆住它的镣铐，而不是
帮它的安全网。旧架构里甚至一度让"多模态模型看表格图片重建表"，实测在某个样例编造了 617 个
源文档里没有的词——这正是"让模型生成文字"的必然代价。

**这次重构把两件事各归其位**，依据是一条朴素的第一性原理——**让每个工具做它最擅长的事**：

- **理解（语义判断）本就是大语言模型（LLM，能读懂并生成自然语言的模型）的强项** → 那就把
  理解**全部**交给它：哪行是标题、哪张表是图片、参考各字段的边界，都由 LLM 判。
- **保证（不编造、合法、可复现）本就是确定性代码的强项** → 那就把保证全部交给规则：机械
  地把 docx 搬成 IR、把公式转成 MathML、把图片外部化、把树序列化、在出口做校验。

而破解"拧巴二"的关键洞察是：**让 LLM 只输出"结构判定"，而不是输出文字**。LLM 的每一句
产出都用一个"源块索引"指回原文的某一块，渲染时按索引把**原始文字**取回来。这样一来，文字
**始终来自 IR、从不来自模型**——内容守恒不再靠"护栏去捆 LLM"，而是**结构性地天然成立**。
护栏于是从"镣铐"变回"安全网"：只在极少数必须由 LLM 切分文字的地方（比如把一行作者切成
逐位作者、把一条参考切成各字段）才发挥作用，为这些切分兜错。

一句话总结这次重构：**LLM 放开手做它最擅长的理解，规则放开手做它最擅长的保证，两者不再
互相拧巴。**（重构后成绩见 §8：不但架构大幅简化，实测缺陷数还从旧架构的 228 降到 198。）

## 1. 四个关键设计立场

下面四条是整套架构的"宪法"，代码里每个取舍都能回溯到它们。理解了这四条，再看流程和模块
就水到渠成。

**立场一：理解全归 LLM。**
凡是需要"读懂"才能下的判断，一律由 LLM 承担——哪行是标题/作者/题注、哪张表是图片还是
网格、参考文献各字段的边界、哪些段落属于同一章节。规则层不含任何"这段内容是什么角色"的
语义先验。
> 依据：`understand/prompts.py` 里三个提示词把 LLM 定位为"精确的文档结构分析器"，只做
> 结构判定与文本切分；`render/` 各模块的文档字符串都写明"渲染器只按 LLM 的判定执行，不再
> 做任何'这段是什么'的判断"（如 `render/body.py`、`render/tables.py`）。

**立场二：内容不由 LLM 重写，靠源块索引引用原文。**
正文类内容（标题、段落、章节、题注……）以"源块索引"引用解析层的原始文字片段，渲染时按
索引取回。这样斜体、上标、下标、加粗等内联格式**零损失**，内容守恒**结构性成立**（文字来自
IR，不来自模型）。只有在**必须把一个源块切成多个语义单元**处——作者行切成逐位作者、参考
行切成各字段、通讯段、结构化摘要按子标题切分——LLM 才给出**子串**，出口再校验它确实是
docx 原文的子串。
> 依据：`semantic/model.py` 的模块说明；序列化时每块带稳定 `[idx]`（`understand/serialize.py`），
> 组装时按 `idx` 取回 `runs`（`understand/assemble.py` 的 `_runs`），只有切分处消费 LLM 的
> 子串并做守恒检查（`_sanitize_ref`、`_split_abstract_runs`）。

**立场三：LLM 只拿占位符，从物理上杜绝 OCR 造字。**
图片、公式、"整张表是图片"这三类东西，喂给 LLM 时只给一个占位符记号——图片是 `⟦IMG#n⟧`、
公式是 `⟦MATH#n⟧`——**不喂字节、不喂渲染图**。LLM 根本拿不到像素，也就**物理上不可能**
去 OCR 造字；它只能引用占位符的编号 `n`，把它当作一个"这里有张图/一条公式"的结构标记。
> 依据：`understand/serialize.py` 的 `_encode_runs` 只把占位符文本写进流；`prompts.py` 的
> 铁律第 4 条明确要求"绝不阅读、转写、描述、OCR 或猜测占位符内容，只能引用其编号 n"。

**立场四：规则只做机械变换 + 出口保证，不含内容语义先验。**
规则代码只干两类活：① **机械变换**——把 docx 搬成 IR、把 OMML 公式转成 MathML、把图片
按原字节外部化、把 JATS 树序列化、把正文里的"Fig. 1/Table 2/[5]"解析成交叉引用；② **出口
保证**——在最后做内容守恒、DTD 合法、结构自洽三项校验。守恒护栏的定位是"为 LLM 的少数
切分动作兜错"，不是"捆住 LLM"。
> 依据：`build/`（jats/formulas/figures/xref）与 `render/` 全是机械构造；`verify/`（conservation/
> verify）做出口校验。见 §4 模块地图、§6 关键机制、§7 出口校验。

## 2. 唯一流程

系统只有一条流程，**没有可选分支、没有降级档、没有"纯确定性档"**。因为理解由 LLM 承担，
模型是这套方法的必要组成，不是可开可关的增量。

```
docx ─parse(机械)────▶ IR（Document：有序的 Paragraph/Table，
     │                     段内是 run 级 TextRun/MathRun/ImageRun/BreakRun）
     ├─serialize(机械)─▶ 内容流（每块一行，带稳定 [idx]；上下标编码为 ^{}/_{}；
     │                     图/式/图片表 → 占位符 ⟦IMG#n⟧ / ⟦MATH#n⟧）
     ├─understand ─────▶ 结构判定 JSON（LLM 三 pass：front / body / references）
     │  (LLM 理解)
     ├─assemble(机械)──▶ 语义模型 SemanticDoc（按 idx 取回原始 runs / 占位符对象）
     ├─render(机械)────▶ JATS 树（复用 build/ 的 jats/formulas/figures/xref）
     └─verify(机械)────▶ 出口校验：内容守恒 + DTD 合法 + 结构自洽
                          → 落盘 XML（+ 图片外部化为独立文件）
```

**数据在各层的形态**（这是理解全流程的骨架）：

| 阶段 | 产物 | 形态说明 |
|------|------|----------|
| parse | **IR**（`Document`） | 贴近 docx 物理结构的中间表示：有序的段落/表格；段落里是一串 `run`（Word 里一段连续同格式的文字/公式/图片）。不含任何语义判断。 |
| serialize | **内容流**（`ContentStream`） | 把 IR 拍平成"给 LLM 看的文档"：每个源块占一行，行首是稳定编号 `[idx]`，LLM 后续全部产出都用这个 idx 指回源块。 |
| understand | **三份 JSON** | LLM 三次调用分别产出前置区/正文/参考区的结构判定，全部以 idx 引用源块、以子串给出切分。 |
| assemble | **SemanticDoc** | 语义模型：按 idx 把原始文字取回来，组成类型化的对象（作者、章节树、图表、参考等）。它是理解层与渲染层之间的唯一契约。 |
| render | **JATS 树**（lxml） | 机械地把 SemanticDoc 构造成 JATS 元素树，再解析交叉引用。 |
| verify | **校验报告 + XML 字节** | 三项出口校验，落盘 `.xml` 与外部图片。 |

> 依据：`pipeline.py` 的 `convert()` 完整串起这条流程——`read_docx`→`understand`（内部
> `serialize`→三 pass→`assemble`）→`render_verify_repair`（内部 `render_document`→`verify`）。
> `cli.py` 只暴露一个 `convert` 子命令，`--llm` 只是选模型后端（默认 `dashscope`），没有
> 开关能关掉理解层。

## 3. 模块地图（`src/word2jats/`）

系统按"机械 → 理解 → 机械"分层，每个包职责单一。

**理解层（`understand/`）——LLM 主理解，本次重构的核心新增：**

| 模块 | 职责 |
|------|------|
| `serialize.py` | 把 IR 序列化成"给 LLM 看的内容流"：每块一行带 `[idx]`；上/下标编码成 `^{}`/`_{}`；图/式/图片表换成占位符；行级标注加粗/居中/样式名/列表等排版信号供参考。 |
| `segment.py` | **机械定位**参考文献区边界——找 "References" 标题或首条 `[1]`，把文档切成"前置+正文区"与"参考区"。这是表示层分块（认字面记号），不是内容判定。 |
| `passes.py` | 跑三个 LLM pass（front/body/references）。参考区可能很多条，按 `[N]` 条目边界分块调用；单次输出被截断时**自适应二分**重试，直到补齐。 |
| `prompts.py` | 三个 pass 的系统提示词，写死"内容守恒"等铁律（英文书写，因为被解析的论文是英文，与对用户用中文交流无关）。 |
| `patterns.py` | 表述层解析助手：从题注剥 "Fig. N" 前缀、规整 ORCID、给无标题的裸声明配规范标题。这些是"把已有文本切成 label+正文"的机械操作，非语义判定。 |
| `assemble.py` | **索引解析**——把三份 JSON 组装成 `SemanticDoc`：按 idx 取回原始 `runs`，只在切分处消费 LLM 子串并做守恒检查。 |
| `understand.py` | 理解层编排：`serialize`→定位参考区→三 pass→`assemble`。 |

**语义模型（`semantic/model.py`）——理解层与渲染层的类型化契约：**
定义 `SemanticDoc` 及其构件（`Author`/`Affiliation`/`Section`/`Figure`/`TableBlock`/
`Formula`/`Declaration`/`Reference`…）。正文类对象直接携带原始 `runs`，切分类字段携带
已校验的子串。**渲染层只消费这个模型，不再回看 docx**，职责由此干净切分。

**渲染层（`render/`）——纯机械消费 `SemanticDoc`：**

| 模块 | 职责 |
|------|------|
| `render.py` | 渲染总装：front/body/back 三部分构造 → 交叉引用解析 → 兜底修复 → 序列化。 |
| `front.py` | 渲染 `<front>`：journal-meta（期刊查表）+ article-meta（作者/单位/通讯/日期/摘要/关键词）。 |
| `body.py` | 渲染 `<body>`：按 Section 树逐块构造 `<sec>`/`<p>`/图/表/公式。 |
| `back.py` | 渲染 `<back>`：声明类小节（按标题关键词路由到 `<ack>`/`<glossary>`/`<sec>`）+ 参考列表 + IMR 固定的 Publisher's Note。 |
| `references.py` | 渲染参考列表：结构化字段齐 → `element-citation`，否则 → 整段原文 `mixed-citation`。 |
| `tables.py` | 渲染表格：`grid` 类型 → `<table>`（裸 `<th>`/`<td>`）；`image` 类型 → `<graphic>`（绝不读图）。 |
| `context.py` | 渲染上下文：把公式/图片 builder 与输出路径打包，只承载机械设施。 |

**出口校验（`verify/`）——机械保证：**

| 模块 | 职责 |
|------|------|
| `conservation.py` | 内容守恒校验：输出词多重集必须被 docx 词多重集（+ 允许的网络/标识补全）覆盖，暴露"编造词"。口径与评测 L1 一致。 |
| `verify.py` | 汇总出口校验：DTD 合法 + 内容守恒 + JATS4R 风格规则（结构自洽），产出报告。 |
| `repair.py` | 渲染 + 出口校验的编排（见 §7 对"为什么不回头重问 LLM"的说明）。 |

**机械设施（`build/`，从旧架构原样保留复用）：**

| 模块 | 职责 |
|------|------|
| `jats.py` | JATS 元素工厂 + 命名空间 + DTD 声明 + 序列化（输出带 `<!DOCTYPE article ... JATS 1.3>`）。 |
| `formulas.py` | OMML→MathML：用微软官方 `OMML2MML.XSL` 的开源移植做转换，重建为 `mml:` 前缀；display 公式把平衡括号折成 `<mfenced>`（与金标准一致）。 |
| `figures.py` | 图片外部化：直写原始字节（md5 命中去重），产出 `<fig>`。 |
| `xref.py` | 正文交叉引用解析：把文本里的 "Fig. N"/"Table N"/"[n]"/"[8–15]" 转成 `<xref>`，支持拼写数字（"Table one"）。 |

**其他：**
`parse/`（docx→IR，机械，`docx_reader`/`ooxml`/`runs`）；`model/blocks.py`（IR 数据模型
`Document`/`Paragraph`/`Table`/`TextRun`…）；`validate/`（DTD 校验器 + JATS4R 风格规则检查 +
悬空 xref/空表行的机械修复）；`enrich/journals.py`（期刊元数据查表，属允许的补全）；
`llm/`（模型接入 + 磁盘缓存）；`pipeline.py`（单一编排）；`cli.py`（命令行）。

> 说明：旧架构的 `classify/`（规则分类）与 `agent/`（视觉闭环）两个包，其源码已在本次重构中
> 删除（目录现为空壳），新代码无一处引用它们——已核实 `pipeline.py` 及全包内无 `import classify`
> / `import agent`。`model/` 仍在使用（作为 IR）。

## 4. 三 pass 契约

理解层把文档分成三段，各由一次 LLM 调用负责。之所以分三次而不是一次喂全篇：前置区、正文、
参考区各自的输出结构差别很大，分开能让每个提示词更专注、更短，也规避单次输出的长度上限。
分段的边界由 `segment.py` **机械**定位（找 "References" 标题或 `[1]`），不是内容判定。

三个 pass 的产物都是 JSON，都遵守"以 idx 引用源块、以子串给出切分"。下面是各自的契约
（字段口径对齐评测 L2 的语义键，见 §8）：

**front pass（前置区）** —— 产出：文章类型/栏目、标题块索引、作者列表（姓/名/单位角标/
通讯/共同贡献/ORCID/邮箱）、单位列表、通讯段块索引、投稿/修回/接收日期、编辑、摘要（是否
结构化 + 各子标题 + 段落块索引）、精要（Capsule）、关键词、**前置声明**（有些期刊把
Funding/Conflict 等放在摘要前）、以及"正文从哪块开始"（`body_start_idx`）。

**body pass（正文区）** —— 产出：`sections`（章节标题块索引 + 层级）+ `declarations`（尾部
声明块索引 + 标题 + 类别）+ `items`（图/表/公式）。**它不逐段枚举普通段落**——组装器按标题
层级重建章节树，两个标题之间的块自动归位；遇到图/表/公式的锚点就插入该对象并"消费"掉它
覆盖的源块跨度（比如一张制表符表覆盖题注行到最后一行）。这样普通段落无需 LLM 一一列出，
既省输出、又不会漏。

**references pass（参考区）** —— 逐条切字段：label、块索引、作者、et al、团体作者、文章标题、
来源（刊名/书名）、年、卷、期、起页、止页、DOI、注记、文献类型。**自适应分块**：把参考按
`[N]` 边界成块调用；若某块返回的条数少于预期（多因输出超上限被截断），就把该块**二分**再
分别重试，直到补齐——这样综述类几十上百条的超长参考也不会丢。

组装器（`assemble.py`）如何消费这三份 JSON：
- 正文类字段：按 idx 调 `_runs()` 取回原始 `runs`，格式零损失。
- 切分类字段：消费 LLM 给的子串，经守恒检查（是否 docx 归一子串）后落库，异常置空。
- 章节树：把正文标题与声明标题合并、按 idx 排序，每个标题拥有"到下一标题为止"的内容；
  正文标题按 `level` 用一个栈建成嵌套树，声明单列到 back。

> 依据：`understand/passes.py`（分块与二分）、`understand/prompts.py`（三份 JSON 的精确
> schema 与 guidance）、`understand/assemble.py`（`_assemble_front`/`_assemble_body`/
> `_assemble_refs` 的索引解析与守恒检查）。

## 5. 关键机制（本次重构挣来的）

这些是"让 LLM 判、让规则搬"这套方法在真实样例上跑通所必需的具体机制，每条都对应一个曾经
的坑。

- **结构化摘要块内切分**：整篇结构化摘要（Background:/Methods:/Results:…）常常挤在同一个
  docx 段落里。组装器把该段的 `runs` 按子标题位置切成多节，避免同一段被重复渲染。
  （`assemble.py` 的 `_split_abstract_runs`）
- **制表符表矩形归一**：有些"表格"是用 Tab 制表符对齐拼出来的伪表格。切分单元后要丢掉纯
  视觉对齐产生的空格，再按表头列数把每行补齐（短行补空单元、长行溢出并入末格）——把"视觉
  对齐的制表符表"正确重建成"逻辑矩形表"。（`assemble.py` 的 `_normalize_grid`）
- **原生表合并单元格**：真正的 `w:tbl` 表格，把 `gridSpan` 转成 `colspan`、`vMerge` 转成
  `rowspan`，并跳过被合并覆盖的续行单元格（否则会产出违反 DTD 的空 `<tr>`）。表头用裸
  `<th>`、表用裸 `<table>`（不加 scope/frame），与金标准一致。（`assemble.py` 的 `_native_grid`；
  `render/tables.py`）
- **前置声明捕获 + 裸声明补规范标题**：有的期刊（如 CEOG）把 Funding/Conflict 等声明放在
  摘要之前——由 front pass 捕获。无显式标题的"裸声明句"（如 "There was no funding..."），
  按类别补上 IMR house-style 的规范标题。（`prompts.py` 的 declarations 约定；`patterns.py`
  的 `CANON_DECL_TITLE`）
- **参考无标签条目按位置补号**：部分文献前几条不带 `[N]`（直接作者名开头），按位置补号，
  防止评测按 label 对齐时错位；ref 的 id 强制全局唯一。（`assemble.py` 的 `_assemble_refs`；
  `render/references.py` 的 `build_ref_list`）
- **参考字段出口守恒 + 结构化判定**：长字段（标题/刊名）与原文词重叠低于 40% 判为编造、
  置空；短字段（卷/期/页）必须是原文子串；作者姓必须在原文出现。只要有"来源 + 作者"就
  结构化成 `element-citation`（书籍无文章标题也能进），否则整段落回 `mixed-citation`。
  （`assemble.py` 的 `_sanitize_ref`）
- **公式安全网**：只有"整块基本就是一条公式（正文为空或仅是编号）"才作 `disp-formula`；
  含实质正文、只是顺带带了内联公式的段落，一律当普通段落渲染（内联公式随文走），**绝不
  丢文本**。（`assemble.py` 的 `_assemble_block` 中 `formula` 分支）
- **display 公式折 mfenced**：display 公式里成对的平衡括号折成 `<mfenced open close>`——这是
  presentation MathML 表示成对括号的标准做法，且与金标准一致（金标准 display 用 mfenced、
  inline 保留 `<mo>` 括号，故只对 display 折叠）。（`build/formulas.py` 的 `_fold_fences`）
- **交叉引用支持拼写数字**：正文里 "Table one"/"Figure three" 也能解析成 `<xref>`；区间
  "[8–15]" 展开为逐个链接；"Supplementary Fig. N" 不误链到正文同号图。（`build/xref.py`）

## 6. 出口校验，以及为什么"兜错在上游、不回头重问"

渲染完成后，`verify/verify.py` 跑三项**机械**校验，产出一份报告：

1. **内容守恒**（`conservation.py`）：把输出 XML 的内容词与 docx 的内容词做多重集比对，
   任何"输出有、docx 无"的内容词就是**编造**——硬违规。这项的词元归一化口径与评测 L1
   （`scripts/eval/fidelity.py`）保持一致，是"让 LLM 主导变安全"的最后一道关。
2. **DTD 合法**（`validate/validator.py`）：用 lxml 对着 JATS 1.3 DTD 校验，赛题硬要求。
3. **结构自洽**（`validate/checks.py`）：手写的 JATS4R 风格规则检查（JATS4R 是 JATS 的一套
   业界最佳实践规约），查悬空引用、空表等结构问题。

一个重要且容易被误解的设计选择：**出口发现问题时，系统并不回头把它重新丢给 LLM 修，而是
依赖上游的确定性守卫在问题产生前就挡住它。** `verify/repair.py` 当前就是"渲染一次 + 出口
校验出报告"，不含"重问 LLM"的循环。

为什么这样取舍？因为在本架构下，**正文按源块索引取回原文、内容守恒结构性成立，出口几乎
没有编造可修**；真正可能出错的只有极少数"LLM 切分子串"的地方，而这些已被**上游守卫**当场
挡下：
- **组装层**：参考字段非原文子串就置空、必要时退回 mixed-citation；无标签参考按位置补号；
  结构化摘要块内切分防重复。
- **渲染层**：交叉引用只在目标存在时才生成、ref id 强制唯一，从源头杜绝悬空/重复。
- **渲染末**：`validate/repair.py` 机械修掉残留的悬空引用、空表行。

上游守卫**确定、即时、无抖动**；回头向 LLM 重问既慢又引入不确定性，得不偿失。所以出口校验
的定位是"自检与留证"，而把"兜错"这件事前移到了确定性守卫上。
> 依据：`verify/repair.py` 的模块说明与 `render_verify_repair` 实现；`verify/verify.py`。

## 7. 模型、超参与技术选型

**理解层模型**：默认走 **dashscope**（阿里云百炼，OpenAI 兼容接口），模型 **qwen3.7-plus**
（文本与视觉同一模型）。关键超参：`temperature=0`（追求确定性复现）、`response_format=
json_object`（强制结构化输出）、关闭 thinking、`max_tokens=8192`、`timeout=240s`。**不做
超参调优**——temp=0 就是为了每次跑出一样的结果。架构 model-agnostic，换更强的模型即可
提升，无需改代码。
> 依据：`cli.py` 的 `--llm` 默认 `dashscope`；`llm/client.py` 的客户端参数。

**其他选型与依据**：

| 选型 | 决策 | 依据 |
|------|------|------|
| 语言 | Python 3.12 | 服务器无 Java/Maven；Python 生态（lxml/python-docx/OMML2MML/openai SDK）最贴本题。 |
| docx 解析 | python-docx + lxml | python-docx 给对象模型，lxml 直接读 `document.xml` 补上 python-docx 不暴露的 OMML 公式。 |
| 公式 | lxml.XSLT + 开源 OMML2MML.XSL | 微软官方样式表的开源移植，输出 presentation MathML，许可合规。 |
| XML 构建 | lxml 直接建 DOM | 正文结构复杂（嵌套 sec/表/图/公式），DOM 构建保证良构可校验。 |
| 校验 | lxml DTD + 手写 JATS4R 风格规则 | 本地集成、对 CI 友好，非 Schematron。 |
| 配置/CLI | YAML + .env / argparse | journals.yaml 可扩展；argparse 零依赖。 |
| LLM 缓存 | 按内容哈希磁盘缓存 | 省钱提速、保证结果可复现（冷缓存后重跑秒级、不产生额外调用）。 |

## 8. 评测成绩

**评测口径**（真值，绝不改动）：对冻结的 `样例数据/*/结构参考.xml`（含金标准里能从 docx
推导的 A 档信息 + 期刊查表补的 B 档，剔除人工编辑的 C 档），做三层**确定性**评测——L0 合法
（DTD + JATS4R 风格规则）、L1 忠实（对 docx 的词多重集 + 图片 md5）、L2 对位（按语义键
对齐 13 类元素）。**无加权总分，产物是缺陷清单，0 缺陷 = 满分。数字越低越好。**完整方法见
`../03-评测/评测体系设计.md`。

**重构后成绩**（10 个样例的缺陷数）：

| 样例 | 01 | 02 | 03 | 04 | 05 | S01 | S02 | S03 | S04 | S05 | **合计** |
|------|----|----|----|----|----|-----|-----|-----|-----|-----|---------|
| 缺陷 | 21 | 29 | 31 | 29 | 14 | 1 | 8 | 38 | 24 | 3 | **198** |

**全部 10 例 DTD 合法。合计 198 缺陷，低于旧规则架构基线的 228**——也就是说，新架构不但把
系统从"两层带分支、含 OCR 风险"简化成"单一无分支方法"，实测质量还略有提升（少 7 个缺陷）。
运行命令：`cd scripts && ../.venv/bin/python -m eval.run --llm dashscope`。

**残余缺陷多为度量伪差**（已知、不硬追）：如面板字母被拆词（"Fig 2a" 里的 "2a" 被拆成
"2"+"a" 而计一个丢词）、公式 MathML 的组合字符差异（92–97% 一致）、制表符表列数（金标准
人工判断本就不一致）、现代文献的"文章号 vs 页码"（纯数字型难区分）、S04 单个 `#` 与日期的
歧义。这些是评测口径的度量噪声，不代表转换实质出错。

## 9. 端到端一例（样例3 JIN49347）

以样例3 为例走一遍完整流程：

1. 命令：`python -m word2jats convert 样例/样例3/初始文件.docx --journal JIN
   --doi 10.31083/JIN49347 --figures 样例/样例3/figures.zip -o output/`
2. **parse** → IR（约 391 段、3 表、16 个 OMML 公式、7 个媒体）。
3. **serialize** → 内容流（每块一行带 idx，公式/图片换占位符）；机械定位参考区起点。
4. **understand（三 pass）** → front（作者/ORCID/摘要/关键词）、body（5 大节嵌套 + 图表公式
   锚点）、references（56 条逐条切字段）。
5. **assemble** → SemanticDoc（按 idx 取回原文 runs，切分字段过守恒检查）。
6. **render** → JATS 树；图片外部化为 `output/JIN49347/fig-0N.jpg`；OMML 转出 disp-formula；
   正文 "Fig. N/[n]" 解析成 `<xref>`。
7. **verify** → 内容守恒 + DTD + JATS4R 风格规则，落盘 `output/JIN49347.xml`。
