# 架构设计

> 本文说明 word2jats 转换系统的整体架构、分层、模块和技术选型。设计目标紧扣竞赛评分（见 `../00-调研/01-竞赛理解.md`）。
>
> 核对/修复闭环（`--agent` 档）的内部细节以 `02-智能循环架构.md` 为权威说明，本文与它一致。
>
> 本文涉及的领域术语（JATS、DTD、OMML、MathML、OOXML、JATS4R、element/mixed-citation、ORCID 等）在 `../00-调研/02-数据与映射规格.md` 有集中解释；**IMR / IMR Press** 指本赛题的目标出版方（总部在新加坡的国际学术出版商，样例论文即出自其旗下期刊）。

## 0. 一句话定位（先读，不可颠倒）

本系统的**核心不变量是"内容守恒"**：本赛题是结构化技术——文字本来就在 docx 里，转换要做的是**给已有文字判定正确的 JATS 结构标签**，而不是产生文字。因此**绝不用模型从图片里"读"字（OCR，光学字符识别），绝不扩写、改写、编造**；每个模块的取舍都以此为准（依据与实测数据见 `../02-开发/03-迭代日志.md` R17）。

由这条不变量推出系统的分工：

- **质量主体是确定性管线**（解析+分类+构建+校验）：确定性代码只会搬运原文，天然守恒。参考文献用**搜索式确定性切分**（每个字段都是原文子串，切不动就整条落回 mixed-citation）；图片表**确定性外部化为 `<table-wrap><graphic>`**（图片就是图片，不 OCR 重建）；制表符表**确定性切 Tab** 还原表格。实测确定性档（`--llm off`）10 样例总缺陷 4316→356（R17 重构前→后，降 91.8%），本身即产出合规、可交付的 XML。
- **LLM 只做结构判断，不生成文字**，两个用途：① 管线内的**难例兜底**——确定性锚点切不动的参考文献（书籍/会议录/APA 等）交 LLM 从原文切分，带**内容守恒护栏**（返回字段归一化后必须是原文子串，否则整条拒绝）；② `--agent` 的**核对/修复闭环**——章节层级、作者归属、声明拆分这类结构歧义由 LLM 判断、确定性代码移动已有内容块落地（权威说明见 `02-智能循环架构.md`）。实测 +LLM+agent 档在确定性基础上**只好不坏**：10 样例总缺陷 356→228，逐样例只降不升（样例1 93→43、样例2 53→28、样例3 63→37 等；`reports/eval/llm_agent`），且无新增编造。

> **两轮重构的关键纠正**：R15 去掉了早期"**结构/层级问题查出却丢弃**"的旧白名单行为——章节层级、作者归属、声明改由 LLM 修复器（阶段 A/B/C）**实际修复**，不再"仅记录、不修"。R17 进一步收编了闭环里"VLM 看图重建表"的 OCR 路径（实测在样例2 编造 617 个源文档没有的词、总缺陷翻倍）：内容补全（D）现只保留**漏作者重抽**一类（作者名在 docx 文本流里、可与源核对，带超集校验），漏表/漏图/漏式仅记录到 trace。系统的硬约束仍是两条——① 最终 DTD 合法（赛题硬要求）、② 不编造源没有的内容（即内容守恒，配守恒校验，改坏即回滚）。

## 1. 设计目标（紧扣评分项）

| 评分项 | 权重 | 架构如何回应 |
|----------|------|--------------|
| 落地性（工程是否扎实好用） | 40% | 分层清晰、模块化；独立 venv + 锁定依赖（结果可复现）；DTD 校验 + JATS4R 风格规则检查保证输出稳定；闭环全程留痕（`{article}.agent-trace.json`）可追溯、可重放；模型/渲染调用按内容哈希磁盘缓存，冷缓存后秒级；**三层确定性评测**（回路无 AI、无加权总分：L0 合法查 DTD + JATS4R 风格规则，L1 忠实对源 docx 做词多重集 + 图片 md5 校验，L2 对位对冻结的 `结构参考.xml` 按语义键逐类出命中/漏标/多标缺陷清单；产物是缺陷清单不是分数，见 `../03-评测/评测体系设计.md`）确保差异可核验、缺陷可追、结果可复现。**确定性档（`--llm off`）不依赖任何模型即产出合规 XML，且承担质量主体** |
| 创新性 | 30% | **核心创新 = 内容守恒不变量下的"确定性优先 + LLM 只判结构"**：参考文献搜索式确定性切分（每个字段都是原文子串，对不齐落回 mixed-citation；难例交 LLM 兜底并加守恒护栏——返回字段非原文子串即整条拒绝）；核对/修复闭环里 LLM 只输出结构判断（章节层级/作者归属/声明拆分/漏作者），由确定性代码移动已有内容块落地，守两条硬约束（DTD 合法 + 不编造）+ 守恒回滚（非一次性流水线、非解析器自证）；其下深入解析 OOXML（OMML→MathML、切 Tab 还原制表符伪表格、图片表确定性外部化） |
| 业务适用性（能不能真正用于实际场景） | 20% | 覆盖全部功能模块；输出严格符合 JATS 1.3 + IMR 出版约定；图片单独存为外部文件。"表是整张图片 / 用制表符拼"这类输入走**确定性处理**（外部化为 graphic / 切 Tab 还原），不冒编造风险；"无样式子标题 / 作者归属错配 / 声明是无标题裸句"这类**死规则永远枚举不完**的结构歧义，交给闭环据证据（docx 样式 / 源文本 / 渲染页）让 LLM 判断补救 |
| 展示度 | 10% | 完整的中文文档；CLI 和日志清晰；闭环全过程留痕落盘 `{article-id}.agent-trace.json`（逐轮记录每个修复器看了什么、判断、是否生效）；评测报告落盘 `reports/eval/<tag>/eval.{json,txt,html}`（三层结果按样例分列、无总分），结构参考核定/审查留痕归档 `评测产物/` |

**核心原则**（1 来自调研见 `../00-调研/02-数据与映射规格.md`，1a/3 由 R17 实测确立见 `../02-开发/03-迭代日志.md`）：
1. **忠实转换 docx 里的真实内容，绝不臆造编辑改动**——金标准里的人工编辑、外部补充信息，无法从输入推导出来。
   - 1a. 落到实现上就是**内容守恒**：只给已有文字判结构标签，绝不 OCR、不扩写、不编造——确定性代码天然守恒，LLM 输出须过守恒护栏。
2. **优先保证换没见过的文档也能处理**——评委会用新样例来测；死规则枚举不完真实输入的花样，结构歧义要让模型据证据去判断。
3. **确定性优先，LLM 只判结构**——凡是字段边界可搜索、结构可推断的活归确定性（`--llm off` 即产出合规、可交付的 XML，承担质量主体）；LLM 只在难例上"从原文切分"和"判结构歧义"。完整档 `--llm local --agent` 在确定性基础上进一步收敛（实测只好不坏）。
4. **所有外部数据都可配置**——journal-meta 查表、DOI 占位或绕过、CrossRef 可选。

## 2. 总体架构：确定性管线为主体 + LLM 增量层

系统是两层结构，主次分明：主体是确定性管线（承担质量主体、天然内容守恒），其上是可选的 LLM 增量层（管线内难例兜底 + `--agent` 核对/修复闭环，只判结构、不生成文字）；模型/渲染不可用时就交管线自身的输出。

```
┌──────────────────────────────────────────────────────────────────┐
│  主体：确定性管线 ── 质量主体，只搬运原文、天然内容守恒             │
│  parse → classify → build → serialize → validate  ── 见 §2.1      │
│  (参考文献搜索式切分 / 图片表→<graphic> / 制表符表切 Tab 还原)      │
│  `--llm off` 即产出合规、可交付的 XML(10 样例总缺陷 356)           │
└──────────────────────────────────────────────────────────────────┘
        │ 输出的 article(lxml)树                 ▲ 就地修复同一棵活树
        ▼ (可选 --agent)                         │
╔══════════════════════════════════════════════════════════════════╗
║  增量层：LLM 核对/修复闭环 (agent/) ── 只判结构,不生成文字          ║
║  渲染输入 Word 为页面图(人眼真值) + VLM 逐页视觉普查(各一次,缓存)   ║
║  → 修复器(看证据 → 判断 → 改 → 校验 → 留痕):                        ║
║    A 章节结构(据 docx 样式重排层级)  B 作者归属(LLM 修单位;ORCID 等确定性)║
║    C 后置声明拆分(裸句→命名小节)     D 漏作者重抽(超集校验,多轮)    ║
║  已删除"VLM 看图重建表"(OCR 必造字);漏表/漏图/漏式仅记录 trace      ║
║  两条硬约束(DTD 合法 + 不编造)+ 内容守恒,不过即回滚                 ║
╚══════════════════════════════════════════════════════════════════╝
```

> 修复器各修什么、凭什么证据、为什么“结构歧义要闭环而不是写更全的规则”、修复能力的诚实边界，
> 详见 `02-智能循环架构.md`（以它为准）。本文重点交代分层与模块。
>
> 编排见 `pipeline.py`：`--agent` 开启闭环；`agent/loop.py` 的 `run_agent_loop` 按
> A→B→C→D 顺序跑修复器，每步即时 DTD 校验 + 内容守恒，不过即回滚。证据来源不止视觉：
> 章节层级以 **docx 标题样式**为权威（视觉清点会把表格分组标签误当标题，故结构层级不采信
> 视觉标题），作者/声明据**源文本**，视觉普查用于发现"漏认了作者"这类计数差。关键区分不在
> "规则 vs 模型"，而在"单遍输出 vs LLM 据证据迭代核对修正"。

### 2.1 确定性管线的内部分层

确定性管线把 docx 转成合规 XML——`--llm off` 时它就是最终输出，开 `--agent` 时闭环在它产出的树上继续修：

```
┌─────────────────────────────────────────────────────────────────┐
│  CLI / Pipeline 编排层  (cli.py, pipeline.py)                      │
└─────────────────────────────────────────────────────────────────┘
        │  docx 路径 + 配置(期刊/元数据/LLM开关/--agent)
        ▼
┌──────────────┐   1. 解析层 parse/                                  │
│  OOXML 解析   │   docx(zip) → lxml/python-docx                     │
│              │   抽取: 段落+run格式 / 样式 / 编号 / 表 / 图(媒体)    │
│              │        / OMML公式 / 脚注尾注 / 超链接书签            │
└──────────────┘   产出: 规范化中间表示 IR (model/)                  │
        │
        ▼
┌──────────────┐   2. 语义识别层 classify/   (规则引擎 + 可选LLM)      │
│  角色判定     │   给每个 IR 块打语义标签:                            │
│              │   title/authortype/authors/aff/orcid/corresp/editor │
│              │   /date/abstract/keywords/heading(级)/figcap/tabcap  │
│              │   /reference/backsection/bodytext ...               │
│              │   低置信→LLM 兜底分类                                │
└──────────────┘   产出: 带语义标签的结构化文档 (StructuredDoc)       │
        │
        ▼
┌──────────────┐   3. 构建层 build/  (各模块 JATS 元素生成器)          │
│  JATS 构建    │   MetadataBuilder / BodyBuilder / FigureBuilder     │
│              │   FormulaBuilder / TableBuilder / ReferenceBuilder  │
│              │   XrefResolver                                      │
│              │   + 外部数据 enrich/ (journals 查表, CrossRef 可选)  │
└──────────────┘   产出: lxml ElementTree (JATS article)            │
        │
        ▼
┌──────────────┐   4. 序列化层 serialize                              │
│  输出         │   DOCTYPE + 命名空间 + pretty-print → .xml          │
│              │   图片外部化 → {article-id}/fig-0N.jpg              │
└──────────────┘
        │
        ▼
┌──────────────┐   5. 校验层 validate/                                │
│  QA          │   lxml DTD 校验 + 手写 JATS4R 风格规则检查 → 报告     │
└──────────────┘
```

**贯穿各层的公共能力**：`llm/`（统一模型客户端，带磁盘缓存——闭环与管线内难例兜底共用）、`config`（YAML/.env）、`logging`（结构化日志，记录每个模块的耗时和模型调用次数，作为落地性的度量依据）。

## 3. 中间表示（IR）

解析层和语义层之间用一套既不依赖 Word、也不依赖 JATS 的数据模型（`model/`），方便单独测试、也方便替换实现：

- `InlineRun`：文本片段 + 格式标志（bold/italic/sup/sub/code）+ 可选公式(OMML节点)/超链接。
- `Block` 基类，子类：`ParagraphBlock`（runs + styleId + styleName + numbering信息）、`TableBlock`（行列单元格，含合并）、`FigureBlock`（媒体引用 + caption）、`FormulaBlock`（OMML，inline/display）。
- `Document`：有序 `Block` 列表 + 全局信息（styles 映射、media 清单、footnotes、headers）。

语义层在 IR 之上产出 `StructuredDoc`：`FrontMatter`（title/authors/affs/abstract/keywords/...）+ `BodyTree`（嵌套 Section）+ `BackMatter`（refs/acks/...）。

## 5. LLM/VLM 的两个角色与受控使用

模型在本系统里担两个角色，共同的红线是**只判结构、不生成文字**（内容守恒）：

1. **核对/修复闭环（`--agent`）**：在 `agent/` 里驱动修复器——据 docx 样式重排章节层级、据源前置区修作者单位归属、拆分后置声明、补抽漏认作者。关键约束：**LLM 只输出结构决策（层级大纲 / 单位归属 / 分组），由确定性代码移动已有内容块落地，不让模型自由改写正文**；作者归属里**仅单位走 LLM**，ORCID/通讯/共同贡献/邮箱这类结构化数据走确定性解析与作者行标记检测（同姓也不混）。
2. **管线内的难例兜底**：确定性锚点切不动的参考文献（书籍/会议录/APA 等）交 LLM 从原文切分（`enrich/refs_llm.py`，带内容守恒护栏——返回字段非原文子串即整条拒绝）；解析作者行、角色分类拿不准时的局部兜底。只在确定性置信度低的局部才调用，**绝不把整篇文章丢给模型自由生成**。

工程上的受控措施（回应落地性顾虑）：
- **两条硬约束 + 多处可靠性护栏（如实披露，不止两处）**：硬约束只有两条："最终 DTD 合法"与"不编造源没有的内容"，每个修复器改完即时 DTD 校验 + 内容守恒校验，任一不过即回滚，绝不改坏。除硬约束外的护栏：A 章节"新增节须有源标题样式支撑"、C 声明"覆盖校验 + 只在能拆出更多命名节时才动"、B 作者"姓名集合不变 + ORCID 仅清张冠李戴"、D 内容补全"只保留漏作者重抽（`REPAIRABLE={extract_authors}`），新列表须涵盖既有作者（超集校验）；漏表/漏图/漏式仅记录到 trace"——旧的"VLM 看图重建表"已在 R17 删除，因为表格图片里的文字不在 docx 文本流里，OCR 读图无法与源核对、实测必造字；参考文献 LLM 兜底另有"字段须为原文子串"的守恒护栏。这些护栏防的是把噪声（表格分组标签、漏切段落、同姓误配、模型幻觉）当真实内容，而非限制 LLM 判断。
- **统一接口**：`LLMClient(provider, model)`，内部都走各后端 **OpenAI 兼容** 的 Chat Completions（本地为 sglang 起的 Qwen VLM 服务；**写具体端点和参数之前务必先查官方文档**）。
- **强制结构化输出**：按 JSON Schema 约束 + `temperature=0` + few-shot，事后再用规则校验（ORCID/DOI 正则、XML 是否合法）排除模型瞎编。
- **磁盘缓存**：按内容哈希缓存——页面不变则视觉普查只做一次；闭环多轮只重做核对+修复；重复运行不再产生额外成本，结果可复现、可秒级重放。
- **可降级**：`--llm off` 或模型/渲染不可用时，闭环自动跳过（`agent/loop.py` 开头即判 `llm.enabled`），直接交确定性管线的输出——仍是完整合规 XML 且承担质量主体，只是难例（参考文献难例、章节/作者/声明的结构歧义）得不到 LLM 的进一步收敛。

## 6. 技术选型与依据

| 选型 | 决策 | 依据 |
|------|------|------|
| 语言 | **Python 3.12** | 服务器没有 Java/Maven；Python 生态（lxml/python-docx/OMML2MML/openai）最适合本题；开发迭代快（见 `../参考资料/baseline代码分析.md` §8、`../参考资料/JATS与开源工具调研.md`） |
| 渲染（视觉真值） | **soffice（docx→PDF）+ pdftoppm（PDF→PNG）** | 纯 CPU、无需 GPU 即可得到“人眼真值”页面图，作为闭环独立核对的基准；真值来源独立于被测解析器，避免循环论证 |
| 本地多模态模型 | **两卡 RTX PRO6000 上 Qwen3.6-35B-A3B VLM（sglang，OpenAI 兼容）** | 本地推理、数据不出机；OpenAI 兼容接口便于在 local/云端间切换与降级 |
| docx 解析 | **python-docx + lxml** | python-docx 提供对象模型（段落/run/表/样式/编号），lxml 直接读 `document.xml` 来补上 OMML 和字段域（python-docx 不暴露 OMML，已查证 issue #213） |
| 公式 | **lxml.XSLT + 开源 OMML2MML.XSL** | 微软官方样式表的开源移植（plurimath/meTypeset），输出 presentation MathML，许可合规 |
| XML 构建 | **lxml 直接建 DOM**（正文）+ 轻量模板（固定元数据） | 正文结构复杂（嵌套 sec/表/图/公式），DOM 构建保证良构、可校验；也便于闭环就地改同一棵活树，无需序列化往返 |
| 配置 | **YAML + .env** | journals.yaml 可扩展；.env 存密钥（python-dotenv 加载） |
| 校验 | **lxml DTD + 手写 JATS4R 风格规则**（`validate/checks.py`，非 Schematron） | 本地集成，对 CI 友好；遵循 JATS4R 关键规则（见 `../00-调研/02-数据与映射规格.md`） |
| CLI | **argparse（stdlib）** | 零依赖，省资源 |
| 测试与评测 | **pytest 单测 + 三层确定性评测** | 单测含修复器安全护栏 `tests/test_agent_fixers.py`（集合不变/内容守恒/源支撑/DTD，守"抖动至多不生效、不改坏"）、闭环确定性核心 `tests/test_agent.py`、端到端回归；质量评测是三层确定性评测（回路无 AI、无加权总分）——L0 合法 `scripts/eval/validity.py`（DTD + JATS4R 风格规则，error/warning/info 三级严重度）、L1 忠实 `scripts/eval/fidelity.py`（对源 docx 词多重集 + 图片 md5）、L2 对位 `scripts/eval/structure.py`（对冻结 `结构参考.xml` 按语义键逐类出命中/漏标/多标 + 覆盖守门遍历两树防漏检 + B 档补全覆盖率单列）；评测器自带 `tests/test_eval.py`、集成 `tests/test_integration.py`，pytest 72 通过（详见 `../03-评测/评测体系设计.md`） |

## 8. 端到端数据流（以样例3 JIN49347 为例）

下面是**确定性管线**的数据流；完整档（`--llm local --agent`）会在第 4、5 步之间插入核对/修复闭环（见 §2、`02-智能循环架构.md`）：渲染页面图 + VLM 普查，再跑修复器（章节结构 / 作者归属 / 声明拆分 / 漏作者重抽），每步 DTD 校验 + 内容守恒、不过即回滚，之后再序列化校验。

1. `word2jats convert 样例/样例3/第一组/初始文件.docx --journal JIN --doi 10.31083/JIN49347 --figures 样例/样例3/第一组/figures.zip -o output/`（加 `--llm local --agent` 即走完整质量档；或用 `PYTHONPATH=src python -m word2jats convert ...`，见 `../../README.md`）
2. 解析层 → IR（391 段、3 表、16 OMML、7 媒体）。
3. 语义层 → StructuredDoc（front: 作者/ORCID/摘要/关键词；body: 5 大节嵌套；back: 56 参考文献）。
4. 构建层 → JATS 树；图片外部化 `JIN49347/fig-01.jpg`...；OMML→6 个 disp-formula。
5. 序列化 → `output/JIN49347.xml` + `output/JIN49347/fig-0N.jpg`。
6. 校验 → DTD 通过 + JATS4R 风格规则检查报告(`validate/checks.py`)。

## 9. 迭代路线（从能跑通的最小版本到现在的样子）

M0–M7 把“docx → 合规 XML”这条确定性管线打磨扎实——经 R17 重构后它承担质量主体（确定性档 10 样例总缺陷 4316→356）；M8 的闭环在其上收敛结构难例：

- **M0 骨架**：CLI + 管线 + IR + 序列化空壳，先把 docx→最小合规 XML 的流程跑通。
- **M1 元数据**：title/article-type/作者/aff/ORCID/corresp/编辑/日期/摘要/关键词 + journal 查表。
- **M2 正文**：sec 树/p/inline 格式/列表。
- **M3 图片**：外部化 + fig。
- **M4 公式**：OMML→MathML + disp/inline。
- **M5 表格**：真 w:tbl → table-wrap。
- **M6 参考文献**：解析 + element/mixed-citation + xref 交叉引用解析。
- **M7 校验 + 外部补全**：跑通 DTD 校验 + JATS4R 风格规则检查流程；CrossRef 可选；参考文献结构化。
- **M8 LLM 核对/修复闭环（收敛结构难例）**：`render/inspect` + 修复器（`structure`/`authors_fix`/`declarations`/`reconcile`+`repair`）+ `loop`——据 docx 样式重排层级、据源修作者单位归属（ORCID/通讯/共同贡献走确定性）、拆分裸声明、补抽漏认作者，循环收敛；两条硬约束（DTD 合法 + 不编造）+ 内容守恒回滚，去掉了早期"结构问题查出却丢弃"的白名单行为（R15），也删掉了"看图重建表"的 OCR 路径（R17）。覆盖死规则枚举不完的结构歧义（无样式子标题、特殊作者行、裸声明句等）。
- 每个里程碑都在样例上重新跑一遍、确认没改坏（见 `../03-评测/`）。
