# 决赛答辩要点（讲稿提纲 + 演示脚本 + 预设问答）

> 给决赛现场用。对着评分四项(落地40%/创新30%/业务20%/展示10%)组织。
> 口径与 `02-智能循环架构.md`、`../03-评测/评测体系设计.md` 一致(R15 重构后):
> **两大创新——① 内容守恒不变量下的"确定性优先 + LLM 只判结构"(修复闭环去掉了早期"结构问题查出却丢弃"的白名单行为,也删掉了"看图重建表"的 OCR 造字路径,R17);② 三层确定性评测体系(合法 / 忠实 / 对位,评测器回路无 AI,对照"结构参考"产出据源核验的缺陷清单、无加权总分,而非给项目打分)。**
> 确定性管线是质量主体(`--llm off` 即合规可交付);优雅降级是兜底底线,一句带过。
>
> 术语速记(现场万一被问):**JATS** = 期刊全文结构化标记 XML 标准;**DTD** = XML 的结构校验规则书,赛题要求输出必须通过;**back** = JATS 文章的"后置区",放致谢/资助/伦理等声明与参考文献;**ORCID** = 作者的全球唯一学者标识号。详见 `../00-调研/01-竞赛理解.md`、`../00-调研/02-数据与映射规格.md`。

## 一、讲清楚问题(30 秒)

学术出版社现在靠人工把投稿 Word 转成 JATS 标准 XML,费时费钱。我们做了一个程序自动干这件事。难点在于真实投稿千奇百怪——**标题无编号、子标题只靠加粗、表可能整张是图片或用制表符硬拼、声明是无标题的裸句子、同姓作者的 ORCID 极易错配**——这些非常规形态**死规则永远枚举不完**。

一句要立住的话:**正确性的真值是"忠实于源 docx",不是"通过我们自己定义的几个指标"。** 而判断"这个加粗行是子标题还是表格分组标签""这句裸声明该归哪个 back 小节"——**正是启发式做不了、LLM 据证据能做的事**。同样关键的是**知道何时不该用 LLM**:像同姓作者的 ORCID 归属、`*`/`†` 通讯/共同贡献标记这类结构化数据,LLM 在多个同姓作者下会张冠李戴,我们改用确定性解析(全名精确匹配)——**按字段选最可靠的方法,而非盲目都交给 LLM**。

## 二、核心创新一:内容守恒下的"确定性优先 + LLM 只判结构"(讲 2.5 分钟)

一句话:**文字本就在 docx 里,确定性管线先出一版合规 XML(质量主体),随后由 LLM 据 docx 样式 / 渲染页 / 源文本判断哪里不忠实于源、该怎么改——只判结构、不生成文字——就地修复并循环至收敛。**

讲透三点,这是和"假循环""一把梭""手搓白名单"拉开差距的地方:

1. **去掉了"结构问题查出却丢弃"的旧白名单行为,又划清了"不生成文字"的边界。** 早期版本把章节层级、作者归属、声明这类视觉/语义查出的问题一律"仅记录、不修"——R15 纠正了它:这些改由 A/B/C 三个 LLM 修复器**实际修复**。R17 进一步收编:内容补全阶段(D)现只保留 `REPAIRABLE={extract_authors}`(漏作者重抽,新列表须涵盖既有作者)——删除了 `rebuild_table`,因为 VLM 看图重建表=OCR 从图片读字,样例2 实测编造 617 个源文档没有的词;漏表/漏图/漏式只记录到 trace、不自动修——作为诚实的能力边界,如实披露。
2. **两条硬约束 + 多处可靠性护栏(明确披露)。** 硬约束:① **最终必须 DTD 合法**(JATS 1.3,赛题硬要求);② **不编造源文档没有的内容**(正确性底线)。除硬约束外还有这些护栏(如实列出,不止两处):A 章节"新增节须有源标题样式支撑"、C 声明"覆盖校验 + 只在能拆出更多命名节时才动"、B 作者"姓名集合不变 + ORCID 仅清张冠李戴"、D 内容补全"只保留漏作者重抽,新列表须涵盖既有作者";参考文献 LLM 兜底另有"字段须为原文子串"的守恒护栏。
3. **每步可校验、可回滚、可留痕。** 每个修复器改完即时做 **DTD 校验 + 内容守恒**(重建后原文每段都在),任一不过即**回滚,绝不改坏**;每步做了什么、是否生效、为何不生效全写进 trace,可复查可复现。

**四个 LLM 主导修复器**(各自都是"启发式做不了、LLM 据证据能做"的判断):

- **A. 章节结构修正** `agent/structure.py`:据 **docx 标题样式序列**(权威层级信号)定正确层级,**只移动已有内容块**重排。样例1 无编号加粗小标题 "Internal/External validation" 被启发式误升为顶级节、还漏了 Heading 3 "Model validation"——LLM 据样式判对层级,把误升为顶级的小标题归位、补回漏掉的子节(此类章节层级修正的效果,由评测 L2 对位层按章节命中/漏标/多标确定性衡量)。
- **B. 作者归属修正** `agent/authors_fix.py`:**只有单位 affs 用 LLM** 做多单位关联;**ORCID 用确定性"姓名:号"全名解析**,通讯/共同贡献/邮箱用热启动阶段对 `*`/`†` 标记的确定性检测——同姓作者下 LLM 不可靠(实测样例2 三个 Wang 曾被 LLM 全标通讯、挂同一邮箱、ORCID 张冠李戴),故这几项不用 LLM。修样例4 第一作者 Carmen 错挂第三作者 Ricardo 的 ORCID、样例2 三个同姓 Wang 的 ORCID 张冠李戴。
- **C. 后置声明拆分** `agent/declarations.py`:把**无标题的裸声明句**(如 "There was no funding...")识别并归入命名 back 小节(保守:仅在确有挤压时才拆,只依据源已有内容)。样例5 back 从 1 个挤压标题 → **5 个命名声明节**。
- **D. 内容补全(多轮)** `agent/reconcile.py` + `agent/repair.py`:页面可见、输出漏掉的内容——现只保留漏作者重抽(新列表须涵盖既有作者),多轮至无可补;漏表/漏图/漏式只记 trace("看图重建表"因 OCR 造字已在 R17 删除)。

> **为什么结构歧义要 LLM、而不是"写更全的规则"?** 输入形态不可穷举,规则总有边界。赛题考的正是用 Agent 吃下规则吃不下的**结构判断**;但文字永远只来自原文——若让模型产生文字,那是编造,不是结构化。

## 三、核心创新二:三层确定性评测,回路无 AI,产出据源缺陷清单(讲 1.5 分钟)

**评测的真值是"把这篇 docx 正确结构化",不是"和出版社上线版逐字节相同"。** 先把三个对象厘清——**源 docx**(内容的唯一权威)、**上线版本**(出版社最终发表 XML,= 忠实结构化 + 出版方编辑加工)、**结构参考**(把 docx 忠实结构化 + 可查补全,**A+B 无 C**,评测的唯一对照物)。**只对"结构参考"评,不拿掺了编辑加工的上线版当准确率标尺**——这是评测能做对的前提。

三个可得性档:**A** = docx 直接就有、该抽对(标题/作者/单位/ORCID/摘要/正文/表/公式/参考文献原文…);**B** = docx 没有但可查表/按出版惯例得到(刊名、article-id、文献 DOI/刊名全称、版权模板、交叉引用关联…);**C** = 纯出版编辑加工、从输入得不到(改写标题、替换重排文献、补写声明句、事后填日期…)。**结构参考只含 A+B、剔除 C**,故 C 档差异一律不作为缺陷。

把"对不对"拆成三件互相独立、各有真值的事,**三层评测器 100% 确定性、回路里没有一点 AI**:

- **L0 合法** `validity.py`:DTD(JATS 1.3,赛题硬要求)+ JATS4R 出版规范规则(公式须有机读式、ORCID 须完整 URL、id 全局唯一、xref 闭合、license 带链接、裸表不带多余属性),分 error/warning/info 三级。
- **L1 忠实** `fidelity.py`:对**源 docx** 的词多重集比对——真丢失 / 真编造(允许清单由结构参考确定性推出,无需手编)+ 图片逐字节 md5;守"只加结构、不改内容"。
- **L2 对位** `structure.py`:对冻结的**结构参考**按语义键(非位置/编号)对齐,逐类(front / 作者 / 单位 / 摘要 / 关键词 / 章节 / 图 / 表 / 公式 / 参考文献 / 交叉引用 / back)产出**命中 / 漏标 / 多标** + 缺陷条目;需联网的 B 档补全(DOI/ORCID/ext-link)单列"补全覆盖率",不混入结构分。

三点讲透,这也是评测的真正创新:

1. **覆盖靠"遍历两棵树"证明,不靠人列清单。** 遍历结构参考 ∪ 输出的每个节点,凡一边有、一边无必然撞见;再用**元素/属性全集守门**(10 例实测 106 种元素 × 40 种属性)断言比对器对每一种都有明确处置,任何未覆盖当场报警——**可证不漏整类**(实测查出并回填了首版漏登的 `pub-id/degrees/mtext` 等)。
2. **产物是据源、可复现、每条有出处的缺陷清单,顶层无加权总分。** 唯一的"分数"是**剩余真缺陷条数**(0=满分)+ 逐类命中率;有上线版(01–05)与无上线版(S01–S05)两组分列、不跨组平均。缺陷清单直接当转换器迭代的 backlog,而不是给项目打一个好看的分。
3. **三层全确定性,同输入同结果、可复现。** 早期评测必须引 AI,正因它拿输出去跟掺了编辑加工的上线版硬比、每处差异要 AI 裁是缺陷还是编辑加工;把对照物换成"无 C 的结构参考"后,输出与参考的任何差异只可能是转换器缺陷,这个判断不再需要 AI。AI 只在**一次性起草结构参考**时用过,且经多代理审查 + 逐疑点法官辩论后**人工核定冻结**,不进评测回路;评测器自身有 pytest 守 4 条不变量(参考自比零缺陷 / 覆盖守门零未覆盖 / 参考过 L0 / L2 两跑一致)。

> **这也是一次对自己的纠错。** 早期评测曾把结果压成"宏平均综合分 0.9X"这类单一分数、甚至一度拿自己的历史输出当参考目标——分数掩盖具体差异、无法指导修复,引入的 AI 打分还强随机。现已彻底重做:对照物永远是外部权威("结构参考",A+B 无 C),产物是确定性缺陷清单(权威设计见 `../03-评测/评测体系设计.md`)。

## 四、LLM 档的增益:实测只好不坏(讲 1 分钟)

用**评测的三层剩余真缺陷数**(L0/L1/L2,越少越好)对照两档(R17 后实测,`reports/eval/deterministic` 与 `reports/eval/llm_agent`):**确定性档 10 样例总缺陷 397,开 `--llm local --agent` 后 269**——逐样例只降不升(样例1 90→40、样例2 66→41、样例3 67→41、S05 25→10,其余持平或小降),且**无新增编造**(残余"编造"类与确定性档相同,系构建层标签词)。增益来自两处:参考文献难例的 LLM 守恒兜底(书籍/会议录/APA 从原文切分)+ 闭环的结构修复(章节层级/作者归属/声明拆分)。**我们不编"闭环 +X 分"**——消融工具在 `scripts/eval/ablation.py`(按阶段关闭、以剩余缺陷数计),各组件的单独贡献以其产物为准。

## 五、省钱的底气:确定性承担主体(讲 1 分钟)

LLM 不是从零烧钱。**一套"看内容判断"的确定性管线**——标题/作者/摘要/图/表/公式/参考文献/交叉引用——绝大多数内容零点几秒就处理对了,又快又稳又不花钱,`--llm off` 即产出合规、可交付的 XML(质量主体,总缺陷 4316→397 的下降全部来自确定性重构,见迭代日志 R17)。

分工一句话:**凡是字段边界可搜索、结构可推断的交给确定性;LLM 只花在两处——难例著录的"从原文切分"和结构歧义的判断,且只输出判断、不产生文字。**

## 六、工程可靠(穿插讲)

- **每步 DTD 校验 + 内容守恒 + 失败回滚**,绝不静默丢内容:表格构建失败有无损兜底;模型空响应不缓存、计入 `stats.failures`。
- **确定性兜稳**:ORCID 等结构化数据用确定性解析(非采样);渲染(docx→PNG)是确定性 CPU 产物,按内容哈希缓存,**dpi 120 实测 OCR 可读**。即便 LLM 偶有抖动,修复器的保守安全校验(集合不变/内容守恒/源标题支撑/DTD)也只会"不生效",不会改坏(`tests/test_agent_fixers.py` 守门)。
- **可复现 + 可消融**:模型调用按内容哈希落盘缓存,可秒级重放;`agent/loop.py` 支持按阶段开关,消融可验证。
- **测试**:`pytest` **72 项全过**(端到端遍历 10 例真跑 + DTD 校验 + 异常输入 + 单元测试 + 修复器安全护栏 4 项 + 评测器 4 条不变量)。
- **成本与依赖**:模型全在**本机两卡 GPU** 上跑,不依赖外网;也支持云端 OpenAI 兼容接口(DeepSeek/DashScope)。

## 七、现场演示脚本(3 分钟)

1. **确定性管线有多快**:`python -m word2jats convert 样例3 ...` → 零点几秒出 XML,当场跑 DTD 校验通过(这就是质量主体,不依赖模型)。
2. **LLM 主导修复(主秀)**:挑 R15 三个有据可查的修复实例,边演边开 `agent-trace.json` 看每步"做了什么/是否生效/为何不生效":
   - 样例1 章节层级错位 → LLM 据 docx 样式重排归位(误升的小标题降回、漏掉的子节补回);
   - 样例4 同姓 ORCID 张冠李戴 → 确定性全名解析归位;
   - 样例5 back 挤压 → 拆成 5 个命名声明节。
   **重点讲:这些是死规则做不到、且一次性流水线会静默漏掉的缺陷,被闭环据证据揪出并修复——质量与创新都在这里。**
3. **评测诚实(亮缺陷清单)**:打开 `reports/eval/latest/eval.html`——三层确定性评测(L0 合法 / L1 对源 docx 忠实 / L2 对结构参考对位)逐类列出命中/漏标/多标 + 每条据源的缺陷条目,**回路里没有 AI、同输入同结果**。讲:真值是"把 docx 正确结构化"(对照结构参考 A+B 无 C),C 档编辑加工不算缺陷;产物是缺陷清单、顶层不报加权总分,直接当迭代 backlog。

## 八、预设问答

- **Q:你们的创新到底是什么?** 两条:① **内容守恒下的"确定性优先 + LLM 只判结构"**——确定性管线承担质量主体(4316→397),LLM 据 docx 样式/渲染页/源文本判断结构歧义并就地修复,只判结构、不产生文字;**去掉了早期"结构问题查出却丢弃"的白名单行为**,守 DTD 合法 + 不编造两条硬约束(另有章节/声明/作者/内容补全各自的可靠性护栏),每步校验回滚留痕;② **三层确定性评测体系**——把评测拆成 L0 合法(DTD + JATS4R 规则)/ L1 对源 docx 忠实(词多重集 + 图片 md5)/ L2 对"结构参考"对位(按语义键逐类命中/漏标/多标),**评测器 100% 确定性、回路无 AI**;覆盖靠遍历两树 + 元素全集守门(可证不漏整类),产物是据源、可复现的缺陷清单、无加权总分,以"把 docx 正确结构化(A+B 无 C)"为真值。
- **Q:为什么不直接整篇丢给大模型?** 那种 naive 用法慢、贵、输出不稳、会编造,且**无从核对对错**。我们不是不用大模型,而是**用对**:确定性承担主体,LLM 只判结构、不产生文字(难例从原文切分带守恒护栏),据证据**定向修**、每步 DTD + 内容守恒校验、失败回滚。
- **Q:去掉旧白名单后,闭环会不会越修越坏、或者乱改?** 不会。两条硬约束(DTD 合法 + 不编造)兜底,每步内容守恒 + DTD 校验,**不过即回滚**;另有多处可靠性护栏(新增节须有源标题样式支撑、声明拆分须覆盖全部声明段且只在能拆出更多命名节时才动、作者姓名集合不变 + ORCID 仅清张冠李戴、内容补全只保留漏作者重抽且新列表须涵盖既有作者),防止把噪声当真实结构。单测守这些护栏。
- **Q:你们的评测可信吗?会不会自证?** 不会,而且比"换个判官"更彻底:**评测三层全确定性、回路里根本没有 AI**——同输入同结果,不存在模型给自己打分的问题。早期把评测压成单一综合分、还曾拿自己历史输出当参考,已彻底拆掉;现在对照物是外部权威的**结构参考**(A+B 无 C,由多代理审查 + 逐疑点法官辩论后人工核定冻结),L1 忠实直接对**源 docx** 校验。产物是缺陷清单不是分数,可重复、每条有出处;评测器自身有 pytest 守 4 条不变量。
- **Q:上线版本里有些内容你们没复现?** 那些是**出版层编辑加工**(分 DOI、补日期、拆表重编号、新增源里没有的声明节、给 ORCID 加认证标记),**无法从 docx 推导**(C 档)。这些在建"结构参考"时就已按 `scope.json` 逐条剔除,评测的对照物只含 A+B、不含 C,故确定性地**不以它们扣分**;我们忠实转源、不臆造,这些本该留给人工终校。
- **Q:只有 5 个样例,会不会过拟合?** 不为单样例特殊毛病写死;另用委员会补充的 5 篇"仅输入"新论文(S01–S05,无上线版、最干净)作**留出集**检验泛化——为它们同样冻结了"结构参考"(A+B 无 C),三层评测覆盖全 10 例,缺陷集中在少数系统性格式项;对异常输入(空/无结构/异常字符)也实测不崩、仍合规。
- **Q:还有哪些已知不足?** 诚实留档在评测缺陷清单(`reports/eval/deterministic`)与 `../02-开发/04-优化清单.md`,当前残差(确定性档 397 条)按处置分三类:**LLM territory**——参考文献难例(书籍/会议录/APA,已交守恒兜底,+LLM 档实测再降)与章节/声明长尾;**确定性可做**——表格 frame/rules 多余属性、aff 放置位置、交叉引用长尾;**度量伪差/金标准人工判断,不宜追**——公式括号写法(mfenced vs mo,数学内容一致)、制表符表列数(金标准系人工取舍)、个别 xref id 命名(金标准自身不一致)。评测按类聚合缺陷、覆盖靠遍历两树 + 元素全集守门(可证不漏整类),故清单可靠、可当迭代 backlog。
- **Q:能用到真实生产吗?** 输出严格符合 JATS 1.3 + 出版约定、过 DTD 校验;分层清晰、有测试有文档、闭环全程留痕可审计,可直接对接出版流程,人工只需终校出版层编辑内容。

> 注:模型/渲染都不可用时,可退回纯草稿档(`--llm off`)仍出合规 XML——这是**优雅降级兜底,以质量下降为代价,不是卖点**,现场一句带过即可。
