# 决赛答辩要点（讲稿提纲 + 演示脚本 + 预设问答）

> 给决赛现场用。对着评分四项（落地 40% / 创新 30% / 业务 20% / 展示 10%）组织。
> 口径与 `01-架构设计.md`、`../03-评测/评测体系设计.md` 一致（2026-07 架构倒置重构后）：
> **两大创新——① 倒置架构：把旧的"规则做理解 + LLM 打补丁"倒置为"LLM 做理解 + 规则做保证"的单一方法，靠"源块索引 + 占位符"让内容守恒结构性成立、物理杜绝 OCR 造字；② 三层确定性评测体系（合法 / 忠实 / 对位，回路无 AI，对照"结构参考"产出据源核验的缺陷清单、无加权总分）。**
> 落地效果一句话：全 10 例合计 **198** 个缺陷、**全部通过 DTD 校验**，低于旧规则架构基线 228，且 temperature=0、同输入确定复现。
>
> 术语速记（现场万一被问）：**JATS** = 期刊全文结构化标记 XML 标准；**DTD** = XML 的结构校验规则书，赛题要求输出必须通过；**LLM** = 大语言模型，能读懂自然语言的大模型；**OCR** = 光学字符识别，从图片里"认字"；**OMML** = Word 内嵌公式的原生格式；**IR** = 中间表示，把 docx 机械解析成的有序段落/表格结构；**back** = JATS 文章的"后置区"，放致谢 / 资助 / 伦理等声明与参考文献；**ORCID** = 作者的全球唯一学者标识号。详见 `../00-调研/01-竞赛理解.md`、`../00-调研/02-数据与映射规格.md`。

## 一、讲清楚问题（30 秒）

学术出版社现在靠人工把投稿 Word 转成 JATS 标准 XML，费时费钱。我们做了一个程序自动干这件事。难点在于真实投稿千奇百怪——**标题无编号、子标题只靠加粗、表可能整张是图片或用制表符硬拼、声明是无标题的裸句子、同姓作者的 ORCID 极易错配**——这些"看内容才能判它扮演什么角色"的判断，**死规则永远枚举不完**。

一句要立住的话：**正确性的真值是"忠实于源 docx"，不是"通过我们自己定义的几个指标"。** 判断"这个加粗行是子标题还是表格分组标签""这张表其实是一整张图片""这句裸声明该归哪个 back 小节""参考文献这一段里作者/刊名/卷页各到哪为止"——**正是死规则做不了、而 LLM 据证据能做的事**。

## 二、核心创新一：倒置架构——LLM 做理解、规则做保证（讲 3 分钟）

### 2.1 先讲"拧巴"从哪来

我们最早的做法是主流做法：**规则做理解 + LLM 打补丁**——用启发式规则去猜每一行的角色、每张表的形态、每条参考文献的字段，猜不动的地方再让模型事后修。这条路越走越拧巴，原因是结构上的：

- **理解是开放问题**：输入形态不可穷举，规则总有边界，于是规则越堆越多、越补越碎，仍然漏。
- **打补丁容易越界**：让模型去"修内容"，一不小心就改了原文、甚至编造；早期还试过让模型"看图重建表"，本质是 OCR 从图片读字，样例 2 实测编造出 **617** 个原文没有的词。
- **边界含糊**：哪些交规则、哪些交模型、查出的问题修还是不修，没有干净的分界，只能靠一层层白名单和补丁勉强圈住。

### 2.2 倒置：让每件事回到它该在的地方

**理解本质上是开放判断 → 整个交给 LLM；保证合法与守恒本质上是封闭的机械活 → 整个交给规则。** 分界一刀切干净，没有可选分支、没有降级档、没有"纯确定性档"。唯一流程只有一条：

```
docx ─parse(机械)→ IR ─serialize(机械)→ 内容流(每块一行带稳定[idx]，图/式/图片表→占位符 ⟦IMG#n⟧/⟦MATH#n⟧)
     ─understand(LLM 三 pass：front/body/references)→ 结构判定 JSON
     ─assemble(机械，按 idx 取回原始文字)→ 语义模型 SemanticDoc
     ─render(机械)→ JATS 树 ─verify(机械：内容守恒 + DTD + 结构自洽)→ 落盘 XML(+图片外部化)
```

### 2.3 四个立场（"化解拧巴"的核心，务必讲透）

1. **理解全归 LLM。** 哪行是标题 / 作者 / 题注、哪张表是图片、参考各字段边界——都由 LLM 判。规则不再含任何对内容的语义先验，不再堆枚举不完的死规则。

2. **内容守恒"结构性成立"，不靠事后补救——这是最关键的一点。** 正文类内容不由 LLM 重写，而是以"**源块索引**"引用 docx 里的原始文字：serialize 时每块打一个稳定编号 `[idx]`，LLM 只判"这块是什么角色"，assemble 时**按 idx 把原始文字原样取回**再渲染。**文字来自 docx、不来自模型输出**，所以斜体 / 上标 / 加粗零损失、守恒天然成立，而不是靠输出后再和原文比对去补救。只有必须把一个源块切成多个语义单元的地方（作者行→逐位作者、参考行→各字段、通讯段、结构化摘要块内），LLM 才给**子串**，出口再校验它确实是 docx 原文的子串——越界即拒。

3. **LLM 只拿占位符，物理杜绝 OCR 造字。** 图片 / 公式 / 被做成图片的表格，喂给模型的只是 ⟦IMG#1⟧、⟦MATH#1⟧ 这样的占位符，**不喂图像字节、不喂渲染图**。模型从头到尾看不到图，也就**不可能**从图里"读"出字来——造字这条路被从物理上堵死，而不是靠规则去防。旧架构"看图重建表"的路径已彻底删除。

4. **规则只做机械变换 + 出口保证。** 机械变换：OMML 公式转 MathML（能机读的数学标记）、图片按内容哈希外部化、JATS 序列化、正文交叉引用关联。出口保证：内容守恒（对源 docx 的词多重集比对）+ DTD 合法 + 结构自洽。守恒护栏的定位是"**为 LLM 兜错**"，不是"捆住 LLM"。

### 2.4 理解层怎么组织：三 pass 契约

LLM 的理解分三趟（pass），各自产出结构化 JSON，组装器机械消费：

- **front（前置区）**：判标题 / 作者（姓、名、单位标签、通讯、共同贡献、ORCID、邮箱）/ 单位 / 通讯段 / 收录日期 / 摘要（含结构化子标题）/ 关键词 / 前置声明 / 正文起点。
- **body（正文）**：判章节标题及层级 + 特殊块锚点（图 / 表 / 公式）。组装器按标题 level 重建章节树，两标题间的块自动归位——**不逐段枚举**。
- **references（参考文献）**：逐条切字段（标签 / 作者 / 刊名 / 年 / 卷 / 期 / 页 / DOI 等）。整块返回条数不足（模型超时或截断）时**自适应二分重试**到补齐。

### 2.5 这次重构挣来的关键机制（挑 2–3 个现场讲）

- **结构化摘要块内切分**：整篇摘要常挤在同一个 docx 块里，按子标题（Background: / Methods: …）切开，防止重复渲染。
- **制表符表矩形归一**：用制表符（Tab）视觉对齐硬拼的"伪表格"，切成内容单元、按表头列数补齐或并入末格，还原成真表。
- **前置声明补规范标题**：有的期刊把资助 / 利益冲突等声明放在摘要前、且不给标题，由 front pass 捕获，无标题的裸声明补上规范的命名节标题。
- **参考字段出口守恒**：长字段（标题 / 刊名）与原文词重叠不足就置空，短字段（卷 / 期 / 页）必须是原文子串，从根上防编造。

## 三、核心创新二：三层确定性评测，回路无 AI，产出据源缺陷清单（讲 1.5 分钟）

**评测的真值是"把这篇 docx 正确结构化"，不是"和出版社上线版逐字节相同"。** 先把三个对象厘清——**源 docx**（内容的唯一权威）、**上线版本**（出版社最终发表 XML，= 忠实结构化 + 出版方编辑加工）、**结构参考**（把 docx 忠实结构化 + 可查补全，**A+B 无 C**，评测的唯一对照物）。**只对"结构参考"评，不拿掺了编辑加工的上线版当准确率标尺**——这是评测能做对的前提。

三个可得性档：**A** = docx 直接就有、该抽对（标题 / 作者 / 单位 / ORCID / 摘要 / 正文 / 表 / 公式 / 参考文献原文…）；**B** = docx 没有但可查表 / 按出版惯例得到（刊名、article-id、文献 DOI / 刊名全称、版权模板、交叉引用关联…）；**C** = 纯出版编辑加工、从输入得不到（改写标题、替换重排文献、补写声明句、事后填日期…）。**结构参考只含 A+B、剔除 C**，故 C 档差异一律不作为缺陷。

把"对不对"拆成三件互相独立、各有真值的事，**三层评测器 100% 确定性、回路里没有一点 AI**：

- **L0 合法** `validity.py`：DTD（JATS 1.3，赛题硬要求）+ JATS4R 出版规范规则（公式须有机读式、ORCID 须完整 URL、id 全局唯一、xref 闭合、license 带链接、裸表不带多余属性），分 error / warning / info 三级。
- **L1 忠实** `fidelity.py`：对**源 docx** 的词多重集比对——真丢失 / 真编造（允许清单由结构参考确定性推出，无需手编）+ 图片逐字节 md5；守"只加结构、不改内容"。
- **L2 对位** `structure.py`：对冻结的**结构参考**按语义键（非位置 / 编号）对齐，逐类（front / 作者 / 单位 / 摘要 / 关键词 / 章节 / 图 / 表 / 公式 / 参考文献 / 交叉引用 / back）产出**命中 / 漏标 / 多标** + 缺陷条目；需联网的 B 档补全（DOI / ORCID / ext-link）单列"补全覆盖率"，不混入结构分。

三点讲透，这也是评测的真正创新：

1. **覆盖靠"遍历两棵树"证明，不靠人列清单。** 遍历结构参考 ∪ 输出的每个节点，凡一边有、一边无必然撞见；再用**元素 / 属性全集守门**（10 例实测 106 种元素 × 40 种属性）断言比对器对每一种都有明确处置，任何未覆盖当场报警——**可证不漏整类**。
2. **产物是据源、可复现、每条有出处的缺陷清单，顶层无加权总分。** 唯一的"分数"是**剩余真缺陷条数**（0 = 满分）+ 逐类命中率；有上线版（01–05）与无上线版（S01–S05）两组分列、不跨组平均。缺陷清单直接当迭代 backlog，而不是给项目打一个好看的分。
3. **三层全确定性，同输入同结果、可复现。** 把对照物换成"无 C 的结构参考"后，输出与参考的任何差异只可能是转换器缺陷，这个判断不再需要 AI。AI 只在**一次性起草结构参考**时用过，且经多代理审查 + 逐疑点法官辩论后**人工核定冻结**，不进评测回路。

## 四、落地效果：198 < 228、全例 DTD 合法、确定复现（讲 1 分钟）

用**评测的三层剩余真缺陷数**（L0 / L1 / L2，越少越好）看新架构成绩（`reports/eval/final`）：

| 样例 | 01 | 02 | 03 | 04 | 05 | S01 | S02 | S03 | S04 | S05 | **合计** |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 缺陷 | 21 | 29 | 31 | 29 | 14 | 1 | 8 | 38 | 24 | 3 | **198** |

- **合计 198，低于旧规则架构基线 228**——倒置架构不是"为创新而创新"，它同时把成绩做得更好。
- **全 10 例 DTD 合法**：每例 L0 的 error 数都是 0。
- **确定复现**：模型 temperature=0（采样温度，0 即每次取最可能的输出、不随机），同输入同结果，评测三层本就全确定性——整条链路可复现、可审计。

## 五、model-agnostic 与工程可靠（讲 1 分钟）

- **架构 model-agnostic，可换更强模型。** LLM 只吃一个契约：`内容流 → 结构判定 JSON`，与具体是哪个模型解耦。当前用阿里云百炼的 **qwen3.7-plus**（文本 + 视觉同一模型），response_format = json_object、关闭思维链、超时 240 秒；换成更强的模型，理解质量随之上涨，而**守恒护栏与出口校验一个字都不用改**——因为守恒不依赖模型，它是结构性成立的。我们不做超参调优（temp=0 求确定复现）。
- **出口每步校验 + 定点修复。** 每次转换在出口做内容守恒（词多重集）+ DTD + 结构自洽；发现悬空交叉引用、空表行等确定性问题时做定点修复并重校。转换结果里直接带 `n_fab`（编造词数）/ `n_lost`（丢失词数）/ `dtd_ok` 三个自检指标。
- **成本与依赖。** 默认走云端百炼（OpenAI 兼容接口）、不占本地 GPU；也支持本地多卡模型（sglang / vLLM）与 DeepSeek。模型调用按内容哈希落盘缓存，可秒级重放。
- **测试。** `tests/` 有端到端集成（遍历 10 例真跑 + DTD 校验）、评测器 4 条不变量、渲染层单元测试，守住"改代码不改坏出口"的底线。

## 六、现场演示脚本（3 分钟）

1. **跑一遍转换**：`python -m word2jats convert 样例3 --journal … --doi … --figures … -o …` → 产出 JATS XML，当场跑 DTD 校验通过；打印转换 stats，指着 `verify` 里的 `n_fab=0 / n_lost=… / dtd_ok=True` 说"守恒与合法是每次转换的自检项"。
2. **展示"理解与内容分离"（主秀）**：现场跑一小段，打印某样例 serialize 后的**内容流**——每块一行、带稳定 `[idx]`，图 / 式 / 图片表都是 ⟦IMG#n⟧ / ⟦MATH#n⟧ 占位符。**重点讲：模型从头到尾只看到这份带占位符的文本、没碰过一个图像字节，也没改过一个正文字；它只回"哪块是什么角色"的 JSON，正文文字全靠 `[idx]` 从 docx 原样取回。** 这就是"内容守恒结构性成立 + 物理杜绝 OCR 造字"的直观证据。
3. **评测诚实（亮缺陷清单）**：打开 `reports/eval/final/eval.html`——三层确定性评测（L0 合法 / L1 对源 docx 忠实 / L2 对结构参考对位）逐类列出命中 / 漏标 / 多标 + 每条据源的缺陷条目，**回路里没有 AI、同输入同结果**。讲：真值是"把 docx 正确结构化"（对照结构参考 A+B 无 C），C 档编辑加工不算缺陷；产物是缺陷清单、顶层不报加权总分。

## 七、预设问答

- **Q：你们的创新到底是什么？** 两条：① **倒置架构**——把"规则做理解 + LLM 打补丁"倒置为"LLM 做理解 + 规则做保证"的单一方法；靠"源块索引"让内容守恒**结构性成立**（正文文字来自 docx、不来自模型），靠"只喂占位符"从**物理上杜绝 OCR 造字**，规则只做机械变换 + 出口校验；② **三层确定性评测体系**——L0 合法 / L1 对源 docx 忠实 / L2 对结构参考对位，评测器 100% 确定性、回路无 AI，覆盖靠遍历两树 + 元素全集守门，产物是据源、可复现的缺陷清单、无加权总分。
- **Q：为什么不直接整篇丢给大模型？** 那种用法慢、贵、输出不稳、会编造，且**无从核对对错**。我们不是不用大模型，而是**用对**：让它只判结构、不产生文字；正文文字由源块索引从 docx 原样取回，切分处只给子串并出口校验为原文子串；图 / 式 / 表只喂占位符，模型看不到图。
- **Q：怎么保证不编造、不丢内容？** 三道结构性防线：① 正文文字来自 docx 的原始 run、不经模型改写，守恒天然成立；② 必须切分处模型只给**子串**，出口校验它是 docx 原文子串，越界即拒；③ 图 / 式 / 图片表只喂占位符、不喂图像，模型**没有渠道**从图里读字。此外出口再做词多重集守恒 + DTD 校验兜底。
- **Q：倒置之后，规则还剩什么？会不会又变成"规则做一切"？** 不会。规则只做两类**封闭的机械活**：机械变换（OMML→MathML、图字节外部化、JATS 序列化、交叉引用）和出口保证（守恒 / DTD / 自洽）。它不含任何对内容的语义先验——所有"看内容判角色"的开放判断都在 LLM 那边。
- **Q：架构绑死在某个模型上吗？** 没有。LLM 只吃"内容流 → 结构判定 JSON"这个契约，与具体模型解耦（model-agnostic）；当前 qwen3.7-plus，可无缝换更强模型，理解质量随之上涨，守恒护栏与出口校验不变。
- **Q：你们的评测可信吗？会不会自证？** 不会：**评测三层全确定性、回路里根本没有 AI**——同输入同结果，不存在模型给自己打分。对照物是外部权威的**结构参考**（A+B 无 C，多代理审查 + 逐疑点法官辩论后人工核定冻结）；L1 忠实直接对**源 docx** 校验。产物是缺陷清单不是分数，每条有出处；评测器自身有 pytest 守 4 条不变量。
- **Q：上线版本里有些内容你们没复现？** 那些是**出版层编辑加工**（分 DOI、补日期、拆表重编号、新增源里没有的声明节、给 ORCID 加认证标记），**无法从 docx 推导**（C 档）。建"结构参考"时已按 `scope.json` 逐条剔除，评测对照物只含 A+B，故确定性地不以它们扣分；我们忠实转源、不臆造，这些本该留给人工终校。
- **Q：只有 5 个样例，会不会过拟合？** 不为单样例特殊毛病写死；另用委员会补充的 5 篇"仅输入"新论文（S01–S05，无上线版、最干净）作**留出集**检验泛化，三层评测覆盖全 10 例。残差集中在少数系统性格式项；对异常输入（空 / 无结构 / 异常字符）也实测不崩、仍合规。
- **Q：还有哪些已知不足？** 诚实留档在评测缺陷清单与 `../02-开发/04-优化清单.md`。当前残余多为**度量伪差**：S03 的图注面板字母被拆词（"Fig 2a"→"2"+"a"，使词元 "2a" 被计丢）、公式 MathML 的组合字符差异（内容一致度 92–97%）、制表符表列数（金标准系人工取舍、本身不一致）、现代文献"文章号 vs 页码"（都是数字、难分）、S04 单个 `#` 与日期的歧义。数学内容与文字均一致，不宜硬追。
- **Q：能用到真实生产吗？** 输出严格符合 JATS 1.3 + 出版约定、过 DTD 校验；分层清晰、有测试有文档、出口每步校验且带自检指标，可对接出版流程，人工只需终校出版层编辑内容。
