# 决赛答辩要点（讲稿提纲 + 演示脚本 + 预设问答）

> 给决赛现场用。对着评分四项(落地40%/创新30%/业务20%/展示10%)组织。
> 口径与 `02-智能循环架构.md`、`../03-评测/01-评测报告.md` 一致(R15 重构后):
> **两大创新——① LLM 主导的修复闭环(去掉了早期"结构问题查出却丢弃"的白名单行为);② 两层诚实评测(以"源"为真值)。**
> 启发式打底是省成本的巧思;优雅降级是兜底底线,一句带过。

## 一、讲清楚问题(30 秒)

学术出版社现在靠人工把投稿 Word 转成 JATS 标准 XML,费时费钱。我们做了一个程序自动干这件事。难点在于真实投稿千奇百怪——**标题无编号、子标题只靠加粗、表可能整张是图片或用制表符硬拼、声明是无标题的裸句子、同姓作者的 ORCID 极易错配**——这些非常规形态**死规则永远枚举不完**。

一句要立住的话:**正确性的真值是"忠实于源 docx",不是"通过我们自己定义的几个指标"。** 而判断"这个加粗行是子标题还是表格分组标签""这句裸声明该归哪个 back 小节"——**正是启发式做不了、LLM 据证据能做的事**。同样关键的是**知道何时不该用 LLM**:像同姓作者的 ORCID 归属、`*`/`†` 通讯/共同贡献标记这类结构化数据,LLM 在多个同姓作者下会张冠李戴,我们改用确定性解析(全名精确匹配)——**按字段选最可靠的方法,而非盲目都交给 LLM**。

## 二、核心创新一:LLM 主导的修复闭环(讲 2.5 分钟)

一句话:**热启动先搭一版草稿,随后由 LLM 据 docx 样式 / 渲染页 / 源文本判断草稿哪里不忠实于源、该怎么改,就地修复并循环至收敛。**

讲透三点,这是和"假循环""一把梭""手搓白名单"拉开差距的地方:

1. **去掉了"结构问题查出却丢弃"的旧白名单行为。** 早期版本把章节层级、作者归属、声明这类视觉/语义查出的问题一律"仅记录、不修"——R15 纠正了它:这些改由 A/B/C 三个 LLM 修复器**实际修复**。内容补全阶段(D)仍按"已实现哪些补全器"取舍:`loop.py` 的 `REPAIRABLE={extract_authors, rebuild_table}`(成员与早期 `ACTIONABLE` 逐字相同)只对漏作者、漏表两类生效;漏图/漏式暂只记录到 trace、不自动修——作为诚实的能力边界,如实披露。
2. **两条硬约束 + 多处可靠性护栏(明确披露)。** 硬约束:① **最终必须 DTD 合法**(JATS 1.3,赛题硬要求);② **不编造源文档没有的内容**(正确性底线)。除硬约束外还有这些护栏(如实列出,不止两处):A 章节"新增节须有源标题样式支撑"、C 声明"覆盖校验 + 只在能拆出更多命名节时才动"、B 作者"姓名集合不变 + ORCID 仅清张冠李戴"、D 内容补全"仅启用已实现的两类补全器"。
3. **每步可校验、可回滚、可留痕。** 每个修复器改完即时做 **DTD 校验 + 内容守恒**(重建后原文每段都在),任一不过即**回滚,绝不改坏**;每步做了什么、是否生效、为何不生效全写进 trace,可复查可复现。

**四个 LLM 主导修复器**(各自都是"启发式做不了、LLM 据证据能做"的判断):

- **A. 章节结构修正** `agent/structure.py`:据 **docx 标题样式序列**(权威层级信号)定正确层级,**只移动已有内容块**重排。样例1 无编号加粗小标题 "Internal/External validation" 被启发式误升为顶级节、还漏了 Heading 3 "Model validation"——LLM 据样式判对层级,**章节分 0.84→1.00**。
- **B. 作者归属修正** `agent/authors_fix.py`:**只有单位 affs 用 LLM** 做多单位关联;**ORCID 用确定性"姓名:号"全名解析**,通讯/共同贡献/邮箱用热启动阶段对 `*`/`†` 标记的确定性检测——同姓作者下 LLM 不可靠(实测样例2 三个 Wang 曾被 LLM 全标通讯、挂同一邮箱、ORCID 张冠李戴),故这几项不用 LLM。修样例4 第一作者 Carmen 错挂第三作者 Ricardo 的 ORCID、样例2 三个同姓 Wang 的 ORCID 张冠李戴。
- **C. 后置声明拆分** `agent/declarations.py`:把**无标题的裸声明句**(如 "There was no funding...")识别并归入命名 back 小节(保守:仅在确有挤压时才拆,只依据源已有内容)。样例5 back 从 1 个挤压标题 → **5 个命名声明节**。
- **D. 内容补全(多轮)** `agent/reconcile.py` + `agent/repair.py`:页面可见、草稿漏掉的内容——漏作者看首页图重抽,漏表 VLM 看页面图重建为 `<table-wrap>`,多轮至无可补。

> **为什么核心必须是 LLM、而不是"写更全的规则"?** 输入形态不可穷举,规则总有边界。赛题考的正是用 Agent 吃下规则吃不下的部分;若规则就能完美解决,这比赛不会存在。

## 三、核心创新二:两层诚实评测(以"源"为真值,讲 1.5 分钟)

**正确性的真值是"忠实于源 docx",而非"通过我们自己定义的某几个指标"。** 这是本作品评测的立场,也是一次对自己的纠错:

> **被推翻的旧做法(R14 pass@k):** 只比 7 个结构计数,**且把我们自己的历史输出当参考目标**——"10/10 全过"只证明"稳定复现了自己(含 bug)的输出",不证明对金标准/源正确。R15 彻底重建。

- **Layer-1(全面可定义指标)** `scripts/eval/`:参考目标**永远是外部权威标签**(委员会金标准 / 独立三方核验伪标签),逐维度比对(章节树与层级、作者全字段、单位、摘要、图表公式、文献、back 各声明节…),**宏平均综合分 0.967**。
- **Layer-2(每输出派独立 subagent 逐字审查)**:对**每个样例的每一次输出**单独派一个**全新** subagent,读入 输出 XML + 标签 + **源 docx**,逐字比对;再派一个**对抗性二审(critic)**找一审漏报。据源把每处差异判为**真缺陷**(源确有、我方没忠实呈现)或**出版层差异**(标签的 DOI/日期/拆表/新增声明等不可推导的编辑)。各样例**对源忠实度 0.80–0.96(宏均 0.93)**;归档 `reports/eval_judge/judge_v2.json`。

**为什么 Layer-2 不可或缺(关键论点):** 它**结构上**能发现 Layer-1 覆盖不到的问题——正是它(及对抗二审)抓出了章节层级错位、核心公式漏抽、ORCID 张冠李戴、表头错置、单元格换行丢失等真缺陷。早期"三方验收"之所以失灵,就是因为审查口径只覆盖同一批可定义计数、**没人拿输出去和标签/源逐字比**;本层从机制上补上了这一点。

> 金标准 ≠ docx 的纯函数:它含大量出版层编辑(分配 DOI、补日期、把标题排成 "2.1"、新增源里没有的声明节、拆表重编号、给 ORCID 加 `authenticated`…),**无法从 docx 推导**。所以"与金标准每处差异都算缺陷"是错的;Layer-2 据源把这些归为出版层差异,不冤枉我方、也不放过真缺陷。

## 四、消融证据:每个组件确实有用(摆数据,讲 1 分钟)

`scripts/eval/ablation.py` 逐个关闭某组件,用 Layer-1 综合分量化各自贡献(对原始样例 1–5):

| 配置 | 宏平均综合 | 贡献 |
|------|-----------|------|
| **全开(热启动 + 四修复器)** | 0.937 | 主路径 |
| 仅热启动(关掉整个闭环) | 0.918 | 闭环整体 **+0.020** |
| 关章节结构修正 | 0.929 | 样例1 **0.905→0.946(+0.041)** |
| 关声明拆分 | 0.930 | 样例5 **0.833→0.870(+0.037)** |
| 关作者归属修正 | 0.933 | 样例4 **+0.012**、样例5 +0.008 |
| 关内容补全 | ≈0.937 | 规范样例无缺表/缺作者,**≈0**——安全网,缺内容才触发(如实标注) |

> 诚实说明:绝对 Δ 偏小,是因为 Layer-1 对金标准的分被出版层差异"封顶"(再修也追不平编辑加工);**各组件在其针对维度上的提升才是价值**(如结构修复把样例1 章节分 0.84→1.00)。消融如实暴露"内容补全在规范样例几乎不触发"——这不藏,它是为非规范输入准备的兜底。

## 五、省成本的巧思:启发式打底(讲 1 分钟)

闭环不是从零烧钱。**先用一套"看内容判断"的确定性规则跑出一版合规草稿**——标题/作者/摘要/图/真表格/公式/参考文献/交叉引用,绝大多数文档零点几秒就处理对了,又快又稳又不花钱。这版草稿给闭环一个好起点:**少转几轮、少调几次模型、省成本**。

启发式是**加速器,不是核心**:它负责"便宜的大多数",闭环负责"难啃但决定质量的少数"。**质量来自闭环。**

## 六、工程可靠(穿插讲)

- **每步 DTD 校验 + 内容守恒 + 失败回滚**,绝不静默丢内容:表格构建失败有无损兜底;模型空响应不缓存、计入 `stats.failures`。
- **确定性兜稳**:ORCID 等结构化数据用确定性解析(非采样);渲染(docx→PNG)是确定性 CPU 产物,按内容哈希缓存,**dpi 120 实测 OCR 可读**。即便 LLM 偶有抖动,修复器的保守安全校验(集合不变/内容守恒/源标题支撑/DTD)也只会"不生效",不会改坏(`tests/test_agent_fixers.py` 守门)。
- **可复现 + 可消融**:模型调用按内容哈希落盘缓存,可秒级重放;`agent/loop.py` 支持按阶段开关,消融可验证。
- **测试**:`pytest` **33 项全过**(端到端 + DTD 校验 + 异常输入 + 单元测试 + 修复器安全护栏 4 项)。
- **成本与依赖**:模型全在**本机两卡 GPU** 上跑,不依赖外网;也支持云端 OpenAI 兼容接口(DeepSeek/DashScope)。

## 七、现场演示脚本(3 分钟)

1. **启发式打底有多快**:`python -m word2jats convert 样例3 ...` → 零点几秒出 XML,当场跑 DTD 校验通过(这是热启动草稿,给闭环省成本)。
2. **LLM 主导修复(主秀)**:挑 R15 三个有据可查的修复实例,边演边开 `agent-trace.json` 看每步"做了什么/是否生效/为何不生效":
   - 样例1 章节层级错位 → LLM 据 docx 样式重排,**章节分 0.84→1.00**;
   - 样例4 同姓 ORCID 张冠李戴 → 确定性全名解析归位;
   - 样例5 back 挤压 → 拆成 5 个命名声明节。
   **重点讲:这些是死规则做不到、且一次性流水线会静默漏掉的缺陷,被闭环据证据揪出并修复——质量与创新都在这里。**
3. **评测诚实(亮 Layer-2)**:打开 `reports/eval_judge/judge_v2.json`——每个输出派独立 subagent 逐字对照标签 + 源 docx,**真缺陷与出版层差异分开记**,据源裁定。讲:我们不拿自己的输出自证,真值永远是外部标签和源 docx。

## 八、预设问答

- **Q:你们的创新到底是什么?** 两条:① **LLM 主导的修复闭环**——热启动后由 LLM 据 docx 样式/渲染页/源文本判断并就地修复,**去掉了早期"结构问题查出却丢弃"的白名单行为**,守 DTD 合法 + 不编造两条硬约束(另有章节/声明/作者/内容补全各自的可靠性护栏),每步校验回滚留痕;② **两层诚实评测**——可定义指标对外部权威标签 + 每输出派独立 subagent 逐字对源审查,以"忠实于源 docx"为真值。
- **Q:为什么不直接整篇丢给大模型?** 那种 naive 用法慢、贵、输出不稳、会编造,且**无从核对对错**。我们不是不用大模型,而是**用对**:启发式打底省成本,LLM 据证据**定向修**、每步 DTD + 内容守恒校验、失败回滚。
- **Q:去掉旧白名单后,闭环会不会越修越坏、或者乱改?** 不会。两条硬约束(DTD 合法 + 不编造)兜底,每步内容守恒 + DTD 校验,**不过即回滚**;另有多处可靠性护栏(新增节须有源标题样式支撑、声明拆分须覆盖全部声明段且只在能拆出更多命名节时才动、作者姓名集合不变 + ORCID 仅清张冠李戴、内容补全仅启用已实现的两类补全器),防止把噪声当真实结构。单测守这些护栏。
- **Q:你们的评测可信吗?会不会自证?** 不会。R15 已拆掉旧 pass@k(它把自己历史输出当参考、只是复现自己含 bug 的输出)。现在参考目标**永远是外部权威标签**(委员会金标准 / 独立三方核验伪标签);并新增**每输出派全新 subagent 逐字对源审查 + 对抗二审**这一层,专抓可定义指标覆盖不到的问题。
- **Q:金标准里有些内容你们没复现?** 那些是**出版层编辑**(分 DOI、补日期、拆表重编号、新增源里没有的声明节、给 ORCID 加认证标记),**无法从 docx 推导**。Layer-2 据源已逐条确认这些是**出版层差异、非我方缺陷**;我们忠实转源、不臆造,这些本该留给人工终校。
- **Q:只有 5 个样例,会不会过拟合?** 不为单样例特殊毛病写死;另用委员会补充的 5 篇"仅输入"新论文 + 三方交叉验证的伪标签检验泛化(Layer-1 对 S1–S5 综合 0.989–1.000);对异常输入(空/无结构/异常字符)也实测不崩、仍合规。
- **Q:还有哪些已知不足?** 诚实留档 `judge_v2.json`:核心公式漏抽(样例1)、个别多层表头/表脚注归置、参考文献字段粒度(edition/PMID/姓名后缀等)、结构修复后段落 `@id` 一致性。**HIGH 级(结构/ORCID)已全部修复**,其余均为热启动/构建层质量,作为下一轮优化的明确清单(见 `../02-开发/04-优化清单.md`)。
- **Q:能用到真实生产吗?** 输出严格符合 JATS 1.3 + 出版约定、过 DTD 校验;分层清晰、有测试有文档、闭环全程留痕可审计,可直接对接出版流程,人工只需终校出版层编辑内容。

> 注:模型/渲染都不可用时,可退回纯草稿档(`--llm off`)仍出合规 XML——这是**优雅降级兜底,以质量下降为代价,不是卖点**,现场一句带过即可。

## 九、PPT 结构建议(8–10 页)
