# 健壮性设计与出口守恒护栏

> 本文回答一个核心疑问：既然"理解"全交给了大模型（LLM），**凭什么保证输出可靠、不出错、不编造**？
> 答案是一套贯穿架构的护栏。本文逐条讲清这些护栏的位置、原理和它挡住的具体风险，用来说明工程做得
> 扎实可靠（对应评分里的"落地性"）。
>
> 本文涉及的 XML / 出版术语（DTD、IDREF/rid、xref、ORCID、element/mixed-citation、词多重集等）
> 在 `../00-调研/02-数据与映射规格.md` 有集中解释，首次用到时也会简要说明；模块位置见
> `01-开发者指南.md`。

## 0. 总纲：三道防线，让"LLM 主导"变安全

把"这段是什么"交给 LLM 判断，天然带来一个担忧：模型可能判错，甚至凭空写出原文没有的字。本架构
用三道彼此独立的防线把这个风险压到最低：

1. **内容守恒结构性成立**（第一道，见 §1）：正文的文字根本不经过模型的手——程序按"源块索引"
   把 Word 原文取回来渲染。文字来自中间表示（IR），不来自模型输出，所以正文层面**没有编造的可能**。
2. **出口守恒硬校验**（第二道，见 §2）：对于确实需要模型切分的地方（作者、参考字段等），在出口把
   输出和 docx 原文做逐词比对，非原文子串的一律置空或整条退回原样。模型即使乱写，也会在这里被拦下。
3. **机械修复兜底**（第三道，见 §3）：渲染末尾用确定性规则修掉任何残留的结构瑕疵（悬空引用、
   空表行等），保证最终一定通过 DTD 校验。

守恒护栏的定位是"**为 LLM 兜错**"，不是"捆住 LLM"——理解上放手让模型判，出口用规则保证不出格。

## 1. 第一道防线：内容守恒结构性成立

**内容守恒**是本项目的核心不变量：赛题是"结构化"技术——文字本来就在 docx 里，转换要做的是给已有
文字**判定正确的结构标签**，而不是产生文字。

做法（在 `understand/serialize.py` 与 `understand/assemble.py`、`semantic/model.py`）：

- 序列化内容流时，图片 / 公式 / 图片表**只给占位符** `⟦IMG#n⟧` / `⟦MATH#n⟧`，不喂字节、不喂
  渲染图。模型物理上看不到图里的字，也就**不可能 OCR 造字**（旧架构曾让模型看图重建表，实测在
  某样例编造了几百个源文档没有的词，这条路径已删除）。
- LLM 的产出以 `[idx]` 指回源块。组装时，正文类内容（段落、章节标题、图表题注）一律用 `idx`
  **取回原始 runs**（`run` = Word 里一段连续同格式的文字），斜体 / 上标 / 加粗零损失。
- 只有"必须把一个源块切成多个语义单元"的少数地方（作者行→逐位作者、参考行→各字段、结构化摘要
  块内切分、通讯段），LLM 才给出**子串**——而子串还要过第二道防线。

因此"正文不丢字、不改字、不加字"是**结构性**成立的，不靠模型自觉。这也是能放心让 LLM 主导理解的前提。

## 2. 第二道防线：出口守恒硬校验

### 2.1 全局内容守恒校验（`verify/conservation.py`）
把 docx 和输出 XML 各自拆成"**内容词多重集**"（token multiset——把文本切成词、按出现次数计的集合），
比对两者：

- **输出有、docx 没有**的内容词 = **编造**（硬违规，`n_fab`）。
- **docx 有、输出没有**的内容词 = 可能漏内容（软信号，`n_lost`；含合法剥离的标签 / 角标）。

口径与评测 L1（`scripts/eval/fidelity.py`）**独立复刻并保持一致**：内容词 = 长度≥2 且非纯数字
（角标 / 年份 / 页码是结构化的天然产物、噪声大，不计）；归一化处理上下标数字、各种连字符、空白。
DOI 链接、ORCID URL 等"B 档网络子树"（`ext-link`/`pub-id`/`contrib-id`/`uri`）属于允许的查表补全，
不计入编造。这道校验让"LLM 若把某字段写成非原文子串"在出口被当作编造词暴露出来。

### 2.2 参考字段出口守恒（`understand/assemble.py::_sanitize_ref`）
参考文献是最容易被模型"脑补"的地方（模型见多了文献格式，可能自动补全一个原文没写的刊名或页码）。
每条参考在组装时逐字段核对其是否来自该条原文：

- **长字段**（文章标题、刊名、注释）：与原文的**词重叠**若低于 40%，判为编造 → 置空
  （用词重叠而非精确子串，是为了容忍跨块拼接时偶尔缺个尾词）。
- **短字段**（卷 / 期 / 起页 / 止页）：必须是原文的归一化子串，否则置空（防编造页码 / 卷号）。
- **年份**：必须原样出现在原文里。
- **作者姓**：必须在原文中出现，否则从作者列表剔除。

只有同时有刊名 / 书名（source）+ 作者 / 文章标题时才判为结构化（渲染成 `element-citation`），
否则整条落回 `mixed-citation`（整段原文兜底）——**宁可少结构化，也不编造**。书籍类无文章标题
但有书名，同样能进结构化引用（否则永远落 mixed）。

### 2.3 子串软守恒（组装期）
作者、单位、关键词等被切出的子串，组装时也做一次"是否 docx 归一子串"的软检查，异常记入 warnings
供出口校验参考。

## 3. 第三道防线：机械修复与结构自洽

### 3.1 交叉引用只在目标存在时生成（`build/xref.py`）
docx 里没有引用域 / 书签，`Fig. 1`/`Table 2`/`[5]` 全靠文本识别转成 `<xref>`（带 `rid` 指向目标
id 的交叉引用元素）。规则：**只有目标 id 确实存在**时才生成 `<xref>`，否则保留原文——绝不产生指向
空处的悬空 IDREF（会导致 DTD 校验失败）。另外两个易错点也已处理：区间展开设上限 40（避免把
"pp. 8–150"这种页码误当引用区间展开）；"Supplementary Fig. N"不链接到正文同号图表。

### 3.2 ref id 强制唯一（`render/references.py`）
参考条目的 id 取自显示编号（`b<n>`）。但无标签条目按位置补的号，可能和某个带标签条目的号相撞，
造成重复 id（重复 id 会让 DTD/IDREF 失效）。渲染时维护一个已用 id 集合，冲突就退避成
`b<n>_<i>`，**保证全局唯一**。

### 3.3 机械 DTD 修复（`validate/repair.py`）
渲染末尾对整棵树做最后一遍确定性修补，纯结构操作、不改语义：

- **悬空 xref**：`rid` 指向不存在的 id → 拆掉 xref 外壳、保留其文字（同时把 tail 文本并到相邻节点，不丢字）。
- **空表格行**：`<tr>` 里没有任何 `<td>`/`<th>`（DTD 规定"一行至少含一个单元格"，记作
  `tr=(th|td)+`）→ 删除该行。

上游已尽量不产生这些瑕疵，这里是对"没见过的奇怪文档"的兜底。

## 4. LLM 误判的机械纠偏

LLM 判错时，用确定性规则在组装 / 渲染阶段就地纠正，不返工重问：

- **抗超时 / 抗截断的参考自适应分块**（`understand/passes.py::_refs_chunk`）：参考文献几十上百条，
  按 `[N]` 边界分块（每块 28 条）调用。某块返回条数少于预期（多因单次输出超上限被截断），就
  **自适应二分**递归重试——半块更小、更容易在输出上限内完成，直到补齐。综述类超长文献也能拿全。
- **无标签参考按位置补号 + label 误抓纠正**（`understand/assemble.py::_assemble_refs`）：部分
  文献前几条没有 `[N]` 前缀（直接作者名开头），按位置补号，防评测按 label 对齐时错位。又因为
  内容流每块带 `[块索引]` 前缀，模型可能把块索引误当参考标签——若 label 号恰是本条的某个块索引，
  判为误抓、改按位置补号。
- **公式安全网**（`understand/assemble.py::_assemble_block`）：只有"整块基本就是一条公式（文本为空
  或仅是编号）"才作块级公式；含实质正文的段落即使带内联公式，也当普通段落渲染（内联公式随文走），
  **绝不丢文本**。
- **结构化摘要块内切分防重复**（`understand/assemble.py::_split_abstract_runs`）：整篇结构化摘要
  常挤在同一个 docx 块里，按子标题（Background:/Methods:…）在块内切 runs——若不这么切而是让每个
  子标题各自引用整块，会把整段摘要重复渲染多次。
- **空元素跳过**（`render/body.py`）：空 `<p>`、只有标题无内容且无子节的空 `<sec>`（多因同级标题
  被误判为兄弟节）一律跳过，丢弃比产出违规空元素稳妥。
- **共同贡献噪声过滤**（`render/front.py::_equal_real`）：只有"有明确共同贡献声明"或"≥2 位作者
  共享该标记"才生成共同贡献脚注；单个作者带孤立 `†/#` 且无声明视为排版噪声，不生成。
- **原生表 / 制表符表机械重建**（`understand/assemble.py`）：原生表按 `gridSpan→colspan`、
  `vMerge→rowspan` 合并单元格并跳过续行单元格（避免空 `<tr>`）；制表符表（用 Tab 对齐的伪表格）
  切内容单元、丢视觉对齐产生的空格、按表头列数归一成矩形。

## 5. 接口与环境健壮性

- **模型不可达 / 缺 Key 的优雅兜底**（`llm/client.py`）：需要 Key 却没有、或客户端初始化失败时，
  `provider` 退回 `off`、`enabled=False`，调用返回 `None`。理解层据此产出空结构，渲染层仍能吐出
  一个 DTD 合法的骨架 XML，不崩溃、不报错。这是接口层的健壮兜底，**不是"可选的纯规则方法档"**。
- **空响应不缓存、失败可观测**（`llm/client.py`）：调用失败 / 返回空内容计入 `stats.failures`
  并打日志；空响应**不写入缓存**，让瞬时抖动下次可重试，而不是把一次失败永久冻结。
- **DTD 加载的中文路径坑**（`validate/validator.py`）：老版 libxml2 无法解析含非 ASCII 字符的
  绝对路径，而本项目目录名含中文，会导致 DTD 静默加载失败、所有校验退化为"跳过"（假通过）。
  修法：先 `chdir` 到 DTD 所在目录、再用相对文件名加载，DTD 内部的 `.ent`/`.mod` 子模块也随之
  按当前目录正确解析，新老 libxml2 均可。
- **JSON 容错解析**（`llm/client.py::_safe_json`）：模型偶尔在 JSON 外裹一层说明文字，解析失败时
  截取首个 `{`/`[` 到末尾再试一次，提升鲁棒性。

## 6. 校验层：DTD 之外还查什么

DTD 只管"格式合不合法"，管不了"提取得对不对、全不全"。`validate/checks.py` 补两类会**泛化**的
质量检查（只报能辨识的一类问题，不针对单个样例）：

- **结构一致性**（`run_checks`）：悬空引用、重复 id、正文为空、缺标题 / 作者、有 ref-list 却没条目、
  正文残留未解析的 `[n]` 但全篇无 `<ref>`（疑似参考整类丢失）、空表行、图缺 graphic、作者无姓名。
- **JATS4R 风格出版规范**（`jats4r_checks`）：ORCID 必须是完整 `https://orcid.org/…` URL、
  图 / 表 / 公式必须有 `@id`（供交叉引用）、公式必须含 `mml:math`、ref 必须有 label 或引用内容、
  license 必须指向许可证链接。

这些信号进入出口校验报告，也是质量度量的一部分。

## 7. 验证：测试怎么守住这些护栏

`pytest` 共 **60 项**（`.venv/bin/python -m pytest -q`），三个文件各司其职：

- `tests/test_eval.py`：**评测器自身回归**——遍历 10 例锁四条不变量（参考自比 L2 零缺陷、覆盖
  守门零未覆盖、参考过 L0 零 error、L2 两跑逐字节一致），再核 `scope.json` 与实测参考一致。
  纯确定性，不依赖模型 / GPU。这保证"用来打分的尺子本身没坏"。
- `tests/test_integration.py`：遍历 10 例端到端转换并断言 DTD 合法 + 出版规范，外加退化输入
  （无 DOI / 无图片包也不崩）。这是"没改坏"的最强保障。
- `tests/test_render_units.py`：渲染层关键机制的单元测试——制表符表切分丢空格、矩形归一补 / 并列、
  结构化摘要按子标题切分且保斜体、标题前缀剥离、规范声明标题、表格 label 剥离、xref 拼写数字。

评测复现性来自机制本身：LLM 温度为 0、响应按内容哈希缓存（同输入必得同输出），护栏都是确定性的，
模型偶有抖动至多导致"某字段被置空 / 某条退回 mixed-citation"，不会把对的改坏。评测口径与实测成绩见
`../03-评测/评测体系设计.md`。**改完代码务必跑 pytest。**
