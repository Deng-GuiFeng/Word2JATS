## R14 稳健性审计待办(2026-06-29,多代理审计确认,按优先级)

> 说明:以下及下方"残留真缺陷"一节均为**面向开发的技术待办**,会直接出现代码内部符号(如 `_table_wrap_from_json`、`refs_llm`)、OOXML 原始标签(`w:sdt` 等)和 JATS 元素(`<thead>/<tbody>`、`table-wrap-foot`、`@id` 等);这些术语的通俗解释见 `../00-调研/02-数据与映射规格.md` 与 `../01-设计/02-智能循环架构.md`。每条结尾尽量点出"对输出的实际影响"。
本轮派多代理审计全管线,确认"相同输入 + 相同模型响应"下核心转换是**确定性**的;主要风险是"模型抖动时静默丢内容"。已修最高杠杆三项(见迭代日志 R14):①表格失败无损兜底 ②失败可观测 + 空响应不缓存 + 表数对账 ③参考文献整类丢失检测。以下为已确认、本轮**未做**的项(留作后续,均不影响默认路径的确定性):

- [ ] **公式转换失败兜底**:OMML→MathML 对个别畸形/不支持构件转换失败时,`disp/inline-formula` 会丢公式;建议回退为含 `<tex-math>`(取 OMML 文本)的合规元素而非丢弃。(注:此处指**能进入转换的**公式都能正常转,故低频;样例1 仍有一条核心公式丢失,但成因是该 OMML 根本**没进入抽取路径**——与本条的"转换失败"是两回事。)
- [ ] **表格 JSON→XML 单元格保真**:`_table_wrap_from_json` 在行单元格数多于表头列数时截断尾部单元格;建议 `ncol = max(表头, 各行最大长度)` 并补空格,保证不丢单元格。
- [ ] **解析层 walker 完整性**:`docx_reader`/`runs` 对 `w:sdt`(内容控件)、`mc:AlternateContent`(图形回退)、单元格内嵌套表、`w:fldSimple` 等未识别结构会静默跳过;建议下钻这些容器并加解析日志。(样例未触发,属防御性。)
- [ ] **确定性专项(仅启用相应功能时才需)**:`--crossref` 冷缓存只缓存成功结果(避免瞬时失败被永久冻结)+ 收紧 top-1 采纳;`copyright-year` 在收/修/录日期全缺时**目前回退为 `today().year`**(见 `pipeline.py` 的 `default_year`),存在跨年漂移、尚未做到完全确定性——待办即把此回退改为"日期缺失则省略 `copyright-year`"。(不开 `--crossref` 时其余路径已确定性。)
- [ ] **图源数目对账**:图号超出可用图片数时,`<fig>` 会无 `<graphic>` 且无诊断;建议告警并记入对账。
