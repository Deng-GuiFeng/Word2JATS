# 02 · 领域基础

这篇是给不熟悉学术出版和 XML 排版的读者准备的入门。看懂本项目需要五块背景知识：JATS 是什么、docx 内部长什么样、公式为什么要转换、参考文献怎么著录、以及 JATS4R 这个"最佳实践"。每块都从零讲起，术语首次出现就解释，并尽量用项目里真实存在的文件片段佐证。每节末尾列出处，方便你追查。

## 一、JATS 1.3 是什么

### 它解决什么问题

**JATS**，全称 **Journal Article Tag Suite**（期刊文章标签套件），是一套用 XML 描述"一篇学术论文"的**标准词汇表**——它规定了标题该用哪个标签装、作者该用哪个标签装、参考文献该用哪个标签装。正式标准号是 **ANSI/NISO Z39.96**，由美国国家医学图书馆（NLM）在 2002 年发起，后交给美国标准化组织 **NISO** 维护。

先厘清两个词：**XML** 是"用成对尖括号标签把内容包起来"的通用数据格式，例如 `<article-title>标题文字</article-title>`；**DTD**（Document Type Definition，文档类型定义）是一份规则文件，规定哪些标签合法、谁能嵌套谁、哪些必填。JATS 本质就是"一套针对学术论文的 DTD 加配套规范"。所谓"生成合法的 JATS XML"，就是产出一份能通过 JATS DTD 校验的 XML。

为什么出版界需要它？同一篇论文，出版社要在网站上排版、要推送到 PubMed 等数据库、要生成 PDF、要做全文检索、要给引文索引匹配参考文献。如果各系统各用各的格式就没法交换。JATS 的价值就是**把论文的"结构语义"从"排版样式"里剥离出来**，存成中立、机器可读、可长期归档、可交换的 XML，下游系统各取所需。这正对应本竞赛"只加结构、不改内容"的本质。

### 三种"口味"，本项目用哪种

JATS 提供三套详略不同的标签集：

| 标签集 | 用途 | 约束 |
|---|---|---|
| Journal Archiving（归档） | 长期保存 | 最宽松 |
| **Journal Publishing（出版）** | **出版发行** | **中等** |
| Article Authoring（写稿） | 作者写稿 | 最严格 |

本项目产出的正是中间那套 **Journal Publishing**。证据在每个样例 XML 的第二行 DOCTYPE 声明（`样例数据/01/结构参考.xml`）：

```
<!DOCTYPE article PUBLIC "-//NLM//DTD JATS (Z39.96) Journal Publishing DTD v1.3 20210610//EN" ...>
```

这一行钉死四件事：标准是 **JATS (Z39.96)**、口味是 **Journal Publishing**、版本是 **v1.3**、发布日期 **2021-06-10**。也就是说，**JATS 1.3 是 2021 年的标准**；NISO 后来在 2024 年又出了 1.4——本项目锁定 1.3 是竞赛既定的基线，不是用了过时版本。

### 一篇文章分三段：front / body / back

JATS 文档的根元素是 `<article>`，下分三段：

- **`<front>`**——头部，装**所有元数据**：谁写的、发在哪本刊、什么时候、版权信息、摘要、关键词。
- **`<body>`**——正文主体：章节、图、表、公式。
- **`<back>`**——尾部：参考文献、致谢、附录、脚注。

`<front>` 内部又分两块：`<journal-meta>`（期刊级信息，同一本刊所有文章都一样）和 `<article-meta>`（本篇独有）。看一段真实的期刊元数据（`样例数据/01/结构参考.xml`）：

```xml
<journal-meta>
  <journal-id journal-id-type="publisher-id">RCM</journal-id>
  <journal-title-group>
    <journal-title>Reviews in Cardiovascular Medicine</journal-title>
  </journal-title-group>
  <issn pub-type="ppub">1530-6550</issn>     <!-- 纸质版刊号 -->
  <issn pub-type="epub">2153-8174</issn>     <!-- 电子版刊号 -->
  <publisher><publisher-name>IMR Press</publisher-name></publisher>
</journal-meta>
```

其中 **ISSN**（International Standard Serial Number，国际标准刊号）是期刊的国际编号，纸质版和电子版各一个。

`<article-meta>` 里几个必知构件，看真实的作者片段：

```xml
<contrib contrib-type="author">
  <contrib-id contrib-id-type="orcid">https://orcid.org/0009-0006-1026-1505</contrib-id>
  <name><surname>Ji</surname><given-names>Yinze</given-names></name>
  <xref ref-type="aff" rid="aff1"><sup>1</sup></xref>   <!-- 上标 1，指向机构 aff1 -->
  <email>jiyz3@sustech.edu.cn</email>
</contrib>
```

这里出现了 JATS 里无处不在的**交叉引用**机制：作者用 `<xref rid="aff1">` 指向某个 `<aff id="aff1">`（机构），靠 `id`（锚点）和 `rid`（引用）配对，就像数据库的外键。**ORCID** 是研究者的全球唯一数字身份码。其余常见构件还有 `<article-id pub-id-type="doi">`（文章的 **DOI**，永久唯一标识符）、`<title-group>`（标题）、`<author-notes>`/`<corresp>`（通讯作者）、`<history>`（收稿/修回/接收日期）、`<permissions>`（版权与开放获取许可）、`<abstract>`（摘要，可再分结构化小节）。

`<body>` 里的构件：`<sec>`/`<title>`/`<p>`（章节/标题/段落，可嵌套）、`<fig>`（插图）、`<table-wrap>`/`<table>`（表格）、`<disp-formula>`（块级公式）/`<inline-formula>`（行内公式）。看一段真实的插图：

```xml
<fig id="F001" position="float">
  <label>Fig. 1</label>
  <caption><title>Calibration plots of models</title></caption>
  <graphic xlink:href="RCM46777/fig-01.jpg"/>
</fig>
```

注意图片是**外部化**的——XML 里只用 `<graphic xlink:href>` 存一个文件名指针，图片本身另存成独立文件、不塞进 XML。图片字节从 docx 内嵌媒体按正文出现顺序提取，外部化为 `{article-id}/fig-0N.<原格式扩展名>`（保留原始格式字节、不重编码：jpeg→.jpg、png→.png、tiff→.tif），XML 里只引用文件名。图片外部存储是竞赛的明确要求。

`<back>` 里最重要的是参考文献 `<ref-list>`，第四节专门讲。

### 两个命名空间

根元素会声明两个 XML **命名空间**（namespace，一种给标签加"来源前缀"避免撞名的机制）：

```xml
<article xmlns:mml="http://www.w3.org/1998/Math/MathML"
         xmlns:xlink="http://www.w3.org/1999/xlink"
         dtd-version="1.3" article-type="research-article">
```

- **`xlink:`** 来自 W3C 的 XLink（XML 链接语言），JATS 用它的 `xlink:href` 属性做"指向外部资源"的链接，如图片、外链。
- **`mml:`** 来自 W3C 的 MathML，公式标签带这个前缀，表示"这段归 MathML 管"（见第三节）。

> **出处**：JATS 全称/标准号/三种口味——<https://jats.nlm.nih.gov/>；版本 1.3=2021、1.4=现行——<https://jats.nlm.nih.gov/versions.html>；结构与元素释义——项目内《JATSv1.3 完整手册.pdf》；真实片段——`样例数据/01/结构参考.xml`；图片外部化——`样例数据/说明.md`。

## 二、docx / OOXML 是什么

要转换 docx，先得知道它内部长什么样。

`.docx` 本质是**一个改了后缀的 zip 压缩包**，正式名叫 **Office Open XML（OOXML）**，由微软主导，2006 年成为 Ecma 标准 ECMA-376、2008 年成为国际标准 ISO/IEC 29500。把任意一个 `.docx` 解压，能看到一堆 XML 和媒体文件（对 `样例数据/01/初始文件.docx` 实测）：

```
word/document.xml      正文主体（标题、作者、正文、参考文献几乎全在这里）
word/styles.xml        样式定义
word/media/image1.wmf  内嵌图片，逐个躺在 media/ 下
word/_rels/document.xml.rels   关系文件：正文里的引用编号 ↔ 实际文件的映射
```

**关键认知：论文的文字内容几乎全在 `word/document.xml` 一个文件里。** 这就是解析器要读的东西。

它的正文是一棵嵌套的标签树，核心是三层（标签前缀 `w:`）：

| 标签 | 含义 |
|---|---|
| `<w:p>` | paragraph，一个段落 |
| `<w:r>` | run，段落内**格式一致的一小段**——改个加粗或字号，就会断成一个新 run |
| `<w:t>` | text，run 里真正的文字 |

这里藏着一个坑：**一句话在 Word 里常被拆成好几个 run**——某个词加粗、某个词斜体，就切成好几个 `<w:r>`。解析器要做的，就是把这些被样式切碎的 run 拼回连续文本，同时记住哪段加粗、哪段斜体、哪段是上下标，将来映射成 JATS 的 `<bold>`/`<italic>`/`<sup>`/`<sub>`。

图片和公式在 docx 里的样子：`<w:drawing>` 是"这里有张图"的占位、`<a:blip>` 用编号指向 `word/media/` 里的真实图片；`<m:oMath>` 是一个数学公式，用的是微软的数学标记 OMML（第三节讲）。

> **出处**：OOXML 是 zip 包、ECMA-376/ISO 29500——<https://en.wikipedia.org/wiki/Office_Open_XML>；docx 内部结构与各标签——对 `样例数据/01/初始文件.docx` 解压实测。

## 三、OMML → MathML：公式为什么要转、怎么转

### 为什么必须转

本质是两套数学标记语言不兼容：

- **Word 的公式用 OMML**——全称 Office Math Markup Language，是 OOXML 标准的一部分，标签带 `m:` 前缀（如上一节的 `<m:oMath>`），微软自家格式。
- **JATS 的公式用 MathML**——本项目的 DTD 正是"Journal Publishing + **MathML 3**"版本（DTD 文件名就叫 `JATS-journalpublishing1-3-mathml3.dtd`）。**MathML** 是 W3C 的国际标准数学标记语言，3.0 版在 2014 年成为 W3C 推荐标准、并被采纳为 ISO/IEC 40314。

所以：docx 里是 OMML，JATS 里必须是 MathML，中间必须做一次 **OMML→MathML** 转换。这是硬约束，不是可选项。

### 怎么转

业界的标准做法是用一张微软官方的 **XSLT 样式表**（XSLT 是"把一种 XML 变换成另一种 XML"的模板语言）：Word 自带一个 **`OMML2MML.XSL`**，专门做 OMML→MathML。它可以脱离 Word 单独使用——直接对从 docx 抽出来的公式跑这张 XSLT，就得到 MathML。本项目用的就是这张样式表（在 `src/word2jats/resources/OMML2MML.XSL`）。学术出版界把 Word 公式转进 JATS，走的正是这条经典路线。

转换结果长什么样？看 `样例数据/03/结构参考.xml` 里一个真实块级公式（有删节）：

```xml
<disp-formula id="E001">
  <label>(1)</label>
  <mml:math display="block" alttext="AF=\frac{\sum_{i}{P(f_i) × f_i}}{\sum{P}}">
    <mml:mrow>
      <mml:mi>A</mml:mi><mml:mi>F</mml:mi><mml:mo>=</mml:mo>
      <mml:mfrac> ... </mml:mfrac>           <!-- 分式 -->
    </mml:mrow>
  </mml:math>
</disp-formula>
```

要点：MathML 用标签描述数学结构——`mml:mi` 是变量（identifier）、`mml:mo` 是运算符（operator）、`mml:mfrac` 是分式；`display="block"` 表示独立成行的块级公式；`alttext` 里还存了一份类 LaTeX 的纯文本，供不渲染 MathML 的场景兜底。

> **出处**：OMML 属于 OOXML、`OMML2MML.XSL` 随 Word 附带且可独立使用——<https://learn.microsoft.com/>、<https://www.ncbi.nlm.nih.gov/books/NBK350572/>；MathML 是 W3C 标准/ISO 40314——<https://www.w3.org/TR/MathML/>；项目用的 MathML3 版 DTD 与样式表——`src/word2jats/resources/`；真实公式——`样例数据/03/结构参考.xml`。

## 四、参考文献著录：element-citation 与 mixed-citation

JATS 提供**两种著录一条参考文献的方式**，都被官方列为推荐用法：

### 结构化著录 `<element-citation>`

把一条文献的每个字段**拆成独立标签**：作者拆成 `person-group/name/surname/given-names`，再有 `article-title`（篇名）、`source`（期刊名）、`year`、`volume`、`fpage`/`lpage`（起止页）……**内部不含排版用的标点**（逗号句号由下游按样式规则生成）。看真实片段（`样例数据/01/结构参考.xml`，有删节）：

```xml
<ref id="b1">
  <label>[1]</label>
  <element-citation publication-type="journal">
    <person-group person-group-type="author">
      <name><surname>Faggiano</surname><given-names>P</given-names></name>
    </person-group>
    <article-title>Cardiac calcification as a marker…</article-title>
    <source><italic>European Journal of Preventive Cardiology</italic></source>
    <year>2019</year><volume>26</volume><fpage>1191</fpage><lpage>1204</lpage>
  </element-citation>
</ref>
```

机器能精确读出"第一作者姓 Faggiano、2019 年、第 26 卷、1191–1204 页"。**何时用**：想要机器可处理的结构化数据——自动匹配 DOI、构建引文网络、按不同期刊样式重排。代价是标注量大、字段要抽准。

### 自由文本著录 `<mixed-citation>`

把一条文献**基本按最终排版的样子存成一串文本**，只做很轻的标注，保留排版时的标点和次序。看真实片段（`样例数据/03/上线版本.xml`）：

```xml
<mixed-citation>Qiu T, Yang Y, Liu C, et al. The association between resilience…
Journal of Affective Disorders. 2020; 265: 85–90.</mixed-citation>
```

**何时用**：手头只有排好版的引用串，逐字段拆解成本高或有风险，而你想 1:1 保住显示效果时。代价是机器难以精确取用某个字段。

### 一个真实且重要的观察

两种方式在真实的 IMR Press 产物里**并存**，选谁取决于产出流程：样例 01 的结构参考用全结构化的 `element-citation`；而 03/04/05 的上线版本却用 `mixed-citation`。**两种都是合法 JATS，没有绝对优劣**，是工程与出版流程的权衡。本项目的"结构参考"统一走 `element-citation` 全结构化，是有意的选择——结构化数据信息量更大、更利于评测和复用（见 `样例数据/说明.md`）。10 个样例里，只有 S03 的结构参考含少量 mixed-citation。

顺带认识一个名字：上面那串文本的排法——"作者姓+名首字母，多作者用 et al.；篇名；期刊名；年份; 卷: 起页–止页"——就是医学文献通行的 **NLM/Vancouver 风格**（PubMed 的引文样式）。认得它，就能理解"为什么参考文献的字段是这几个、顺序是这样"。

> **出处**：两种著录方式及其定位——项目内《JATSv1.3 完整手册.pdf》；真实片段——`样例数据/01/结构参考.xml`、`样例数据/03/上线版本.xml`；本项目统一 element-citation 的口径——`样例数据/说明.md`；NLM/Vancouver 风格——美国国家医学图书馆《Citing Medicine》。

## 五、JATS4R：比 DTD 更进一步的最佳实践

### 是什么

**JATS4R**，全称 **JATS for Reuse**（为"复用"而生的 JATS），是一个社区工作组（2018 年起挂靠 NISO），专门为"怎么用 JATS 标注才能让内容最大程度被复用和交换"制定**最佳实践推荐**。

### 为什么需要它——DTD 管不到的地方

关键在于：**JATS DTD 只能校验"结构合不合法"，管不了"标得好不好、一不一致"。** 例如 DTD 允许 `<year>` 里放任意文本，却没法要求"年份必须是 4 位数字"；DTD 允许一个公式给出多种表示，却没法要求"这几种表示必须数学等价"。这类超出 DTD 表达能力的规则，正是 JATS4R 要补的。技术上它把推荐写成 **Schematron**（一种基于规则和断言的 XML 校验语言，能表达 DTD 表达不了的约束），按错误级别和主题（math、permissions 等）分别校验。

### 举两个例子

- **公式**：当一条公式用 `<alternatives>` 同时给多种表示（如 MathML 加 LaTeX）时，JATS4R 要求每种表示都正确、完整、且彼此逻辑等价——并且**明确不偏向 MathML**，`<alternatives>` 内没有隐含的首选表示。
- **版权与许可**：对 `<permissions>`（版权声明、许可证、开放获取标记）如何标注给出统一规范，让下游能可靠判断"这篇能不能被复用、以什么许可复用"。

### 对本项目的意义

DTD 合法只是"及格线"，JATS4R 代表"更专业的做法"。是否逐条落地 JATS4R 是一个取舍；但理解它，能解释很多"样例为什么这么标"的细节——比如公式为什么既给 `mml:math` 又在 `alttext` 存一份文本、版权为什么要完整地给出 `copyright-statement` 加 `license`。本项目的评测在 DTD 合法之外，也参考了 JATS4R 的部分规范（见 [06-评测与成绩](06-评测与成绩.md)）。

> **出处**：JATS4R 的宗旨与归属——<https://jats4r.niso.org/>；用 Schematron 编码、超出 DTD——<https://github.com/JATS4R/validator>；公式推荐原文——<https://jats4r.niso.org/math/>。

## 一句话把整条链串起来

**word2jats 做的事，就是：读一个 `.docx`（OOXML 的 zip 包，正文在 `document.xml`，靠 `w:p`/`w:r`/`w:t` 承载文字、`w:drawing` 承载图、`m:oMath` 承载公式）→ 把内容"只加结构、不改字"地重新组织成一份合法的 JATS 1.3 Journal Publishing XML（front/body/back 三段，图片从 docx 内嵌媒体提取、外部化为 `{article-id}/fig-0N.<原格式>` 独立文件，公式经 OMML→MathML 转成 `mml:math`，参考文献著录成 `element-citation`）→ 并尽量向 JATS4R 的最佳实践看齐。** 后面几篇讲这件事具体怎么做到、做得怎么样。
