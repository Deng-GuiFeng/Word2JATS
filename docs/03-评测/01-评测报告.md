# 评测报告

> 本文给出本作品的**诚实评测**:正确性的真值是"**忠实于源 docx**",而非"通过我们自己定义的
> 某几个指标"。评测分两层(可定义指标 + 每输出独立逐字审查),并辅以消融分析与复现性度量。
>
> **R15 重构纠正的根本错误**:早期评测(pass@k)只比 7 个结构计数,**且把我们自己的历史输出
> 当作参考目标**——于是"10/10 全过"只证明"稳定复现了自己(含 bug)的输出",不证明对金标准/源正确。
> 现已彻底重建:参考目标永远是**外部权威标签**(委员会金标准 / 独立核验伪标签),并新增**每个输出
> 派独立 subagent 逐字对照标签 + 源审查**这一层,专门抓可定义指标覆盖不到的问题。

## 0. 评测哲学:为什么要两层、为什么以"源"为真值

- **金标准 ≠ docx 的纯函数**。委员会金标准是**已发表**的 JATS,含大量**出版层编辑**:分配 DOI、
  补收录/发表日期、把无编号标题排成 "1./2.1"、新增源里没有的声明节(数据可得性/致谢"Not applicable"等)、
  为参考文献补 DOI、把整表拆成多张并重编号、给 ORCID 加 `authenticated` 标记……这些**无法从 docx 推导**。
- 因此"输出与金标准的每处差异都算缺陷"是错的(会变成频繁误报);"只比我们定义的几个计数都对就算正确"
  也是错的(会漏掉结构/内容错)。**正确的判据是:输出是否忠实呈现了源 docx 里真实存在的内容与结构。**
- 两层评测据此设计:
  - **Layer-1(可定义指标)**:确定性、可复算,逐维度对照标签给差异 + 分值,描述性、不简化为单一 pass/fail。
  - **Layer-2(逐字独立审查)**:每个输出派一个全新 subagent,输入=输出 XML + 标签 + **源 docx**,
    逐字比对,把每处差异判为 **真缺陷**(输出不忠实于源)或 **出版层差异**(标签含源没有/不可推导的编辑)。

## 1. Layer-1:全面可定义指标(对照权威标签)

代码 `scripts/eval/`(`profile.py` 抽画像 / `compare.py` 逐维度比对 / `run.py` 跑全样例)。
- **参考目标**:原始样例 1–5 = 委员会金标准 XML;补充样例 S1–S5 = 独立三方核验的伪标签 JSON。
- **维度**:章节树与层级、标题、作者(姓名/顺序/通讯/共同贡献/ORCID/邮箱/单位)、单位、摘要(结构化+子标题)、
  关键词、图、表、公式、参考文献、xref、back 各声明节。
  > **参考文献口径(重要):综合分对参考文献只按"条数匹配"计权**;另有"抽样逐条"核对(对作者姓名等),实测分偏低
  > (S1=0.46/S2=0.13/S3=0.25/S4=0.45/S5=0.15),但**不计入综合分**——所以下表"文献"列与综合分都只反映条数对齐,
  > 逐条内容质量(臆造期号、丢 PMID/edition/姓名后缀等)属真缺陷,单独见 §5,不要把"文献=1.00"读成内容全对。

## 2. Layer-2:每输出派独立 subagent 逐字审查(本作品评测核心创新)

代码:Workflow `layer2-judge`,归档 `reports/eval_judge/judge_v2.json`、源 dump `reports/eval_judge/source/`。
- **机制**:对**每个样例的每一次输出**单独派一个**全新** subagent,读入 输出 XML + 标签 + 源 docx dump,
  逐维度逐条比对;再派一个**对抗性"完整性批判"二审**找一审漏报。两者都强制结构化输出(StructuredOutput)。
- **判据(据源)**:差异若源支持标签那一方(源确有此内容/结构、我方没忠实呈现)→ **真缺陷**(附源证据);
  差异若来自标签的出版层加工(DOI/日期/新增声明/拆表/ORCID 认证/title-case…)→ **出版层差异**,不计缺陷;
  存疑默认判缺陷。另列"源里有、输出丢失"的内容。
- **为什么这层不可或缺**:它结构上能发现 Layer-1 覆盖不到的问题——正是它(及对抗二审)抓出了
  章节层级错位、核心公式漏抽、ORCID 张冠李戴、表头错置、单元格换行丢失等真缺陷。早期"三方验收"之所以失灵,
  就是因为审查口径只覆盖同一批可定义计数、**没人拿输出去和标签/源逐字比**;本层从机制上补上了这一点。
- **结果(最终 judge,归档 `reports/eval_judge/judge_v2.json`)**:各样例对源**忠实度
  faithfulness_to_source = 0.80–0.96,宏平均 0.93**;与标签吻合度 0.72–0.98。真缺陷分级留档,见 §5。
  > 诚实标注:该次 judge 运行于样例2 的两处 HIGH(通讯/共同贡献归属、丢失参考文献[69])**修复之前**,
  > 故样例2 当次记为 0.80;这两处已随后修复(Layer-1 作者→1.00、文献→1.00,并经 §6 独立验收确认),
  > 最终实际忠实度高于此。受 LLM 子代理会话额度所限未再整轮重判,改由验收复核兜底。

## 3. 消融分析:每个组件确实有用(逐个关闭量化贡献)

代码 `scripts/eval/ablation.py`(`agent/loop.py` 的 `agent_phases` 开关逐个关闭某阶段),对原始样例 1–5
用 Layer-1 综合分量化。**Δ = 关掉该组件相对全开的掉分**(负值=该组件在做贡献):

| 配置 | 宏平均综合 | 说明 |
|------|-----------|------|
| **全开(热启动 + 四修复器)** | 0.937 | 主路径 |
| 仅热启动(关掉整个闭环) | 0.918 | 闭环整体贡献 **+0.019** |
| 关章节结构修正 | 0.929 | 主要体现在样例1:**0.905→0.946(+0.041)** |
| 关作者归属修正 | 0.933 | 样例4 +0.012、样例5 +0.008(ORCID/单位/通讯归属) |
| 关声明拆分 | 0.930 | 主要体现在样例5:**0.833→0.870(+0.037)** |
| 关内容补全 | ≈0.937 | 这批规范样例无缺表/缺作者,**贡献≈0**——它是安全网,缺内容时才触发(诚实标注) |

> 诚实说明:绝对 Δ 偏小,是因为 Layer-1 对金标准的分被出版层差异"封顶"(再修也追不平编辑加工);
> 各组件在其**针对维度**上的提升才是其价值(如结构修复把样例1 章节分 0.84→1.00)。消融如实暴露了
> "内容补全在规范样例上几乎不触发"——这不藏,因为它是为非规范输入准备的兜底。

## 4. 复现性

- LLM/VLM 即便温度 0 仍可能逐次微抖。本作品的修复器都带保守安全校验(集合不变/内容守恒/源支撑/DTD),
  抖动至多导致"不生效",不会改坏(`tests/test_agent_fixers.py` 守门;全套 33 项单测通过)。
- ORCID 等结构化数据用确定性解析(非采样),稳定。渲染(docx→PNG)是确定性 CPU 产物,按内容哈希缓存。

## 5. 残留真缺陷清单(诚实披露,后续优化方向)

Layer-2 在最终 v2 上确认的、仍待改进的真缺陷(均为热启动/构建层质量,非结构性错误;HIGH 结构/ORCID 已修)。
（下列术语:**OMML**=Word 内置公式格式;**element-citation/mixed-citation**=JATS 里结构化/半结构化的参考文献标签;**`<thead>/<tbody>`**=表格的表头区/数据区;**table-wrap-foot**=JATS 的表脚注容器;**@id**=元素的唯一编号。更全的术语见 `../00-调研/02-数据与映射规格.md`。）

- **公式**(样例1,中):正文一处核心 logistic 回归显示公式(源为 OMML)未抽出,留下文字空洞。
- **表格结构**(样例1/5,中–低):个别多层表头的第三层被放进 `<tbody>`;少数表脚注作为表后独立 `<p>` 而非 `table-wrap-foot`。
- **参考文献粒度**(多样例,低):element-citation 个例丢失 edition/publisher-loc/PMID/姓名后缀/"(In Chinese)"注记;个别姓名转写讹误;偶发臆造期号。
- **章节 @id 一致性**(样例1,低):结构修复移动内容块后,段落 `@id` 沿用旧编号,内部不一致(不影响 DTD/xref)。

> 这些已在 `reports/eval_judge/judge_v2.json` 逐条留档(含严重度与源证据),作为下一轮优化的明确清单,
> 而非藏匿。详见 `../02-开发/04-优化清单.md`。
