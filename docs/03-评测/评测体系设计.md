# 评测体系设计(从第一性原理重做)

> 本文是评测体系的**权威设计与实施规范**。后续所有实现动作必须严格照此执行,不得擅自变形。
> 一切结论均有实地证据支撑,证据出处随文标注(样例实测 / 委员会资料 / 外部权威 / 代码行号)。
>
> 术语首次出现即解释,面向"懂工程、但不熟本领域"的读者。JATS = 美国国家信息标准协会(NISO)制定的
> 学术期刊内容结构化 XML 标准;DTD(Document Type Definition)= 规定 XML 元素如何合法嵌套的模式文件。

## 0. 定位与任务边界(先把"在评什么"钉死)

### 0.1 竞赛任务(委员会原始资料)

选题一 **word2xml**:把学术论文的 Word 排版稿,自动转换成符合 JATS 标准的 XML。功能要求覆盖
标题层级、作者信息(姓名/单位/ORCID)、关键词、摘要、图片、列表、数学公式、参考文献等模块的
**结构化识别与标记**。交付物 = 输入样例 docx + 自动生成的输出 JATS XML + 可运行代码。
> 出处:`学术期刊结构化技术创新大赛项目介绍.pptx` slide 15。

**这是一场"结构化技术"竞赛。结构化 = 只给内容加结构标记,绝不修改内容本身。** 作者的拼写/时态/
罗马音错误、大小写、疑似 l/I 混淆、多余空格等一切源内容,一律逐字保留;改了就是篡改语义,判为错误。

### 0.2 官方评分里没有"对上线版的准确率"

决赛综合评分:落地性 40% + 创新性 30% + 业务适用性 20% + 展示度 10%,**无任何"输出与某个 XML 精确
匹配"的硬指标**。业务适用性(20%)看的是"问题解决完整性 + 对出版场景的适配"。
> 出处:同上 slide 24–28。

**推论(评测体系的定位)**:本评测**不是**给比赛打分的裁判,而是**我们自迭代用的内部标尺**——
把转换器逼向"忠实、完整、合规的结构化",从而在"业务适用性/出版场景适配"上拿分。
定位决定一切:评测存在的唯一目的是**给出可执行的改进方向**,不是产出一个好看的分数。

### 0.3 三个关键对象与术语(不再用"金标准")

> 文件命名(用户 2026-07-02 定):委员会给 01–05 的发表 XML = `上线版本.xml`;为 10 例各建的评测对照物 = `结构参考.xml`。

委员会从未称其样例为"金标准",只说明那是**最终上线版本**。本任务是结构化技术,必须严格区分:

| 术语 | 指什么 | 在评测中的角色 |
|---|---|---|
| **源文件** | `初始文件.docx` | **内容的唯一权威**(A 档内容以此为准) |
| **上线版本** | 委员会给 01–05 的 `最终文件.xml`(出版社最终发表 XML) | = 忠实结构化 **+ 出版方编辑加工**。**不是评测目标**。仅用于:① house-style 格式模板;② 抽全性核对;③ B 档元数据旁证 |
| **结构参考** | 为 10 例各建一份的 `结构参考.xml` | = "把 docx 忠实结构化 + 补 B 档"的理想产物(**A+B,不含 C**)。**这才是评测打分的对照物**。人工核定、冻结、进版本库 |

### 0.4 可得性三档(任务边界的精确定义)

判断"能不能从输入得到"时,算上领域知识、出版惯例、外部数据库(真实部署本就用得上)。

- **A 档(docx 直接有)**:标题、作者姓名、单位、ORCID、邮箱、关键词、摘要正文、正文各段与标题、
  内嵌图片、OMML 公式、真表格(`w:tbl`)、参考文献原文、收/修/录日期(部分样例有)。→ **必须照抽,评测严格计分**。
- **B 档(docx 没有,但可查/按惯例可得)**:期刊名/缩写/ISSN(按刊代号查表)、article-id(=DOI 去前缀,
  真实部署由出版方作为已知输入)、参考文献 DOI/刊名全称/规范卷页(CrossRef 反查)、版权年+版权/许可模板、
  Publisher's Note 模板、图片外部化命名路径(出版惯例)、正文交叉引用关联(文字→目标 id)。
  → **该做,评测计分;需联网的项(DOI 反查)单独一档报告(见 §6.3)**。
- **C 档(docx 得不到,纯出版编辑加工)**:改写标题/摘要/正文、替换或重排参考文献条目、参考文献字符串
  copyedit(作者截 et al./页码格式/`doi:`→URL)、补写声明句、把 docx 笔误改对、事后填入的录用日期。
  → **不做、不编造;评测中一律不作为扣分依据**(通过"建干净参考"从对照物中剔除,见 §2、§5)。
> 出处:5 样例实地比对(见 §4 已知编辑加工目录);外部方法论亦印证"参考文献强域依赖、需按字段评"。

## 1. 第一性原理:评测要回答的那一个问题

> **转换器的输出,离"把这篇 docx 正确结构化"还差多少?具体差在哪?**

注意是"docx 的**正确结构化**",不是"和上线版本逐字节相同"。后者从根本上是错的目标,三条铁证:

1. **上线版大量内容 docx 根本没有**:刊号/ISSN/DOI、`authenticated="true"`、版权模板;编辑**改写**的
   标题(样例5 docx `How do…?` → 上线版 `How…:`)、录用年份(样例1 docx 笔误 2025 → 上线版改对 2026)。
   转换器不可能、也不该造出来。→ 精确匹配上线版 = 要求编造。
2. **上线版自身不统一**:同为 docx 纯文本参考文献,上线版 01/02/04 做成结构化 `element-citation`、
   03/05 大半留成 `mixed-citation`(样例03 = 14 element + 42 mixed,同篇内两种混用)。→ 不存在唯一"标签真值"。
3. **精确匹配会给错信号**:在含编辑加工的 01/03/05 上,"忠实转 docx"(正确行为)反被判缺内容而**系统性扣分**;
   在忠实 docx 的 S01–S05 上又系统性得分。同一个转换器,两组分数人为背离,**混合平均是错的**。
> 出处:`真实差异考察` A/B 类;`金标准范围刻画` 三、四节;§3.2 频次实测。

**正确目标的精确定义**:输出达到最高,**当且仅当**——凡是能从 docx(A)或可查外部源(B)得到的内容,
输出都放进了与"结构参考"相同的 JATS 结构里(结构参考 = A+B、无 C)。C 档差异不参与评判。

## 2. 总体架构:把"对不对"拆成三件独立的事

一个输出是否正确 ⇔ 同时满足三条**互相独立、各有各的对照物**的性质:

| 层 | 查什么 | 对照物 | 手段 | 需要结构参考吗 |
|---|---|---|---|---|
| **L0 合法** | 符合 JATS 格式规矩(DTD + 出版规范) | 规则集(不看参考) | 纯确定性 | 否 |
| **L1 忠实** | 内容与 docx 一致:不丢字、不加字、不改字 | **源文件 docx** | 纯确定性(词多重集+图片md5) | 否 |
| **L2 对位** | 每块内容装进对的 JATS "盒子" | **结构参考 XML** | 纯确定性(归一化→分类对齐→比对) | 是 |

**为什么这么拆是对的(第一性原理)**:把每种检查放到它的"真值"真正所在之处——合法性←DTD、
忠实性←docx、结构←参考。旧系统把三件事全搅在一起去比上线版,所以永远在跟"docx 里没有的编辑加工"
缠斗(这正是它必须引入不可复现 AI 的根因)。拆开后:L0、L1 完全确定、不用参考、100% 可复现,且专抓
最要命的错(编造、丢内容——实测已抓到样例1 那条 185 字符回归大公式被转换器整条丢弃);L2 把唯一的
难点(编辑加工、house-style)前移到"一次性建参考"里解决。

**数据流**:
```
docx ──转换器──> 输出XML
                    │
         ┌──────────┼───────────────┐
         ▼          ▼                ▼
     L0 合法    L1 忠实(对docx)   L2 对位(对 结构参考.xml)
         │          │                │
         └──────────┴────────────────┘
                    ▼
          缺陷清单 + 分类命中率(按样例、按两组分列;无加权总分)
```

## 3. 关键决策与依据(所有会引发"后续再决策"的点,在此一次定死)

### 3.1 【决策】评测器 100% 确定性,不含 AI,不留任何可选 AI 分支

**依据**:评测打分回路里不存在需要临场判断的语义决策。原先担心的三类"语义边界"——①某段是标题还是
正文;②italic 是语义还是排版;③输出少一块是漏抽还是编辑补写——**没有一个是评测器的活**:
- ①②是**转换器**的决定,评测只需拿输出与参考里已定好的正确答案逐位比对,一致/不一致纯确定性。
- ③**只在"比上线版"时才存在**;既然对照物换成"无 C 的干净参考"(§3.2),输出与参考的任何差异只可能是
  转换器缺陷,不再有"要不要算编辑加工"的模糊判定。
- 旧系统必须用 AI 的唯一原因,就是它比的是掺了编辑加工的上线版(复盘:`semreview.workflow.js` 每处差异
  要 AI 判 A/B/C、`semreport.py:131` 自认 3 轮不收敛=召回下界)。剔除编辑加工,这个理由消失。

**AI 的唯一合法位置**:一次性起草"结构参考 XML"时可用(如 S01–S05 已做),但必须人工逐条核定、
跑 docx↔参考忠实校验、冻结进库——这是"造数据",与"评测打分"两回事,冻结后无随机性。
> 出处:`旧系统复盘` 第2(c)、3;`真实差异考察` D/E 类;本决策与 §3.2 因果绑定。

### 3.2 【决策】为 10 例各建"结构参考 XML"(A+B,无 C);上线版本降级为模板/核对/旁证

**依据**:见 §1 三证据。只有把 C 从对照物剔除,评测才能纯确定性(§3.1),两组样例才在同一把尺子上。
- 结构参考 = 一个完美转换器"应当"输出的东西 = docx 忠实结构化(A)+ B 档补全。
- 上线版本(01–05)**不再是评测目标**,仅作:house-style 格式模板 / 抽全性核对 / B 档旁证。
- S01–S05 现有 `最终文件.xml` 就是按此思路(忠实 docx + house-style)构建的,可复用为其"结构参考",
  但须按 §4/§5 的最终规则**重新逐条核定**后冻结。
> 出处:用户 2026-07-01 决策;`金标准范围刻画` 四节(C 可枚举、可一次性固化)。

### 3.3 【决策】参考文献:参考一律 `element-citation` 全结构化;按字段确定性比对;DOI 单列 B 档

**依据**:上线版的 element/mixed 不一致是"出版方流水线是否命中 CrossRef"的产物,不是结构化目标。
结构化任务的目标就是**尽量结构化**,故参考一律做成 `element-citation`(与 S01/S02/S04 现状一致;
`element-citation` 在 10 例全出现)。评测按字段比:person-group 内 surname/given-names 集合、article-title、
source、year、volume、fpage/lpage 各自命中;**容器形态不作为独立评分轴**(输出用 mixed 即"未完成结构化",
按"字段全缺"计入 L2 召回,信号正确)。DOI/ext-link 属 B 档且需联网,**单列"B 档补全覆盖率"报告**(§6.3),
不混入 A 档结构分。参考文献字符串的忠实度由 L1 对 docx 校验(不对上线版,因上线版字符串被 copyedit)。
> 出处:`真实差异考察` A/B;`金标准范围刻画` 二节;外部方法论(GROBID 按字段+按记录两级评)。

### 3.4 【决策】覆盖靠"遍历数据结构",不靠"人列清单"

**依据**:旧 `dimensions.json` 188 条靠 5 角色 subagent 穷举 + 多轮 critic 补漏,"零新增"只证明"这几轮
没再想到",不可证完备(尾部 #186/#187/#188 就是不断"想起还漏了 X"的补丁化石)。
**新做法**:遍历结构参考与输出**两棵树的每个节点**——凡参考有而输出无、或输出有而参考无,遍历时必然
撞见。覆盖 = 两树元素/属性并集,程序可证。守门:自动枚举 10 例结构参考出现过的全部 106 种元素 ×
40 种属性(见 §附录A),断言比对器对每一种都有明确处置,报告任何未覆盖项。
> 出处:`旧系统复盘` 2(a)、开放决策1;元素/属性全集实测(§附录A)。

### 3.5 【决策】比对前先归一化,消除"写法不同但意思相同"的假差异

**依据**:直接比原始 XML 会被空白/属性序/命名空间/等价写法污染(实测:样例1 表内 bold 假差 +48、
italic 假差 −57)。用 W3C 规范化(C14N)+ 项目自定等价折叠。归一化规则清单见 §6.3-L2。
> 出处:外部方法论(C14N、lxml `etree.canonicalize`);`真实差异考察` G/L 类。

### 3.6 【决策】按语义键对齐,不按位置;图/表按内容对齐,不按编号

**依据**:样例1 上线版把一张表挪去附录,导致其后编号整体 +1;按编号比会把 Table2/3/4 全判错。
各类对齐键见 §6.3-L2 表。
> 出处:`真实差异考察` H 类。

### 3.7 【决策】产物 = 缺陷清单 + 分类命中率;**绝不做加权总分**;两组分开报

**依据**:单一总分掩盖硬缺陷、可被糊弄(旧 `compare.py:157` 把"漏一个作者"算 0.8 分显黄)。
唯一的"分数"= **剩余真缺陷条数(0=满分)**,配每类结构的命中/漏标/多标计数。01–05(有上线版)与
S01–S05(无上线版)**分组分列**,不跨组平均。
> 出处:`旧系统复盘` 2(f)、3;用户明确反对堆分数。

### 3.8 【决策】去过拟合:出版惯例做成"按刊查表的规则库",不写死 5 篇 IMR 常量

**依据**:旧 `dimcheck.py:35-70,408` 把 DOCTYPE/模板/字段序等写死到 5 篇 IMR,换刊即误报,且这些常量
本身是"跑出误报→回源修正→再硬编码"攒出来的补丁。新设计:house-style 规则外置为带证据来源与适用刊
范围的配置(`journals.yaml` 扩展),评测按 `journal_id` 选规则。
> 出处:`旧系统复盘` 2(h)、开放决策6。

## 4. A/B/C 判定规则 + 已知编辑加工目录(逐样例冻结)

本节把"哪些是 C 档、参考里怎么处置"定死,使建参考成为**照规则执行**、而非临场再决策。

### 4.1 判定规则(对"上线版有、docx 无"的内容)

1. 若属**可查/按惯例可得**(刊号/ISSN/DOI/版权模板/Publisher's Note/交叉引用关联/图片命名)→ **B 档**,
   参考纳入(DOI 类需联网的按 §6.3 单列)。
2. 若属**自由文本编辑加工**(改写句子、补写声明句、替换/重排参考文献、改笔误、事后填日期)→ **C 档**,
   参考**不纳入**;该字段用 **docx 忠实值**;docx 无该内容则**不产出该元素**。
3. 边界项(house-style 规范化,如 Title Case、邮编前置)→ 归 **B 档惯例**,但**做成可开关规则**并在参考里
   保留 docx 原形态作兜底;评测**不因大小写差异判错**(归一化吸收)。

### 4.2 已知编辑加工目录(实测,冻结;建参考时按此剔除 C、取 docx 值)

| 样例 | 位置 | docx(忠实值,参考用它) | 上线版(C,参考剔除) | 档 |
|---|---|---|---|---|
| 01 | 录用日期 | `2025/1/16`(年份笔误) | `16/1/2026`(改对) | C:参考用 docx 值 2025 |
| 01 | 摘要/正文 | 原文 | 数十处词级润色(`declined`→`reduced` 等) | C:参考用 docx 原文 |
| 01 | 标题 | 词全同、非 Title Case | Title Case | B 惯例:归一化吸收 |
| 01 | back | Funding/Conflict/Author contrib/Ethics | 新增 Availability/Acknowledgment/Supplementary、重排改名 | 新增句=C 剔除;命名/顺序=B 归一 |
| 03 | 录用日期 | `Accepted: 待接收`(占位,无有效日期) | 事后填真实日期 | C:参考**不产出** accepted 日期元素 |
| 03 | 单位 | `Shanghai 200433, China` | `200433 Shanghai, China`(邮编前置) | B 惯例:归一化吸收 |
| 03 | back | — | 多一节 `Declaration of AI…` | 若 docx 无该节→C 剔除;docx 有→A 保留 |
| 05 | 标题 | `How do…survival? A stratified analysis.` | 彻底改写 `How…survival: A Stratified Analysis` | C:参考用 docx 原文 |
| 05 | 摘要 | 原文 | 大幅 copyedit | C:参考用 docx 原文 |
| 05 | 声明区(6节) | docx 原句 | 补写 Helsinki/数据不可公开/Not applicable 等 | C:参考用 docx 原句,补写句剔除 |
| 全体 | 参考文献字符串 | docx 原文 | copyedit(作者截 et al./页码/`doi:`→URL/补 DOI) | 忠实度只对 docx 校验;DOI=B 单列 |
> 出处:`金标准范围刻画` 一节(逐样例带实例)。02/04 及 S02–S05 按 §4.1 规则于建参考时逐条核定并补入本表。

### 4.3 参考里必含的 B 档 house-style 模板(实测,冻结)

- `journal-meta`:journal-id / journal-title / abbrev-journal-title(publisher & pubmed)/ ISSN ppub+epub /
  publisher-name=IMR Press —— 按刊查表(`journals.yaml`)。
- `article-id`:doi + publisher-id(= DOI,由 `--doi` 参数传入)。
- `permissions`:`Copyright: © {录用年} The Author(s). Published by IMR Press.` + `copyright-year` +
  license open-access CC BY 4.0(带链接)。
- `fn-group` 里 Publisher's Note:`IMR Press stays neutral with regard to jurisdictional claims…`(定值模板)。
- `article-categories/subj-group[heading]/subject`:取自 docx 稿件类型(A),模板结构为 B。
> 出处:样例01 实样(permissions/fn-group/article-categories,本文档 §附录B)。

## 5. "结构参考 XML" 构建规范(A+B,无 C,可审计、可冻结)

### 5.1 权威度与铁律

1. **内容权威 = docx**:参考里正文/标题/作者/参考文献/表格/图题的每个字符,必须能追溯到 docx OOXML 原文;
   **逐字忠实**(拼写/时态/大小写/l-I 混淆/多余空格一律原样,绝不"修正")。
2. **上线版本仅作**:house-style 格式形状(元素嵌套、id 约定)、B 档模板取值、**抽全性核对**(有没有漏段/
   漏表/漏参考文献)。**内容以 docx 为准**;docx 与上线版有出入时一律用 docx,分歧记入 `scope.json`。
3. **禁止导入 C**:凡上线版有而 docx 无、且不属 B 档的自由文本(§4.2),一律不进参考。
4. **B 档纳入**:§4.3 模板 + 按刊 journal-meta + `--doi` 的 article-id + 交叉引用关联;参考文献做成
   `element-citation`(§3.3);DOI 若可核实可填入并在 `scope.json` 标 B-网络。

### 5.2 强制校验(每篇参考建成后必须全过,否则不冻结)

- **DTD 合法**:lxml 对本地 JATS v1.3 DTD 校验通过。
- **docx↔参考 词多重集守恒**:参考正文词多重集 ⊆ docx 词多重集 + 已知 B 档结构词允许清单(§6.3-L1);
  **反查任何"参考有、docx 无"的实词**,防止误导入 C(此法已在 S02 反查出伪标签 53→50 的错误)。
- **图片 md5**:`figures.zip` 内每图与 docx `word/media/` 对应图**逐字节 md5 相同**;`graphic/@href` 前缀=
  `<article-id>/`、文件名在 zip 内。
- **计数对账**:作者/单位/图/表/参考文献/back 小节数与实测事实一致。

### 5.3 人工核定与冻结

结构参考 XML + `scope.json`(记录逐字段 A/B/C 档、docx 忠实值、上线版值、B-网络标记)必须**人工逐条核定**
后进版本库冻结。冻结后评测回路只读、不改。AI 可用于起草(§3.1),但核定与冻结由人负责。

### 5.4 数据文件布局(冻结)

```
样例数据/<key>/
├── 初始文件.docx        # 源文件(输入,内容权威)
├── 结构参考.xml         # 评测对照物(A+B,忠实结构化)—— 全 10 例
├── 上线版本.xml       # 仅 01–05(委员会发表版:模板/核对/旁证);S01–05 无(委员会只给 docx)
├── figures.zip          # 参考图片(与 docx 内嵌图 md5 一致)
├── scope.json           # 逐字段 A/B/C 标注 + 已知编辑加工目录 + B-网络标记(冻结,可审计)
└── 附件.zip             # 仅 01
```
说明:现 `最终文件.xml` 在 01–05 更名为 `上线版本.xml`、在 S01–05 更名为 `结构参考.xml`;01–05 另建
`结构参考.xml`。10 例文件层级的唯一实质差异(01–05 多一个 `上线版本.xml`)源于真实数据差异(补充样例
无发表版),记录于 `样例数据/说明.md`。

## 6. 评测三层规范(逐层:输入 / 算法 / 输出 / 可判定性)

### 6.1 L0 合法层(不看参考,给绝对质量底座)

- **输入**:输出 XML。
- **算法**:
  1. 良构 + XML 声明/编码/DOCTYPE 逐字符核对;命名空间 URI 精确核对。
  2. **DTD 校验**(JATS v1.3,本地 DTD,lxml)。
  3. **出版规范规则集**(JATS4R / NLM StyleChecker 风格,声明式,分 error/warning/info 三级),按刊配置。
     首批规则(据 JATS4R 推荐,逐条列于 §附录C):公式须含 `mml:math`/`tex-math`(否则 warning);
     ORCID 须完整 URL 且 `authenticated`;图/表/公式须有 `id`;license 须带链接;id 全局唯一;
     `xref/@rid` 必须闭合(无悬空引用);裸标签不应携多余属性(如 table 多加 frame/rules)。
- **输出**:通过/不通过 + 违规点清单(定位到节点 + 严重度 + 人类可读消息)。
- **可判定性**:100% 确定性。
> 出处:外部方法论 1/2;`旧系统复盘` §4 可保留的确定性零件;`真实差异考察` C/J。

### 6.2 L1 忠实层(对 docx,守"只加结构不改内容")

- **输入**:输出 XML + 源 docx。
- **算法**:
  1. 从 docx `word/document.xml` 抽全部正文文本;从输出 XML 抽全部文本节点。各构建**词多重集**(Counter,
     保留重复与计数,不用 set)。
  2. 归一化(小写、Unicode NFC、折叠空白、连字符/破折号统一)后取差集:
     - **docx 有、输出无** → 疑似**丢失/漏抽**(扣除 docx 的页眉页脚/水印等"可丢弃源词"允许清单)。
     - **输出有、docx 无** → 疑似**编造**(扣除 B 档结构词允许清单:元素 label 如 `[1]`/`Fig. 1.`、
       §4.3 模板定值、journal-meta 值)。
     - 序列对齐进一步定位"改字"(输出与 docx 在同一段落内的词替换)。
  3. **图片 md5**:输出外部化图片与 docx 内嵌图(或 figures.zip)逐字节比对。
- **输出**:编造 / 丢失 / 篡改 三类清单,每条附 docx 出处与输出位置。
- **可判定性**:100% 确定性(允许清单是冻结数据,非 AI)。
> 出处:`旧系统复盘` §4(词多重集、图片 md5 是应新增的确定性零件);`真实差异考察`(样例1 丢公式)。

### 6.3 L2 对位层(对结构参考,核心迭代信号)

- **输入**:输出 XML + `结构参考.xml` + `scope.json`。
- **算法**:
  1. **归一化(两侧同规则)**:lxml C14N(属性排序、命名空间、空白)+ 自定等价折叠:
     标题/声明小节标题大小写归一;去表内纯排版 bold/italic(噪声层);实体/编码统一;数字-单位等价写法。
     (归一化规则逐条列于 §附录D,冻结。)
  2. **分区分类对齐**(按语义键,非位置):

     | 类别 | 对齐键 | 比对内容 |
     |---|---|---|
     | front 元数据 | 字段名 | journal-meta/article-id/日期/permissions 逐字段 |
     | 作者 | surname(+given 消歧) | 姓名/aff 关联/corresp/ORCID/email/共同贡献 |
     | 单位 aff | 归一化全文(**不截断**) | 全文 + id + 上标 label |
     | 章节 | 归一化标题 + 树深 | 层级结构、段落归属、编号 |
     | 图 fig | 归一化 caption | label/caption/graphic href |
     | 表 table-wrap | 归一化 caption(**非编号**) | 列数/表头/单元格/表脚注/scope |
     | 公式 | 所在段上下文 + token 序列 | MathML token 树(mi/mo/mn 序列),捕获丢失 |
     | 参考文献 | label / 归一化字段 | 按字段:作者集/title/source/year/vol/fpage/lpage(§3.3) |
     | 交叉引用 xref | rid + 类型 | ref-type/rid 闭合、区间展开正确性 |
     | back 声明 | 标题关键词归类(集合) | ack/app-group 语义映射、命名归一 |

  3. 逐类产出 **命中 / 漏标(参考有输出无)/ 多标(输出有参考无)** 计数 + 具体差异条目。
  4. **多级匹配**(诊断用,不生成总分):strict(归一化后完全相同)定"对";soft(忽略标点/大小写/空白)与
     编辑距离仅用于给差异标"接近程度",辅助定位,不计入分数。
  5. **DOI/B-网络项**:`scope.json` 标 B-网络的字段(参考文献 DOI 等)**单列"B 档补全覆盖率"**,不混入结构分。
- **输出**:逐类命中率(命中/漏标/多标)+ 缺陷条目清单(每条:类别、参考片段、输出片段、定位、接近度)。
- **可判定性**:100% 确定性(参考无 C,差异即缺陷;归一化规则冻结)。
> 出处:外部方法论 3/4(C14N + 分元素 P/R/F1 + strict/soft);`真实差异考察` A–L;`金标准范围刻画`。

## 9. 自迭代闭环(评测存在的目的)

```
① 跑评测(10 例)→ ② 读缺陷清单(按类别聚合出"系统性根因")→ ③ 改转换器对应模块
    → ④ 重跑 → 缺陷条数下降、且已修类别不回弹(回归基线)→ 回到 ①
```
- **回归基线**:每轮把"剩余真缺陷条数(按样例、按类别)"存档;新一轮任何类别缺陷数**上升**即回归告警。
- **迭代优先级**:按"出现样例数 × 类别重要度"排序缺陷(重要度来自 §0.1 功能要求,不做加权求和成总分)。
- **两组用途**:S01–S05(无 C、最干净)= 主迭代信号;01–05(有上线版)= 额外覆盖 + 抽全性核对旁证。

## 11. 验收自检(本设计是否达标)

- **100% 覆盖可证**?→ 是:靠遍历两树并集 + 元素/属性全集守门(§3.4、§附录A),非人列清单。
  **已落地**:`structure._coverage_gate` 遍历参考∪输出,元素全集外即报"未覆盖";10 例现零未覆盖,由 `tests/test_eval.py` 锁定(见附录E)。
- **可复现**?→ 是:三层全确定性,无 AI 进回路(§3.1);归一化/允许清单/参考全部冻结。
- **可审计**?→ 是:每缺陷附证据;参考与 `scope.json` 人工核定冻结、进库;编辑加工目录留痕(§4.2)。
- **支持迭代**?→ 是:产物是可执行缺陷清单 + 回归基线(§9),非一个总分。
- **贴合任务本质**?→ 是:严守"只加结构不改内容"(L1 对 docx);目标 = docx 正确结构化(A+B,非精确匹配上线版)。

## 附录 E:实现补记(2026-07-05,代码已落地并实测)

代码落在 `scripts/eval/`:`samples.py / normalize.py / validity.py(L0)/ fidelity.py(L1)/
structure.py(L2)/ report.py / run.py / ablation.py`。旧体系已全删。实测中定死的口径细节:
