# 04 · 系统设计

这篇讲整个方案的骨架和最要紧的取舍：这个任务为什么难、两条常见路线各差在哪、我们选的第三条路是什么，以及它靠什么保证"结构标得聪明、内容却一个字都不改"。读完你会明白这个项目和常规做法的根本区别在哪里，也会看到数据是怎么一步步从一份 Word 稿变成一份合规 XML 的。

## 任务里两个方向相反的要求

任务是把一篇 Word 投稿稿转成 JATS XML（JATS 是学术出版界通用的、用 XML 描述期刊论文结构的标准，见 [02-领域基础](02-领域基础.md)）。关键词是"结构化"：只把稿子里隐含的结构显式标出来——哪段是标题、哪段是作者、哪段是参考文献——而**不改动任何内容**（[01-竞赛与任务](01-竞赛与任务.md)）。

难就难在，这件事内部藏着两个方向相反、却必须同时满足的要求：

1. **判断结构，得先看懂内容。** 一段文字到底是标题、正文、图题还是参考文献，Word 文件本身常常说不清。理论上每个段落带一个"样式名"可作依据，但真实投稿里样式名经常缺失或标错（作者随手排版，套用了默认样式），所以判断某段扮演什么角色，很多时候只能读懂它写的是什么才知道。这是需要"理解力"的活，靠死板的规则枚举不完。

2. **搬运内容，得一个字都不动。** 作者的拼写、时态、大小写、甚至疑似笔误，都要原样保留；斜体、上标、下标这些内联格式也要一并留住。这是需要"死板"的活——任何"顺手改一下"都是违规。

一句话概括这对张力：**结构判断要聪明，内容搬运要死板**。下面两条最容易想到的路线，各自只顾了一头，所以都不够。

## 为什么不走纯规则模板

最直接的想法是写规则：按样式名和排版特征识别标题、作者、参考文献，再套一套模板生成 XML。主办方随赛提供的基线代码（`references/baseline-develop/`，Java 实现，用 Apache Tika 抽文本、FreeMarker 套模板）走的大体就是这条路。

它把"内容搬运"这一头做得没问题——模板只搬不改，天然不会动到内容。坏就坏在"结构判断"这一头太脆：

- 真实 docx 的样式名不可靠，一旦缺失或标错，基于样式的规则立刻失灵。
- "这段是不是标题""这条参考文献的作者名到哪儿结束"这类判断，本质要理解内容；死规则只能枚举有限的模式，长尾情形永远覆盖不全。
- 结果要么漏判错判，要么规则越堆越多、越堆越难维护，却仍挡不住没见过的排版。

结构判断撑不住，这条路就到头了。

## 为什么不走纯大模型改写

另一个极端：把 docx 的文字整段喂给大模型，直接让它吐出 JATS XML。大模型理解力强，"结构判断"这一头它很在行；但"内容搬运"这一头会失守：

- 大模型是"生成"模型。让它输出全文，它会顺手改写——调措辞、丢斜体上标、补字删字，甚至凭空编造。这直接踩了"不改内容"的红线。
- 输出不确定：同一篇稿子两次转换可能不一样，没法复现、没法逐字核对。
- 最危险的是**看图造字**。论文里常有"整张表其实是一张图片"、公式是截图。若把这些图喂给能看图的模型让它"读出"内容，凡是它看不清的地方就会替你编。这类编造是无中生有的正文，性质最恶劣，本方案从架构上把这条门堵死（见下文）。

理解力它有，坏就坏在内容会被它改写、编造。

## 第三条路：把"判断结构"和"搬运内容"彻底分开

一条路强在结构、弱在内容，另一条正好反过来。那就别让一个机制同时干两件相反的事，而是**把这两件事拆开，各交给擅长它的一方**：

> **大模型只负责判断结构，从不产出正文文字；所有正文文字，按源块的编号从 docx 原文里原样取回。**

落到实现上，是三层各司其职：

- **大模型负责理解。** 它读文档，判断每一段扮演什么角色（标题 / 作者行 / 正文 / 图题 / 参考文献……）、层级关系、以及参考文献里各字段的边界。它交出来的东西全部是"**第 N 个源块是什么**"这样的**结构判定**——用源块的编号（下文叫索引，idx）来指代内容，而不是把内容抄一遍出来。
- **原文按索引取回。** 解析层先把 docx 拆成一串有序的"源块"（每个段落、每张表各算一块），逐块编号。到了组装环节，凡是正文类内容，就拿着大模型给的编号回到解析层，把那一块的**原始 runs**（run 是 Word 里带同一套格式的最小文本片段，斜体、上标、加粗都记在上面）原样取出来输出。**文字自始至终没有流经大模型的输出口。**
- **确定性规则负责落地。** 把结构判定机械地翻译成合法 XML：数学公式做 OMML→MathML 转换（把 Word 的公式格式转成通用数学标记，见 [02-领域基础](02-领域基础.md)）、图片外部化成独立文件、按 JATS 规则拼装元素树、把正文里"Fig. 3""[5]"这类交叉引用解析成链接、最后做 DTD 合法性校验。这些全是确定的、可复现的机械变换，不含任何"这段是什么"的内容判断。

这三层里，中间那层——"大模型判结构、原文按编号取回"——是整个方案的命根子，也是它区别于上面两条常规路线的地方。

## 内容守恒：不是靠小心，是结构上就做不到改

"内容守恒"（[01-竞赛与任务](01-竞赛与任务.md) 提出的那条铁律）说的是：**转换后的正文文字，和 docx 原文逐字一致，不增、不减、不改。** 这是任务的硬约束，也是评测最看重的东西（[06-评测与成绩](06-评测与成绩.md)）。

很多方案会把守恒当成一个"事后目标"：先转换，再拿输出跟原文比对，发现改动了就补救。本方案不是这样——它的守恒是**构造性成立**的：正文文字压根不经过大模型，而是按编号从原文取回，所以**想改都改不了**。斜体、上标、下标跟着原始 runs 一起回来，格式零损失。这不是"我们很小心所以没改坏"，而是"这条路径上根本没有能改坏的环节"。

只有一种情形绕不开切分：**必须把一个源块拆成好几个语义单元**。比如"张三¹, 李四², 王五\*"这样一行要拆成一位一位的作者；一条参考文献要拆成作者、标题、刊名、年卷期页各个字段；通讯作者那段要分出姓名、地址、邮箱；结构化摘要一段里要分出小标题和对应正文。这些地方，大模型交回的**不是编号、而是"子串"**——它说"这一段里第 3 到第 12 个字是标题"。这就有了被改写的一丝缝隙，所以组装环节紧跟着一道**出口子串校验**：确认这些子串确实是 docx 原文的逐字子串才采用；对不齐就退回更保守的表示。例如一条参考文献若字段切不干净，就整条落回自由文本著录（mixed-citation，见 [02-领域基础](02-领域基础.md)），宁可结构粗一点，也绝不放任编造。参考文献的长字段（标题、刊名）还会用词集重叠度兜底，重叠不足就把该字段置空——把守恒的第二道网也织上。

## 从物理上堵死"看图造字"

看图造字是纯大模型路线最危险的失效方式，本方案在架构层面让它无从发生：**喂给大模型的从来不是图，而是占位符。**

图片、公式、以及"整张表其实是一张图片"这些情形，在序列化成给大模型看的文档表示时，一律换成形如 `⟦IMG#1⟧`、`⟦MATH#2⟧` 的记号，**不含任何图像字节**。大模型看不到像素，也就无从"读图"，看图造字这件事根本不可能发生——不是靠提示词劝阻，是根本没给它可读的图。

图片和公式的真实内容，交给确定性规则去处理：图片字节直接来自 docx 里的内嵌媒体，按正文出现顺序抽出、按原始格式外部化成独立文件（保留原始字节、不重编码），XML 里用 `<graphic>` 引用；公式用微软官方的 OMML→MathML 样式表转成标准 MathML。这些都是死板的搬运，不涉及任何"猜内容"。

## 确定性：同一篇稿子，逐字节可复现

一个要被反复评测、逐字核对的工程，必须做到"同样的输入，永远得到一模一样的输出"。本方案靠两样东西合起来做到：

- 大模型调用把**采样温度设为 0**（尽量只取最可能的那一个输出），并强制它返回 JSON 结构。
- 每次请求的响应按请求内容做**磁盘缓存**：某个输入第一次调用时把响应冻结存下，之后同样的输入直接从磁盘取回。

这里有个容易被忽略、也是我们实测踩过的点：这些云端大模型 API 的 temp=0 **并不是位级确定**的。底层的专家混合路由和批处理浮点运算带有非确定性，裸调用即便温度为 0，逐次结果也会有微小差别。所以逐字节复现**真正靠的是缓存**，不是温度——缓存把首次响应钉死，与后续的调用顺序、并发情况都无关。

这也划出了复现能力的边界，得说清楚：**"逐字节复现"只在缓存还在的那台机器上成立**。缓存是本地可再生产物、不入库、不随代码分发；换一台机器从头跑，等于重新向模型问一遍，拿到的成绩会有微小出入（量级见 [07-消融与方法验证](07-消融与方法验证.md)）。所以本项目承诺的是"同一份缓存下逐字节可复现"，不是"任何人任何时候重跑都得到同一个数"。

顺带一提并发：各理解任务彼此独立，10 个样例、以及每篇内部的多个理解任务，都是**全量并发**跑的。云端模型支持很高的并发量，串行只是白白浪费时间，所以并发被直接固定进了管线（三处并发点见下文与 [05-模块实现](05-模块实现.md)）。

## 数据怎么一步步流过

> **状态说明（2026-08-21）**：本节描述 `rebuild-core` 分支的现行架构——2026-08-18 起按[施工图纸](11-重构工程/施工图纸.md)完成的系统重构，重构仍在检查点 B 的逐项修复期（台账见 [11-重构工程/检查点B工作清单](11-重构工程/检查点B工作清单.md)）。本篇前几节讲的设计理念（判断与搬运分开、内容守恒）重构前后一脉相承，且被重构进一步强化。

整条管线仍是四大阶段：parse（解析）→ understand（理解）→ render（渲染）→ 出口门（自检与交付），但层间传递的**数据契约**在重构中整体更换：从"字符串在层间传递"换成"**源地址在层间传递**"。

```
 docx（Word 投稿稿）
  │  parse       直接读 OOXML 包建"源对象图"：正文/脚注/尾注/文本框逐部件读全，
  ▼               每个字符有稳定地址（节点+区间），每次图片/公式/嵌入对象出现都登记在册，
                  格式按 Word 样式继承链算出实际生效值；读不懂的结构显性报告，绝不静默丢
 源对象图（一切后续工作的事实基准）
  │  serialize   铺成带节点号的全文清单给大模型看；图⟦图#o5⟧、公式⟦公式#o9⟧、
  ▼               制表符⇥、软回车分行——文档里存在的东西必须在清单上可见，什么都不许隐身
 全文清单
  │  understand  多路大模型判断全部并发：正文逐节点判角色、参考文献切条跑"两个问法不同的
  ▼               独立实例"（两路一致才采纳，分歧交第三套提示词裁决）、每条参考文献单独一次
                  调用析字段、正文引用与文献实体做身份匹配。模型的回答一律是"原文摘抄+位置"，
                  程序拿摘抄回原文落锚成字符坐标——找不到唯一位置就不认（宁可不认，不许认错）。
                  各路结果再全局归并：每段文字恰有一个主角色，冲突进裁决，裁决不下的拦下不交付
 DocumentAssignment（全局归并结果）+ 落锚坐标
  │  assemble    按坐标从源对象图机械取回文字，装进 SemanticDoc v2——它的一切内容字段
  ▼               存的都是源地址（SourceText），不存模型写的字
 SemanticDoc v2（语义模型，理解层与渲染层之间的类型化契约）
  │  render      机械渲染成 JATS：文字按地址抄回、格式按语义槽位投影、ID 由文档级发号器统一发、
  ▼               交叉引用只给原字符套标签；同时逐段登记"这段输出文字从哪来"（来源映射）
 候选包（XML + 图片，先进暂存目录）
  │  出口门      11 道门全过才升为正式交付：XML 良构、DTD、ID 唯一、引用闭合、图片字节逐一
  ▼               核对、格式如实、无多余文件、两本账对平（源覆盖账：原文每段字都有去向；
                  输出来源账：输出每段字都指得出来处）、词级守恒独立复查、理解层无未决阻断
 正式交付 或 failed 隔离（候选保留，报告点名差在哪；评测器评的就是候选包）
```

与重构前的关键差别，逐条对应第一节的两难：

- **参考文献不再靠正则划线**。旧版用"References 标题正则 + [1] 编号切分"，三份真实投稿三种死法（标题多两个词就全灭、无编号切不动、伪 JATS 标记束手无策）；现在切条完全是大模型的语义判断，程序只负责把每条的开头摘抄落锚成坐标、相邻坐标之间即一条——与条目之间用什么记号分隔完全无关。
- **模型只指路，不写字**。旧版模型返回的字段文字被直接采信，靠"词重叠不足 40% 作废"的门槛防改写，仍有漏网（bioprosthesis→bioprostheses 就是从门槛下钻过去的）；现在模型的字不进输出，进输出的是"坐标指向的原文"，那道门槛连同它的漏网风险一起删除了。
- **出口从"报告"变成"门"**。旧版校验完照常写出 XML；现在候选包不过门就进 failed 隔离目录、明确标记未交付，整类内容静默消失在账上兜不住。
- **例外要如实交代**：文首元信息（题名、作者、单位、日期这一小块）现走"模型直接生成 JATS 片段"的特殊通道，不经逐字落锚——这是检查点 B 修复期的一次架构调整，其保证边界（依赖提示词纪律 + DTD 门 + 词级守恒，弱于其余部分的逐字符保真）登记在[施工图纸](11-重构工程/施工图纸.md)附录 E 与工作清单 B-20；去留已于 2026-08-24 裁决为维持直出，指针制退路整条删除。

**渲染层和出口门只认 SemanticDoc v2 与源对象图，不再回头解读 docx**——类型化契约把"聪明但不确定"的理解层和"死板但可靠"的机械层隔开，这一分界线与重构前相同，只是契约本身从字符串换成了源地址。

## 出错兜底为什么不靠"再问一次大模型"

模型会答错，这是设计前提而不是意外。兜底仍然放在**确定性的机械层**，只在明确定义的一处使用重问：模型的回答没通过机械校验（格式不对、摘抄落不了锚）时，带着失败原因**重问一次**；仍不行就走确定性退路，绝不反复循环：

- 参考文献某个字段锚不上：该字段空着，其余照常；多数关键字段都锚不上：整条退回"原文照抄"的自由文本著录（mixed-citation）——按条目区间机械取回整段，永远可行；
- 压平表格的格子归属没通过"每段恰用一次、拼回等于原行"的校验：整表退回原文照抄；
- 高影响判断（如参考文献切条）不靠重问提高把握，而靠**两个独立实例交叉验证**——两次问法不同的判断很难错得一模一样，分歧处才请第三套提示词裁决，裁决不下的拦下不交付、留给人复核。

退路的共同点是**都退到"按坐标机械取原文"**：无论模型摘抄质量如何，进入输出的文字永远是原文，最坏情况只是结构粗一点（整段照抄而不是拆好字段），绝不会是错一个字母的"近似原文"。之所以不做"出口发现问题→回问大模型→再生成"的循环，理由与重构前相同：守恒是构造性成立的，出口几乎不存在"编造出来、需要修"的正文；回问循环慢且重新引入不确定性，得不偿失。

## 这套设计好在哪

把上面几点收一收，这套设计的价值集中在四处：

- **内容零改写、零编造，而且是结构上做不到改，不是靠运气或事后补救。** 这是整个方案最硬的一条保证，直接对着任务的核心约束。
- **结构判断有大模型的理解力，不依赖脆弱的样式名。** 换一份没见过的排版也能应付——补充组的 S01–S05 就是完全没给过"正确答案"的泛化测试，方法照样立得住（[06-评测与成绩](06-评测与成绩.md)）。
- **可复现、可核对、可并发，工程上扎实。** 同输入逐字节复现，评测能一字不差地重跑出成绩。
- **分层清晰、职责单一。** 解析只搬物理结构、理解只判语义、渲染只做机械变换、自检只做核对，每一层都好懂、好测、好维护（逐模块拆解见 [05-模块实现](05-模块实现.md)）。方法本身不绑死某一家模型或厂商——换更弱、更便宜、可私有化部署的模型，一样能跑通、一样合规、一样不编造，这是它"能真正落地"的底气（[07-消融与方法验证](07-消融与方法验证.md)）。
