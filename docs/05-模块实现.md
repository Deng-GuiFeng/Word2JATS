# 05 · 模块实现

这篇是一张代码地图。读完你会知道：转换器的代码分成哪几层、每层放在哪个包、一份 Word 稿怎么一步步流过这些包变成 JATS XML，以及"正文不被改动"这条硬要求具体落在代码的哪几处。上一篇 [04-系统设计](04-系统设计.md) 讲方法和取舍，这一篇把那套思路落到文件上，好让人不读源码也能维护和扩展它。

> **状态说明（2026-08-21）**：本篇描述 `rebuild-core` 分支的现行代码——2026-08-18 起的系统重构已整体更换了层间数据契约（详见 [11-重构工程/](11-重构工程/README.md)）。重构前的旧管线模块还有一部分留在仓库里但已不在生产路径上，文末"旧代码的处置"一节专门交代，免得读者误入。

约定：JATS、docx/OOXML、OMML、element-citation 等术语见 [02-领域基础](02-领域基础.md)；"内容守恒"见 [04-系统设计](04-系统设计.md)。

## 分层总览

代码在 [`src/word2jats/`](../src/word2jats/) 下，按一份稿子被处理的自然顺序分层。**理解整套组织，抓住一条主线就够了：层间传递的不是文字，是"源地址"。** 解析层给文档里每个字符、每个对象编好地址；理解层的大模型只回答"哪个地址扮演什么角色"；渲染层按地址把原文机械抄回。要改"判断什么"，动 `understand/`；要改"怎么变成 XML"，动 `render/v2.py` 和 `build/`；两边靠 `semantic/model.py` 的类型化契约隔开。

| 包 / 文件 | 职责一句话 |
|---|---|
| `parse/` | 直接读 OOXML 包建**源对象图**：每个字符有稳定地址，每次对象出现登记在册，只搬事实不判语义 |
| `model/source.py` | 源对象图的数据类型（节点、字符区间、对象出现、二进制资源） |
| `understand/` | 全项目**唯一判语义的地方**：多路大模型并发判断 + 摘抄落锚 + 全局归并 |
| `semantic/` | `SemanticDoc v2`——理解层与渲染层之间的契约，一切内容字段存源地址不存字 |
| `render/v2.py` | 把 SemanticDoc 机械渲成 JATS，同时逐段登记"输出来源映射" |
| `build/` | 机械构件：文档级 ID 发号器（`ids.py`）、JATS 元素工厂与序列化（`jats.py`） |
| `verify/` | 出口体系：两本账（`ledger.py`/`audit.py`）、来源映射（`provenance.py`）、词级守恒（`conservation.py`）、媒体核验（`media.py`）、事务式交付（`delivery.py`） |
| `validate/` | JATS 1.3 DTD 校验器（含"根元素必须是 article"的补充核对） |
| `llm/` | 与厂商无关的流式客户端 + 磁盘缓存 + 离线重放（`replay.py`） |
| `config.py` | 出版配置 `PubConfig`：出版年、出版方声明等工作流元数据的显式来源 |
| `snapshot.py` | 各层中间产物的版本化 JSON 快照（离线定位与重放的基础） |
| `enrich/` `resources/` | 期刊元数据查表；JATS DTD、`OMML2MML.XSL`、`journals.yaml` |

顶层编排在 [`pipeline.py`](../src/word2jats/pipeline.py) 的 `convert()`：解析 → 理解 → 组装 → 渲染 → 过门 → 交付/隔离。命令行入口 `cli.py`，除原有六参数外新增了 token 预算与超时重试类配置（`--input/boundary/output-token-budget`、`--llm-timeout`、`--llm-transport-retries` 等，见 [09-安装与使用](09-安装与使用.md)）。

## 逐包详解

### parse —— 源对象图（事实层）

docx 本质是 zip 包。旧版把它读成"段落列表"的中间表示；现行 `docx_reader.py::read_source_docx`（`SourceDocxReader`）不经任何压平，直接从 OOXML 构建**源对象图**——设计立场写在 `model/source.py` 模块头："这一层只记录源文档里有什么、在哪里，不判断语义角色"。

- **每个字符有地址**。文档拆成节点（段落 `doc/p42`、表格单元格 `doc/tbl3/r2/c4/p0`、脚注段 `fn2/p0`、文本框段 `txbx1/p0`），节点内是一条字符流：制表符原样、软回车记 `\n`、每次对象出现占一格（U+FFFC）。`TextRange = (节点, 起, 止)` 就是全项目通用的"源地址"。
- **对象按 OOXML 语境建模**（`media.py`）。每次图片/公式/嵌入对象出现记一条 `ObjectOccurrence`，并区分两类语义相反的组关系：**替代表示组**（AlternateContent 的新旧两份、OLE 对象与其预览图——交付时选一个主表示）与**组成组**（一图多面板——全部保留）。二进制资源与出现分开存，同一资源被多处引用不算重复。旧版"WMF/EMF 一律当垃圾"的扩展名判据已废除。
- **格式是算出来的**（`styles.py`）。粗体斜体不能只看文字上的直接标记——Word 的格式藏在 docDefaults→段落样式链→字符样式→直接格式的继承链里，这里按继承规则算出**实际生效值**，段落的提纲级别、编号、对齐同理。
- **读全整个包**。脚注/尾注部件、浮动文本框、域代码（只取显示结果、丢内部指令）、修订痕迹（按"接受全部修订"）都进图；读不懂的可见结构进 `_unsupported` 清单显性报告，绝不静默丢弃。

### understand —— 理解层（唯一判语义的地方）

调度入口 `understand.py`，一次转换的模型调用分四批、批内全并发：

```
第一批  头部任务 ‖ 正文任务 ‖ 参考切条A ‖ 参考切条B
第二批  （切条 A/B 比对，仅分歧处）边界裁决
第三批  逐条参考文献析字段（一条一次调用，全并发） ‖ 全局归并（含角色冲突裁决、弃置复核）
第四批  正文引用→文献实体匹配 ‖ 压平表格子归属
```

- `serialize.py`：把源对象图铺成带节点号的**全文清单**。图 `⟦图#o5⟧`、公式 `⟦公式#o9⟧`、制表符 `⇥`、软回车分行标号——文档里存在的东西必须在清单上可见。正文任务的清单还附带 Word 结构事实行（样式、提纲级别、编号、生效格式区间），只给证据、不做映射。
- `ground.py`：**落锚器**，本架构的安全要害。模型返回的文字只是定位证据，程序拿它回字符流找唯一位置：精确匹配 → 归一匹配（弯直引号、连字符、空白折叠）→ 上下文与顺序消歧 → 仍歧义一律拒绝。参考文献各字段用"候选区间联合分配"（互不重叠、符合源顺序的唯一解才认），摘抄默认不得跨过对象占位。**宁可不认（有确定性退路），不许认错（无人能发现）。**
- `passes.py` + `prompts.py`：各路任务与提示词。参考切条跑**两个问法不同的独立实例**（A 语义切分、B 对抗式边界审计，路标写进缓存键，确保不是同一份缓存自我表决），落锚后的锚点集一致才采纳，分歧才发第三套提示词裁决。逐条析字段一条文献一次调用——输入一两百字、输出一两百字，旧版"28 条一包、截断二分重试、书籍补轮"整套机制删除。**头部是例外通道**：边界判定（JSON）→ 元信息由模型直接生成 JATS 片段（不落锚）→ 摘要/关键词走源指针，其保证边界见 [04-系统设计](04-系统设计.md) 末节与 [11-重构工程](11-重构工程/README.md) B-20。
- `merge.py`：**全局归并总闸**。各路结果汇成 DocumentAssignment——每段文字、每个对象恰有一个主角色；冲突不靠"谁优先级高"静默压掉，进裁决调用；裁决不下的标记为内容性未决、拦下不交付。参考文献边界在这里实体化。
- `xrefs.py` + 实体匹配：每条参考建"可匹配身份"（作者姓、年、年后缀、题名辅助键），正文引用（数字制 `[3,5-7]` 与作者—年份制 `Anderson & Fowers, 2020` 同一机制）只能从身份目录里选目标实体，配上了就给原字符套 `<xref>`，配不上唯一目标保留纯文本并报告。
- `math.py`：OMML→受控 MathML 转换（转不出的公式以原预览图交付，公式不会消失）。
- `assemble.py`：按落锚坐标从源对象图机械取回文字，装配成 SemanticDoc v2；一切切分处都以"区间拼回等于原文"为校验。

### semantic —— 契约层

`model.py` 是 SemanticDoc v2：一切内容性字段（题名、作者、单位、摘要段、章节、图表说明、参考各字段、脚注）的类型都是 `SourceText`（源地址列表），**不保存任何模型写的字符串**；行内类型是封闭枚举，非法样式直接报错；注释/脚注带完整关系（身份、作用域、目标、引用出现）；参考文献带可匹配身份与字段顺序。`enrich.py` 把期刊元数据、DOI、许可这些**显式配置**以 `ConfigText` 注入——与源文字分开记账，出口可核对每个模板字来自哪个配置键。`normalize.py` 存放有名有据的规范化变换（如 ORCID 号→标准 URI）。

### render / build —— 机械渲染

`render/v2.py` 只消费类型化语义对象和源地址：文字按地址抄回、格式按语义槽位投影（标题的整段粗体不进输出、真斜体上下标保留；地址行等简单文本槽位按 JATS 封闭内容模型投影，不生成 DTD 禁止的子元素）、遇到不支持的语义类型立即失败——**没有"保存原始 XML"的逃生口**。渲染同时向 `verify/provenance.py` 逐段登记输出文字的来源（源区间 / 配置键 / 白名单变换 / 模型直出），这份"来源映射"是出口第 9 门的核对对象。`build/ids.py` 的 `DocIdAllocator` 按对象种类统一发号，显示编号只写 `<label>`——"显示编号≠内部身份"，无编号对象照样有合法 ID。`build/jats.py` 是元素工厂与序列化。

### verify / validate —— 出口体系（11 道门）

候选包先在暂存目录建好，`pipeline.py` 依次过门，全过才升为正式交付：

| 门 | 查什么 | 实现 |
|---|---|---|
| understanding | 理解层无未决阻断项 | 归并/装配的 issues |
| supported_ooxml | 无读不懂的可见结构 | 解析层 `_unsupported` |
| well_formed / dtd | XML 良构、JATS 1.3 DTD 合法（含根元素必须是 article 的补充核对） | `validate/validator.py` |
| id_unique / rid_closed | ID 全局唯一、引用全部闭合 | `verify/audit.py` 独立重查 |
| media_bytes / media_format | 输出媒体与源字节逐一相同、扩展名与真实格式相符（矢量图验签名结构，不用位图库硬解） | `verify/media.py` |
| no_redundant_files | 交付包无未被引用的文件 | 同上 |
| source_coverage | **源覆盖账**：原文每段文字、每个对象都有去向或有白名单弃置理由；有依据的复用合法、记录在案 | `verify/ledger.py` |
| output_provenance | **输出来源账**：来源映射完整、变换全在白名单；另跑独立实现的词级守恒（`conservation.py`）交叉报警 | `verify/audit.py` |

问题分三档：`high`（确定有错，阻断）、`review_blocking`（内容性未决，不交付、候选保留供人复核）、`warning`（低风险，交付但点名）。任一门不过：候选整包移进 `failed/<文章号>-<运行号>/` 并附结构化 `report.json`（哪道门、差在哪），`delivered=False`——**评测器评的就是候选包**，被拦下的结果照样能诊断。交付本身是"可恢复的事务式"（`verify/delivery.py`）：文章级锁、旧产物备份、分步替换、异常回滚，同文章并发运行互不覆盖。

### llm —— 模型接入

`client.py`：OpenAI 兼容的**流式**客户端（DeepSeek / 阿里云百炼 / 本地部署同一接口），响应逐片拼回、`finish_reason` 不是正常结束就直接报错——半截响应绝不进理解层；不再硬编码超时，瞬时传输故障指数退避重试；进程级并发闸门。**缓存优先于密钥**：查缓存在网络客户端初始化之前，已录制响应可在无密钥环境重放。`replay.py` 的 `ReplayLLM` 只读录制快照、永不联网，是离线测试的基础。缓存键含提示词与任务路标——切条 A/B 两路请求体不同，天然不会互相命中。

## 内容守恒落在代码里的三道闸

1. **指针主闸**：模型的回答是"摘抄+位置"，程序落锚成坐标、按坐标抄原文——模型的字不进输出（头部元信息通道是登记在案的例外，见上）。旧版"字段须与原文词集重叠 40%"这类概率守卫已随新契约整体删除。
2. **两本账**：覆盖账保证"原文的字都有去向"（整类内容静默消失出不了门），来源账保证"输出的字都指得出来处"（无中生有出不了门）。两本账各自独立实现、互为备份。
3. **独立报警器**：`conservation.py` 词级守恒不读任何账本、直接数词，作为与账本不同实现路径的交叉校验。

## 评测与网页应用两个包

### scripts/eval_v1 与 scripts/eval_v2 —— 两套平级评测器

口径与成绩详见 [06-评测与成绩](06-评测与成绩.md)。两套都 100% 确定、不含大模型、可复现。样例已扩成 **14 例**（主组 01–05、补充组 S01–S05、外部组 X01–X04），唯一名单在 `样例数据/样例登记.json`。V1 出三层缺陷清单（L0 合法 / L1 忠实 / L2 对位），V2 做语义树严格比对出八维质量向量；两器数字不可相加也不可互替。重构期间评测器的度量与评分逻辑保持只读，仅有两类获准改动：编排层适配（转换器写**运行清单** `manifest.json`，两套评测器按清单定位候选包——被门拦下的产物也能评）与 L0 合法性判定的一处收紧（根元素核对，附零差异证据）。

**注意**：`eval_v1/ablation.py` 的模块消融臂仍指向重构前的旧符号（`refs_pass`、二分重试等已删除），当前不可运行；[07-消融与方法验证](07-消融与方法验证.md) 的结论产于旧架构，重构收束后须整体重算。

### webapp —— 校样工作台

给期刊编辑用的网页应用（FastAPI 单进程 + 原生 JS），设计与端点详见 [08-Web应用](08-Web应用.md)、部署见 [10-部署上线](10-部署上线.md)。它在进程内直接调 `pipeline.convert`，是转换器的消费方；重构给 `ConvertResult` 新增的 `delivered/candidate_dir` 字段带默认值追加，对外接口未破坏。

## 旧代码的处置

重构采取"新旧并行、整体切换"的路线，切换完成后旧管线已整体脱离生产路径（`pipeline.py` 只 import `render.v2`，不再触及旧渲染器）。本次维护（2026-08-21）按"确定性包袱清除、可能复用的挂牌保留"处理，清单与理由见 [11-重构工程/交接盘点](11-重构工程/交接盘点-2026-08-21.md)：

- **挂牌保留**（与悬置的架构裁决绑定，未定论前不删）：旧交叉引用识别器 `build/xref.py::XrefResolver`（图/表 xref 能力的参考件，见工作清单 B-14）。
- **2026-08-24 已清除**：指针制头部的整条通道——`front_pass`、`front_response_failures`、提示词 `front.md`、`FRONT_SYSTEM`／`FRONT_RESPONSE_FORMAT`、`assemble.py` 里只服务它的 13 个方法、1 个模块级函数与 `direct_head` 开关；连同 11 个只测这条通道的用例，净减约 1600 行。它曾作为头部方向裁决（B-20）的退路挂牌，但那条路自改为直出 XML 起从未在当前基线上执行过，退路名不副实；真要退回，从 git 历史取回与重新调通的成本相同。删除不改变生产行为：文首内容仍由头部任务直出的 JATS 提供，摘要与关键词仍走源指针装配。
- **已清除**：其余确定性旧管线模块及其守护测试（旧渲染器、旧出口校验、旧中间表示等——它们的功能已被新契约完整接替，且部分文档字符串仍在宣讲已废除的规则，留着只会误导）。
