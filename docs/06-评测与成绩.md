## 验证条件

转换在 Python 3.12 环境运行；主流程使用 qwen3.7-plus，文首使用 qwen3.8-max。每例使用新的响应缓存，一篇完成再开始下一篇。报告的单篇耗时从调用转换入口到返回结果，不包含人工校样时间，也不是批量总耗时除以篇数。

真实调用数汇总主流程与文首客户端；429 传输重试单列。一次模型回答可能被不同判断记录复用，因此不能直接把审计记录行数当调用数。

最终生成文件与其检查摘要相互对应，文件清单记录 XML 哈希。两套已有真实回答还用于无联网重放；重放用于核对代码修改影响，不用于替代全新调用的结果。

## 怎样读这些数字

DTD 合法：XML 满足本地 JATS 1.3 DTD 的结构约束，不保证作者关系、公式含义或表格列归属全部正确。

自动检查通过：除了 DTD，还通过 ID 与引用闭合、媒体字节与格式、源文覆盖、输出来源、理解状态等联合检查。其中某些可保留内容的结构性不足作为警告交给编辑，不一定阻止自动通过。

参考文献条数一致：逐例核对文末条目数量，不表示每条文献的字段都达到同样细的结构化程度。未完全抽取字段的条目可保留为 mixed-citation。

公式完整性：直接读取原稿 OMML，将完整 XSLT 结果的文本序列与输出 MathML 核对，检验是否丢掉等式右端或其他顶层节点。这不是对全部数学布局语义的形式化证明。

ORCID 与媒体：核对原稿中的 ORCID 是否保留，以及已输出图片是否来自原稿内嵌资源。图片字节一致并不能单独证明每个图都放在正确位置，位置仍需要校样核对。

## 结构比较工具的作用

V1 按合法性、词级差异与结构对位列问题；V2 比较完整语义树，给出元素、文本和关系等维度的 F1。二者共享输入名单但比较逻辑独立，适合找出不同种类的问题，不应将两套数字相加。

结构参考由团队整理，有明确使用边界。V2 的“通过”要求接近完整参考树一致，它与转换器的“自动检查通过”不是同一判定。词级差异也可能来自结构化字段切分、配置注入或同一地址在不同字段重复出现，不能将每一行差异直接称作模型凭空编造。

因此，报告优先列真实文件中可核对的事实和处理状态；结构比较用于定位需要看的位置。内部差异清单长度不是官方得分，也不是模型或产品质量的唯一总分。

## 已知需要编辑处理的情形

压平表格：部分原稿用制表符和换行排出多列，结构恢复不可靠时按原行保留文字。这类输出通常仍是合法 JATS，但需要核对列结构，必要时先整理 Word 再转换。

旧式对象与复杂图文：X01、X02 存在正文、图表或旧式公式区覆盖不足，候选保留并提示，不冒充自动完成。

手工排版公式与占位：X04 的两处用普通文字和制表符排出的分式未完整输出，需在原稿中整理成原生公式后复验；其日期占位行也没有有效日期。它们均列为待核对内容，不能因原生 OMML 检查通过而忽略。

引用与文首：少量引文无法唯一连线；作者、机构、通讯关系走专门生成与检查通道，仍需编辑查看。无未登记的源外词不等于所有关系都正确。

这些限制不以修改原稿内容或放宽检查来掩盖。实际产品流程提供原稿定位和复核记录，处理意见随当前 XML 一起导出。

## 测试与复现入口

最终测试套件为 539 项通过、5 项跳过；跳过项包含需要特定缓存或可选条件的测试，不算作已通过。

scripts/finals_run.py 用于新缓存逐篇运行与严格重放；scripts/finals_evidence.py 从输入和实际输出独立核对内容；scripts/evalsuite.py 运行两套结构比较；scripts/verify_finals_web.py 实际操作上传、预览、复核和下载。

历史原型与旧口径的数字保留在开发记录中，不作为本篇的当前成绩。进一步评估通用性与编辑效率，应使用未参与开发的经授权稿件，并测量从收稿到完成校样的总处理时间。
