# 06 · 评测与成绩

这篇讲三件事：我们用什么办法衡量一篇转换得对不对、现在做到了什么程度、以及剩下的缺陷为什么大多不该再修。读完你会明白，为什么"把分数刷得更好看"在这个项目里反而是条错路。

> **状态说明（2026-08-21）**：本篇的评测方法与"当前基准"（2026-08-14，10 计分例合计 276）持续有效，基准产物冻结在 `reports/*/baseline-2026-08/` 作对照。转换器正在系统重构（[11-重构工程/](11-重构工程/README.md)），重构中最新一轮全量评测是 `integrated-057302a-r1`：X 组大幅恢复（X01 604→120、X03 103→65、X04 1056→350，三例参考文献精确恢复 30/35/70 条），10 计分例暂时全面高于基准（合计 2084，根因已逐项定位）。**读这轮数字必须守一条纪律：V1 的合计是问题清单行数不是质量总分**——大块结构从无到有恢复后，评测器会展开记录其中的细粒度差异，条数上涨可能是"能评了"而不是"变差了"；逐例逐类的正确读法见 [11-重构工程/交接盘点](11-重构工程/交接盘点-2026-08-21.md)。重构通过最终验收（检查点 C）后，本篇的"当前成绩"才会更新为新基准。

## 为什么是"缺陷清单"，不是"一个分数"

衡量转换质量，最省事的做法是给每篇输出算一个加权总分，越高越好。我们没有这么做。评测产出的是一份**缺陷清单**——完整、可复现、每条都指得出出处，逐类列出"这篇输出离正确结构化还差在哪"。唯一的"分数"就是清单上剩几条，0 条就是满分。

不用总分是有实在理由的。一个加权数字会把不同性质的问题揉成一团：一处图漏标和一个作者单位关联错，权重怎么定都是拍脑袋，而且总分一旦掩盖了具体差异，就没法指导下一步该改哪里。一份"第几条参考的哪个字段错了、哪张图漏标了"的清单，才能一条条追问、一条条归因、一条条修。

要先说清一个边界：这份缺陷数是我们**自建的代理指标**，用来指导自己迭代，不是竞赛评委给的分。评委从落地性、创新性等维度综合评判（见 [01-竞赛与任务](01-竞赛与任务.md)），跟这里数出来的缺陷条数不是一回事。把它当成"离忠实结构化还差多少"的一把内部尺子来看，才是它的正确用法。

## 评测回路里没有大模型

这套评测有两条硬纪律，是它能当"真值"用的前提。

第一，**评测回路里完全没有大模型，100% 确定**。三层打分函数都是规则代码，同一份输出喂进去，逐字节复现同一份结果。如果打分环节也塞进大模型，结果就不可复现了，还会反过来污染"方法到底有没有效"的判断——你分不清是方法变好了还是评委模型今天心情不同。

第二，**对照物永远是外部冻结的金标准**（见 [03-数据与结构参考](03-数据与结构参考.md)），绝不拿程序自己以前的输出当参考。金标准是为每个样例人工核定、冻结、只读的一份 JATS 文件（`结构参考.xml`）**加一个图片包**（`figures.zip`，字节逐字取自 docx 内嵌媒体），装着源文件里该保留的内容加上可查可推的标准元数据，剔除了出版社的编辑加工。**两部分都参与评分**：XML 决定结构，图片包决定"这个图位上的图是不是这一张"。

评测脚本都在 [`scripts/eval_v1/`](../scripts/eval_v1/) 与 [`scripts/eval_v2/`](../scripts/eval_v2/)（见 [05-模块实现](05-模块实现.md)）。

### 评测器不是"冻结不改"的，它自己也要被检验

这里要纠正一个曾经写在本文里的说法："评测脚本一经冻结只读不改"。听起来严谨，实则站不住：**标准是本，评测器是末**。评测器是用来逼近"假设转换器百分之百正确，它应从这份 docx 生成怎样的 JATS"这个标准的工具，工具对不上标准，该改的是工具。把评测器供起来，只会让它的盲区变成事实上的标准。

2026-08 的一次外部独立审查把这件事摆到了台面上：对金标准做 17 个"保持 XML 合法、尽量保持词多重集不变"的单点破坏——调换作者、地址改挂到别人名下、两个表格单元格对调、`rowspan` 从 2 改成 99、两张图的字节掉包、把 `mfrac` 换成 `mrow`——当时的评测器只报出 5 个，其余 12 个全判零缺陷。反过来，一次纯 id 重命名（引用关系与可见文字一字不变）却被误判 97 条。

所以评测器自身也需要被检验，而且不能只检验"自洽"。`tests/test_eval.py` 锁的是自洽（参考与自身比零缺陷、参考本身合法、两跑一致），但一个永远返回"零缺陷"的比对器同样满足这些。真正的检验在 `tests/test_eval_sensitivity.py`：

- **变异测试**：对金标准做单点破坏，断言"必须有人报出来"。漏检就是评测器在那个维度上失明。
- **等价测试**：对金标准做语义等价的改写（重命名全部 id、给 MathML 套一层多余的 `mrow`、改缩进），断言"一条都不许报"。误报就是在逼转换器迎合无关紧要的表示细节。

新增比较器时配一条变异用例，放宽归一化时配一条等价用例。当前 25 条变异全部被报出、7 条等价变换零误报。

## 三层评测

"一篇输出是否正确"这个笼统的问题，被拆成三件相互独立、各有各对照物的事，从"结构本身立不立得住"到"内容有没有被改"再到"结构对不对得上参考"，逐层收紧。

### L0 合法层——对 JATS 规矩，不看参考

这一层只问"结构本身成不成立"，不跟任何参考比。核心是拿 JATS 1.3 的 DTD（那份规定"哪些标签合法、能怎么嵌套"的规则文件，见 [02-领域基础](02-领域基础.md)）校验整棵树，再逐字核对文件头的 DOCTYPE 声明是不是精确指向 JATS v1.3 那一版。之后跑一批出版规范规则：编码必须是 UTF-8、xlink 和 MathML 两个命名空间的 URI 得一字不差、每个 id 全局唯一、正文里对图表和文献的每一处交叉引用都要能在文档里找到落点（不能"悬空"）、公式要含机读的数学式、图形要带 `xlink:href`、许可证要带链接，等等。

每条违规带一个严重级别：error / warning / info。**只有 error 级计入缺陷**，warning 和 info 只在报告里呈现、不扣分。举例：公式退化成图片、表格带了多余的 `frame` 属性、ORCID 没标 authenticated、ORCID 校验位对不上（可能是源文件本身写错，不能算转换器的账），都只是提醒。这一层判 `ok` 的条件是同时满足：文档格式良好、DTD 通过、DOCTYPE 逐字正确、且没有 error 级违规。

三处口径在 2026-08 收紧过，都有实测依据：**DOCTYPE 的 system id 也逐字核对**（原先只查 public id，等于放过指向错版本甚至本地路径的 system id，而下游解析器是按 system id 取 DTD 的）；**非 UTF-8 从 warning 升为 error**（JATS 交付的硬要求，编码错了下游取字必错）；**没有 `rid` 的 `xref` 从 warning 升为 error**——DTD 把 `@rid` 定为可选，但一个不指向任何东西的交叉引用是坏输出，渲染成死链、检索工具解析不到目标，14 例金标准实测零处，升级不会误伤。

### L1 忠实层——对源 docx，守"只加结构不改内容"

这一层守的是本项目的立身之本：转换后的正文文字必须和源文件逐字一致，不增、不减、不改（这个"内容守恒"的承诺见 [04-系统设计](04-系统设计.md)）。做法是把源 docx 和输出各拆成一个"词多重集"——就是"每个词连同它出现几次"的清单——再做差集，抓两个方向的失真：**丢失**（docx 里有、输出里没了）和**编造**（输出里冒出来、docx 里没有）。

#### 取词：两侧都按块内拼合，且必须对称

Word 常把一个词拆进多个 run（首字母单独成 run、拼写检查痕迹、局部改格式），逐个 `<w:t>` 取词会把 `Age` 切成 `A`+`ge`、`Keywords` 切成 `Key`+`w`+`ords`，凭空虚报一堆丢失和编造。JATS 侧同样会拆：`stat<italic>ins</italic>` 逐元素取就是 `stat`+`ins`。

所以两侧都拼合，而且**必须对称**：docx 侧按 `<w:p>` 段落拼（制表符、换行当空格，保住词边界），XML 侧按块级边界拼（`bold`/`italic`/`sup`/`xref` 这些内联元素并入当前块，`<break/>` 当空格）。只拼一侧会造出新的假差——实测只拼 docx 侧时，`Ca<sup>2+</sup>` 一类立刻虚报；而把 `<break/>` 误当成粘合点（它是换行、是词边界），表格里由它分隔的多行会粘成 `smokingldl` 这种怪词，一度虚报 30 条。

#### 三个桶，各归各管

- **主内容**：正文文字，守恒口径唯一计缺陷的部分。
- **公式**：MathML 子树、docx 的 `<m:t>`、`tex-math`，两侧同时分离。数学符号的正确性是**运算树**的事，归 L2 的公式类目；塞进词多重集只会因表示差异虚报——参考写 `<mi>f</mi><mi>i</mi>`、docx 里是 `fi`，一减就是一条假丢失。
- **B 档网络**：`ext-link`/`pub-id`/`contrib-id`/`uri`，DOI 链接与 ORCID URL 这类允许补全的内容，不入编造。

**纯数字不再静默丢弃。** 过去的口径是"长度至少 2 且不是纯数字"才算内容词，理由是角标和编号属结构化天然产物。代价太大：表格里 `281/343` 被改成 `999/999`、作者联系方式整块丢失，全都查不出来——而数字恰恰是论文最要命的内容。现在数字照常计缺陷、在报告里单列一栏。实测这一改在 10 例上多报 17 条，逐条核过全是真丢失（01 的邮编 `100037`/`518055` 与电话 `88322131` 是整块通讯地址没输出，S03 的 `14`–`28` 是参考文献日期没输出），零噪声。

#### 两个口径，都出，不混淆

- **gold_free**：只用 docx 与输出，不看金标准。任何新样例可跑，是真正的"安全不变量"口径。
- **gold_ref**（主口径，计入缺陷数）：以冻结参考作"应保留内容"的仲裁——参考里同样没保留的词不算丢失，参考里同样补上的词不算编造。它扣掉了金标准同样不承载的 C 档编辑加工剔除项，噪声低。

关键在于**别把两者混为一谈**。gold_ref 用到了金标准，拿它论证"本方法不依赖金标准"就是循环论证。消融实验里那条"编造词数是 gold-free 安全不变量"的结论，必须引 gold_free 那一栏才成立——2026-08 之前的版本正是把两者混用了，现在有一条测试（`test_gold_free_does_not_use_reference`：换一份参考，这一栏的数字不许变）把界限钉死。

#### 图片

L1 只验"外部化的文件真实存在且能被解码"。**装了图像库就以图像库为准，不给魔数兜底**——兜底的正当理由只有"图像库不认识某种合法格式"，而兜底能认的那几种（JPEG/PNG/TIFF/GIF/BMP）它本来全都支持；留着后门的结果是一个 243 字节、只有 `\xff\xd8\xff` 开头的空壳被判成真图。至于图**是不是这一张**，归 L2 的媒体字节类目按语义槽位比 SHA-256。

**L1 缺陷数 = 丢失的词种数 + 编造的词种数 + 坏图数**（数的是"有几种不同的词"出了问题，不是词频总数）。

### L2 对位层——对结构参考，比结构对不对得上

前两层过了，输出已经是一棵合法、且内容一字没改的 JATS 树。L2 再问：结构本身跟结构参考对不对得上——该有的章节、作者、图表、公式、参考文献都在不在，属性填得对不对。

做法是先归一化消掉格式假差异，再**按"语义键"对齐**，而不是按位置或编号对齐。为什么不按位置？因为结构化输出里元素的先后、编号都可能跟参考不完全一致，硬按位置比会满盘皆错。语义键就是"用这个实体本身的特征去认领它的对应物"。各类实体的对齐键和比对内容如下：

| 类别 | 按什么对齐 | 比什么 |
|---|---|---|
| front 元数据 | 字段名 | 刊号 / 标题 / **带类型的 ISSN 与 article-id** / 卷期页 / 日期 / 版权与许可 |
| 作者 | 姓 + 名 | 单位关联（比语义目标）/ 通讯 / 共同贡献 / ORCID / 邮箱 / **联系地址 / 学位 / 角色 / 作者注释 / 署名顺序** |
| 章节 | **直接父标题** + 归一标题 | 集合 + **同一父下的先后顺序** |
| 图 | **编号**（Figure N），取不到才退到归一图注 | 图注 + 图形张数（不比文件名和格式） |
| 表 | **编号**（Table N），取不到才退到归一表注 | 形状 + 表脚注内容 + 表头 scope + **合并展开后的单元格矩阵** |
| 公式 | MathML 记号序列 | **运算树结构**（规范化后） |
| 媒体字节 | 承载对象（图 / 表 / 图文摘要…） | 该图位上图片的 **SHA-256 序列** |
| 内联格式 | 格式集合（bold / italic / sup…） | 该格式下的词多重集 |
| 参考文献 | 编号 label，**无编号时用内容指纹** | 作者（有序）/ 标题 / 刊名 / 年 / 卷 / **期** / 起止页 / **elocation-id / DOI / PMID / 出版者**，逐字段；**加著录顺序** |
| 交叉引用 | 类型 + **目标的语义键** | **按出现次数**比 |
| 声明 | 序号 + 容器名 + 归一标题 | 集合 |

对齐之后，逐类给出**命中 / 漏标（参考有、输出无）/ 多标（输出有、参考无）**，再加字段值不符的缺陷。漏标时还会用相似度找出输出侧最接近的那一项标注出来，方便人判是真漏了还是只是没对上。

上表加粗的都是 2026-08 补的判别力，每一项都对应一个当时报不出来的真实盲区。其中几条的道理值得单说：

**id 一律解析成"指向什么"再比，绝不比 id 字面。** id 是文档内部标识，委员会取 `aff1`、转换器取 `A1`，都对；引用关系闭合、指向同一个对象就够了。原先直接比 `@rid` 字符串，一次纯 id 重命名会被误判 97 条——那等于逼转换器去猜委员会的内部命名。现在所有 `@rid` 先翻译成（目标元素类型 + 目标的语义键）。

**顺序用相邻对捕获，而且只看两侧都在的项。** 作者次序、章节先后是硬语义（谁是第一作者、Introduction 在不在 Methods 前面），必须比。但按绝对序号比会级联：漏掉第 2 节，后面每一节都错位，一处错误虚报一整片。所以比的是（前驱, 当前）二元组——换位必然改变相邻关系被抓住，漏一项只波及相邻两对。至于漏项本身，所属类目已按漏标计过，顺序比较只在两侧都存在的项之间做，避免同一处错误被计两遍。

**章节用直接父而不是完整路径。** 完整路径下，某一层错位会让它底下每个子孙的键全变；直接父只波及该节点的直接子女，定位准、不级联。

**合并单元格按网格展开逐格比。** `rowspan`/`colspan` 决定的是"这个值管辖哪几格"，把 `rowspan="2"` 写成 `rowspan="99"`，行数、单元格数一个不变——只有展开成网格才看得见。

**MathML 比运算树，但先做规范化。** 字符序列相同而结构不同（分式写成并列、上标写成下标）在记号序列里看不出来。反过来，W3C MathML 里有几种等价形不能算差异：只有一个子节点的 `<mrow>` 是冗余分组、`<semantics>` 是 presentation 与 content 的捆绑容器、`<math>` 的多个子女在规范上隐含成一个 `mrow`。不归一，OMML 转出来的每个式子都会因包装风格不同虚报树不符（03 的 18 个式子当时全中）。

**内联格式按格式桶比，不按元素。** `<bold>A</bold> <bold>B</bold>` 与 `<bold>A B</bold>` 渲染一致、语义一致，按元素比会虚报一对漏标加多标。所以按"字符承载的格式"分桶，比各桶的词多重集。缺陷也按桶聚合：转换器把 31 处章节标题冗余包上 `<bold>`（JATS 里标题的强调由 `<title>` 承载，不该再套视觉标记）是一个系统性问题，不该炸成几十条淹没别的类目。

**图片比字节。** 金标准是"结构参考 + figures.zip"两部分，图的身份是它的字节而不是文件名——委员会命名 `fig1.tif`、转换器命名 `fig-01.jpg`，是同一张图；反过来两张图的 `href` 对调，文件都在、都能解码，只有比字节才发现张冠李戴。所以按语义槽位（哪张图、哪个表、哪份图文摘要）比 SHA-256 序列。

**覆盖守门是处置登记，不是白名单。** 遍历参考树和输出树里出现的所有元素类型，每一种都必须写明"由哪个比较器负责"，没登记的报"未覆盖"，逼着补规则。这里有过一个教训：原先它就是一个元素名的字符串集合，把名字塞进去只让守门闭嘴，不代表它真的被比较过——`address`/`addr-line` 曾经"已覆盖"却无人比对，把整块地址改挂到另一位作者名下，三层全部零缺陷。现在登记表的值是负责的类目名，有意"不在 L2 单列比对、由 L1 逐字守恒兜底"的元素会在报告里被点名，免得"登记了"被读成"比较过"。

**参考文献的对齐键必须能应付无编号的情况。** 原先用 `<label>` 作唯一键、且用字典推导建表，X03 那 35 条全无编号的参考文献于是塌缩成 1 条——前 34 条静默消失，连自比测试都发现不了。现在无编号时退到内容指纹（第一作者姓 + 年 + 标题前缀），同键多实例按序配对。另外容器形态不同（一侧 `element-citation`、一侧 `mixed-citation`）时只报一条容器差异，不逐字段比——两侧字段体系压根不可比，逐字段比会把同一件事报成五六条。

DOI/ORCID/外链这类标准元数据补了多少，仍单列一份"补全覆盖率"呈现，不混进结构缺陷里算账。

**L2 缺陷数 = 各类别缺陷条目之和**（含覆盖守门报出的未覆盖项）。

### 三层合起来

```
总缺陷 = L0 error 数 + L1 缺陷数 + L2 缺陷数
```

顶层不出加权总分，产物就是这份逐样例、逐类的缺陷清单，连同机器可读的 `eval.json` 和人类可读的 `eval.txt` / `eval.html` 一起落在 `reports/eval_v1/<标签>/` 下。报告还会把所有样例的缺陷按"类别 + 类型"聚一张频次表，一眼看出哪种问题是系统性的、哪种是个案。

## 历史：旧的 80 条为何失效

本文此前写的"10 例合计 80 条缺陷"**已经不成立了**，原因是它的两个前提在 2026-08 同时变了。

- **金标准变了**。14 例结构参考经过一轮外部独立审查、逐例裁决后修订：01–05 的 figures.zip 里有 16 张图不是 docx 原字节（TIFF 被转成 JPEG、分辨率被改、图被裁切）已全部换回原字节；05 的 691 个表格单元格重做了列模型；03 的 MathML 原先照搬了上线版（连畸形花括号一起），已按 docx 的 OMML 重建；X02 的 11 处交叉引用错绑已改按可见标签匹配。
- **评测器变了**。就是本文上面讲的那些：判别力从 17 个变异只抓 5 个提到全抓，同时消掉了 97 条 id 重命名假阳。

拿那批旧输出（2026-07-10 生成）配新金标准 + 新评测器重新打分，得到 277 条。**这个数是个过渡值**，当时只用来证明旧的 80 已失效——那批输出是老的。2026-08-14 用当前转换器重跑之后，同样 10 例得 276 条，逐例与这 277 只差 S04 一条，等于回头确认了一件事：**从 80 涨到 276，全部来自评分口径变严与对照物变准，不是转换器退步。**

逐类看，这 276 条里绝大多数是过去看不见的真缺陷，抽查核实过的例子：

## 剩下的缺陷是什么，为什么不再磨

> **这一节写于旧口径（80 条）时期，其中的分类判断在金标准定稿与评测器改造后已部分作废**，逐段的更正标在原处。四类划分本身仍然成立，但"哪条属于哪类"需要拿新一轮输出重新核过——尤其是"结构参考取舍空间"这一类，当时归进去的好几条，在金标准逐例裁决之后已经确认是真差异。方法论那一段（下面的"一条方法论纪律"）反而更该读：它讲的正是怎么避免把真 bug 误判成"参考的锅"。

把当时那 80 条逐条核过之后，它们大体分成四类。其中**有三类是结构性地修不动、也不该修的**——硬修就是把这 10 个样例的偶然细节写死进程序，在没见过的文档上必然倒退，这正是过拟合的定义。

### 一、结构参考自身的取舍空间（占比最大）

有些地方，结构参考本身就没有唯一正确的做法，而**源 docx 里根本没有任何信号能预测该往哪边靠**。这种时候，建参考的人只能二选一，硬去追平他当时的那一选，等于把一次随机取舍刻进转换器。真实例子：

- ~~**提示框（callout）**：像 02 里的 "Key Points" / "Key Updates" 方框，在 docx 里没有任何结构信号——没有标题样式、没有大纲级别、没有编号，只是加了个圆点和粗体。结构参考把它升成了独立章节 `<sec>`，我们的输出忠实地作粗体段落。两种都说得通，docx 无从判定该是哪种。~~ —— **已作废**：金标准逐例裁决时定了这 10 个小节就是独立 `<sec>`，评测现在报的是输出漏了它们，是真差异不是口径分歧。
- **行内小公式的降级**（03）：结构参考把一批行内小公式连同括号一起降成了普通斜体文字，我们忠实保留成行内公式 `<inline-formula>`。评测按 MathML 记号比对，就记成了十几处差异——可数学内容其实一模一样。
- **参考文献容器的随意性**（S03）：这是 10 例里唯一含自由文本著录参考的样例，结构参考把某几条留成了自由文本、其余用结构化著录，我们统一做结构化，反而因"拆出来的字段比它多"被记成差异。——**部分更正**：金标准那 3 条留自由文本是因为它们确实不可结构化著录，不是随意；不过评测这边确实报重了，现在容器形态不同只报一条容器差异，不再逐字段炸成五六条。
- **参考自身的笔误**：个别地方结构参考把变量顺序写反、或把团体作者误并进姓氏。追平它，等于把本来正确的输出改错去复刻一个错误，显然得不偿失。

### 二、度量的分词伪差

这一类里，输出其实完全忠实，缺陷是"评测逐段分词 + Word 把词切碎 + 参考偶尔省略"三者叠加造出来的假差异。根子在 docx 的一个坑：Word 会因为格式变化把一个词拆成好几段（见 [02-领域基础](02-领域基础.md) 讲的"分 run"）。真实例子：

- **"Keywords" 被切碎**：某些样例里 Word 把它拆成了 `Key`、`w`、`ords` 三段。逐段取词永远拼不回 "Keywords" 这个整词，于是我们忠实重建出的 "Keywords" 反被判成"编造"。
- **"3rd" 被拆成 `3`+`rd`、"Age" 被拆成 `A`+`ge`**：同样是切词造出来的幽灵丢失和幽灵编造。
- **邮箱的多重集幽灵**：结构参考把通讯邮箱同时挂在作者和通讯两处（docx 里只有一份），做多重集减法时就凭空多算出几处"丢失"。

**这一节此前的结论已经作废，连同它的论证。** 原文写的是"评测脚本是冻结的、不能为迁就它去改"，还算了一笔账说改切词的收益是净零（只把 L1 缺陷从 18 减到 17），因此保持逐段切词不动。

两处都错了。

先说立场：把评测器说成"冻结不能改"是本末倒置。评测器是逼近标准的工具，它对不上标准，该改的是工具——为迁就评测器的缺陷而在解读时"认下这笔账"，等于让工具的盲区变成事实上的标准。

再说那笔账。它之所以算出"净零"，是因为只改了 docx 一侧的取词，而 XML 侧仍逐元素切——**两侧不对称，消掉的假差和新造的假差正好抵消**。实测把两侧都改成块内拼合之后：`ge`、`age`、`authors` 这些假丢失假编造确实消失了，同时**暴露出真丢失**——02 的 `bioprosthesis` 少了一次（原先因为 docx 那一侧被切碎、次数少算，正好抵消掉了），逐字节核实是转换器把它写成了 `bioprostheses`。这不是净零，是原先在拿假差掩盖真差。

至于"粘连假象"，确实存在但量极小：10 例里只有 `continued`、`continuedcontinuedegfr` 这类 docx 本身相邻文字之间既无空格也无标点也无制表符的情况（表格续页标记），共 2 个词，属不可约。用 2 个不可约的粘连词，换掉一批可约的拆分假差、外加暴露真丢失，是明确划算的。

同一节里"结构参考取舍空间"的几个例子也要更新：**02 的 "Key Points" 已不再是取舍空间**——金标准把它定为独立 `<sec>`，现在评测报的是输出漏了这 10 个小节，是真差异不是口径分歧；**S03 的参考文献容器**同理，金标准那 3 条留自由文本著录是因为它们确实不可结构化，输出强行拆成结构化著录会被报一条容器差异（一条，不是原先的五六条）。

### 三、真正的难例

少数情形确实难，但难在需要看图或做语义判断、没有稳健的确定性判据。比如某个公式是以内联图片形式嵌进正文的，要转成 MathML 就得从图片里读字——而本项目明令禁止"看图造字"（见 [04-系统设计](04-系统设计.md)），这恰恰是被有意排除掉的行为，不是没做到。又比如"紧挨着图题的那段末尾到底算不算图注的一部分"，没有词法上的硬判据，硬定规则就会误吞正文。这类要么触碰已禁的 OCR、要么把普通正文误判成结构，修法的收益只够救本例这一处。

### 四、通用的真 bug——这些已经修了

第四类跟前三类性质正相反：docx 里有明确信号、根因单一、跨样例都适用、修了不引入回归。这类是**该修、也已经修掉**的，比如参考文献列表标题重复泄漏、单个页码被同时填进起页和止页、图表按编号混排时取错了图片字节、书籍类参考的编者和出版社字段缺失、日期里日和月的顺序消歧，等等。这些才是真正抬升质量的工程改动。

### 一条方法论纪律

把一条缺陷归到"结构参考的取舍空间"之前，**必须先做跨样例一致性核验**，否则很容易把一个真 bug 当成"参考的锅"放过去。一个真实教训：S05 的共同贡献标记一度被判成"参考自身不一致"，复核时把 5 个样例横着一比，发现参考其实是**一致的**——用 † / # 这类符号标记的作者才加脚注引用，用与通讯相同的 \* 号的不加；乱的是我们程序把符号写死了。于是它被正确地重判成第四类的通用真 bug 并修掉。"参考确实无源信号可判"和"看着乱、其实横向一比有规律"，必须分清：前者不追，后者要修。

### 结论：为什么停在这里

> **这个结论需要重做。** 它建立在"剩余 80 条里三类修不动、只剩少量真 bug"这个判断上，而那个判断有一半是评测器的盲区撑起来的——当时归进"分词伪差"的一批，实测是两侧取词不对称造出来的，改对之后不但假差消失，还暴露出真丢失；当时归进"取舍空间"的几条，金标准逐例裁决后确认是真差异。新一轮输出跑出来之前，"还能修的真 bug 有多少"这个数是未知的。

原结论如下，保留以见判断的演变：前三类修不动的缺陷（取舍空间 + 分词伪差 + 难例）加起来，远多于还能修的真 bug。继续磨它们只有一条路可走：把这 10 个样例里建参考时的偶然取舍、Word 的切词伪影、参考自身的笔误，一条条硬编码进转换器。这在没见过的文档上**必然倒退**。

"不为追平参考而硬编码"这条纪律本身没有变，仍然管用。变的是它的适用面：过去它被用来解释"为什么这 80 条大多不必修"，而现在评测器能分清哪些是真差异了，它就该退回它本来的位置——**只在源 docx 确实无信号可判时才援引**，不能当成免修的挡箭牌。

这套"换模型、换温度、逐个拆模块"的实验，我们成体系地做过，用它量化坐实了"系统只会漏、绝不会造"这一条最硬的结论，具体在 [07-消融与方法验证](07-消融与方法验证.md) 展开，这里不重复。

## 诚实的边界

- **泛化的信心来自"判据有据"，不是来自大规模留出验证**。除了 S01–S05 这 5 个真正的留出样例，以及后来自行找来的 X01–X04 这 4 篇外部投稿件，我们手上没有更多带核定参考的 IMR 数据。每一处修复到底通不通用，靠的是它读的是不是"跟哪家出版社无关的硬信号"——OOXML 的结构、JATS 规范、源文里明摆着的东西、逻辑上的必然——而不是"这几篇碰巧是怎么做的"。这条边界如实摆在这里。
- **X01–X04 不入成绩**。这 4 篇是本队自己找的外部投稿件，金标准也是本队建的，与转换器同源，拿来报成绩会自证。它们只用于评测器自身的回归与盲区探测——事实证明这个用法很值：X03 的 35 条无编号参考文献暴露了对齐键塌缩，X02 的图文摘要与 X04 的 `elocation-id` 暴露了三个未覆盖元素，全是 10 例样本里碰不到的形态。
- **数字会随口径变，而且真的变了**。旧的 80 与新的 277 不是同一把尺子量的：金标准与评测器都换过。评测口径本身是我们自建的、可讨论的，它衡量的是"离忠实结构化还差多少"，不等于竞赛得分。它的全部价值在于可复现、每条有出处、能一条条指导迭代——这也正是我们要它、而不要一个漂亮总分的原因。
- **评测器不是唯一的**。本篇讲的是 `scripts/eval_v1/`；另有一套从第一性原理重造的 `scripts/eval_v2/`（完整语义树严格比对 + 通过判定 + 八维质量向量），两者**平级、判分逻辑互不引用**，同时评估同一批转换输出，只共用 `样例数据/样例登记.json` 这一份样例名单。两器数字不可相加也不可直接对照：V1 出缺陷清单条数，V2 按语义事实逐项展开，量级天然差一到两个数量级。一致时结论更可信，不一致处最值得查——这正是同时养两把尺子的理由。一条命令跑完两器并出并排小结：`python -m scripts.evalsuite`。
