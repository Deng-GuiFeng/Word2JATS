# 06 · 质量、效率与模型用量

实验围绕三个问题展开：整篇稿件的内容与关系能否得到正确表示，完成转换需要多长时间，以及模型调用消耗多少资源。采用 01–05、S01–S05 共 10 篇稿件，在相同转换流程下比较两种模型配置；各项质量、时间和用量均对应同一次实际转换的输出。

**稿件与结构参考。** 01–05 配有 Word 原稿与上线 JATS XML，S01–S05 提供 Word 原稿。为统一比较范围，团队为这 10 篇稿件整理了逐篇的 JATS 结构参考，覆盖元信息、章节、图表、公式、文献及引用关系。上线 XML 可用于了解出版标记形式，但其中经过编辑加工的文字、补充信息与原稿未必一致，因此评价以 Word 内容为依据，而不要求转换结果复现上线版的所有改动。结构参考用于评价，不作为转换器输入。

**评价对象与单位。** 从结构参考和转换结果中分别提取可比较的字段、对象与关系，按内容身份对齐，不直接比较 XML 字符串或内部 ID。作者与单位分别计数，作者—单位、通讯作者—邮箱及作者—ORCID 按关系计数；章节以标题及所属层级识别；作者和章节顺序按相邻项关系核对，首项也计入。摘要内容与段落、小节组织分别核对；表格合并区域展开为逻辑网格，只有行列位置与内容同时匹配的单元才计为正确。文献条目与著录字段分别评价，作者名单作为一项字段，页码先合并为起止范围；引用按正文位置和实际目标计数，区间引文展开为各个目标关系。

匹配前统一排版空白、页码缩写、人员名单的等价标签分拆等表示差异。例如，`1191–204` 与 `1191–1204` 作为同一页码范围，内部 ID 的不同命名不影响目标匹配。参考提供的是一套可核对的结构表达，不将等价的 JATS 写法判为内容错误。

各项报告“应有数、输出数、正确匹配数”。应有数来自相应评价依据，输出数是结果中实际提取的同类事实数，正确匹配数是两者相符的数量；召回率为正确匹配数除以应有数，精确率为正确匹配数除以输出数。汇总时先跨稿件累加计数，再计算比率，避免把规模不同的稿件简单平均为一个质量分数。

**直接对照原稿的检查。** 全文词项保留率从 DOCX 独立读取文字，按归一化词项及出现次数与输出核对，范围包括文首、正文、表格、文献及 DOI、ORCID 等标识内容。它衡量文字保留，不衡量顺序，需与章节、字段和关系指标共同阅读。原生公式直接读取 OMML，经样式表变换后比较 MathML 树中的运算节点、属性和内容；忽略不影响结构的外层分组与标识差异。图像型公式按原稿载体核对；图片归属与导出字节一致性分别检查。JATS DTD 校验则独立判断输出是否符合目标格式。

**模型配置与执行条件。** 本文将两套模型配置简称为 Qwen 配置和 DeepSeek 配置，表内简写为 Qwen、DeepSeek。2026 年 9 月 14 日实测采用以下 API 调用标识，版本说明依据同日的模型文档：

| 配置 | 任务与实际调用标识 | 对应版本说明 |
|---|---|---|
| Qwen | 主流程 qwen3.7-plus；文首元信息 qwen3.8-max | Plus：qwen3.7-plus-2026-05-26；Max：qwen3.8-max-0902（2026-09-02） |
| DeepSeek | 全部任务 deepseek-flash | DeepSeek-V4.1-Flash |

两种配置使用同一版原稿解析、语义任务、组装及检查流程，温度为 0，关闭思考模式，单篇内部请求并发上限为 32。运行环境为 Linux x86_64、Python 3.12.7、AMD EPYC 9334，模型经云端接口调用，本机不加载模型权重。

每种配置对每篇稿件执行一次完整转换，稿件之间顺序执行，单篇内部按图2并行。每篇均不复用应用本地保存的模型回答，服务端上下文缓存则按实际命中量计量。耗时从开始处理 DOCX 计至完成 XML、媒体及检查结果，包含通信等待和限次重试，不包含上传与人工校样。逐篇请求、响应返回的 Token 用量和输出文件对应保存，Token 不采用全文词项评价中的分词结果估算。

## 复现实验

使用 `scripts/finals_run.py` 分别以 dashscope 和 deepseek 运行同一批稿件，再用 `scripts/proposal_metrics.py` 核对全文分项内容。实际输出、媒体、逐篇用量与运行说明随原型提供。安装及命令示例见 [安装与使用](09-安装与使用.md)。
