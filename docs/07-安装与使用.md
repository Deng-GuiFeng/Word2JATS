# 07 · 安装与使用

这篇讲怎么把 word2jats 跑起来：装环境、转换一篇论文、跑评测复现成绩、跑测试。命令都可直接照抄。

## 运行环境

- **Python**：3.9 及以上（项目在 3.12 上验证）。
- **依赖库**：
  - `python-docx`、`lxml`、`Pillow`、`PyYAML`——解析 docx、构建/校验 XML、转换图片、读配置，缺一不可。
  - `openai`、`python-dotenv`——调用大模型做结构理解、读取密钥。**本项目的转换方法必须用到大模型**（理由见 [04-系统设计](04-系统设计.md)），所以这两个也是必需项，而非可选。
- **大模型后端与密钥**：默认用阿里云百炼 DashScope 的 `qwen3.7-plus` 模型（OpenAI 兼容接口）。需要一个 API Key，填在项目根目录的 `.env` 里。**没有可用密钥时，程序不会报错，但只会产出一个"空壳"——结构合法却几乎没有内容的 XML**，不是可用结果。

> **关于 lxml 版本的一个坑**：评测环节要用 JATS 官方 DTD（文档类型定义，见 [02-领域基础](02-领域基础.md)）校验 XML 合法性，这一步对 lxml 背后的 libxml2 版本敏感。实测项目自带虚拟环境的 lxml 6.1.1 可正常加载 JATS DTD；而某些较旧的构建（如一台机器上 Anaconda 自带的 lxml 5.2.1）会在加载 DTD 时报 `DTDParseError`。**跑评测请用项目自带的 `.venv`，不要用系统里别的 Python。**

## 安装

项目自带一个装好依赖的虚拟环境 `.venv/`。全新安装时：

```bash
# 方式一：用项目自带虚拟环境（推荐，已验证）
.venv/bin/python -m pip install -r requirements.txt

# 方式二：新建虚拟环境
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

配置密钥：把 `.env.example` 复制成 `.env`，填入真实 Key（至少配一个后端）：

```bash
cp .env.example .env
# 然后编辑 .env，填入 DASHSCOPE_API_KEY=...
```

## 转换一篇论文

命令行入口是 `word2jats convert`。不安装也能用 `python -m word2jats` 调用（需要把 `src` 加进模块搜索路径）：

```bash
PYTHONPATH=src .venv/bin/python -m word2jats convert \
    样例数据/S01/初始文件.docx \
    --doi 10.31083/CEOG48513 \
    --journal CEOG \
    --figures 样例数据/S01/figures.zip \
    -o output/
```

参数说明：

| 参数 | 作用 |
|---|---|
| 第一个位置参数 | 输入 docx 路径 |
| `--doi` | 文章 DOI（数字对象标识符），用于生成 `article-id`、并推断期刊 |
| `--journal` | 期刊代号（如 `RCM`/`JIN`/`HSF`/`CEOG`），缺省时从 DOI 前缀推断 |
| `--figures` | 外部图片包（zip 或目录）。JATS 要求图片外部存储、XML 里只引用文件名；缺省时退而从 docx 内嵌图片提取 |
| `-o`/`--out-dir` | 输出目录（默认 `output/`） |
| `--llm` | 大模型后端，`dashscope`（默认）/`local`/`deepseek` |
| `--no-validate` | 跳过出口校验（DTD + 内容守恒 + 结构自洽），一般不用 |

运行完会在输出目录得到 `<文章号>.xml`（如 `CEOG48513.xml`）和外部化的图片文件，并在终端打印统计（作者数、参考文献数、图表公式数、DTD 校验是否通过等）。

## 跑评测复现成绩

评测会对 10 个样例逐一转换，再用三层评测（合法/忠实/对位，见 [06-评测与成绩](06-评测与成绩.md)）打出逐类缺陷清单。**必须用项目自带的 `.venv`**（DTD 校验需要），命令：

```bash
PYTHONPATH=scripts .venv/bin/python -m eval.run --llm dashscope
```

常用变体：

```bash
# 只评指定样例
PYTHONPATH=scripts .venv/bin/python -m eval.run --llm dashscope --samples 01,03,S01
# 给这次结果起个标签（产物落在 reports/eval/<tag>/）
PYTHONPATH=scripts .venv/bin/python -m eval.run --llm dashscope --tag mytest
```

- 产物：`reports/eval/<tag>/eval.json`（机读）、`eval.txt`（逐样例逐类缺陷清单）以及各样例的转换输出。
- **并发**：10 个样例、每个样例内部的多个理解任务都是全量并发执行的（云端模型支持高并发，串行是纯浪费），已硬编码进脚本，无需配置。
- **确定复现**：模型调用温度设为 0 并带磁盘缓存，同一输入逐字节复现，与并发顺序无关。首次运行会真实调用模型并把响应缓存到 `reports/eval/_llm_cache/`；之后再跑直接命中缓存，几秒完成。

## 跑测试

```bash
.venv/bin/python -m pytest
```

- 单元测试（渲染、评测口径等）任何时候都能跑。
- 集成测试会真正跑一遍转换，它依赖上面评测预热出来的 DashScope 缓存（`reports/eval/_llm_cache/dashscope/`）；缓存不存在时该测试自动跳过，并提示先跑一次评测预热。

## 常见问题

- **输出几乎是空的**：多半是没配好大模型密钥，程序退化成了只出合法空壳。检查 `.env` 里的 Key 是否有效。
- **评测在 DTD 校验处报 `DTDParseError`**：用了不兼容的 lxml/libxml2。改用项目自带 `.venv`。
- **图片没出来或对不上**：确认传了 `--figures` 指向该样例的 `figures.zip`；不同样例的图片包不通用。
