# 07 · 消融与方法验证

## 现有实验能证明什么

项目在重构前做过方法消融：关闭模型理解、调整内容取回与检查环节、比较不同模型，以观察各组件的作用。它们属于旧版技术路线的实验，原始记录保留在开发仓库的消融分析目录；不能直接作为决赛版的实测成绩，也不能据此声称任意输入都不会遗漏或改写。

决赛版继承“模型判断结构、程序取回原文”的思路，但源对象图、著录定位、文首生成通道、归并及检查体系均有变化，因此采用下面的组合验证现行实现。文首与其他通道的具体处理方式见 [系统设计](04-系统设计.md)。

## 决赛版采用的验证组合

确定性重放：同一输入与同一模型回答下修改装配代码，检查预期问题是否修复，文献引用等无关内容是否保持稳定。已有两套独立真实响应均用于重放验证，不允许缓存缺失时联网补答。

全新冷跑：使用新缓存，一次一篇，记录每篇耗时、实际调用数、检查结果和最终文件。它检验模型新回答带来的波动，而不是只展示固定缓存的一次成功。

独立内容核对：直接解析 DOCX 与输出 XML，核对参考文献条数、OMML 转换后的完整公式文本、ORCID、图片来源字节及引用目标。公式文本完整仍不等于所有数学布局语义得到形式化证明；引用闭合也不等于所有引用语义正确。

针对性测试：使用能触发根因的最小样例，防止公式多根节点截断、真实标识被剪除、著录漏人名、数字角标粘连、嵌套排版表漏表头等回归。

网页验收：既检查自动通过样例，也检查待确认样例，实际执行上传、预览、保存复核和下载，保证人工确认不会改变 XML 或自动检查状态。

## 如何继续检验通用性

已有 14 例都参与过开发，不能代替独立测试集。进一步验证应使用未参与开发、经授权的不同期刊稿件，按文献体例、表格形式和公式类型分组，记录内容遗漏、错误关系、人工核对耗时与完整处理耗时。

未来的人机协作效率主指标应是“从收到 Word 到完成可交付校样所需的总时间”，而不只是模型生成 XML 的时间。当前尚未开展编辑用户的受控计时实验，不报告未经实测的人工节省比例。
