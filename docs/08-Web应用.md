# 08 · Web 应用：转换、查看与修改

Web 应用供需要转换 Word、但不希望部署环境或运行脚本的用户使用。开发者与非开发者使用同一套流程：上传 Word 稿件（.docx 格式），查看生成的稿件，按需要修改文章信息，下载 JATS XML 和配套图片。

## 上传与转换

选择或拖入一个 Word 文件，选择 DeepSeek 或 Qwen，点击“开始转换”。文件选错时可更换或移除；空文件、非 .docx 格式和超过 300 MB 的文件会在上传前提示。图片、表格和公式从 Word 中读取，不需要另外上传。

DOI 与期刊放在可展开的“出版信息”中。可以先选择已配置期刊，也可以暂不设置，转换后再补充。两种模型共用相同界面，具体调用型号在结果页的“用量”中查看。

上传时显示文件传输进度；上传结束后显示排队、读取文档、识别结构、生成文件和检查结果等阶段。上传期间需保持页面打开。文件上传完成后，可返回首页或复制任务链接，不会中断服务器上的转换；刷新页面可继续查看，临时断网会自动重连，不必重复提交。

首页“最近转换”保留此浏览器打开过的最近 12 篇稿件入口，正在处理的稿件会更新状态。记录仅包含任务链接、稿件名称、题名、模型、时间与状态，不在浏览器保存 Word 或 XML。其他浏览器不会看到这份列表；移除记录只隐藏入口，不删除服务器文件。清理浏览器数据后仍可通过原任务链接打开结果。重要成果应下载留存。

## 查看结果和原稿

转换结果以稿件预览为主体，目录按章节层级排列，可查找章节名、图表标题并跳转，也可收起目录扩大阅读空间。预览展示 XML 中的实际内容；“XML”用于查看对应标记，不提供任意源码编辑。无法生成预览时，仍可查看 XML 或下载当前结果。

目录还可按文章信息、摘要与关键词、图表、公式或参考文献筛选，显示当前保存 XML 中的数量或文字。公式标明 MathML、图像等表示形式，表格区分单元格结构与图像，文献区分字段著录与混合著录；点击具体条目可定位预览。这些信息用于了解转换结果，不是自动质量评分：数量不能证明内容完整或正确，不同的合法著录形式也不等于质量高低。

“对照原稿”直接读取上传的 Word，呈现段落、粗斜体、上下标、表格、图片和原生公式。桌面默认左右并排显示，手机以独立侧栏显示。选择有原稿位置记录的章节或段落，会定位并突出显示相关原稿，不重新加载全文；没有精确映射时保留原稿阅读位置并明确说明，不以猜测位置代替精确对应。浏览器不支持的媒体提供原文件入口，也可下载完整 Word。

“检查详情”区分两类信息：

- 可在网页补齐的信息，例如期刊名称与 ISSN，直接进入对应编辑表单。
- 需要对照内容的问题，例如表格列结构、图片或引用关系，展示可用的原稿摘录并进入相关位置。正文结构可以在下载的 XML 中继续编辑，或在 Word 中整理后重新上传；标签级诊断放在折叠的技术详情中，不将原始 DTD 报错放在主页面要求普通用户自行解释。

格式检查验证 XML 是否符合 JATS 文档类型定义（DTD），不等同于全文内容正确；具体内容可通过预览与原稿对照查看。

## 修改与保存

网页支持以下字段编辑；正文、复杂表格和公式可在 Word 中修改后重新转换。

| 入口 | 可修改内容 | 对文件的作用 |
|---|---|---|
| 文章信息 | 题名、已有作者姓名与顺序、ORCID | 更新对应 JATS 元素，保留未修改的行内格式与其他作者信息 |
| 文章信息 | 单位文字、作者与已有单位的关联 | 更新单位内容及作者的单位引用 |
| 文章信息 | 通讯作者标记、已有通讯说明和邮箱 | 更新通讯字段；已有其他关联和脚注保留 |
| 出版信息 | DOI、期刊名称、印刷版或电子版 ISSN、出版方 | 更新文章与期刊元数据；支持选择已有期刊或填写自定义期刊 |

输入后点击“保存修改”，当前结果的 XML、预览、格式检查和下载内容一并更新。修改不调用模型，不增加模型用量。只改 DOI 不会重建期刊信息；作者重排移动的是原有作者元素，不通过重写整段文首丢弃脚注和标识。

编辑表单可直接跳到题名、作者、单位或通讯信息。结果顶部区分自动转换结果、未保存修改、正在保存和已保存修改；预览与下载始终对应保存版本。未保存时关闭编辑或离开页面，会先提示是否放弃输入。下载时也会说明文件不包含未保存修改。保存期间不能切换任务，保存失败保留输入，便于重试；若另一页面已更新同一任务，则提示重新载入，避免后提交的旧版本覆盖新结果。

同一稿件内切换文章信息、出版信息、原稿、检查、用量或下载说明，会保留输入，不要求先保存。编辑表单中的“对照原稿”可随时查阅原文，再通过“继续编辑”返回，编辑位置和原稿阅读位置也会保留。关闭原稿后，结果顶部仍提供继续编辑入口。文章信息与出版信息的修改属于同一份草稿，点击“保存修改”一并保存。草稿只保留在当前打开的页面中，不写入浏览器的近期记录；刷新、离开稿件或主动取消编辑时仍需确认。

“更多”中的“恢复自动生成的原始版本”会恢复本次自动转换的 XML。原自动文件始终单独保留，人工修改另存版本。原稿和图片资源不会因修改或恢复而被覆盖。

恢复版本或创建重新转换任务时，页面也会显示处理状态并阻止中途切换任务，避免操作结果与当前页面错位。请求失败可重试，原结果继续保留。

## 下载和再次转换

“下载转换成果”导出 `Word2JATS-稿件标识.zip`，主体为当前保存版本的 XML 和图片压缩包 `figures.zip`，并附检查摘要与转换用量；有人工修改时附修改记录。稿件标识优先使用明确的文章号，其次采用原文件名或当前题名，不沿用“初始文件”等通用名。将图片包解压到 XML 所在目录即可使用其中的资源。XML 只有一个当前版本；下载原稿时返回最初上传的 Word 字节。

“更多 → 下载文件说明”列出本份成果包的实际文件组成与解压方法；“单独下载 XML”适合接入后续编辑和处理。下载绑定当前查看版本：若另一页面已保存新版本，先提示重新载入，避免看到旧预览却拿到新文件。网络或打包失败会留在原页面显示处理提示，重试不会损坏已有结果。服务器为下载生成的临时 ZIP 在响应发送结束后删除，自动结果与修订文件独立保留。

“转换下一篇”回到上传页。“重新转换”重新处理最初上传的 Word，可切换模型，默认沿用当前已保存的出版信息，也可选择首次上传时的出版设置。DOI、期刊名称、ISSN 和出版方可以作为新任务的出版设置；题名、作者等内容仍从 Word 重新识别，不带入人工修订。未设置期刊时，不以空白信息覆盖新识别的期刊内容。新任务不会覆盖旧任务，页面提供返回原结果的入口。

“用量”统一列出生成所用分析的输入、输出、缓存命中、缓存未命中及总 Token。Token 是模型处理文字的计量单位；输入等于缓存命中与未命中之和，总量等于输入加输出。数值来自模型实际响应或所复用回答的原始计量；未单列未命中数时，以输入减命中计算。本次新增量单独说明；完全复用仍保留分析结果的原始用量。旧任务若缺少原始记录，则显示缺失提示。

## 部署与实现

以下信息面向部署和维护人员。普通网页用户不需要配置密钥或理解任务目录。

FastAPI 提供服务，前端使用原生 HTML、CSS 和 JavaScript，无需前端编译。网页与命令行共用转换入口。后台线程执行转换，页面轮询进度；任务快照原子保存到磁盘，已完成任务可在服务重启后恢复。重启时仍在处理的任务明确提示中断，不显示永久等待。

上传采用 2 MiB 分片、最多 3 片并发、失败重传及整包大小校验。浏览器支持时，对不超过 64 MiB 的文件补充 SHA-256 传输校验。大于该范围的文件仍有分片与完整大小校验，不宣称已做浏览器端全文哈希校验。

预览使用 NLM/NCBI 的 JATS Preview Stylesheets 在服务器生成 HTML，MathML 由浏览器显示。TIFF 按需转 PNG；WMF 在具备相应解码器时可生成预览，原始媒体仍随 ZIP 导出。原稿侧不能显示的媒体提供下载入口。

| 接口 | 用途 |
|---|---|
| `/api/upload/*`、`/api/convert` | 分片或单次上传 |
| `/api/status/{task_id}`、`/api/result/{task_id}` | 任务状态与当前结果 |
| `/api/workbench/{task_id}` | 可编辑字段、目录与问题位置 |
| `/api/edit/{task_id}`、`/api/restore/{task_id}` | 保存修订或恢复原始结果，均检查当前版本 |
| `/api/render/{task_id}`、`/api/source/{task_id}` | 结果预览、真实 Word 原稿视图 |
| `/api/original/{task_id}`、`/api/source-media/{task_id}/{occ_id}` | 原稿及原稿媒体下载 |
| `/api/download/{task_id}`、`/api/reconvert/{task_id}` | 导出或创建新的转换任务 |
| `/api/delivery/{task_id}`、`/api/xml/{task_id}` | 当前成果组成与独立 XML 下载；下载接口可携带 version 校验 |

`webapp/editor.py` 限定可修改字段并检查格式和关联；`workbench.py` 组织修订接口；`source_view.py` 与 `presentation.py` 分别组织原稿和结果浏览；`task_store.py` 保存任务快照；`delivery.py` 用同一结果快照生成说明、XML 和成果包。前端 `session.js` 只管理浏览器内的近期入口，`app.js` 负责各页面与异步状态。人工保存后重做的是当前 XML 的格式与结构检查，自动转换时的原稿覆盖等检查仍作为该次转换的记录，不冒充针对人工改稿重新执行的全流程检查。

默认任务与上传目录为 `webapp/_runs`、`webapp/_uploads`，可通过 `W2J_RUNS_DIR`、`W2J_UPLOADS_DIR` 指定。仍按单机单进程部署，不支持直接启动多个独立工作进程共享任务状态。模型凭据仅在服务器配置；部署者负责访问范围、调用额度和稿件留存策略。基本启动步骤见[安装与使用](09-安装与使用.md)。
