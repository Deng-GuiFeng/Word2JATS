# 08 · Web 应用：校样工作台

网页面向期刊编辑，不要求操作者理解 XML。它将自动转换和人工核对接成一条实际可执行的流程：

    上传 Word → 自动转换 → 浏览校样 → 定位核对
             → 保存处理意见 → 必要时修订 Word、重新转换 → 导出

## 编辑怎样使用

上传 DOCX，可补充 DOI 与期刊。系统自动提取内嵌图片，后台执行转换，页面显示真实阶段和耗时。默认可复用相同请求的模型分析；勾选“重新识别全文”会使用本次任务独立缓存，不复用已有回答。完成后会标明本次是否调用了模型，避免把缓存重放当成全新转换速度。

结果页包含五个面板。成品预览展示标题、作者、正文、图表、公式与文献；原文核对展示词级差异与逐项处理清单；内容清单汇总文章组成；合规检查展示自动结果；XML 源文件供技术人员查看。

结果状态以转换器最终自动检查结论为准，而非仅凭 DTD 通过。检查通过表示可以下载并继续校样复核，不表示已满足所有出版社的生产规则。未通过的候选仍可查看和下载，页面明确要求先核对。

## 从问题提示到复核记录

检查清单将可定位的问题关联到原稿摘录，并给出处理建议。例如：

- 文献字段未抽全：整条原文保留，核对著录结构。
- 压平表格不能可靠分列：对照原稿，必要时整理为原生 Word 表格再转换。
- 原稿内容尚未输出：查看具体摘录，确认其在成品中的去向。
- 引文关系不确定：核对引用与文末条目的对应关系。

已正常完成的标题拆分不作为待办展示，避免让编辑逐项确认无须处理的技术记录。每个待办可标记“待核对”“已核对，保留当前结果”“需修改后重新转换”，并填写备注、复核人。

保存后，复核记录与当前 XML 的 SHA-256 一起写入文件，随下载包导出。它记录针对哪一版文件作出的判断。人工记录不修改 XML，也不会将未通过自动检查的结果改为通过。当前没有网页内任意 XML 编辑器；需要改内容或结构时在 Word 中修订，再上传复验。

## 工程实现

FastAPI 提供服务，原生 HTML/CSS/JavaScript 实现前端，无需前端编译。网页与命令行调用同一个转换入口。上传完成后立即返回任务号，后台线程执行，前端轮询进度与结果。

大文件采用 2 MiB 分片、最多 3 片并发、失败重传与整包校验，降低不稳定链路中重传整份稿件的成本。预览在服务端用 JATS 样式表生成 HTML，浏览器显示 MathML；TIFF 可临时转 PNG，WMF 在系统提供 GdkPixbuf 与 WMF 解码器时也可生成预览，但下载文件不改变原始字节。缺少可选解码器时，WMF 仍可下载到本地查看。EMF 当前以原文件链接呈现，提示下载到支持该格式的软件中查看。

主要接口是 /api/convert、/api/upload/*、/api/status/{task_id}、/api/result/{task_id}、/api/render/{task_id}、/api/review/{task_id} 和 /api/download/{task_id}。

## 运行边界

这是单机原型，不是已经接入出版社生产系统的多人审稿平台。任务索引在内存中，重启后旧任务链接不再有效；复核文件仍留在对应运行目录。部署者应及时导出结果并管理稿件留存。API 密钥仅在服务端，调用云模型前应确认稿件有相应处理授权。公网开放前还需按实际业务配置登录、配额和数据保留策略。
