# 10 · 部署上线

## 单机运行

原型由一个 Python Web 服务提供页面、上传、转换调度与结果下载。默认仅监听本机；如需局域网访问，可显式指定地址：

    .venv/bin/python -m webapp --host 0.0.0.0 --port 8000

部署时按网络环境选择反向代理或受控隧道，并配置 HTTPS。原型不自带用户账号系统，不应直接开放给无限制、不可信的上传流量。本文不把演示部署等同于生产安全认证。

已有在线演示入口：https://word2jats.jianglab.work。可用性取决于服务与网络，应在演示前核验，不将公网始终可达作为离线交付条件。

## 容器

    docker build -t word2jats .
    docker run --rm -p 8000:8000 --env-file .env word2jats

密钥在运行时注入，不加入镜像。容器里的任务文件与缓存若需长期保留，应配置持久卷；否则容器移除后可能丢失。部署者应按稿件保密要求管理这些文件。

## 缓存与数据

默认缓存位于 webapp/_cache，可用 W2J_WEBAPP_CACHE 指定专用位置。上传件、候选和复核记录放在 webapp/_runs；分片暂存放在 webapp/_uploads。任务索引在内存中，服务重启后旧链接不再可查，重要结果应先下载。

普通转换允许复用已有回答；“重新识别全文”使用该任务的独立缓存。缓存只影响模型回答的获取方式，不绕过源解析、组装和检查。保留原稿、代码版本、配置与完整响应，才能重放同一结果。

## 上线核验

按顺序检查：首页能打开；期刊列表可加载；小样例上传成功；任务状态正常推进；预览及图片可打开；复核保存与下载有效。仅得到首页 HTTP 200 不代表转换功能已验证。

如果使用 systemd 管理，代码修改后需重启应用服务；前端资源采用版本化地址减少旧缓存干扰。重启前确认没有需要保留链接的正在运行任务。

## 演示准备

同时准备在线工作台、本机运行环境和随包冻结结果。现场随机指定样例时可直接上传；若选择全新识别，应明确等待时间随稿件复杂度变化。可以在等待时解释技术，再展示同一稿件已有结果，但必须说明展示的是冻结结果，不能把它说成这次冷跑刚完成。

网络不可用时，离线预览仍可展示 XML 与媒体的实际成果；它不等于离线模型推理。五分钟演示应重点展示转换成果、原文依据和处理问题的方式，不把全程押在云端长文的返回时间上。
