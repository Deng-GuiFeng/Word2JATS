# 10 · 部署上线

## 单机运行

原型由一个 Python Web 服务提供页面、上传、转换调度与结果下载。默认仅监听本机；如需局域网访问，可显式指定地址：

    .venv/bin/python -m webapp --host 0.0.0.0 --port 8000

部署时按网络环境选择反向代理或受控隧道，并配置 HTTPS。原型不自带用户账号系统，不应直接开放给无限制、不可信的上传流量。本文不把演示部署等同于生产安全认证。

已有在线演示入口：https://word2jats.jianglab.work。可用性取决于服务与网络，应在演示前核验，不将公网始终可达作为离线交付条件。

## 容器

    docker build -t word2jats .
    docker run --rm -p 8000:8000 --env-file .env word2jats

密钥在运行时注入，不加入镜像。容器里的任务文件与缓存若需长期保留，应配置持久卷；否则容器移除后可能丢失。部署者应按稿件保密要求管理这些文件。

## 缓存与数据

默认缓存位于 webapp/_cache，可用 W2J_WEBAPP_CACHE 指定专用位置。上传件、自动结果、人工修订及任务快照放在 webapp/_runs，分片暂存放在 webapp/_uploads；两者可用 W2J_RUNS_DIR、W2J_UPLOADS_DIR 指定。完成任务的快照保存到磁盘，服务重启后可继续使用原链接；重启中断的在途任务会明确提示重新提交。重要成果应及时下载，并按实际业务设置文件留存策略。

普通转换允许复用已有回答；结果页的“重新转换”使用新任务的独立缓存。缓存只影响模型回答的获取方式，不绕过原稿解析、组装和检查。保留原稿、代码版本、配置与完整响应，才能重放同一结果。

## 上线核验

按顺序检查：首页和期刊列表能打开；样例上传成功；任务状态正常推进；预览、图片和原稿可打开；字段修改保存成功，更新后的 XML、预览与下载一致；恢复原始版本有效。仅得到首页 HTTP 200 不代表转换功能已验证。

如果使用 systemd 管理，Python 代码修改后需重启应用服务；前端资源采用版本化地址减少旧缓存干扰。静态文件直接来自部署目录，改动会立即影响后续请求，因此应先在独立目录或测试服务验收，再统一发布。重启前确认没有正在运行的转换，并备份任务目录；从不具备任务快照的旧版本升级时，先迁移仍在内存中的任务结果。

## 离线查看结果

提交包提供已经生成的 XML、图片与离线预览。网络不可用时，仍可直接打开各例的预览.html 查看已有成果。

新稿件的自动转换仍需要连接所选模型服务；原型不在本地部署大语言模型权重。
