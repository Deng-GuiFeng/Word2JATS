# 14 例转换内容与缓存验收

## 目标和边界

目标是为评委测试与现场演示准备 14 篇已知 Word 稿件的稳定、高质量转换结果。网页提供 DeepSeek 和 Qwen 两种选择，因此验收对象为 28 组。原稿为内容依据，结构参考仅帮助定位差异，不是标准答案。

本轮不修改 Web 功能，不开展新一轮界面重构，不修改已提交材料，不制作 PPTX。采用真实模型响应的筛选、必要的重新生成与缓存预热；不改写模型原始回答，不伪造用量、检查状态或来源记录。若确认问题必须改程序才能消除，单独报告依据和最小修改范围，不用缓存掩盖。

上线代码为 `45896ae`，工作树为项目 `tmp/web-release-r02`；开发起点为 `097f907`，工作树为 `tmp/web-next`。用户对 AGENTS.md 的修改不覆盖、不提交。现有任务不变，新缓存独立准备，通过验收后才切换。

## 已确认的运行机制

依据 `webapp/app.py`、`webapp/workbench.py`、`src/word2jats/llm/cache.py` 和 `client.py`：缓存保存模型请求、回答及真实接口用量，普通上传仍执行 Word 解析、结构组装、校验和打包。旧任务 XML 的人工修改不会被下一次上传继承。重新转换使用独立缓存并重新调用模型，不能承诺与缓存复现相同。两种模型分别准备缓存；改变出版设置不应串用其他任务的信息。

## 固定顺序

1. 固定 Git 回退点，登记原稿摘要、候选任务、代码和缓存来源。审查历史记录，优先利用已有真实调用，受解析修改影响的 01 使用修复后的候选。
2. 在独立目录按当前代码复现 28 组，禁止新增网络调用，发现缺失就报告；保留完整回答和用量。检查格式、媒体、原稿覆盖、结构差异与实际预览。
3. 逐篇审查题名作者机构、摘要关键词、章节正文列表声明、图表表注、公式、引用文献和交付一致性。差异回到原稿判断，不按参考的相似度挑答案。
4. 对模型错误优先选择已有合格真实候选；必要时有界重新生成。不随意拼接互相依赖的多轮回答。程序缺陷与缓存缺失分别记录。
5. 合并候选后再次执行禁止模型网络请求的复现与重复运行校验，确认无缓存冲突、遗漏、用量缺失。公网验证逐一上传、完整预览、下载；额外检查改名和正常出版设置变化。
6. 仅在内容和运行检查通过后切换缓存；避免打断活动任务，保留旧配置和旧缓存。复核既有任务未变，停止临时服务，输出逐篇结论及剩余问题。

## 内容验收与收敛

必须排除题名截断、作者遗漏或关系错误、段落缺失或重复、章节明显错位、错图缺图、图题表注错配、表格数据遗漏、公式或特殊字符损坏、引用错连、文献串条、包内媒体不全等明显缺陷。合法的结构表达差异不强求与参考一致。

程序通过、DTD 合法、词量接近均不能代替内容审阅。机器检查用于定位疑点，逐篇核查结论与截图实阅分别登记。不得把未审内容、历史未审帧或跳过项算作通过。本轮不恢复历史百万帧审查，也不重跑无关的全部按钮排列。

证据统一保存在 `reports/sample-cache-20260915/`；脚本和维护文档纳入 Git，缓存及稿件不入 Git。现有网络设置保持不变；如外部环境影响测试，先检查，不自行更改网卡。
