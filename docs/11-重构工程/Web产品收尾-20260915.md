# Web 产品收尾：范围、实施与验收

## 当前任务与恢复入口

用户已经提交决赛材料。本轮获批的是产品审视后的有限收尾，不是再次重构整个前端。每次上下文压缩后，先读本文件、AGENTS.md、用户最新指令，再接续当前状态。

Web 服务需要转换 Word、但不愿接触代码和部署的用户。主线为上传、自动结构化、查看原稿与结果、必要的关键字段修改、下载当前成果。人工操作必须服务于结果；不增加逐项打勾、签收、审核流或质量评分。统一使用 Word2JATS、Word、JATS XML、DeepSeek、Qwen。

业务依据是比赛选题一（章节、作者、摘要关键词、图表、公式、文献的结构化识别），评分以最新决赛通知的 25/30/25/20 为准。原始会话首条长指令强调完赛与竞争力，避免无限完美主义。已提交说明书明确限定关键字段修订，不承诺全文在线编辑。

## 本轮固定范围

1. **必须完成：编辑与原稿对照连贯。** 同篇稿件内切换原稿、文章信息、出版信息、检查或用量，不丢草稿、不迫使提前保存。保留编辑位置和原稿阅读位置，提供明确的继续编辑入口。离开稿件、刷新、主动取消编辑、恢复结果等真正会丢弃输入的动作仍受保护。保存失败、其他页面更新、窄屏和键盘使用必须覆盖。
2. **次优先：有限的结构查看。** 沿用目录与预览，增加按内容类型查找的入口和必要的结构说明；只反映当前保存 XML 中的事实，不当作正确率、完整率，不引入新的人工待办。覆盖文章信息、摘要关键词、章节、图表、公式和文献，不只强调参考文献。
3. **次优先：重新转换的出版设置。** 区分已经确认的出版设置和待重新识别的内容，优先沿用当前保存的出版信息。仍保留首次设置的明确选择和原结果，不带入题名、作者等内容修订。若实现需要改变转换核心或扩大出版配置体系，则记录依据并延后，不阻断主项收敛。

不做全文编辑、作者/单位增删、正文图表公式编辑、批量管理、账号权限、审核、PPT、说明书或提交包更新。不得因为验收发现无关问题扩大任务。

产品审视依据包括 18640 实际操作：编辑中切换原稿会弹出放弃输入；同篇真实结果有相同文献条数而承载形式不同；重新转换明确使用首次出版设置。行业资料用于界定转换与后续出版加工的分工，不把 PMC 入库要求强加给比赛原型：

- [JATS Publishing 定位](https://jats.nlm.nih.gov/publishing/index.html)
- [PMC 数据要求](https://pmc.ncbi.nlm.nih.gov/pub/min_requirements/)
- [eLife 的转换后编辑工具设计](https://elifesciences.org/labs/8de87c33/texture-an-open-science-manuscript-editor)

## 执行顺序与验收

先提交计划与恢复标签，再实现主项及有界次优先项；补测试后启动独立夹具，浏览器走查，修复首个失败边界再继续。完成全量回归、独立截图视觉检查及最终临时服务验收，最后提交代码和更新本记录。

本轮新增场景：

- C01 作者、题名、单位关联、通讯字段在对照往返中保留；原稿和编辑阅读位置可继续。
- C02 文章信息与出版信息切换共同保存；预览和下载不展示未保存输入。
- C03 检查、用量、下载说明及关闭原稿后仍可继续编辑；主动取消与离开稿件仍确认。
- C04 保存失败、版本冲突、异步保存期间切换、刷新与任务切换保护。
- C05 桌面、笔记本、平板、手机的继续编辑入口、焦点、滚动、布局与提示。
- C06 各内容类型定位、结构说明、空结果和长列表；与实际 XML 对照，不修改 XML。
- C07 当前出版设置/首次设置的重新转换、未保存保护、旧任务保留及失败重试。

既有 76 项功能矩阵继续回归；测试数量、场景覆盖和代码覆盖分别报告。新旧相关视觉状态重新截图并实际查看，不能以生成截图冒充验收。沿用现有脚本时只调整已批准改变的行为，不删场景降低要求。核心转换未变，不为回归重复消耗所有样例的模型额度；真实新任务只在必要的端到端边界验证时运行。
