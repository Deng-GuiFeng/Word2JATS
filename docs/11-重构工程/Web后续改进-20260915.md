## 走查结论及固定取舍

依据：最新用户要求、第一次 Web 批准范围与验收、实际首页/结果/对照截图（`reports/web-next/baseline/`）、`app.js`/`presentation.py`/`workbench.py`/下载接口实际行为。

| 问题 | 对完成任务的影响 | 本轮处理 |
|---|---|---|
| 上传首页垂直留白过多 | 常见笔记本首屏看不到主按钮 | 压缩布局，明确输入和下载产物，保留简单模型选项 |
| 离开任务后只有地址能找回 | 下一篇或关闭页面后容易丢失入口 | 最近转换仅存本浏览器的任务链接和必要摘要，不建服务器任务列表或账号系统 |
| 固定目录与工具栏挤占阅读空间 | 原稿与结果并排时都难读 | 紧凑结果布局、分层可收起目录、原稿对照优先分配空间 |
| 每次选段重建原稿 iframe | 对照跳动、上下文与阅读位置丢失 | 原稿只加载一次，准确落点后局部定位；无映射时明确保留原稿当前位置 |
| 检查提示缺少具体处理路径 | 用户只知道有问题，却不知道能改什么 | 出版信息直达对应编辑；内容定位有出处；网页不能修改的结构问题明确下载 XML 后处理，不伪装成已修复 |
| 下载为裸接口跳转，内容说明靠猜 | 失败离开页面，难判断拿到哪一版 | 当前保存版本提示、下载失败留在原页、独立 XML 入口、文件组成与命名一致 |
| 异步任务/保存/路由交错 | 旧请求可能覆盖新页面、误丢输入 | 绑定任务与代次，保存/离开保护；上传中导航明确处理 |

保留已完成的受控编辑：题名、作者姓名/顺序/单位/通讯信息/ORCID、出版信息；保存更新实际 XML，原自动结果可恢复，媒体和未改内容保持不变。保留真实 Token 用量，复用仍显示原始消耗与新增情况。这里不添加估算价格、评分、完成率仪表盘或新编辑范围。

界面参考只用于交互原则，不照搬外观：

- [GOV.UK 错误摘要](https://design-system.service.gov.uk/components/error-summary/)：错误应帮助返回相关字段；本项目区分用户输入错误与转换检查，不能把后者归责用户。
- [GOV.UK 核对答案](https://design-system.service.gov.uk/patterns/check-answers/)：浏览与修改有明确关联；不照搬提交审核流程。
- [W3C 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：焦点进入、约束与返回；用于窄屏编辑及确认对话框。
