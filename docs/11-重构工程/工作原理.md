## 一、总览：一份 Word 从进到出

```
Word 文件 (docx)
  │
  │ ① 解析（机械，毫秒级）
  │    把文档拆成一串"块"（段落、表格），编号 0、1、2……
  │    每块内部建立"字符流"：所有文字按顺序拼成一条串，
  │    每个字来自哪个片段、什么格式（粗体/斜体/上下标）、是不是链接，全部记录在案。
  │    每张图片、每个公式、每个嵌入对象，登记一条"出现记录"。
  │    同时开一本台账：文档里的每样东西都记上一笔，后面谁用了它都要记账。
  ▼
  │ ② 铺开（机械）
  │    把这串块写成带编号的文本清单，交给大模型看。
  │    图片写成 ⟦图#3⟧，公式写成 ⟦公式#7⟧，嵌入对象写成 ⟦对象#2⟧——
  │    什么都不许隐身，大模型必须看见文档里的每一样东西。
  ▼
  │ ③ 大模型判断·第一轮（三路同时发出，互不等待）
  │    三路的输入是同一份全文块清单，只是问的问题不同：
  │    封面路：标题、作者、单位、日期各是原文哪段字 → 答"原文摘抄 + 块号"
  │    正文路：每一块扮演什么角色（几级标题/正文段/图说明/表格……）→ 答"块号 → 角色"
  │    文献路：哪些内容是参考文献条目 → 答每条的开头摘抄，落锚后相邻锚点之间即一条
  ▼
  │ ④ 大模型判断·第二轮（全部并发，等最慢的一个）
  │    每条参考文献单独一次调用 → 这条的作者、标题、刊名、年卷期页各是原文哪段字
  │    零星裁决：压平表格的格子归属之类
  ▼
  │ ⑤ 落锚核对（机械）
  │    大模型的每句摘抄，回到原文里找。找到唯一位置 → 认下，记住坐标。
  │    找不到 → 不认。不认的字段就空着，或整条退回"原文照抄"。
  │    大模型的字永远不直接进输出——进输出的是"坐标指向的原文"。
  ▼
  │ ⑥ 组装 + 生成 XML（机械）
  │    按坐标取回带格式的原文片段，拼成 JATS。
  │    斜体上下标自动跟着原文走；ID 统一发号；交叉引用只套标签不改字。
  ▼
  │ ⑦ 出关检查（机械）
  │    在临时目录把整包（XML + 图片）建好，过九道门，全过才交货。
  │    任何一道不过：不交货，留在 failed 目录，报告点名哪道门没过。
  ▼
JATS XML + 图片文件夹
```

和旧版对比，骨架没变（还是"解析→给模型看→模型判断→机械拼装→自检"），变的是四件事：

1. **模型看得见一切**——旧版把 WMF/EMF 图直接藏起来连占位符都不给，X02 的 26 个公式模型压根不知道存在；
2. **模型只指路、不写字**——旧版模型返回字段文字直接被采信，改一个字母（bioprosthesis→bioprostheses）就混进了输出；
3. **文献不再靠正则划线切条**——旧版靠"References"标题正则和 [1] 编号切分，X01/X03/X04 三份真实投稿三种死法；
4. **出口有总账**——旧版整个参考文献区消失了都没人吭声，新版每样东西必须有着落，对不上账就不交货。

## 二、逐步详解

### 第①步　解析：把文档里的每样东西登记在册

打开 docx（它本质是个 zip），读里面的 XML。产出三样东西：

**块清单。** 段落和表格按出现顺序编号。这个块号是后面一切定位的基准。

**每块一条字符流。** 块里所有文字片段按顺序拼成一条字符串，附三张对照表：

| 对照表 | 记什么 | 用来干什么 |
|---|---|---|
| 片段表 | 第 0~18 字来自片段甲（斜体），第 19~40 字来自片段乙（正常） | 取回文字时格式跟着走 |
| 链接表 | 第 52~89 字是超链接，指向 https://doi.org/10.1016/… | DOI 按原文形态输出 |
| 对象表 | 第 120 字的位置有一张图（出现记录 #5） | 图和公式在文中的确切位置 |

制表符（Tab）原样留在字符流里，不丢、不合并——它是压平表格唯一的列位置线索。

**媒体出现记录。** 每次图片出现记一条：在哪块哪个位置、字节内容、真实格式（按字节开头判断，不信文件名）、**通过什么途径出现**。途径就是 Word 存这张图的方式：

- 正常插图（DrawingML）——论文的图；
- 老式插图（VML）——老版 Word 的图；
- 嵌入对象的预览图——MathType 公式在 Word 里显示的那张小图，和它背后的对象互相关联；
- 新旧两份中的一份（AlternateContent）——Word 为兼容存了两个版本，标记清楚哪份是首选。

旧版在这里犯的错是"看文件名定生死"：WMF/EMF 一律当垃圾丢。X02 证明这是错的——它的真图和公式图恰恰就是 EMF/WMF（金标准图包 31 个文件里 19 个）。新版**不做任何取舍**，每条出现记录都进台账，是垃圾还是宝贝由后面按途径和角色判断。

一个容器里有几张图就登记几张。01 的图 1 是五张小图拼的，旧版只取第一张就收手，新版五张全登记。

**读全整个文件，不只读正文主干。** Word 文件里除了正文（document.xml），还有几个容易被忽略的角落，规范里都有明确语义，解析层照规范办：Word 脚注/尾注（存在单独的部件里）读入并挂到引用点；浮动文本框的内容读入（01 就有 4 个）；文献管理器（Zotero/EndNote）插入的"域"只取显示结果、丢弃内部指令数据（03 有 48 个这种域，指令里是一堆管理器私有数据，绝不能漏进内容）；带修订痕迹的稿件按"接受所有修订"处理（被删除的字不进正文，新插入的字进）；页眉页脚是模板内容，登记后明确弃置。**判断依据是 Word 文件规范本身，不是"14 个样例里见过什么"**——样例里恰好没有的结构（比如非空脚注、修订痕迹），真实投稿里都会出现，处理不了的必须点名报告，绝不静默。

**台账开账。** 每个有内容的块、每条媒体出现记录、每个公式对象，各记一笔。从这一刻起，文档里的每样东西都有了身份，谁也别想悄悄消失。

### 第②步　铺开：让大模型看见完整的文档

把块清单写成给大模型看的文本，样子大致是：

```
[0] Comparison of preoperative factors between patients undergoing …
[1] Zhang San 1, Li Si 2,*, Wang Wu 1
[2] 1 Department of Cardiology, Fuwai Hospital, …
…
[47] The mechanism is shown in ⟦对象#3⟧ where the ion channel …
[49] Table 1: comparison of preoperative factors …
[50] Preoperative factor ⇥ ⇥ elective ⇥ SAVR (%) ⇥ urgent SAVR (%) ⇥ p ⇥ X²
…
```

规矩只有一条：**文档里存在的东西必须在清单上可见**。图是 ⟦图#n⟧，公式是 ⟦公式#n⟧，嵌入对象是 ⟦对象#n⟧，制表符是可见的 ⇥。旧版对"被判为回退图"的对象直接跳过、连占位符都不给——模型看到的是句子中间莫名断开，它当然不知道那里有个公式。新版模型看到 ⟦对象#3⟧，就会去判断"这个位置的对象是什么角色"。

### 第③步　大模型判断·第一轮：三路同时出发

先说清定位单位：docx 的 XML 里没有"页"——页码是 Word 打开文件排版时临时算出来的，文件本身只存块的顺序。所以一切范围都用块号表示。

**三路的输入完全相同：同一份全文块清单（第 0 块到最后一块），三路只是问的问题不同。** 不做任何"封面在前多少块、文献在后百分之几"的范围预判——那类数字全是对排版习惯的猜测，X01 实测就打脸：它的参考文献区从第 246 块就开始，全文 1261 块，起点在全文的**前 20%**，任何"后百分之几"的规则都罩不住。全文都给，猜测就不需要存在。唯一的程序规则是：全文超过单次输入预算时按长度机械切窗、窗口间重叠一段——切在哪只看字数，不含任何判断；一般论文全文几万字，一窗装下。

三路互相不依赖，同一时刻发出去，等最慢的一路回来。旧版"封面路跑完才能跑正文路"的串行等待不存在了——正文路自己看全文就能判断"第几块之前是封面、之后是正文"，不需要别人告诉它。

**封面路。** 问封面的事（标题、作者、单位、摘要、关键词、日期）。模型回答的每一项都是**原文摘抄 + 块号**，不是自由发挥（本文示例用中文字段名便于阅读，实际字段名以施工图纸第七.4 节的模式为准）：

```json
{
  "标题": {"摘抄": "Comparison of preoperative factors …", "块": 0},
  "作者": [
    {"姓": "Zhang", "名": "San", "单位角标": "1", "通讯": false},
    {"姓": "Li",   "名": "Si",  "单位角标": "2", "通讯": true}
  ],
  "日期制式": "日/月/年",
  "收稿日期": {"摘抄": "5/1/2026", "块": 7},
  "学位": [{"作者": "Zhang|San", "摘抄": "M.D., Ph.D.", "块": 3}],
  "通讯地址": {"摘抄": "1 Premium Care Center, Department of Cardiology, …", "块": 4}
}
```

两处新东西：

- **日期制式是整篇判一次**。模型看到同一组日期里有 26/2/2026，26 只可能是"日"，于是整篇按日/月/年解析。旧版逐个日期独立猜，S04 的 5/1 被猜成 5 月 1 日（正确是 1 月 5 日）。
- **学位和通讯地址第一次有了去处**。旧版中间档案里作者压根没有这两个字段，模型判出来也没处放，01 因此丢了 47 个词。

**正文路。** 输入全文块清单。回答每块的角色——这本来就是指针式的（块号→角色），保留旧协议，扩两点：一是对象角色（"⟦对象#3⟧是行内公式""⟦图#5⟧是图 2 的第三张小图""⟦图#8⟧是装饰性花边"），二是图文归属（"第 51 块是图 2 的说明文字"）。

**文献路·切条。** 输入还是那份全文块清单，任务只有一个：

> 这里面哪些内容是参考文献条目？每条的**开头几个词**是什么？不是文献的块（标题行、致谢、脚注）各是什么？

输出是每条的开头摘抄 + 块号提示：

```json
{
  "文献区标题": 304,
  "条目开头": [
    {"摘抄": "Pellikka PA, Sarano ME, Nishimura", "块": 305},
    {"摘抄": "Carabello BA. Introduction to",     "块": 306},
    {"摘抄": "Owens DS, Bartz TM, Buzkova P",     "块": 306},
    …
  ],
  "非文献": [{"块": 335, "是": "致谢"}]
}
```

系统把每个开头摘抄落锚成字符坐标，**相邻两个锚点之间就是一条文献**。注意上面第二、三条锚在同一个块里——这不是笔误，是必须支持的真实情况：Word 里回车（Enter）才产生新块，软回车（Shift+Enter）只在段落内部留一个换行记号 `<w:br/>`，视觉上像分了行、XML 里仍是同一个块。作者用软回车分条贴参考文献时，几十条会挤在一个块里；14 例实测参考区暂没有这么干的，但同样的现象已经在日期区出现（03 的一个块里挤着 Submitted/Revised/Accepted 三个日期，靠软回车分隔）。

而且软回车还**不是"一块多条"的唯一成因**。OOXML 规范只承诺"段落是存储单位"，从未承诺语义条目和任何物理记号对齐——条目之间可以是软回车、老式回车（`w:cr`）、分页符，也可以**什么记号都没有**（纯文本相接：`…179–185. [2] Carabello BA. …`，从 PDF 转 Word 或乱贴粘时真实存在）。这正是锚点定界的深层优势：它从不问"条目之间用什么隔开"，只问"每条从哪开始"，**与分隔记号完全无关**——一条占一块、一条跨多块（X01）、多条挤一块、无记号相接，全部被同一个机制处理，不需要任何特判。

顺带说明为什么不能走"预处理时把软回车替换成硬回车"的捷径：同一个物理换行，金标准在不同语境下的处理完全不同（14 例实测）——表格单元格里变 `<break/>`（03 的金标准单元格里有 67 个）、摘要里被抹平（X02 的摘要段内有软回车，金标准 abstract 只有 1 个 `<p>`、0 个 `<break/>`）、表脚注区拆成 3 个独立 `<fn>`（01）、文献区当条目边界。**物理记号本身没有固定含义，含义由语境决定**——所以解析层必须把记号原样保留（软回车在字符流里以 ↵ 可见），怎么处置由模型和渲染层按语义槽位决定；预处理替换会把"软回车=边界"这个有时对有时错的猜测焊死在模型看到文档之前，X02 的摘要就是现成的反例。

为了让模型指认更省事，给它看的清单里块内按换行记号编行号（`[306]`、`[306.2]`、`[306.3]`……）——这只是显示格式，源结构一个字节不动，模型摘抄开头或直接报行号皆可，落锚照常校验。

这里必须分清**两个"切"**：程序切的是喂料窗口（按字数），模型切的是条目边界（按语义）。条目边界百分之百是模型的判断——不认编号、不认标题词、不认段落格式；程序在这一步只做三件机械事：喂料前按长度切窗、收到输出后落锚并验格式（每个开头摘抄要在原文找到唯一位置、锚点按文档顺序严格递增，违反即无效重问；锚定失败的条目按 ↵ 换行记号退到行级照抄兜底）、事后对账（正文路对同一块的角色判断与切条矛盾就标记复核，台账保证文献区每个字符都有着落）。

这一步**没有任何形态假设**。旧版三条死路在这里全部走通：

- X03 的标题是 "References and Notes"，条目以作者名开头、没有编号——模型读一遍就知道哪是文献，不需要正则认识这个标题；
- X04 的 70 条温哥华式、无编号——每条一段，模型按内容分条；
- X01 有人把 JATS 标签逐行贴进了 Word（`<ref id="b1">`、`<label>[1]</label>` 各占一块，1014 块）——模型看见的是带标签的文本，照样能判断"从这块到这块是一条"。

超长文档（如 X01，全文 1261 块）超出单窗输入预算时，按模型的输入预算机械切窗并行问；每窗分**中心区**和**边界区**，只直接采纳中心区的结论，边界上的对象合并相邻窗的上下文重判——防止一条文献、一个章节恰好被切在窗口边界上。

**三路回来之后有一道"归并对账"（机械 + 裁决调用）。** 三路各自读全文、各自下判断，可能对同一块给出矛盾的角色（封面路说是作者行、正文路说是普通段落；正文路说是致谢、文献路说是文献条目），也可能三路都没认领某个有字的块。归并层把三路结果合成一张总表——**每一段文字、每个对象都恰有一个主角色**，冲突不靠"谁优先级高谁赢"静默压掉，而是把分歧交给一次专门的裁决调用重判。裁决仍定不下来的分两等处置：**牵涉内容本身的**（这段是文献还是正文、这段非空文字要不要丢）**拦下不交付**——候选和报告留给人复核；不牵涉内容对错的小事（比如版权年用了近似兜底）记入报告但不拦。三路都没认领的有字内容，直接算对不上账，出不了门。切条这类影响面大的判断还会**跑两个独立实例**——而且必须是**真独立**：两路用不同的问法问同一件事、各自记录响应，绝不许把一份答案复读两遍冒充两票（系统的响应缓存按"同样的请求给同样的答案"工作，原样重发第二次只会得到第一次的复读）；两份锚点一致的部分直接采纳，分歧处才进第三套问法的裁决。

### 第④步　大模型判断·第二轮：一条文献一次调用，全部并发

切条结果回来后，**每条参考文献单独发一次调用**，全部同时发出。一条文献的输入就是它自己那一两百个字（按锚点区间从字符流机械取出），输出是各字段的摘抄：

```
输入：
  [306] Carabello BA. Introduction to aortic stenosis. Circ Res.
        2013;113:179–185. doi: 10.1161/circresaha.113.300156

输出：
  {"类型": "journal",
   "作者": [{"姓": "Carabello", "名缩写": "BA"}],
   "题名摘抄": "Introduction to aortic stenosis",
   "刊名摘抄": "Circ Res",
   "年摘抄": "2013", "卷摘抄": "113",
   "起页摘抄": "179", "止页摘抄": "185",
   "DOI摘抄": "10.1161/circresaha.113.300156"}
```

为什么必须这么拆——这正是旧版"二分重试"不合理的根子：

旧版把 28 条文献捆成一包发出去，指望模型一口气返回 28 条的全部字段。输出太长就被截断，截断了就把包一分为二重来，二分是**串行叠加**的——切一次多等一轮，切两次多等两轮。02 那篇 69 条文献的综述耗时 252 秒（其他样例 110~143 秒），多出来的一百多秒全是二分重试等出来的。

新版一条一调用，输入一两百字、输出一两百字，**截断在物理上不可能发生**，二分重试机制连同它的全部复杂度直接删除。70 条文献就是 70 路并发，总等待时间等于最慢的那一条，与条数无关。书籍类文献的编者、出版社字段旧版还要等全部分块跑完再补一轮调用——新版在单条调用里一次问全，补轮也删除。

同批并发的还有零星裁决类调用，最典型的是**压平表格的格子归属**（05 那种整表被 Word 存成纯文本段落的）：

```
输入：
  表头行 [50]：Preoperative factor ⇥① ⇥② elective ⇥③ SAVR (%) ⇥④ urgent SAVR (%) ⇥⑤ p ⇥⑥ X²
  数据行 [52]：Age ⇥①…⇥⑨ <0.001 ⇥⑩ 22.3
  问题：表头共几列？每个编号段落到第几列？

输出：
  {"列数": 5,
   "表头": {"第1列": ["Preoperative factor"], "第2列": ["elective", "SAVR (%)"], …},
   "行[52]": {"第1列": ["Age"], "第4列": ["<0.001"], "第5列": ["22.3"]}}
```

模型只回答"哪段归哪格"，**一个字都不写**。系统机械校验：每段恰好用一次、每行按列序拼回去等于原文。校验不过，这张表退回"整段原文照抄"的保底形态，绝不硬凑。

### 第⑤步　落锚：模型的每句话都要回原文对质

模型返回的每一句摘抄，系统拿着它回到对应块的字符流里找：

```
第1步  一字不差地找 → 找到且只有一处 → 认下，记住坐标（节点 + 起止字符位置）
第2步  找不到？把空格连写、弯直引号、连字符这类写法差异归一后再找 → 唯一 → 认下
第3步  找到不止一处？看这类内容有没有天然顺序——
       条目开头、作者名单这类确有先后的序列，按文档序从上一锚点之后找起
       （同作者的重复条目、重复年份多数就这样自然分开）；
       参考文献的各个字段没有固定顺序（不同著录体例里年份可以在题名前也可以在
       页码后），就把这一条所有字段的候选位置摆在一起做整体分配——互不重叠、
       符合原文先后的唯一解才认 → 仍没有唯一解 → 不认
第4步  不认怎么办 → 见下表
```

一条压倒性的原则：**宁可不认，不许认错**。锚定失败有兜底（下表），代价只是结构粗一点；锚错位置则是把错误的原文当成某个字段悄悄输出，没有任何后续环节能发现。所以歧义一律拒绝，预实验验收的指标是"错误锚定必须为零"，不是"成功率有多高"。另外摘抄默认不许跨过图片、公式这类对象占位——要跨必须显式声明，防止一句摘抄从公式两侧各抓半句拼出根本不存在的"原文"。

| 不认的东西 | 退路 |
|---|---|
| 文献的某个字段（如卷号） | 该字段空着，其余字段照常 |
| 文献的多数关键字段 | 整条退回"原文照抄"（mixed-citation）——按块区间机械取回整段，永远可行 |
| 封面的关键字段（如标题） | 带着"没找到"重问一次；仍失败 → 用正文路判定的标题块**整块**原文顶上 |
| 表格归属校验不过 | 整表退回原文照抄形态 |

注意退路的共同点：**都退到"按块号机械取原文"**。块号是模型指的路，块的内容是系统自己取的——所以无论模型摘抄质量如何，进入输出的文字永远是原文，最坏情况只是结构粗一点（照抄整段而不是拆好字段），绝不会是错一个字母的"近似原文"。

旧版那道"字段与原文词重叠不足 40% 就作废"的防线，防的就是模型改字。新版模型的字**根本不进输出**，这道防线连同它的漏网风险（40% 门槛下 bioprosthesis→bioprostheses 溜过去了）一起消失。

### 第⑥步　组装与生成 XML：照着坐标抄，一个字不多

按角色和坐标，从解析层取回带格式的原文片段，填进中间档案（代码里叫 SemanticDoc），再机械生成 JATS。几条铁规矩：

**输出里的每个字只有三个合法来源**：

1. 按坐标从原文抄来的（绝大多数）；
2. JATS 结构本身（标签名、属性名）；
3. 期刊模板配置里白纸黑字声明的（刊名、ISSN、版权句、Publisher's Note——有清单，可核对）。

除此之外一个字符都不许出现。旧版的几处"热心肠"全部废除：连续引用 [1,2] 不再被展开成 "1, 2"（逗号后那个凭空多出的空格，V2 评测报了 261 条）；通讯段不再被拼进逗号、不再补第二个星号；DOI 前不再拼 "https://doi.org/"；年份上不再加金标准没有的属性；无编号的文献不再凭空补 [1]、[2]。

**格式两步走：先算清事实，再按位置取舍。** 第一步是解析层把每段文字的**实际生效格式**算出来——Word 里斜体可能直接标在文字上，也可能藏在字符样式、段落样式的继承链里，只看文字上的直接标记会漏，所以按 Word 的样式继承规则算到底，这是事实层的活。第二步是渲染层按**语义位置**决定用不用：期刊名的斜体照抄（05 原文 "Circ Res" 带斜体，输出就是 `<source><italic>Circ Res</italic></source>`；04 原文没斜体，输出就没有——金标准正是跟着原文走的）；但文章标题、章节标题整体的加粗**不进输出**——那是"这行是标题"的视觉样式，标题的身份已由标签本身表达，金标准也不保留它；标题里真正的斜体、上下标仍然保留。每类位置的取舍规则都有对应测试钉住。DOI 同理：原文是超链接就输出 `ext-link`，原文是裸文本就输出 `pub-id`，链接表里记着呢，不用猜。

**交叉引用认"实体"，不认"格式"。** 每条参考文献建一个可匹配的身份（作者姓、年份、年份后缀、题名辅助）；正文里的引用不管长什么样——`[3,5-7]` 这样的编号，还是 `Anderson & Fowers, 2020` 这样的作者—年份（X03 的金标准里有 43 处这种）——都拿去和文献身份做匹配，配上了就给**原文那几个字**套上 `<xref>` 标签，一个字不改；配不上唯一目标就保持纯文本并在报告里点名，绝不随手连到第一条。

**身份和门牌分开。** 图、表、公式、文献的内部 ID 由文档级发号器统一发，保证全文唯一；显示编号（"Table 1"）只写在 label 里当门牌。X02 那五个没有编号的表，旧版全撞成 T000 导致整份 XML 不合法；新版发号器照发不误，编号有没有跟身份无关。**脚注也一样凭身份连线**：作者名字后的 † 角标和"前两位作者贡献相同"那条注释是一对关系（02/03/04/S03 的金标准里都有），表和表底下的多段注释也是一对关系（S05 的一条表注有 5 段）——这些关系在中间档案里用内部 ID 显式连接，XML 里的 `xref` 就是照着关系生成的，不是靠渲染时猜。

**表格属性分两类。** 对齐、边框这类**物理排版属性**按 OOXML 的继承链（整表样式→行→格）机械算出——哪些子项真能和金标准对上，由施工前的全表实验逐项定，对不上的子项如实放弃并报告；"这行是表头、这列是行头"是**语义判断**，优先用 Word 自己的表头标记，没有标记时由大模型看内容判。

**公式分三路。** OMML 公式机械转 MathML（现成转换器，不经模型）；单个变量符号（原文里的斜体 *P*、*q* 这种）按其 OMML 结构简单判定后输出为斜体文字，不硬套公式标签；MathType 等老式公式转不出 MathML 的，输出为公式配图——图的字节就是 Word 里那张预览图元，台账记明“对象#3 以配图形式交付”。**三路都有去处，公式不可能消失。**

中间档案还保留几类容易被“看起来差不多”掩盖的结构差别：图题可同时有直接 `title` 和多个 `p`；表脚既可是关系化脚注，也可是金标准中已存在的直接段落；参考文献作者组保留个人、团体和 `et al` 的原始次序与可见文字；图形公式按原位置区分行内和独立展示。这些都由类型化字段承载，不靠保存原始 XML 回放。

### 第⑦步　出关检查：九道门，全过才升为正式交付

先在暂存目录把完整的**候选包**建好（XML + 图片文件夹），依次过门：

| # | 门 | 拦什么 |
|---|---|---|
| 1 | XML 良构 | 语法坏了 |
| 2 | DTD 合法 | 结构违反 JATS 1.3 |
| 3 | ID 全局唯一 | T000 撞号这类 |
| 4 | 引用闭合 | xref 指向不存在的目标 |
| 5 | 图片字节一致 | 输出的每张图和 docx 里的原字节逐字节相同 |
| 6 | 格式如实 | 扩展名与字节真实格式相符——每种格式用各自的验证办法（位图试解码；WMF/EMF 这类矢量图验签名和结构头，通用图片库解不了它们） |
| 7 | 无多余文件 | 交付包里混进没被引用的文件 |
| 8 | **覆盖账对平** | 原文每段文字、每个对象都有去向或有记录在案的弃置理由。**有依据的复用是合法的**——同一个地址进多位作者名下、同一邮箱既在作者又在通讯段，金标准就是这么写的，账上记复用关系即可；只有无缘无故的重复和无人认领的缺口才拦。内容性的"待复核"（角色没裁定、非空文字弃置存疑）也在这道门拦下 |
| 9 | **来源账核对 + 守恒报警器** | 独立核对另一本账：输出里每段文字都指得出来处（原文坐标 / 模板配置 / 白名单里的具名变换如日期重排、公式转换）——这不是把第 8 门的账再读一遍，是对另一本账的独立检查；另跑一个**独立实现**的逐词守恒报警器交叉核对（直接数词，不读任何账本），两套机制互为备份 |

全过：文章加锁、旧产物先备份、分步替换、出错回滚——**可恢复的事务式交付**（最终摆放位置和现在完全一样）。任何一道不过：候选包移进 failed 目录（带运行号，并发互不覆盖），报告点名哪道门、差在哪、是"确定有错"还是"内容性待复核"；**评测器评的就是候选包**（评测的编排层为此做了最小适配：转换时写一份"样例 → 候选包位置"的运行清单，两套评测器照清单找产物——评分逻辑一行不动），所以被拦下的结果照样能诊断"还差什么"。

要说清九道门的边界：它保证的是**交付安全和来源真实**——不合法的 XML 出不了门，无中生有的文字出不了门，没人认领的内容丢失出不了门。它**不保证语义判断正确**：假如模型稳定地把整个参考文献区判成普通正文段落，文字都在、账也能平、XML 也合法——这类错要靠第③步末尾的双独立实例分歧（两路问法不同，很难错得一模一样）、"内容性待复核不交付"的闸门和两套评测器去抓，不是靠账。

## 三、时间花在哪：调度账

机械部分（解析、落锚、组装、生成、检查）全部是本地计算，秒级——旧代码不调模型时 10 个样例并发跑完只要 2.7 秒，新增的落锚是字符串查找、台账是记账，还是秒级。**转换时间几乎全部是等大模型回话，所以调度就是时间的全部。**

旧版的调度：

```
时间轴 ────────────────────────────────────────────▶
封面路  ├────────┤
正文路           ├──────────┤          ← 必须等封面路先回
文献路  ├──────28条一包───┤├─二分重试─┤├─再二分─┤├─书籍补轮─┤   ← 串行叠加
                                     总耗时:110~252 秒
```

新版的调度：

```
时间轴 ────────────────────────▶
封面路    ├────────┤
正文路    ├──────────┤              ← 三路同时出发,互不等待
文献切条  ├──────┤
                    ├─70条并发─┤    ← 第二轮:每条一调用,等最慢的一条
                    ├─杂项裁决─┤       (与切条同时回来的先发先跑)
          └── 第一轮 ──┴─ 第二轮 ─┘
                总耗时 ≈ 两轮往返 ≈ 最慢的两个调用相加
```

要点（以下是**设计预期**，以实测为准，不是写死的承诺；并发数、超时、重试都做成可调配置）：

- **轮次由依赖关系决定，预期两轮上下**：第一轮各专项判断并发（互相无依赖），第二轮逐条文献与各裁决并发（依赖切条结果，这个依赖省不掉）；归并层发现分歧时会多出少量裁决小调用。
- **耗时基本与文献条数无关**。70 条是 70 路并发不是 70 倍时间；02 那种 69 条的综述预期不再比别人慢一倍。并发池有上限（可配置），条数极多时会分批，但批内仍全并发。
- **旧版的截断问题不复存在**。单条文献的调用输入输出各一二百字，远够不着输出上限；二分重试和书籍补轮这两个串行大户直接删除。异常长的单条依然设上限保护，超限走原文照抄兜底。
- 单篇预期总耗时一两分钟量级，瓶颈是单次往返的模型响应速度，不是调用数量。

## 四、答错了怎么办：从模型到出口的五层防线

大模型会答错，这是设计的前提而不是意外。五层防线，一层比一层靠外：

```
第1层  模型只指路不写字      → 答错最多是"指错地方",不可能"造出假文字"
第2层  落锚核对              → 指的地方在原文里对不上号,当场不认
第3层  块级退路              → 字段锚不上就退到整块照抄,文字永远是原文
第4层  台账平账              → 整块整条被漏掉,出口点名,不会静默
第5层  九道门 + failed 隔离  → 上面全失手,交付包也出不了门
```

举例串一遍：模型把 X04 第 63 条文献的题名摘错了两个字——落锚找不到（第 2 层），题名字段作废；这条其余字段正常，条目照常输出；假如它连作者刊名全摘错，整条退回原文照抄（第 3 层），文字仍是对的，只是没拆字段；假如切条把第 63 条整个漏了、也没有别路认领那个块，台账发现第 371 块没人认领（第 4 层），点名报告；假如台账代码本身有 bug 放过去了，第 9 道门的逐词守恒复查还会数出"输出比原文少了一条文献的词"（第 5 层）。**但要老实交代这套防线的盲区**：假如第 63 条被稳定地误认成了正文段落——文字有去向、账是平的、词也守恒，第 4、5 层都抓不住。抓这种错靠的是别的机制：切条跑两个问法不同的独立实例（很难错得一模一样，分歧就会暴露）、裁决定不下来就"待复核不交付"，最后还有两套评测器对着金标准数条数——这正是第③步末尾归并对账存在的理由。

## 五、拿真实文件走一遍流程

**X03（标题 "References and Notes"，条目无编号）** 旧版：标题正则不认识，[1] 兜底也找不到，判定"这篇没有参考文献"，35 条全灭，静默交货。新版：切条模型直接读懂，35 条各归各位；就算读漏，台账拦住不让出门。

**X01（伪 JATS 贴进 Word，文献区 1014 块、从全文前 20% 就开始）** 旧版：划线划到了，但 [N] 切分面对 `<label>[1]</label>` 这种一块一个标签的碎片束手无策，30 条全灭。新版：全文清单超出单窗预算，按长度切几窗并发切条，模型看懂"从 `<ref>` 到 `</ref>` 是一条"；字段摘抄就是标签里的文本，落锚照常。

**X04（70 条温哥华式无编号）** 旧版：切不出边界，整区一包塞给模型，输出撑爆截断，解析失败返回零条，连锁导致 860 个词丢失、125 处交叉引用崩掉。新版：切条一轮 + 70 路并发一轮，完事；无编号就不输出编号，不凭空补 [1]。

**X02（26 个 MathType 公式 + EMF 真图 + 无编号表）** 旧版：WMF/EMF 一律当垃圾，公式连占位符都没有，模型全程不知情，输出公式数为零；五个无编号表撞成 T000，XML 不合法。新版：每个对象都登记、都占位；能转 MathML 的转，转不出的以公式配图交付，台账保证 26 个一个不少；表 ID 发号器发，DTD 合法。

**01（五联图 + 通讯地址）** 旧版：容器里只取第一张图，后四张丢；地址模型判出来也没处放，47 个词丢失。新版：五张全登记全交付，字节逐一与原文核对；地址有字段、有坐标、有落锚。

**05（DOI 裸文本 + 压平表格）** 旧版：DOI 一律拼成网址输出，25 条全错；压平表"丢空白单元格"导致列位置塌陷，31 条缺陷。新版：链接表里没这条链接，输出 pub-id 抄原文；表格由模型归属格子、机械校验拼回原文，校验不过就整段照抄保底。

## 六、和施工图纸的对应关系

| 本文的说法 | 施工图纸里的名字 |
|---|---|
| 字符流 + 对照表 + 出现记录（部件—节点—区间） | 第七.1 节源对象图 |
| 模型只指路不写字、摘抄回原文对质、宁可不认不许认错 | 不变量 2、第七.3 节落锚协议（精度优先） |
| 中间档案装得下一切、装不下必须明说 | 不变量 3、第七.2 节 SemanticDoc v2 |
| 输出的字只有三个来源、每个字指得出来处 | 不变量 4、第七.5 节来源映射 |
| 归并对账、分歧裁决、复核分级（内容性待复核不交付） | 第七.4 节 DocumentAssignment、第七.5 节复核分级 |
| 脚注凭身份连线（作者↔注释、表↔表注） | 第七.2 节 Note 契约 |
| 双实例必须真独立（不同问法、各自记录） | 第七.4 节独立性契约 |
| 两本账、九道门、候选/交付两态、failed 隔离 | 不变量 5、第七.5/7.6 节 |
| 三路并发 + 每条文献一次调用 + 双实例切条 | 第七.4 节专项判断与调度 |
| 格式两步走（算清事实 + 按位置取舍） | 第七.1 styles.py + 第七.2 槽位投影 |
| 交叉引用认实体（编号制与作者—年份制同一机制） | 第七.4 节引用实体匹配 |
| 压平表格的格子归属 | 第七.4 节归属调用、阶段 5 |
| 公式三路分流 | 第七.2 Formula + 对象图建模 |
