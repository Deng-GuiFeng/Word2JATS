# 第一部分　根源分析

## 一、任务的本质：一条判据划清大模型与代码的边界

这项任务的本质是**角色指派**：docx 里的每一个字符、每一次媒体出现、每一个格式属性，都是给定的源事实；JATS 输出只是给这些事实穿上语义标签。转换器不创造信息，它做三件事——认全事实、判定角色、按规范表达。

这三件事需要的知识性质完全不同：

| 环节 | 依赖的知识 | 知识集合的性质 | 应该由谁做 |
|---|---|---|---|
| 认全事实 | OOXML 规范（ECMA-376） | **封闭**（按受支持配置划界后可完备实现，见七.1） | 确定性代码 |
| 判定角色 | 人的写作排版习惯 | **开放**：每个作者、每家期刊、每种投稿模板都不一样，永远枚举不完 | 大模型 |
| 按规范表达 | JATS 1.3 + 出版社体例 | **封闭** | 确定性代码 |

这就是规则与大模型的分界判据：**封闭集用代码，开放集用大模型。** 规则只在它被写出来的那个集合上成立；集合封闭，规则就是规范的实现，一劳永逸；集合开放，规则就是对人类习惯的猜测，每来一份新稿件就赌一次。

拿这条判据检验当前系统，病灶立刻现形：**开放集问题被交给了封闭规则**。参考文献区在哪，靠一条标题正则加一条 `[1]` 正则（`understand/segment.py`）；条目边界在哪，靠 `[N]` 编号切分（`understand/passes.py`）；表格列在哪，靠"丢掉空白单元格"的启发式（`understand/assemble.py:108`）。X 组四份真实投稿逐一击穿这些猜测，不是运气差，是必然：

- X03 的标题是 `References and Notes`——正则只认 `References` 整行，**多两个词就全军覆没**，35 条文献一条不剩。实测 `REFERENCES_HEAD.match('References and Notes')` 返回 False。
- X04 的 70 条文献没有编号——`[N]` 切分切不动。
- X01 的参考区是有人把 JATS 标签逐行贴进 Word（`<ref id=“b1”>`，还是弯引号）——任何形态规则都无从谈起。

而这三种形态，恰恰是大模型闭着眼都能读懂的东西。识别"这一段是不是一条文献著录"是语义理解的基本功，不分编号制、作者年份制还是伪 JATS。系统里最擅长开放集的组件被规则挡在了门外，等规则失败把垃圾喂给它时才轮到它出场。这是当前架构最深的一处错位。

## 二、逐层病理：信息在流水线的每一站是怎么死的

沿流水线定位（docx → ①解析 → ②序列化 → ③大模型判断 → ④组装进语义模型 → ⑤渲染 → ⑥出口校验）。每一层的病都不是"某个 bug"，而是**契约错了**。

### ① 解析层：事实在进门时就被销毁

契约本该是"无损认全"，实际在做取舍：

- **媒体身份按文件扩展名判定**（`parse/runs.py`：`_META_EXT = (".wmf",".emf")` → `is_fallback`）。这个假设已被事实推翻：X02 金标准图包 31 个文件中 **15 个 EMF、4 个 WMF**——它们是真实插图和公式图形，不是回退截图。媒体是什么，由它所处的 OOXML 上下文决定（DrawingML 插图 / VML / OLE 对象预览 / AlternateContent 的 Choice 与 Fallback），不由扩展名决定。
- **每个容器只取第一个 `a:blip`**（`_resolve_run_image` 里 `break`）。01 的五联图只剩第一张，直接源于此。
- 制表符的位置信息、参考文献区的 run 格式，读进来了，但走到下游就被压平丢弃。
- 解析只读 document.xml 主干：脚注/尾注部件不读（04 实测有脚注部件）、浮动文本框无口径（01 实测有 4 个）、域代码无状态机（03 实测 48 个 ADDIN 文献管理域）、修订痕迹无口径、run 格式只读直接属性不解析样式继承链（字符样式里的斜体会漏）。

事实一旦在这里死掉，下游任何聪明都救不回来，只能靠猜——**规则就是这么繁殖的**。

### ② 序列化层：判断者看不到被销毁的事实

`understand/serialize.py:105`：`is_fallback` 的图**连占位符都不生成**。X02 的 26 个 OLE 公式在喂给大模型的文本里是一片空白，模型看到的是句子中间莫名断开。判断者只能判断它看得见的东西——序列化的契约应是"完整的事实清单"，现在是"过滤后的摘要"。

### ③ 理解层：契约是"返回文本"，应该是"返回指针"

除了第一节说的规则占位问题，还有一个更隐蔽的契约错误：**大模型的回答被当作文本采信**。模型返回 `article_title`、`source` 等字段的字符串，系统拿它去渲染。于是需要 `_sanitize_ref` 里 40% 词重叠守卫来防编造——而 02 的 `bioprosthesis→bioprostheses` 改字正是从这个门槛下钻过去的。守卫再严也只是把漏网概率调小，**改契约才能把概率变成零**：模型只回答"这个字段是原文的哪一段"（引文 + 机械落锚到唯一源区间），最终文字一律从源区间抄回。锚定不到，字段就不进输出。守恒从"事后抽查"变成"构造保证"，40% 门槛这类补丁整个失去存在的理由。

项目的立身之本"正文文字不流经模型"在正文通道是做到了的（按块编号回填），**但参考文献、通讯段、日期这些通道没有贯彻同一契约**——病灶不是理念错了，是理念没有贯彻到底。

### ④ 语义模型：容量小于输出空间

`semantic/model.py` 的表达力装不下金标准需要的东西（14 例定稿 XML 实测清单）：

- `Author` 没有 degrees、地址、电话、邮编——01 的 47 个丢失词（`fuwai hospital / beijing / 100037`…）不是没读到，是**读到了也没处放**；
- `Figure` 只能带一张图——五联图装不下；X02 有 2 个 `fig-group`、5 个 `inline-graphic`；
- 摘要表达不了 `abstract-type="graphical"`（S05/X02）与 `abstract-type="precis"`（S03）；
- 公式表达不了"以图形呈现的公式"（X02 金标准图包里有 `eqn-08.wmf`、`eqn-16.emf` 这类公式图）；
- 没有 glossary/def-list（02/04/X03 金标准有）、没有 author-comment（S04 有）；
- 著录类型实测有 confproc(5)/report(1)/thesis(1)，现有模型枚举装不下；
- `Reference` 字段只存纯字符串，**源 run 的斜体、超链接目标在装进模型那一刻全部蒸发**。

模型判对了也白判。语义层的容量必须覆盖输出空间，否则正确的判断被中间层截断，表现出来像"判错"，实际是"没处放"。

### ⑤ 渲染层：发明内容，并把源事实误当体例

两类错，性质不同。

**发明内容**——输出里出现了源文档没有的字符：连续引用间塞 `", "`（`build/xref.py:108`，04 的原文是 `[1,2]` 无空格，V2 报 261 条）；通讯段拼接用 `", ".join`、又无条件补一个 `<sup>*</sup>`（原文的星号还在，星号出现两次）；DOI 前拼 `https://doi.org/`；`<year>` 上加金标准没有的 `iso-8601-date`（521 条）；无编号文献凭空补 `[1]、[2]` 可见编号（`assemble.py:713` 起，对 X03/X04 是错的）。

**把源事实误当体例**——期刊名是否斜体、DOI 用 `pub-id` 还是 `ext-link`，**不是出版社的统一模板，而是源文档的事实**。实测坐实：05 的 docx 里 `Circ Res` 这个 run 带 `w:i`（斜体），金标准就有 `<italic>`；04 的 docx 参考文献不带斜体，金标准 145 个 `<source>` 就**全部没有** `<italic>`；X01 同理。金标准忠实跟随源文档。所以正确做法不是任何"包不包斜体"的规则，而是把有效格式随字段一路携带到渲染层，按语义槽位的投影策略转写（见七.2/七.4）。DOI 同理：源文档是超链接就输出 `ext-link`（S04 的 41 个，现在就是对的），是裸标识符就输出 `pub-id`（05 的 25 个，现在错），无需任何猜测，只需要事实别在半路丢掉。

另有一个身份混淆：表的内部 ID 直接用显示编号生成（`render/tables.py:36`），X02 五个无编号表全部撞成 `T000`，DTD 直接不合法。**显示编号是内容，内部 ID 是身份**，两者职责不同，不能互相兼任。

还有一处功能遗漏：**作者—年份制正文引用**（X03 金标准有 43 个 `Austen R. Anderson & Blaine J. Fowers, 2020` 形态的 bibr xref），现有交叉引用只认数字编号。

### ⑥ 出口：不闭环

- 校验门槛是坏的且不拦截：`verify/verify.py:29` 对 dataclass 调 `.get()`（会抛 `AttributeError`，靠 `n_fab==0` 永假被短路挡住）、比对不存在的 `"error"` 级别；就算修好，`pipeline.py` 只是把 `vreport` 记下来，**照常写出 XML**——门槛不管门。
- **没有消费台账**：系统不知道每个源块、每次媒体出现是被用了一次、用了多次、还是被静默丢弃。X01/X03/X04 交出没有参考文献的 XML 时一声不吭，`validate/checks.py` 那条检查要求"有 `<ref-list>` 但没条目"才报警——`<ref-list>` 压根不存在，警报在结构上就响不了。整类内容消失之所以能静默发生，就是因为没有"每个事实必须有去向"的总账。
- 输出不是事务性的：图片先写进目标目录、后校验 XML，失败不回滚；未知格式媒体默认给 `.jpg` 扩展名（`build/figures.py`），产出"名字是 JPEG、字节不是 JPEG"的文件。
- 版权年取自运行当天的系统时钟（`pipeline.py`：`datetime.date.today().year`），同一份 docx 跨年转换结果不同；且 01 金标准版权年是 **2025**（等于其 accepted 年），"统一当作 2026"这类假设是错的——版权年应从源日期推导。

## 三、目标架构：一个契约，五条不变量

把上面所有病灶收拢，目标架构一句话：

> **一切输出内容可追溯到源；一切判断以指针表达；一切源事实有明确去向。**

展开为五条**机器可验证**的不变量：

**不变量 1（事实无损）** 解析后，每个文本字符、每次对象出现、每个有效格式属性都有稳定地址（部件/节点/字符区间，见七.1），媒体身份由 OOXML 上下文建模。解析实现受支持的 OOXML 配置，配置外的可见结构显性失败。*验收：从 IR 能重建 docx 的全部可见内容与对象清单（独立参考实现比对）。*

**不变量 2（判断只指不写）** 大模型的一切输出都是（源地址，角色标签）二元组；实现上取"模型给引文、系统落锚"——引文机械匹配到唯一源区间，锚定成功才有效，最终文字一律从源区间抄回。模型返回的字符串永不直接进入输出。*验收：删除 40% 重叠守卫后守恒依然成立；落锚错误率为零（精度优先，见七.3）。*

**不变量 3（语义层覆盖输出空间）** SemanticDoc 的表达力 ⊇ 金标准用到的 JATS 子集（14 例装载为下界检验），且**不完备必须显性暴露**：装载器/渲染层遇到装不下的结构明确报错，禁止以"保存原始 XML"作逃生口。

**不变量 4（渲染零发明）** 渲染器输出的每个字符只有三个合法来源：源区间的机械抄写、JATS 规范要求的结构、显式声明的期刊模板配置。渲染同时产出**来源映射**（每个输出文本区间 → source(区间)/config(键)/transform(具名变换)），出口核对映射完整、变换在白名单内。格式按"有效格式事实 + 语义槽位投影策略"转写。

**不变量 5（出口闭环）** 文档级 ID 分配器；**两本账**（输出来源账 + 源覆盖账，见七.5）；候选产物过九道门才升为正式交付（可恢复的事务式交付，见七.6）。**九道门保证可交付性与来源真实性，不单独保证语义正确性**——语义质量靠双独立调用与分歧裁决（七.4）、复核分级（内容性未决不交付，七.5）与两套评测器。

### 病灶消解表：为什么这不是打补丁

打补丁和系统修复的分水岭有一条可检验的标准：**修复之后，规则总量是增是减。**下表左列是全部已知问题，中列是消解它的不变量，右列是随之被**删除**的规则——不是新增：

## 四、对外部审查的取舍（两轮汇总）

**首轮采纳**：来源跨度主线、媒体上下文建模、ID 分配器、事务性输出、消费台账、显式出版配置、表属性三分、验收标准修正（类目条数不许涨是错的）。**首轮修正两点**：其参考文献方案仍在枚举形态（枚举六种和枚举一种是同一方法论）；其制表符表"字体度量+约束求解"是伪精确（05 无制表位定义，列归属取决于渲染宽度，XML 层拿不到）。

**二轮采纳**（细目见附录 D）：台账两本账、部件/节点/区间地址、全局分区与分歧裁决、落锚精度优先、有效格式继承+槽位投影、作者—年份引用、可恢复事务交付+候选/交付两态、来源映射落地第九门、往返测试三分+ID 双射+隔离测试、施工前置原型、表格预实验重设计、版权年源推导、语义模型补全（glossary 等）、离线重放无密钥化。**二轮拒绝一条**：参考文献"顺序片段流"——实测 14 例金标准的 element-citation 直接子元素间**无任何字段间标点**（仅有的 7 处非空 tail 全是字段内部行内元素的续文，SourceText 的 run 机制本就覆盖），mixed-citation 保全原文，片段流是不必要的复杂度。

## 五、重构的总体形态

这不是推倒重来，是**换契约的修复式重构**。现有代码里，DTD 校验、OMML→MathML、期刊查表、LLM 客户端、JATS 元素构件这些封闭集实现都是对的，保留；要换的是贯穿全线的**数据契约**——从"字符串在层间传递"换成"源地址在层间传递"。

主线：**先用原型钉死契约（阶段 P），再定义语义层新契约（SemanticDoc v2），然后从两端向它会合**——

```
                 ┌────────── 上半场(阶段3-4) ──────────┐   ┌──── 下半场(阶段1-2) ────┐
docx ─→ 事实层(无损寻址) ─→ 理解层(引文落锚+分歧裁决) ─→ SemanticDoc v2 ─→ 渲染层(按源转写+来源映射) ─→ JATS
                                                        ▲
                                          金标准反向装载器 + 手写夹具
                                          ——下半场的测试基准,不依赖大模型
```

验证方式由此决定：**下半场完全离线开发**（金标准装载→渲染→双射归一比对，不涉及大模型）；**上半场以落锚精度、两本账平账和分歧率验证**。架构重构不能逐模块 A/B——契约变了，中间状态没有可比性。全程只有**三个端到端对照检查点**：阶段 0 结束（检查点 A：模型输入未变，输出差异可位级归因到代码改动）、阶段 4 结束（检查点 B：契约切换完成，按 F1 对照基准）、阶段 5 结束（检查点 C：终检回归门，防"阶段 4 通过、阶段 5 引入回归仍宣布完成"）。中间各阶段靠分层测试验收，不靠跑分。

执行顺序：P → 0（检查点 A）→ 1 → 2 → 3 → 4（检查点 B）→ 5（检查点 C）。P 与 0 可穿插；1–2 与 3 无依赖可穿插；4 最后整体切换，不做半新半旧——半切换的契约没有可测的中间态。

## 七、核心契约定义

### 七.1　源对象图（model/source.py）

```python
@dataclass
class SourceNode:
    """有稳定路径的源节点:段落/表/行/格/脚注段/文本框段…"""
    node_id: str          # 稳定路径,如 'doc/p42'、'doc/tbl3/r2/c4/p0'、'fn2/p0'、'txbx1/p0'
    part: str             # document | footnotes | endnotes | header | footer
    kind: str             # para | table | row | cell
    parent: str | None
    order: int            # 全文阅读序(浮动对象按锚点位置定序)
    # 仅 para 类节点携带字符流,构成规则定死:
    #   TextRun 文字原样(含 \xa0,不归一);<w:tab/>→'\t';软回车 w:br/w:cr→'\n';
    #   对象出现→U+FFFC 占一格;域代码取"域结果"文字、弃"域指令";修订按接受口径。
    text: str
    run_spans: list       # [(start,end,RunRef)] RunRef 携带**有效格式**(经 styles.py 继承解析)
    links: list           # [(start,end,url)] 含 w:hyperlink 与 HYPERLINK 域两种来源
    objects: list         # [(pos,occ_id)]

TextRange = tuple[str, int, int]      # (node_id, start, end) end 不含

@dataclass
class SourceText:
    """语义层一切内容性字段的统一类型:只存地址,文字与格式渲染时机械取回。"""
    ranges: list          # list[TextRange] 按输出顺序
    def runs(self, doc): ...   # 按 run 边界切片,部分覆盖时切割 run

@dataclass
class ObjectOccurrence:
    occ_id: str           # 'o1','o2'… 按文档序
    kind: str             # image | omml | ole | chart | smartart
    node_id: str; char_pos: int
    # 两类组关系语义相反,必须分开建模——"同组"才能明确是去重还是全保留:
    representation_group_id: str | None  # 替代表示组:同一逻辑对象的多种物理表示
                          # (AlternateContent 的 Choice+Fallback、OLE 对象+其预览图);
                          # 交付时按能力选一个主表示,其余标 superseded 及原因入弃置账
    representation_role: str | None      # choice | fallback | object | preview(组内有优先级序)
    composition_id: str | None           # 组成组:复合对象的成员(一图多面板),有序,默认全部保留
    composition_index: int | None
    resource_id: str | None
    relations: list       # 显式引用边,不靠字符串猜:choice_of/fallback_of/preview_of/
                          # member_of/anchored_to(浮动对象与文本框的锚点)

# 资源是联合类型:OMML/图表/SmartArt 的本体是 XML,不得塞进"二进制"里冒充:
#   Resource = BinaryResource | OmmlResource | ChartResource | SmartArtResource

@dataclass
class BinaryResource:
    res_id: str; rel_target: str; content_type: str
    blob: bytes; fmt: str     # fmt 按字节魔数;同一资源被多处出现引用是常态,不算重复

@dataclass
class OmmlResource:
    res_id: str; part: str; node_path: str
    omml_xml: str             # 原始 OMML 子树原文(MathML 转换与"图形公式"降级都从这取材)
# ChartResource/SmartArtResource 同构:保存所属部件、节点路径与原始 XML
```

**受支持的 OOXML 配置（划界声明）**：WordprocessingML Transitional（ECMA-376，Word 2007+ 的 .docx）；document/footnotes/endnotes/headers/footers 部件；DrawingML(wp:inline/wp:anchor)/VML/OLE/AlternateContent/chart/SmartArt 对象；域代码（取结果弃指令，HYPERLINK 域目标入 links）；修订痕迹（按接受口径）。**配置之外的可见结构显性失败并给出节点路径**，不静默。页眉页脚视为模板内容、修订按接受态处理，这两条是**项目政策**，写入 PubConfig 说明而非冒充规范结论。

### 七.2　SemanticDoc v2（semantic/model.py 重写要点）

在现有 `semantic/model.py` 之上：

- **类型替换**：一切内容性字段（标题、作者姓名、单位、摘要段、章节标题、图表说明、参考文献各字段、通讯段、脚注、声明）从 `str`/`runs` 改为 `SourceText`。
- **Contributor 通用化**：`Author` 增 `degrees、addresses（列表，可多址）、postal_code、phone`（均 SourceText 可空）；`email` 也走摘抄+落锚；`Editor` 保留。**地址与作者是多对多**：`Address` 独立成表，作者持引用（01 实测两条地址映射多位作者）。
- **注释与脚注带关系，不只带文字**（统一契约，承载作者脚注/author-comment/表脚注/正文脚注）：

  ```
       paragraphs: list[SourceText],# 多段(S05 表脚注 5 段、S04 同类,实测)
       owner_scope,                 # article | contrib-group | table | body
       target_ids: list,            # 被注释的贡献者/表等语义实体(内部 ID)
       reference_occurrences: list) # 源文中的引用出现区间(如作者名后的 † 角标)
  ```
  作者与注释、表与表脚经内部 ID 显式连接，`<xref ref-type="fn">` 由关系生成（02/03/04/**S03** 金标准实测各有 2 个 contrib 内 `xref@fn`——外部审查只点名前三例，恰说明关系要通用建模、不按样例点名）；往返测试验证**关系同构**，不只验证文字尚在。
- **显示对象**：`Figure.graphics: list[occ_id]`；`FigureGroup(label, caption, figures)`——子图各有自己的 label/caption；`GraphicalAbstract`；`InlineGraphic`；`Formula(presentation ∈ {mathml, image}, omml_occ | image_occ)`——保留对原始 OMML 出现的引用与嵌入位置；`TableBlock` 单元格为 `TableCell(content: SourceText, colspan, rowspan, header_kind ∈ {col,row,None}, 有效物理属性)`；表脚为多条 `Note`（owner_scope=table，实测 33 个全带 id、全无 label、可多段）。
- **P1 装载实施时补齐的显式容量**：`Caption(title?, paragraphs)` 同时承载 01 的图题直接 `title+p`；`TableBlock` 除关系化 `Note` 外还承载 05 实有的直接表脚 `p`，并保留两类子项次序；`ReferencePersonGroup` 保留 `name/collab/etal` 原序，`etal` 的可见文字也必须是 SourceText；图形公式同时支持 `disp-formula/graphic` 与 `inline-formula/inline-graphic`；摘要小节显式区分有 `sec` 包装和摘要下直接 `title/p`。这些均是 14 份定稿金标准的已验证结构，不是按样例编号分支。
- **摘要**：`Abstract(kind ∈ {main, graphical, precis}, sections)`，结构化小节带标题归属。
- **后置区**：`Glossary/DefList`、多段落声明块；一切脚注类走上述统一 `Note` 契约。
- **Reference**：字段全 SourceText；增 `month、day、suffix、elocation_id、chapter_title、pmid`；`publication_type` 为**开放字符串**（实测集 journal/book/chapter/confproc/report/thesis/web + other，JATS 合法值内由模型判）；`doi_carrier ∈ {bare, url, hyperlink}`；另有**可匹配身份**（作者姓集、年份、年份后缀、题名辅助键）供交叉引用实体匹配（七.4）。
- **完备性口径（防过拟合）**：14 例装载是**下界检验**；完备性无法先验证明，配套要求**不完备显性暴露**——装载器/渲染层遇到装不下的结构抛明确异常，**禁止用"保存原始 XML"作逃生口**。扩容同步改本图纸。

### 七.3　落锚协议（understand/ground.py）——精度优先

```python
def ground(quote, doc, *, scope: TextRange | None, after: Position | None,
           block_hint=None) -> TextRange | None
```

```
第1步 精确:quote 在 scope 内、after 之后出现且唯一 → 锚定
第2步 归一:双方按归一集归一后唯一命中 → 锚定(返回区间仍指原始字符)
       归一集(初版定死):连续空白(含\xa0,\t,\n)折单空格;弯引号→直引号;en/em 连字符→-;
       不做大小写归一、不做 Unicode 兼容分解。扩充机制:仅经预实验/夹具证明必要后扩充,
       同步改图纸+加性质测试。已知候选(预实验重点):零宽字符 U+200B/U+FEFF、
       软连字符 U+00AD、全角/半角。
第3步 多处命中 → 用 after(顺序约束)与 block_hint 消歧;仍歧义 → 拒绝(不猜)
第4步 拒绝/失败 → None,按处置表兜底
```

三条硬规矩：**(a) 精度压倒成功率**——错误锚定率必须为零，宁可拒绝走兜底；预实验按判真集（阶段 P4）分别统计精确锚定/归一锚定/**错误锚定**/歧义拒绝/兜底比例，错误锚定>0 即修协议。**(b) 联合分配代替贪心推进**——`after` 顺序约束**只适用于确有文档序保证的序列**：切条条目开头、作者名单、同类段落序列。参考文献各字段的字面顺序因著录体例而异（年份可在题名之前也可在页码之后），**禁止按字段表固定顺序贪心推进 `after`**——那会把正确摘抄因"位于上一字段之前"错误拒绝。字段锚定的定式：先为每个摘抄收集作用域内**全部**候选区间，再做一次联合分配——区间互不重叠、符合源文档顺序、符合字段类型约束的一致解**唯一存在**才采纳；无唯一解整体拒绝走兜底。同作者重复条目、重复年份的歧义由不重叠约束消解。**(c) 摘抄默认不得跨对象占位**（U+FFFC）——需要跨越时模型显式声明，否则拒绝。

处置表（锚定失败时）：

| 失败的东西 | 处置 |
|---|---|
| 参考文献某字段 | 该字段置 None，其余照常 |
| 参考文献关键字段普遍失败 | 整条退 mixed-citation（按条目区间机械取回原文） |
| front 关键字段（标题/作者姓名） | 带失败反馈重问一次；仍失败 → 标题退整节点原文，作者整行入 raw |
| 切条条目开头 | 按 `\n` 退行级候选，进逐条调用复判 |
| 表格归属校验不过 | 整表退原文照抄，记账 |

### 七.4　理解层：分区、专项判断、归并裁决（passes.py / merge.py / understand.py）

**给模型看的清单格式（定死）**：

```
[<节点号>] <文本>            ← 段落节点;软回车分行时续行标 [<节点号>.<行序>](行序从2起)
[<节点号>|表] 后接逐行:[<节点号>.r<行序>] 格1 ⇥ 格2 ⇥ …   ← 原生表逐行铺开
```
`\t`→`⇥`；U+FFFC 按对象登记显示 `⟦图#o5⟧`/`⟦公式#o9⟧`/`⟦对象#o12⟧`。**任何对象不得隐身。**

**切窗协议**：按模型真实 token 预算切窗（不按裸字符数），每窗分**中心区**与**边界区**——只直接采纳中心区结论，边界区对象合并相邻窗上下文重判；跨窗长对象用可延伸区间处理；全部并发结果**按源地址排序归并**，与返回先后无关。窗宽/边界宽为配置（七.8）。

**专项判断任务（输入均为全文清单，全部并发）**：

- **front**：输出模式在原有基础上补齐——`editors`（学术编辑）、`addresses: [{lines, postal_quote, phone_quote, author_refs}]`（多址+作者映射）、`precis`、结构化摘要小节（标题+段落归属）、`email_quote`（摘抄制）、图文摘要。日期为文档级制式默认假设（`date_format`），代码解析遇矛盾分量即报错重问。
- **body**：逐块角色（含 `blank/decorative`）、章节层级、图表归属、对象角色；原生表输出 `header_rows` 与行头判断（`row_header: bool`，供 `scope="row"`；`w:tblHeader` 存在时机械优先）。
- **refs 切条**：每条条目**开头摘抄**（`head_quote`+节点提示），代码按七.3 落锚（条目开头是有序序列，适用 `after`）；条目终点=下一锚点/非文献节点/连续文献段末端三者先到者。**高影响判断做双独立调用**，独立性契约（防"同一缓存自我表决"——实测缓存键仅 provider/model/system/user+采样参数，同请求第二次调用是第一次响应的逐字重放）：A/B 两路用**不同提示词版本**（同一任务、不同表述与视角），请求体不同故缓存键天然不同，另以路标（A/B/裁决）显式入缓存键；任何一路不得复用另一路的响应；裁决调用用第三套提示词，同时看到原文窗口、两份结论及各自落锚证据；ReplayLLM 分别录制回放三份响应，禁止一份缓存复制成三份；报告记录每路的模型、提示词版本、采样参数与缓存命中状态。追求的不是统计独立，而是至少消除缓存复读与同题复诵的假独立；服务端 seed 仅作补充手段。锚点集一致处直接采纳，分歧处进裁决；仍不一致 → 按七.5 复核分级处置（条目边界属内容性未决，`review_blocking`）。
- **refs 逐条析字段**：一条一次调用全量并发，字段全摘抄（模式含 label/authors/collab/etal/title/source/editors/edition/publisher/chapter_title/year/month/day/volume/issue/fpage/lpage/elocation/doi/pmid/comment/publication_type）。书籍字段同调用问全。`doi_carrier` 代码判定（定死）：DOI 区间与 links 相交→`hyperlink`；可见文本以 `http(s)://`、`www.` 开头或含 `doi.org/`→`url`；其余→`bare`。
- **压平表格归属**：分段编号→列号纯归属，输出含 `n_cols、header_lines`；机械校验每段恰用一次、行内序不变、可拼回原行。

**全局归并（merge.py，新增的理解层总闸）**：各专项结果汇成 `DocumentAssignment`——**每个源字符区间与对象恰有一个主角色**，保留各路证据。冲突（front 说作者、body 说正文；body 说致谢、refs 说文献；跨窗层级不一致）不靠固定优先级静默覆盖，进**独立裁决调用**（独立性契约同上）；仍无法一致 → 按七.5 复核分级：**内容性未决**（角色分歧、条目边界、对象取舍、非空文字弃置、关键关联）标 `review_blocking`——候选保留、`delivered=False`；仅不影响内容与关系的低风险事项标 `warning`——交付但点名。三路都没认领的有字区间 → 源覆盖账缺口，阻断。

**交叉引用（实体匹配，数字制与作者—年份制同一机制）**：为每条参考建立可匹配身份（作者姓集/年份/后缀/题名辅助键）；正文可见引用区间（`[3,5-7]` 或 `Anderson & Fowers, 2020`）与参考实体匹配——数字制按标签映射，作者年份制按姓+年+后缀，多候选用题名/邻近上下文裁决；**只给原字符套 `<xref>`，绝不改写可见文本**；无唯一目标保留纯文本并报告，不许连到第一条了事。X03 的 43 个作者年份引用是验收硬指标。

**调度**：轮次由真实依赖决定（预期形态：专项判断并发 → 归并/裁决 → 逐条与归属细化并发），不把"两轮"写成契约。所有调用并发，重试 `MAX_REASK=1`（针对格式错误与锚定失败反馈）。

### 七.5　两本账（verify/ledger.py）

**输出来源账**：每个输出文本片段、媒体引用、由源推导的属性 → 指向源区间/源对象/显式配置键/白名单内的具名变换（日期重排、OMML→MathML、实体转义…）。由渲染层的来源映射（`verify/provenance.py`）落地，第九门核对完整性。

**源覆盖账**：每个应保留的源字符区间与对象出现 ≥1 个去向，或有受限弃置理由。**字符区间做区间运算**：报未覆盖区间、重复覆盖区间、交叉覆盖、弃置区间。**有依据的复用合法**（同一地址进多位作者、同一邮箱进 contrib 与 corresp）——一对多允许，复用关系记录在案；**同一语义实例的无意重复**（同一段落被当两个正文段输出）才报错。媒体区分出现与资源：两个出现引用同一资源不算重复。

**复核分级（三档，取代笼统的 review_required）**——两本账只能证明"文字有去向"，不能证明"去向的语义角色正确"；因此**内容可能放错或丢失的未决事项不许正式交付**：

| 判级 | 情形 | 处置 |
|---|---|---|
| high | 有字区间未覆盖未弃置；切条范围内区间无归属；drawingml/choice 对象出现未消费；同一语义实例无意重复；来源映射缺口 | 阻断：候选入 failed/，`delivered=False` |
| review_blocking | **内容性未决**：归并/裁决后遗留的角色分歧、文献条目边界未决、对象取舍未决、关键关联（作者—注释、xref 目标）未决；非空可见文字的 `decorative/blank` 弃置既无部件政策依据、独立复核调用又未同意 | **不正式交付**：候选同走 failed/ 隔离（报告区分档位），供诊断/评测/人工复核，`delivered=False` |
| warning | 不影响内容与关系正确性的低风险事项：版权年走近似兜底、多候选已消歧的记录等 | 正常交付 + 报告点名 |
| ok | 空白区间；受限弃置：`blank、decorative(经独立复核)、ole_preview_superseded、fallback_superseded、ref_notation(条目内编号括号/字段间标点/伪 JATS 标签壳,随条目消费——14 例实测金标准的 element-citation 不保留字段间标点)、header_footer_template(部件政策)` | — |

模板注入内容登记 `(配置键, 值, 配置版本)` 三元组，供第九门核对；不进守恒豁免词表。

### 七.6　出版配置与交付（pipeline.py / verify/repair.py）

```python
@dataclass
class PubConfig:
    journal_id: str | None
    doi: str | None
    publication_year: str | None      # 显式提供;None 时按下述推导
    include_publisher_note: bool      # 由期刊/工作流配置决定,不无条件 True
```
**版权年取值（定死，绝不读系统时钟）**：出版年份是**出版工作流的元数据，不是稿件内容**——投稿 docx 里本不存在"将于哪年出版"，它与 `journal_id`/`DOI` 同类，主通道是显式输入。顺序：显式 `publication_year` > 源 accepted 日期年（依据是"出版通常发生在录用同年"这条出版常识的**近似**，报告中标注近似及其来源日期地址）> 源日期最晚年（更弱的同类近似，同样标注）> **无任何依据 → 不生成依赖年份的模板内容并在报告点名**。金标准数据（01 版权年 2025==accepted 年，其余 2026）只作"未证伪该近似"的佐证，不是规则依据——这 14 例区分不了"录用年"与"出版年"两种政策，样例统计定不了规则。近似兜底的存在使评测运行无需传参、评测器保持完全只读，这是顺带效果不是设计目的。

**可恢复的事务式交付**（不夸称原子——两个并列路径无法一次重命名替换）：候选在 `<out_dir>/.staging-<article_id>-<运行号>/` 构建 → 过九道门 → 文章级锁内分步替换（旧产物先备份、异常回滚）→ `delivered=True`。任一门不过：候选整包移 `<out_dir>/failed/<article_id>-<运行号>/` 附失败报告，`delivered=False`。**评测统一读候选产物**（`ConvertResult.candidate_dir`），交付状态单独记录。运行号保证并发同文章不互相覆盖。

| # | 门 | 检查 |
|---|---|---|
| 1 | 良构 | XML 可解析 |
| 2 | DTD | JATS 1.3 Journal Publishing 校验通过 |
| 3 | ID 唯一 | 全文档 `@id` 无重复 |
| 4 | 引用闭合 | 每个 `@rid` 指向存在的 `@id` |
| 5 | 媒体字节 | 输出媒体字节 == 对应 BinaryResource.blob |
| 6 | 格式如实 | 扩展名==魔数；**分格式验证器**（栅格用解码验证；WMF/EMF 用签名+结构头验证，不用 Pillow）；unknown → 失败 |
| 7 | 无冗余 | 交付包内每个文件都被 XML 引用 |
| 8 | 源覆盖账 | 覆盖账结论：无 high、无 review_blocking；弃置与复用记录合规；warning 清单入报告 |
| 9 | 输出来源账 | **独立核对**渲染产出的来源映射：完整覆盖输出文本、变换全在白名单（不是重读第 8 门的同一份账，是对另一本账的独立检查）；另跑**独立实现**的词级守恒探测器交叉校验（直接数词，不读任何账本） |

**九道门回答"能否安全交付"，不回答"语义是否正确"**——后者靠双独立调用与分歧裁决、复核分级（内容性未决不交付）与两套评测器。

### 七.7　ID 分配器（build/ids.py）

`DocIdAllocator.take(kind)`：按 kind 独立计数、文档级唯一；显示编号只写 `<label>`。**测试比对时 ID/rid 按全局双射归一**（金标准存在 `T001/F1/E25/GA1.g1` 等多种历史命名，不要求字面相同，要求引用关系同构）；媒体文件名按字节身份归一。

14. 参考文献不引入"顺序片段流"。**架构性理由**（不依赖样例统计）：新契约下各字段本就是指向原文区间的投影，整条原文始终可寻址、零丢失；若体例日后要求保留字段间标点，只需改渲染层投影方式，架构不动——片段流是不必要的前置复杂度。金标准全量核查（element-citation 直接子元素间无字段间标点）仅作体例现状佐证。
15. 交叉引用做参考实体匹配，数字制与作者—年份制同一机制。
