# 文档体系导览

本目录是 word2jats 项目的完整文档，既是**项目执行记录**，也是一本**学习手册**。建议按顺序阅读。

> **一句话定位**：本作品的核心是 **LLM 驱动的 Agent 视觉闭环**——把输入 Word 渲染成页面图（人眼真值），用本地多模态模型独立核对我们产出的 XML，发现差异就地修复、再核对、循环收敛，质量从这里来。确定性管线（解析+分类+构建）是闭环之下的**热启动加速器**（给闭环一个好起点、省成本）；`--llm off` 仍出合规 XML 是**向后兼容兜底**（以质量下降为代价），不当卖点。详见 `01-设计/02-智能循环架构.md`。

## 🎯 三条阅读线

1. **想了解竞赛与策略** → `00-调研/01-竞赛理解.md` → `02-数据与映射规格.md`（§1 最关键认知）。
2. **想理解/维护代码** → `01-设计/01-架构设计.md` → `02-开发/01-开发者指南.md` → 看 `../README.md` 把项目跑起来。

## 🔑 三条贯穿全项目的核心结论

1. **金标准 ≠ 由 docx 唯一算出来的结果**：金标准里掺了人工编辑和外部补充的信息，不可能、也不该要求逐字节对得上；我们的目标是产出**合规、完整、尽量还原原文结构**的 JATS（详见 `00-调研/02` §1）。
2. **样式名不可靠**：真实投稿的 docx 经常没有样式名或样式名乱标，判断各部分扮演什么角色主要靠分析内容本身，这样换没见过的文档也能处理。
3. **质量来自 Agent 视觉闭环，确定性只是它的热启动加速器**：死规则永远枚举不完真实投稿的花样（表是图片、表用制表符拼、作者行分隔特殊、公式是图……），唯有让模型看着页面图去核对、去补救才扛得住——这是评分"创新性"的落点。确定性管线又快又稳又省，先搭一版草稿给闭环打底（"落地性"的工程基础）；`--llm off` 仍出合规 XML 是**向后兼容兜底**（质量降级），是底线，不是"默认更优"。
