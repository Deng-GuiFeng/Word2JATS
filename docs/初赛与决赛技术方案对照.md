# 初赛与决赛技术方案对照

## 先看结论

决赛版并不是换一个更大的模型，也不是把初赛转换器推翻重做成另一类工具。两版都采用“模型理解结构、程序组装 XML”的分工。主要变化是：从以段落为单位的取回，推进到可核对的字符与对象定位；从较粗的文献处理，推进到边界与字段分开识别；从交一个结果文件，推进到能发现问题、供编辑复核的工作台。

这些变化增强了复杂稿件的内容保留与问题定位能力，同时增加了结构理解与核对任务。决赛版着重提高转换结果的可用性与可复核性，长稿处理速度仍有优化空间。

## 比较对象

初赛原始提交包是当时作品的快照。开发仓库中的 master 分支继承初赛技术路线，但后来又加过交付检查等工程修复。因此，master 的复测结果可以说明初赛路线的某些表现，不能将其所有行为追溯为初赛提交包原本就有。

源码对照中，原始包与 master 的主要理解任务、分段和提示词保留了相同谱系。下文以“初赛路线”指这一技术体系；决赛版则采用 rebuild-core 的源对象图与语义装配架构。复测数据来自对应分支，而非直接运行原始提交压缩包。

## 上层视角的差异

| 问题 | 初赛路线 | 决赛版 | 对编辑的实际意义 |
|---|---|---|---|
| 文字怎样进入 XML | 正文主要按源块取回，部分字段由模型返回字符串 | 正文与文献字段定位到源字符范围，文首另设受检查通道 | 更容易检查某段输出具体来自哪里 |
| 怎么处理复杂 Word | 以块序列组织内容 | 段落、表格、对象出现与资源组成源对象图 | 能分别检查文字和图片、公式的去向 |
| 文献怎样切条 | 较依赖编号与局部切分 | 两路独立边界判断，分歧裁决，再逐条抽字段 | 无编号、多段著录等形式更可处理 |
| 字段抽不全怎么办 | 旧字段安全检查较粗 | 检查实际已输出区间；有实义文字缺口则整条原文保留 | 不用“字段齐全的外观”换掉真实作者或年份 |
| 图表、文献引用 | 依赖较粗的结构映射与后处理 | 单独识别提及，再按实体及原文位置连接 | 链接可以核查，不确定项可提示 |
| 怎样判断可以使用 | 以转换和基础校验为主，master 后加工程检查 | 源覆盖、输出来源、DTD、媒体、引用等联合检查 | 不能处理的内容有提示和位置 |
| 等待怎样安排 | 调用较少，流程相对简单 | 任务较多，按真实依赖并发推进 | 在增强检查的同时减少无必要等待 |
| 使用结果的方式 | 上传、查看与下载为主 | 真实原稿对照、文章与出版信息修改、版本恢复及同步导出 | 用户的针对性修订直接更新最终 XML，无需重跑整篇识别 |

## 哪些是已经观察到的实质改进

初赛路线复测中，X01、X03、X04 的参考文献曾出现整类缺失；决赛版能识别对应的 30、35、70 条。X02 两版均识别出 32 条。逐例条目数量已核对，未完全拆字段的著录仍以完整原文保留。

两版均采用 OMML→MathML 机械转换。决赛版增加对完整变换节点的核对，覆盖等式右端与多个顶层片段，当前验证结果见评测章节。

当前的调度优化使引文识别与其他理解任务同时开始，文献字段在边界确认后立即运行，表格处理也不再等待不相关的文献任务。实际速度采用同机逐篇冷跑测量，与响应复用耗时分别记录。

## 为什么不继续追求完全端到端

复杂表格、老式嵌入对象以及不规范的引文，不一定能在一次自动转换中可靠处理。继续增加猜测规则可能把显性待办变成隐性错误。决赛版把这些问题交给有原文依据的复核流程：先生成能用的结构，明确指出需要判断的位置，编辑修订原稿后重新转换。

产品围绕 Word2JATS 的实际编辑流程，自动完成可确定的标注，让剩余工作可定位、可记录。人工节省比例有待真实编辑计时实验进一步验证。
