# Word2JATS 可运行原型

Word2JATS 将学术论文的 Word 稿件转换为 JATS 1.3 XML 与配套图片，处理文章信息、正文层级、图表、公式和参考文献。网页提供转换、内容预览、原稿对照、文章与出版信息修改以及结果下载；命令行提供同一转换流程，便于接入已有处理程序。

首次使用建议通过网页完成一篇稿件的转换。

## 1. 运行准备

- 稿件：准备一份 Word 文件（`.docx` 格式，网页上传上限为 300 MB）。图片、表格和公式随稿件处理，无需另行上传；旧版 `.doc` 文件须先另存为 `.docx`。
- 环境：本地安装使用 Linux/macOS 和 Python 3.10 及以上，建议 Python 3.12；不需要 GPU，也不需要安装 Word。Windows 请使用第 6 节的 Docker 方式，或在 WSL2 的 Linux 环境中按第 2 节安装。
- 网络：安装依赖和调用云端大语言模型需要联网。转换时会向所选模型服务发送稿件相关内容，请使用允许通过云端服务处理的稿件。

本目录的 `.env` 已配置 DeepSeek 和 Qwen 两套测试密钥，各提供 **20 元评审测试额度**，可在网页中任选一种使用，无需另行申请密钥。

| 网页选项 | 使用的模型 | API Key 字段 |
|---|---|---|
| DeepSeek | `deepseek-flash` | `DEEPSEEK_API_KEY` |
| Qwen | 文首信息提取使用 `qwen3.8-max`，其余流程使用 `qwen3.7-plus` | `DASHSCOPE_API_KEY` |

测试密钥仅供本原型评审试用，请勿公开传播。需要使用自己的账户时，修改 `.env` 中对应的密钥；若账户使用不同接口地址，同时修改对应的 `DEEPSEEK_BASE_URL` 或 `DASHSCOPE_BASE_URL`。修改配置后重新启动服务。`.env.example` 是不含密钥的配置模板，首次运行不需要用它覆盖现有 `.env`。

## 2. 安装与启动

在终端中进入解压后的 `JiangLab/可运行原型` 目录，确认能看到 `README.md`、`requirements.txt`、`src/` 和 `webapp/`。以下命令均在此目录执行。

先检查 Python 版本并创建独立环境：

```sh
python3 --version
python3 -m venv .venv
source .venv/bin/activate
```

第一条命令显示的版本应为 3.10 或更高。若机器上有多个 Python 版本，可将前两条命令中的 `python3` 替换为已安装的 `python3.12` 等对应命令。

安装依赖和转换程序：

```sh
python -m pip install -r requirements.txt
python -m pip install . --no-deps
```

启动网页服务：

```sh
python -m webapp
```

在这台机器的浏览器中打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。出现 Word 文件上传页面，即可开始使用。

运行期间保持终端开启；使用结束后按 `Ctrl+C` 停止。以后再次启动时，进入同一目录，执行 `source .venv/bin/activate` 和 `python -m webapp` 即可，无需重复安装。

## 3. 完成一次网页转换

### 3.1 上传稿件

1. 选择或拖入 Word 文件。
2. 选择 DeepSeek 或 Qwen。
3. 如已知稿件的 DOI 和期刊，可展开“出版信息”填写；尚未确定时可以留空，转换后再补充。
4. 点击“开始转换”。页面依次显示读取文档、识别结构、生成文件和检查结果的进度，完成后进入结果页。

耗时随稿件长度、内容复杂度和模型服务响应速度变化。文件上传完成后，刷新页面可以继续查看进度，无需重复上传。

### 3.2 查看与修改

先通过“内容预览”和左侧文章目录浏览结果；需要查看标签结构时，切换到“XML”。选择“查看原稿”可并排对照 Word 内容，在预览中选择章节或段落，可定位到有对应关系的原稿位置。

需要修订时使用以下两个入口：

- “文章信息”：修改题名、已有作者的姓名与顺序、ORCID、通讯作者标记、作者与单位的对应关系，以及已有单位和通讯信息。
- “出版信息”：补充或修改 DOI、期刊名称、ISSN 和出版方；选择已配置期刊可自动填入相应刊名与刊号，也可以填写自定义期刊。

修改后点击“保存修改”，预览和待下载的 XML 随即更新，Word 原稿保持不变。网页中的直接编辑范围为上述信息；正文、图表或参考文献需要修改时，请修改 Word 后重新上传。

若页面出现提示，打开“检查详情”查看具体内容。缺少期刊信息时，可在“出版信息”中填写刊名和至少一个有效 ISSN 后保存；内容相关提示可通过“对照原稿”查看。格式检查通过表示 XML 满足相应结构约束，仍应结合预览确认文章内容。

### 3.3 下载结果

点击“下载结果”，取得 `Word2JATS-稿件标识.zip`。下载的是当前已保存版本；如有尚未保存的修改，请先保存。

| 文件 | 用途 |
|---|---|
| `稿件标识.xml` | 当前版本的 JATS XML，主要转换成果 |
| `figures.zip` | XML 引用的配套图片资源 |
| `文件说明.txt` | 成果文件及图片解压方式说明 |
| `检查摘要.json` | 当前版本的格式与结构检查结果 |
| `转换用量.json` | 模型用量和本次转换新增用量 |
| `修改记录.json` | 已保存的人工修改记录，仅在修改后提供 |

解压成果包后，再将 `figures.zip` 解压到 XML 所在目录，保留图片包内的目录结构。向出版处理程序导入结果时，请同时提供 XML 和配套图片目录，不要单独移动 XML 或改动图片相对路径。

如需取回上传的 Word，可在“更多”中选择“下载 Word 原稿”。

### 3.4 查看用量与再次转换

“用量”显示输入、输出及合计 Token（模型处理内容的计量单位），并列出输入中的缓存命中和未命中量。再次上传相同稿件时，程序可复用本地保存的分析，页面仍显示生成这些分析时的原始用量，并注明本次新增消耗；全部复用时，本次没有新增模型消耗。模型服务的输入缓存命中仍属于在线调用，与本地复用已有分析不同。手动修改文章或出版信息不调用模型。

需要再次处理时，根据目的选择：

- “转换下一篇”：上传另一份稿件，或上传修改后的 Word。
- “更多 → 重新转换”：重新识别当前 Word，可更换模型，会产生新的模型用量。新任务沿用首次上传时的出版设置，不带入之后的人工修改；原任务仍保留。
- “更多 → 恢复自动生成的原始版本”：撤回当前结果中已保存的人工修改，恢复本次自动转换的 XML，不重新调用模型。

## 4. 结果保存与服务关闭

网页上传的 Word、转换结果和已保存修改存放在 `webapp/_runs/`，本地模型分析缓存存放在 `webapp/_cache/`，上传临时文件存放在 `webapp/_uploads/`。

需要以后继续查看时，请保存结果页地址。保留原运行目录并重新启动服务后，可用该地址打开已完成的任务；停止服务会中断尚未完成的转换。重要成果请下载留存，清理这些目录前先确认所需文件已保存。

默认服务仅供本机访问。若部署在服务器上供他人使用，需要另行配置访问控制后再开放访问。

## 5. 命令行转换（可选）

完成第 2 节安装并激活环境后，可不启动网页，直接执行：

```sh
python -m word2jats convert "论文.docx" --llm deepseek -o output/
```

将 `论文.docx` 替换为实际稿件路径；路径包含空格时保留引号。使用 Qwen 时，将 `--llm deepseek` 改为 `--llm dashscope`。

如需补充已确认的出版信息，可添加 `--journal`、`--doi` 或 `--publication-year` 参数。期刊参数填写预设期刊代码，可查阅 `src/word2jats/resources/journals.yaml`；完整参数说明为：

```sh
python -m word2jats convert --help
```

命令行会打印 XML 路径和检查结果：

- 自动检查通过：退出码为 0，XML 和配套图片目录位于 `output/`。
- 提示“转换结果需要处理”：退出码为 1，已生成的 XML 和图片保存在 `output/failed/本次运行标识/candidate/`，对应检查报告为上一级的 `report.json`。请按终端打印的路径查看结果与报告。

命令行直接输出 XML、图片目录与运行报告，不生成网页成果压缩包。处理多篇稿件时，建议为每篇指定不同的输出目录，避免同名结果被替换。

## 6. Docker 运行（可选）

已安装并启动 Docker 时，可用此方式代替第 2 节的 Python 安装；Windows 需使用 Linux 容器。在 `可运行原型` 目录执行：

```sh
docker build -t word2jats .
docker run --rm --name word2jats-prototype -p 127.0.0.1:8000:8000 --env-file .env -v word2jats-runs:/app/webapp/_runs -v word2jats-cache:/app/webapp/_cache word2jats
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，按第 3 节操作。`.env` 在启动时传入，不写入镜像。两个命名数据卷分别保存任务结果和分析缓存；按 `Ctrl+C` 停止后，再次执行同一条 `docker run` 命令即可继续使用已保存的结果。

## 7. 常见问题

| 现象 | 处理方法 |
|---|---|
| 找不到 `webapp`、`word2jats` 或依赖模块 | 确认当前目录为 `可运行原型`，已激活 `.venv`，并完成第 2 节的两条安装命令。 |
| 8000 端口被占用 | 本地启动改为 `python -m webapp --port 8001`；Docker 将端口映射改为 `-p 127.0.0.1:8001:8000`。浏览器相应访问 `http://127.0.0.1:8001`。 |
| 提示 Word 文件无法打开或已损坏 | 先用 Word 确认文件能正常打开，再另存为 `.docx` 后上传；不要只修改文件扩展名。 |
| 模型服务不可用，或转换未能完成 | 先检查网络、所选服务的测试额度与密钥配置；也可选择另一种模型重试。使用自有 Qwen 账户时，需同时有权调用表中两款模型。 |
| 修改 `.env` 后仍使用旧配置 | 停止后重新启动服务；若终端预先设置了同名环境变量，它们会优先于 `.env`，请同步更新或取消该设置。 |
| 预览的分页与 Word 不同 | 内容预览按 JATS 结构排版，不复刻 Word 页式；需核对原有版式时，通过“更多”下载 Word 原稿。 |
| 个别图片无法预览 | 使用对应的原图下载入口查看；下载成果中的图片仍保留原始资源。 |
