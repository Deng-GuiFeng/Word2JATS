## docx 段落 style → 语义角色：本例**无任何语义 style**

关键结论：本 docx 由 WPS Office 生成，`word/styles.xml` 只有通用 style（Normal/heading 1-6/Title/Subtitle/TableNormal），且**正文中所有段落的 `w:pStyle` 全为空**（无 `<w:pStyle>` 元素）。因此语义角色**100% 靠内容、位置、文本特征推断**，不能查 style 表。

实测 `body` 共 376 个顶层块（372 个 `<w:p>` + 3 个 `<w:tbl>` + 1 个末尾 `<w:sectPr>`），每个 `<w:p>` 的 pStyle 都打印为空：
```
  0 P style=  | Review
  2 P style=  | Antiseizure Medications impact mitochondrial ion channels...   ← 标题
  4 P style=  | Carmen Rubio1#, Norma Serrano-Garcia1#, ...                     ← 作者行
  6 P style=  | 1 Department of Neurophysiology, ... Mexico                     ← 单位行
 32 P style=  | Abstract                                                        ← 摘要标题
 38 P style=  | 1. Introduction                                                 ← 一级标题(带编号)
```

### 角色推断规则（本文档）
- **栏目标记** = 正文第 0 段纯文本 "Review"
- **文章标题** = 第 2 段（标题与栏目间有空段）
- **作者行** = 含上标数字+逗号分隔人名、出现 `#`/`*` 标记的段
- **单位行** = 以阿拉伯数字开头、含 "Department/University/Institute" 的连续段（1–6）

- **参考文献** = "References" 之后形如 `^\[\d+\]` 的段

## body 结构

### sec 嵌套与 title 层级
9 个一级 `<sec id="S1".."S9">`，**无二级 sec**（本文只有一级编号标题）。`<sec>` 的 id 用 S+序号；**section title 保留 docx 的编号前缀**（不剥离）：
```xml
<sec id="S2">
  <title>2. Mitochondria as a Regulator of Neuronal Excitability</title>
  <p id="S2.p1">...</p>
  <fig id="F001">...</fig>

```
段落 id 命名规则：`{secid}.p{n}`（如 `S2.p1`、`S11.p1`）。

### p（段落）
docx 每个非空正文段 → 一个 `<p>`。空段（间隔用）被丢弃。

### 列表（list）
**本文无任何 `<list>`/`<list-item>`**（XML 计数 0）。docx 里逐行的缩写表、ORCID 行都未转成列表，而是合并为单 `<p>`（缩写）或拆成多个 fn（ORCID）。

### inline 格式
- `<sup>` 112 处、`<sub>` 1 处（来源见「上下标处理」节）
- `<italic>` 5 处、`<bold>` 6 处（图注里的 BioRender 标记如 `<italic> </italic>`、`<italic>. </italic>`，及图注首句加粗标题）
- 无 `<sc>`、无 `<styled-content>`

### xref 交叉引用
正文 xref 共 366 个（bibr 361 / fig 2 / table 3）；连同 front 区的 aff 10 / corresp 1 / fn 2，全文 xref 合计 379。正文三种 ref-type：
1. **bibr（361 个）**：docx 正文纯文本 `[21,22]` → XML 按逗号/区间**拆分为独立 xref**：
```xml

```
rid 命名 `b{n}`，与 ref-list 的 `<ref id="b{n}">` 一致。
2. **fig（2 个）**：docx "Figure 1" → XML 规范为 `Fig. <xref>`：
```xml

```
3. **table（3 个）**：docx "Table 1" → `Table <xref ref-type="table" rid="T001">1</xref>`

### glossary（缩写表）
docx 把缩写做成**逐行段落**（para 142-203，每行 "ADP: Adenosine diphosphate"），XML 合并为**单个 `<p>`、用 `; ` 连接、冒号改逗号**：
```xml
<glossary id="S10">
  <title>Abbreviations</title>
  <p id="S10.p1">ADP, Adenosine diphosphate; AIF, Apoptosis-inducing factor; ...; Ca<sup>2+</sup>, Calcium ion; ...</p>
</glossary>
```
docx 标题 "List of abbreviations" → XML title "Abbreviations"。

### sec 类（Author Contributions / Funding / Conflicts / Ethics）
docx 形如 "Author Contributions: C. R.: ...; N. S.-G.: ..."（label 在行首带冒号），XML 把 label 提为 `<title>`，正文进 `<p>`，且**作者缩写规范化**（"C. R." → "CR"，去点去空格）：
```xml
<sec id="S11"><title>Author Contributions</title>
  <p id="S11.p1">CR: Conceptualization, Investigation, Original Draft Preparation, Writing &amp; Editing; NS-G: ...</p>
</sec>
```
标题大小写规范：docx "Conflicts of interest:" → XML title "Conflicts of Interest"。docx "Data Availability Statement" 在本金标准里未单列 sec（被并/略）。

## 图片三方对应关系（核心）

链路：docx 段落 `<a:blip r:embed>` → `word/_rels/document.xml.rels` 的 image rId → `word/media/imageN.png` → figures.zip 的 `figN.jpg` → XML `<graphic xlink:href="JIN52316/figN.jpg">`

实测对应表：
| docx 正文位置 | r:embed | media 实际文件 | figures.zip | XML graphic href |
|---|---|---|---|---|
| para 53 (Figure 1) | rId7 | word/media/**image2**.png | **fig1.jpg** | `JIN52316/fig1.jpg` |

## 上下标处理（替代"公式"的主要内容）
化学式/离子（Ca²⁺、Na⁺、ΔΨm、KATP 等）不进公式元素，而是**行内 `<sup>`/`<sub>`**（XML 共 sup 112、sub 1）。两个来源：

1. **Unicode 上下标字符**（最常见）：docx 摘要中是真 Unicode，如 `Na⁺/Ca²⁺`（⁺=U+207A、²=U+00B2），无 vertAlign 标记。转换器必须识别这些 Unicode 上标字并还原为 `Na<sup>+</sup>/Ca<sup>2+</sup>`：
```xml
the mitochondrial Na<sup>+</sup>/Ca<sup>2+</sup> exchanger (NCLX), ...
regulates critical processes in epilepsy, including Ca<sup>2+</sup> homeostasis
```

2. **vertAlign run**（少量）：docx `<w:rPr><w:vertAlign w:val="superscript|subscript"/></w:rPr>`，如单位上标数字(para6-11)、KATP 的下标 "ATP"(6 处)。

注意 ΔΨm 在 XML 里直接用字面 Unicode 字符（Δ Ψ + 普通 m），未做 sub 处理（本文 XML 片段为便于阅读用了数字实体写法，真文件实际存的是字面 Unicode，二者对解析等价）；说明上下标识别是**字符级模式匹配 + 化学命名规则**，非简单 1:1。

## 参考文献

- **总数：docx 145 条([1]–[145]) → XML 144 条([1]–[144])**，少 1 条且发生编辑性重排（见下）。

## 自动化最难点（按难度排序）

1. **参考文献是编辑后状态、非纯转换**：docx 145 条→XML 144 条，且发生首作者级别的重排/替换（docx[10]Brodie→XML[10]Singh）。仅凭 docx 无法复现金标准的删改与重编号——这是数据本身的"编辑黑箱"，机器转换无法学到。这同时让 xref rid 的金标准答案与 docx 文本编号不完全对应。

2. **style 名零语义**：所有正文段 pStyle 为空，角色识别必须靠正则+位置启发式（"Review"/标题正则 `^\d+\.`/"Abstract"/"Keywords:"/"References"/`^\[\d+\]`），易误判（如缩写行 "ADP: ..." 与正文行难区分）。

3. **作者 ↔ 单位 ↔ ORCID ↔ 通讯 的三方关联回填**：docx 作者行只有上标数字+`#`/`*`；ORCID 在文末独立段落、格式还不统一（`0000000242784814` 需插连字符成 `0000-0002-4278-4814`）；只有通讯作者 ORCID 进 contrib-id，其余进 author-notes/fn——这套分配规则需专门逻辑。

4. **上下标双轨识别**：既有 vertAlign run（单位上标/部分 KATP 下标），又有 Unicode 上下标字符（Na⁺/Ca²⁺），还要按化学命名补 `Na<sup>+</sup>`，且 ΔΨm 又不做 sub。纯字符层面的规则化难做全。

5. **图片重命名映射**：docx media 文件名（image2/3.png）与 XML href（fig1/2.jpg）顺序错位、扩展名不同、还要剥掉 header logo（image1）、加 DOI 目录前缀——必须按"正文出现顺序"重建，不能靠文件名。

6. **mixed vs element 的判定边界**：为何恰好 8 条退化为 mixed-citation 没有显式规则，需引用解析器对"拆不干净"的容错策略，难以稳定复现金标准的同一选择。

7. **大量文本规范化**：title-case 标题、关键词小写、邮编补全与地址重排、"C. R."→"CR"、"Figure 1"→"Fig. 1"、`[21,22]`拆分为独立 xref——都是规则化但琐碎、易漏的归一化。

## 固定模板（可硬编码/查表，docx 中不存在或与内容无关）
- **整个 journal-meta**：JIN / Journal of Integrative Neuroscience / 缩写 / ISSN 0219-6352,1757-448X / IMR Press
- **DOCTYPE 与根属性**：JATS v1.3 20210610 PUBLIC 标识、`dtd-version="1.3"`、`xmlns:mml`、`xmlns:xlink`
- **permissions 整块**：Copyright 文案、`<license license-type="open-access">` + CC BY 4.0 ext-link（docx 无 "Copyright/open access" 字样）
- **author-notes 的 "Correspondence:" 文案**、fn-group 的 **"Publisher's Note: IMR Press stays neutral..."**（docx 无）
- **ack 致谢全文**（docx 完全没有，发表新增）
- **href 目录前缀 `JIN52316/`**（=publisher-id 去 10.31083/）
- **命名规则**：sec id=`S{n}`、p id=`{secid}.p{n}`、aff id=`aff{n}`、fig id=`F{nnn}`/graphic `{figid}.g1`、ref id=`b{n}`、xref rid 同步
- **表格 border 样式串**（`border-top:0.5pt solid #000000;...`）、th/td 的 align/valign/scope 模板

## 文档特有（必须从 docx 提取）
- 文章标题、栏目(Review)、摘要、关键词
- 作者姓名拆分、单位文本、ORCID、通讯邮箱、Academic Editor、收/修/录日期
- 9 个 sec 的标题与全部正文段、3 张表的单元格内容、2 张图的图题
- 缩写表全部条目、Author Contributions/Funding/Conflicts/Ethics 文本
- 145(→144) 条参考文献的题录字段
- 2 张图片的二进制（来自 figures.zip）
