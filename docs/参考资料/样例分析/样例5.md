## Body 映射

### sec 与 title 层级
docx 小节标题为**加粗、无编号**的单段（"Introduction"/"Methods"/"Results"/"Discussion"/"Conclusions"）。XML 统一为顶层 `<sec id="S1..S5">`，并**自动加阿拉伯数字编号**到 title：
```xml
<sec id="S1"><title>1. Introduction</title> ...
<sec id="S2"><title>2. Methods</title> ...
<sec id="S3"><title>3. Results</title> ...
<sec id="S4"><title>4. Discussion</title> ...
<sec id="S5"><title>5. Conclusions</title> ...
```
本文 body 只有一级 sec（无嵌套子 sec）。sec id 用 `S+序号`，无字母后缀。

### p 段落
每个正文段 → 一个 `<p id="S{n}.p{m}">`，id 按所属 sec 顺序编号，例 `<p id="S1.p1">`、`<p id="S2.p1">`、`<p id="S2.p2">`、`<p id="S3.p1">`…`<p id="S4.p4">`。

### inline 格式（italic / bold / sup / sub / styled-content）
- **italic**：XML 大量出现语义斜体，但**多数 docx 里并不存在**——属编辑加工。典型："i.e."、统计符号 p / t、期刊名：
```xml
Urgent SAVR was defined as ... (<italic>i</italic>.<italic>e</italic>., within days)
... Student’s <italic>t</italic>-test ...
... (<italic>p</italic> &lt; 0.001; Cohen’s d = 0.535)
```
- **sup（上标）**：用于单位/统计量，如 `mm<sup>2</sup>`、`χ<sup>2</sup>`、`BMI &gt;30 kg/m<sup>2</sup>`。docx 中这些常是 Unicode 上标字符或 "X²" 字面量。
- **styled-content**：用于带颜色的字符，最典型是表头 χ：
```xml
<styled-content style="color:#474747;">χ</styled-content><sup>2</sup>
```
（docx 里写作字面 "X²"，XML 改为灰色 Greek chi + JATS sup）
- **bold**：主要出现在表/图 caption 内（见“图片处理”节），正文内极少。

### xref 交叉引用（rid / ref-type）三类
docx 正文里只是纯文本（"Table 1"、"Figs. 3,4"、"[1]"、"[7,8]"），XML 全部转成 `<xref>`：
- 文献引用：`ref-type="bibr"`，rid 指向 `b{n}`：
```xml
... highly fatal once symptomatic [<xref ref-type="bibr" rid="b1">1</xref>].
... earlier investigations [<xref ref-type="bibr" rid="b7">7</xref>,<xref ref-type="bibr" rid="b8">8</xref>].
```
- 表引用：`ref-type="table"`，rid 指向 `T00{n}`：
```xml
Table <xref ref-type="table" rid="T001">1</xref> shows ...
```
- 图引用：`ref-type="fig"`，rid 指向 `F00{n}`：
```xml
Figs. <xref ref-type="fig" rid="F001">1</xref>,<xref ref-type="fig" rid="F002">2</xref>, and tables <xref ref-type="table" rid="T010">10</xref>,<xref ref-type="table" rid="T011">11</xref>
```
注意 rid 命名空间不对称：文献 `b1`（小写b，无前导零）、表 `T001`（大写T+三位零填充）、图 `F001`（大写F+三位零填充）。

### 列表
本文 body **无 `<list>` 元素**；docx 也未用 List Paragraph 样式承载真正列表（研究问题以问句形式写在段内）。

## 图片处理

### 嵌入顺序与哈希核对
docx 4 张图按文档出现顺序（`<a:blip r:embed>`）：
| 文档顺序 | r:embed | rels Target | docx 内文件 | 体积 | figures.zip 内文件 | XML graphic |
|---|---|---|---|---|---|---|
| Fig.1 (para214) | rId6 | media/image1.png | word/media/image1.png 46918B | ≈ | fig-01.png 45760B | `HSF49106/fig-01.png` |
| Fig.2 (para225) | rId7 | media/image2.png | word/media/image2.png 31215B | ≈ | fig-02.png 29850B | `HSF49106/fig-02.png` |
| Fig.3 (para237) | rId8 | media/image3.png | word/media/image3.png 46629B | ≈ | fig-03.png 45849B | `HSF49106/fig-03.png` |
| Fig.4 (para248) | rId9 | media/image4.png | word/media/image4.png 31080B | ≈ | fig-04.png 30322B | `HSF49106/fig-04.png` |

**关键结论**：
1. **三方文件名互不相同**：docx 内 `image1.png` ≠ figures.zip 内 `fig-01.png` ≠ XML 引用 `HSF49106/fig-01.png`。
2. **不能靠文件名匹配，只能靠"文档内出现顺序"对齐**：docx 第 N 张内嵌图 → figures.zip 的 `fig-0N.png` → XML 的 `HSF49106/fig-0N.png`。
3. MD5 **不一致**（image1=d5bf… vs fig-01=d22c…），体积相近但被重新保存/压缩，因此**像素哈希无法对齐**，必须用顺序。
4. XML 路径模板 = `{DOI去前缀的文章号}/fig-{两位序号}.png`，即 `HSF49106/fig-0N.png`；`<graphic>` 带 `id="F00N.g1"`。

## 公式处理

- **docx 侧**：`m:oMath` = 0，`m:oMathPara` = 0 → 文档中既没有 OMML 公式，也没有作为公式图片插入的对象（4 张 drawing 全是 Kaplan-Meier 生存曲线图，属 figure，非公式）。
- **XML 侧**：`<disp-formula>` = 0，`<inline-formula>` = 0，`<mml:math>` = 0。
- 文中出现的"类公式"成分（如 `mm<sup>2</sup>`、`χ<sup>2</sup>`、`kg/m<sup>2</sup>`、统计量 `p < 0.001`）**不作为公式处理**，而是用行内 `<sup>` + `<italic>` + `<styled-content>` 表达（见“Body 映射”节）。

### 推断的通用规则（供有公式的文档参考，本例未触发）
若 IMR docx 含公式，按 JATS v1.3 惯例应为：
- 行内：`<inline-formula><mml:math>…</mml:math></inline-formula>`
- 块级（独立成行、带编号）：`<disp-formula><label>(1)</label><mml:math display="block">…</mml:math></disp-formula>`
- 命名空间用 `xmlns:mml="http://www.w3.org/1998/Math/MathML"`（已在根 `<article>` 声明），元素带 `mml:` 前缀。
- OMML → MathML 需经 OMML2MML 转换（XSLT 或库），通常不保留 `<semantics>`/annotation。

本样例**无法从中得到公式转换的真实证据**——这是该样例对的能力盲区，需用含公式的其他样例补充。

- **element-citation 与 mixed-citation 混用**：
  - `<element-citation publication-type="journal">`：**4 条** → b2, b5, b8, b10
  - `<mixed-citation>`：**23 条** → b1, b3, b4, b6, b7, b9, b11–b27
- 每条 `<ref>` 内先有 `<label>[n]</label>`，再接 citation 元素。

### 极重要：XML 文献是"重新规范化/外部比对"的结果，非机械解析 docx
docx 文献是作者原始混合格式（缩写刊名 + PubMed 风格卷期页）：
- docx [1]: `Pellikka PA, …, Tajik AJ. Outcome of 622 adults … Circulation. 2005 Jun 21;111(24):3290-5. doi: 10.1161/CIRCULATIONAHA.104.495903.`
- docx [2]: `Carabello BA. Introduction to aortic stenosis. Circ Res. 2013;113:179–185. doi: 10.1161/circresaha.113.300156`

而 XML：
- b1: `Circulation. 2005; 111: 3290–3295.`（去掉了 "Jun 21"、期号 "(24)"、对原本就含 et al. 的条目把 "et al." 风格统一，8 位作者保留前 6 位、其余以 et al. 代替）
- b2: 刊名展开为全称 **Circulation Research**，DOI 大小写规范为 `CIRCRESAHA.113.300156`

→ **结论：金标准的 element-citation 结构化字段（surname/given-names/source 全称等）是与 PubMed/CrossRef 等外部库比对后重建的，无法仅靠 docx 文本拆分得到。** mixed-citation 则更接近"清洗后的整句"。哪些条目升级为 element-citation 似乎取决于能否在外部库精确匹配（b2/b5/b8/b10 恰好匹配成功）。

### element-citation 子元素清单（以 b2 为证据）
person-group(person-group-type="author") > name > surname + given-names；article-title；source(内含 `<italic>`)；year；volume；fpage；lpage；ext-link(DOI)。
```xml
<ref id="b2">
  <label>[2]</label>
  <element-citation publication-type="journal">
    <person-group person-group-type="author">
      <name><surname>Carabello</surname><given-names>BA</given-names></name>
    </person-group>
    <article-title>Introduction to aortic stenosis</article-title>
    <source><italic>Circulation Research</italic></source>
    <year>2013</year>
    <volume>113</volume>
    <fpage>179</fpage>
    <lpage>185</lpage>
    <ext-link ext-link-type="uri" xlink:href="https://doi.org/10.1161/CIRCRESAHA.113.300156"> https://doi.org/10.1161/CIRCRESAHA.113.300156</ext-link>
  </element-citation>
</ref>
```
b8 为无 DOI 的早期文献（仅到 lpage，无 ext-link），b10 单页码（fpage=e001336，无 lpage）。

### mixed-citation 结构（以 b1、b7 为证据）
整条作为纯文本（首尾各留一个空格），不再拆字段，DOI 以裸 https 链接尾随，**不**包裹 ext-link：
```xml
<ref id="b1">
  <label>[1]</label>
  <mixed-citation> Pellikka PA, Sarano ME, Nishimura RA, Malouf JF, Bailey KR, Scott CG, et al. Outcome of 622 adults with asymptomatic, hemodynamically significant aortic stenosis during prolonged follow-up. Circulation. 2005; 111: 3290–3295. https://doi.org/10.1161/CIRCULATIONAHA.104.495903 </mixed-citation>
</ref>
<ref id="b7">
  <label>[7]</label>
  <mixed-citation> Mistiaen W, Deblier I, Dossche K, Vanermen A. Clinical Outcomes after Surgical Aortic Valve Replacement in 681 Octogenarians: ... Geriatrics (Basel, Switzerland). 2024; 9: 44. https://doi.org/10.3390/geriatrics9020044 </mixed-citation>
</ref>
```

## 最难自动化的点

1. **段落无 style、零语义信息**：325 段全是默认 `Normal`，无 `w:pStyle`，无 IMR 自定义样式名。所有角色（标题/作者/单位/摘要/关键词/各级 heading/图表标题/文献）都得靠**位置 + 文本正则 + 直接格式**启发式判定，鲁棒性差。例：小节标题靠"加粗 + 文本∈{Introduction,Methods,…}"识别，换一篇用别的小节名就可能漏判。

2. **伪表格还原（最难）**：docx 有 **0 个 `<w:tbl>`**，14 张表全用"普通段落 + `<w:tab/>` 制表符"模拟。要把连续的含 tab 段落聚类成一张表、按 tab 切列、用前导空 tab 的数量推断 colspan/rowspan 与分组行（如 "Demographic"/"Cardiovascular" 跨列小标题行 colspan=3），还要算出 colgroup 各 col 的百分比宽度——纯靠 tab 几乎不可能精确复原 XML 里那套 col width / colspan / scope / border style。

3. **参考文献需外部库比对，非解析**：docx 文献是缩写刊名 + PubMed 风格（"Circ Res. 2013;113:179–185"），XML 却展开成全称刊名、规范卷页、并把 4 条升级为带结构字段的 element-citation。这只能通过 DOI/标题去 CrossRef/PubMed 反查重建，**无法从 docx 文本直接生成**；且"哪条用 element、哪条用 mixed"的判定标准不在 docx 内。

4. **编辑加工导致 docx≠XML**：标题被改写（"How do…?"→"How…:"）、摘要首句改写、单位补 "Belgium"、缩写 W.M.→WM、heading 自动加 "1./2." 编号、图例大幅扩写。转换器若严格"忠于 docx"反而对不上金标准——金标准混入了人工编辑。

5. **语义 italic 与排版 italic 错位**：docx 的 `<w:i/>` 用在 "Article"、表内分类小标题（Demographic 等）；而 XML 的 `<italic>` 用在 "i.e."、统计符号 p/t、期刊名——两者几乎不重叠。不能直接把 docx 斜体映射成 XML italic，需按内容语义重新判定。

6. **特殊字符规范化**：docx 表头 "X²"（拉丁 X + 上标 2 字符）→ XML 灰色 Greek chi `<styled-content style="color:#474747;">χ</styled-content><sup>2</sup>`；作者上标混用 vertAlign 与 Unicode `²`，需统一识别为上标编号并关联 aff。

7. **作者-单位-通讯三向关联**：作者行的上标数字、单位段的前导数字、通讯块的 email/姓名分散在不同段，要拼成 contrib 内的 aff xref + corresp xref + email。

8. **中文标签**：学术编辑用中文 "学编：" 标注，需识别并映射为 `contrib-type="editor"` + `<role>Academic Editor</role>`。

9. **图片对齐靠顺序而非文件名/哈希**：三方文件名全不同、MD5 也不同（重压缩），只能用文档内出现顺序对齐 `fig-0N.png`，且 XML 路径要拼 DOI 文章号前缀 `HSF49106/`。

## 固定模板 vs 文档特有

### 固定不变（IMR/HSF 模板，可硬编码或按刊查表）
- 整个 `<journal-meta>`：HSF、The Heart Surgery Forum、缩写刊名、ISSN 1098-3511/1522-6662、publisher IMR Press。
- DOCTYPE / DTD 声明、根 `<article>` 的命名空间（mml、xlink）、`dtd-version="1.3"`。
- `article-categories` 的 `<subject>Article</subject>`、`article-type="research-article"`（research 类固定）。
- `permissions` 整块措辞：`Copyright: © {year} The Author(s). Published by IMR Press.` + CC BY 4.0 license-p（链接固定 https://creativecommons.org/licenses/by/4.0/）。
- back 的声明类小节**标题文字**固定且顺序固定：Availability of Data and Materials → Author Contributions → Ethics Approval and Consent to Participate → Acknowledgment(ack) → Funding → Conflicts of Interest。
- `<fn-group>` 的 Publisher's Note 整段（IMR Press stays neutral…）。
- 当声明为空时的占位语：Acknowledgment→"Not applicable."、Funding→"This research received no external funding."、Conflicts→"The authors declare no conflicts of interest."（docx 原句被替换为这些标准句）。
- id 命名规则：sec=`S{n}`、p=`S{n}.p{m}`、aff=`aff{n}`、corresp=`cor{n}`、fig=`F00{n}`/graphic=`F00{n}.g1`、table=`T00{n}`、表脚注=`T00{n}-fn1`、文献=`b{n}`。
- 表格样式串模板：`border-top/border-bottom:0.5pt solid #000000`、`vertical-align`、`text-align`、`scope="col"/"row"`；χ 的灰色 `#474747`。
- 图路径前缀模板：`{文章号}/fig-{NN}.png`（文章号来自 DOI）。
- label 规范：图 "Fig. N."、表 "Table N."、文献 "[n]"。

### 文档特有（必须从 docx 提取/外部比对）
- 标题、摘要、关键词、全部正文文字（含小节标题文本与顺序）。
- 作者姓名、上标编号、单位文本、通讯 email、收稿/修回/接受日期、学术编辑姓名。
- DOI 文章号（决定 article-id 与图路径前缀；**docx 内无，需出版方/命名约定提供**）。
- copyright-year（取自接受年）。
- 全部图（顺序、对应 fig-0N.png）、全部表数据（伪表格还原）、图/表 caption。
- 全部参考文献内容（且需外部库规范化、决定 element vs mixed）。
- 正文交叉引用的目标编号（bibr/table/fig 的 rid）。

### 本样例的特殊性提醒
该 docx 的 style 名**不是**题面预期的混淆名（afa/afb/aff1），而是退化到完全无 style——这说明 IMR 不同投稿的 docx 形态差异极大，转换器不能依赖任何固定 style 命名，必须以内容启发式为主。
