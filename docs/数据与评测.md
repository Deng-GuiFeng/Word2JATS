# 数据与评测

## 样本及参考

`样例数据/样例登记.json` 是唯一的样本名单，登记编号、期刊、DOI 和分组：

- 01–05：赛事主样例，含 Word 和发表版 XML。
- S01–S05：赛事补充样例，提供 Word。
- X01–X04：初赛期间补充的测试样例。

14 例都参与过项目开发，不作为独立盲测集。每例的 `结构参考.xml` 是项目整理的结构对照，不是组委会提供的标准答案。原稿内容判断以 Word 为准，发表版可能包含后续编辑加工，不能直接当作转换应输出的内容。

`figures.zip` 和其他附件用于对照。转换器直接读取 Word 内的图片和公式，不读取参考 XML 或参考图片包。组委会重新整理的原始包保存在 `references/10个样例.zip`。

## 评价方法

独立评价工具位于 `scripts/eval_v2/`，比较候选输出与原稿、结构参考及媒体。检查范围包括文首关系、章节、表格、公式、文献、引用、媒体与原文覆盖。实现中的 `engine.py`、`policy.py` 及各检查模块定义具体规则；诊断结果不是比赛官方评分。

评价一个已生成的输出：

```bash
.venv/bin/python -m scripts.eval_v2 evaluate \
  --sample 03 --candidate /path/to/candidate --json
```

批量评价要求候选根目录按样本编号分目录，或提供工具支持的 `manifest.json`：

```bash
.venv/bin/python -m scripts.eval_v2 batch \
  --candidate-root /path/to/outputs --samples all \
  --report-dir output/evaluation
```

结构不同不必然表示内容错误。自动诊断发现差异后，应检查原稿的表达及 JATS 是否允许相应结构，而不是直接向参考靠拢。

## 固定测试数据与实验数据

`tests/fixtures/articles/` 保存网页预览与字段修改测试实际使用的 28 份 XML，以及其中一例 API 测试必需的媒体；不包含历次转换目录。它们用于回归测试，不代表当前每次转换的正确答案。

`样例数据/评测结果/` 保留技术方案说明书所用的最终逐篇内容指标、用量与成本表，以及 Qwen、DeepSeek 两组原始实验记录。对应的是提交时实验，不是当前版本重新测得的成绩。输入、输出及缓存用量来自服务响应；费用为按当时采用单价折算的数据。

`runtime/cache/` 为本机保存的最终请求缓存，14 例、两种配置的离线集成测试通过它重走转换流程，并禁止网络请求。新文件缓存未命中时仍按普通流程调用大模型，不使用样本编号或参考 XML 替换转换结果。
