# 系统设计

## 转换目标与分工

JATS 是学术期刊文章的 XML 表达规范，用标签区分题名、作者、摘要、章节、图表、公式和参考文献。Word 的字号、缩进、表格与文本顺序并不直接等于这些出版结构，因此转换既要识别内容的角色，也要保留原文及对象之间的关系。

Word2JATS 使用大语言模型（LLM）识别结构，用程序定位和取回原稿内容，再生成 JATS。正文和文献字段主要通过原文位置取字；文首作者、机构等复杂关系由大模型生成局部 JATS，再检查其格式和内容。

## 处理流程

```text
Word → 原稿对象与位置 → 并行结构识别 → 定位、合并与组装
     → 语义文档 → JATS 与媒体 → 自动检查 → 网页修改与下载
```

1. **读取原稿。** 记录段落、文字范围、表格网格、图片和公式的出现位置，并读取自动编号、脚注及相关格式。资源字节与其出现位置分开保存。
2. **识别结构。** 文首、正文、文献边界、文献字段、引文和压平表格分别处理。文献字段在条目边界确定后并行提取，避免等待无依赖的任务。
3. **定位与合并。** 将识别得到的文字线索对应到原稿位置，检查角色冲突和未归属内容。正文与文献组装时按位置取回内容。
4. **生成输出。** 语义文档表达章节、对象及引用关系；渲染器生成 JATS，图片随文章输出。
5. **检查和交付。** 检查 XML 语法、文档类型定义（DTD）规定的元素顺序与嵌套约束、引用目标、媒体和内容覆盖；保留检查信息供用户处理。

实现入口是 [pipeline.py](../src/word2jats/pipeline.py)。原稿读取位于 `parse/`，结构识别与组装位于 `understand/`，语义表示位于 `semantic/`，输出位于 `render/`，检查位于 `validate/` 和 `verify/`。

## 主要内容的处理

| 内容 | 处理方式 |
|---|---|
| 文首 | 生成局部 JATS，检查格式、来源及内容；摘要、关键词结合原文定位 |
| 正文 | 按原文位置组织段落和章节，保留公式、图片前后的文字 |
| 参考文献 | 双路识别条目边界，按字段定位；无法完整表达的条目保留混合著录 |
| 交叉引用 | 将数字制、作者—年份制引文及图表提及关联到目标 |
| 原生表格 | 保留单元格、合并关系与对齐；压平表格单独识别列结构 |
| 公式 | OMML 经 XSLT 转为 MathML；复合公式与图像公式保留对应载体和顺序 |
| 图片 | 输出保留原始资源；不被浏览器直接支持的格式另做预览转换 |

OMML 是 Word 使用的公式格式，MathML 是 XML 中表达数学公式的格式；XSLT 用于将前者转换为后者。图片和公式不通过猜测补写内容。结构参考仅用于开发评价，不是转换器输入。

## 大模型与缓存

Qwen 配置的主流程使用 `qwen3.7-plus`，文首使用 `qwen3.8-max`；DeepSeek 配置使用 `deepseek-flash`。实际配置见 [client.py](../src/word2jats/llm/client.py)，提示词位于 `understand/prompts/`。

缓存按请求内容和配置查找，命中后仍执行原稿解析、组装和检查。缓存保存服务返回的用量信息，网页分别展示结果对应的用量和本次新增用量。缓存复用不等于结果原始用量为零。

## Web 应用

[app.py](../webapp/app.py) 提供上传、任务状态、预览与下载接口；[workbench.py](../webapp/workbench.py) 管理修改和重新转换；[editor.py](../webapp/editor.py) 处理受支持字段的修改。

用户可修改题名、作者、单位、通讯信息、ORCID 和出版信息。修改保存为独立版本，预览、检查与下载同步更新，原自动结果可恢复。重新转换创建新任务，不覆盖已有任务。

任务快照保存到磁盘，重启后可以恢复已结束任务。在途转换不会跨进程继续执行，重启前应等待其完成。网页不提供全文自由编辑或多人审签。
