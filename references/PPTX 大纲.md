# Word2JATS 决赛答辩 PPTX 大纲

## 一、叙事主线与展示安排

面向了解学术出版与比赛题目、但尚不了解 Word2JATS 的评委，展示我们如何理解问题、准备数据、选择方案、解决关键难点，并用转换结果和可运行产品验证设计。

整体沿用五部分思路：

**需求理解与拆解 → 数据清点与评价依据 → 技术选型与实现 → 转换结果评估 → 用户操作与成果交付。**

贯穿全篇的一句话：

> Word2JATS 将大语言模型的语义识别与程序的原文取回、标准组装相结合，让 Word 稿件转为可检查、可校订、可交付的 JATS 出版数据。

建议主讲约 12 页、4 分钟，再用约 1 分钟现场操作。页数是制作参考，不与五部分一一对应；内容较密时可拆页，讲述仍只抓每页结论。完整指标、逐篇结果和技术细节放在备查页，供会后阅读和现场提问时调用。

## 二、逐页完整大纲

### 第 1 页｜Word2JATS：面向学术出版的 Word 智能结构化转换

**页面内容**

- 主标题：Word2JATS。
- 副标题：面向学术出版的 Word 智能结构化转换。
- 功能概括：Word 稿件 → JATS XML ＋ 配套图片资源。
- 团队：JiangLab；比赛选题：Word → JATS XML 的语义映射与自动化生成。

**画面建议**：以标题和输入—输出关系为主体，可用一小块真实稿件与转换结果作背景，不在封面堆架构和成绩。

**讲述重点**：一句话介绍作品和交付物，直接进入“我们怎样理解这项任务”。

### 第 2 页｜从期刊与文章类型出发，明确转换对象

**核心结论**：需要转换的不只是文字和格式，还有论文各部分的含义以及它们之间的关系。

**页面内容**

1. **业务范围**：面向 IMR Press 的多期刊、多文章类型投稿场景，围绕 21 本期刊的作者指南与公开 Word 模板梳理需求。文章类型包括研究论文、综述、社论、病例报告、读者来信、手术技术等；不同期刊采用的类型不完全相同。
2. **输入与输出**：输入为 Word 稿件（.docx）；输出为符合 JATS Journal Publishing 1.3 的 XML，以及 XML 引用的图片资源包 `figures.zip`。
3. **转换内容分为三层**：

   - 内容对象：题名、作者、单位、摘要、关键词、章节、列表、图表、公式、参考文献与文末声明。
   - 对象关系：作者—单位、通讯作者—邮箱、正文—图表、正文—文献，以及章节从属与先后关系。
   - 交付要求：文字与资源完整，结构符合标准，引用能够定位，用户能够检查和修订结果。
4. **需求带来的技术问题**：相同含义可能采用不同排版；相近外观也可能承担不同角色。例如，加粗的一行可能是章节标题，也可能是图题；一张表可能是原生表格，也可能由制表符排成。

**画面建议**：左上放期刊模板目录的小截图，展开 HSF 或 CEOG 的多种文章模板；主体用“内容—关系—交付”三层图，不铺满 21 本期刊名称。模板目录用于展示需求调查的范围，不作为转换质量成绩。

**讲述重点**：从期刊与模板差异引出“语义映射”，不重复向评委介绍学术出版行业常识。

### 第 3 页｜清点稿件内容，建立可核对的结构参考

**核心结论**：先明确稿件里有什么、用什么依据评价，后面的质量数字才有含义。

**页面内容**

1. **实验稿件**：01–05 与 S01–S05 共 10 篇。前 5 篇配有 Word 和上线 JATS XML，后 5 篇提供 Word。
2. **清点内容形态与规模**：涵盖作者和机构关系、章节、图表、公式、文献及引用；10 篇合计 64 位作者、167 个正文章节、35 个图对象、46 个表对象、525 条参考文献。另有 26 个原生公式和 2 个公式图像部件。
3. **构建评价依据**：

   - 以 Word 为内容依据，读取其中的文字、对象、排版线索与关联。
   - 参照 JATS 规范和已有上线 XML 的结构表达，逐篇整理 `结构参考.xml`。
   - 从结构参考中提取字段、对象和关系；对图片字节、原生公式、全文文字另作直接对照 Word 的检查。
4. **评价协议**：按内容身份对齐，不比较 XML 字符串或内部编号；先归一化空白、页码缩写等表示差异，再统计应有数、输出数和正确匹配数。分别计算召回率与精确率。

**页面脚注**：上线稿可能经过编辑加工；结构参考用于评价，不作为转换输入。评价保留等价的 JATS 表达，不要求逐字复现上线版本。

**画面建议**：上方是一张“5 篇 Word＋上线 XML / 5 篇 Word”的资料关系图，下方用一条文献说明如何从原稿形成字段与引用关系。规模数字只选几项醒目呈现，逐篇清单放备查页。

**讲述重点**：这里的“标签构建”是建立评价用的结构标注，不是训练模型，也不是把上线 XML 当成唯一标准答案。

### 第 4 页｜三条路线：规则识别、模型辅助、智能体自主处理

**核心结论**：选择由程序组织流程、由大语言模型辅助语义识别的混合方案，在适应性、处理效率和输出控制之间取得平衡。

**页面内容**

首次引入“大语言模型（Large Language Model，LLM）”；“智能体”指能够规划步骤、调用工具并根据结果调整后续操作的系统。第二、三条路线都可以使用大语言模型，区别主要在于谁控制处理流程。

| 比较维度 | 规则驱动转换 | 模型辅助的固定处理流程——本项目 | 智能体自主处理 |
| --- | --- | --- | --- |
| 主要机制 | 根据样式、关键词、正则和模板识别并映射内容 | 程序划分任务；模型识别角色与关系；程序定位、组装和检查 | 智能体自行选择解析、生成、检查及修正步骤 |
| 优势 | 速度快，资源消耗低，规则行为明确 | 利用上下文识别非统一写法；任务可并行；输出和检查方式统一 | 可按异常情况动态选择工具，适应开放式处理任务 |
| 对变化的适应 | 新体例、非规范排版往往需要增加或调整规则 | 在通用原稿表示上识别结构，减少按期刊逐一编写识别分支 | 可探索不同处理路径，潜在适应范围较广 |
| 主要代价 | 依赖领域规则积累；规则数量与交互增加后维护困难 | 仍需处理模型判断错误、调用延迟和任务间一致性 | 多轮规划与工具调用可能拉长等待；运行路径和资源消耗更难预估 |

**选型理由**：本任务的交付格式明确、主要内容类别相对稳定。把已知结构交给程序，把上下文判断交给模型，再通过统一检查与必要人工校订形成成果，适合稿件逐篇转换的使用方式。

**画面建议**：三列比较卡片，突出中间方案。基线代码可作为规则驱动路线的具体参照，但准确表述为“启发式规则与样式解析”，不将其简化成只有正则。

**讲述重点**：讲清取舍，不给三类路线排绝对高低。智能体路线保留作为复杂异常处理的可扩展方向，不把它说成已经完成同条件实验的对照系统。

### 第 5 页｜语义识别与标准生成分工协作

**核心结论**：模型负责判断内容的角色与关系，程序负责解析原稿、取回内容并生成标准文件。

**页面内容**

整条流程分为五步：

1. **解析原稿**：读取 Word 文字、有效样式、自动编号、表格网格、图片及公式，建立带位置标识的原稿记录。
2. **识别结构**：分别处理文首、正文、图表、文献边界、文献字段和正文引用。
3. **定位与组装**：将识别结果定位到原稿范围，归并为章节、图表、文献及关系等语义对象。
4. **生成与检查**：映射为 JATS XML，导出媒体，核对格式、内部链接、资源与内容来源。
5. **查看与交付**：网页预览、原稿对照、文章和出版信息修订，下载当前版本成果。

图中单独标明文首元信息分支：题名、作者、单位与通讯关系采用限定原稿区域的局部 JATS 生成与校验；摘要、正文、文献等主要采用原文定位方式。

**画面建议**：总体架构图，用两种颜色区分模型任务与程序任务。保留“原稿内容直接进入组装”的箭头，让评委看出内容并非全部经过模型重写。

**讲述重点**：明确各层分工，以及网页与命令行共用同一转换核心。避免只展示模块名称而没有输入、输出和连接关系。

### 第 6 页｜识别结构，定位原文，再完成组装

**核心结论**：用原稿位置连接语义判断、内容生成和结果核对。

**页面内容**

以一段正文或一条文献做贯穿示例，展示四步：

1. **原稿记录**：每段文字、表格单元等具有位置标识，如 `doc/p30`；图片与公式另有资源及出现位置记录。
2. **模型判断**：返回内容角色、原文摘抄和必要的前后文线索。例如，将“2. Materials and Methods”识别为章节标题。
3. **程序定位**：先精确匹配；对空白、引号等作受控归一化；重复片段再结合上下文、顺序和范围判断。
4. **标准组装**：从定位成功的原稿区间取回文字与行内格式，生成章节或字段，并保留来源位置供检查和对照。

页面下方用三个短语概括设计价值：

- 结构判断与文字取回分离。
- 从局部字段贯通到全文组织。
- 同一位置记录服务于生成、检查与原稿对照。

**画面建议**：左侧真实原稿片段，中间标注“角色＋原文范围”，右侧仅放 3–5 行 JATS 片段。用相同颜色连接同一段原文，代码只是解释手段。

**讲述重点**：这是核心方法页，说明设计如何降低长文本重新生成造成的改写、遗漏风险；不把“依据原文组装”表述成“所有字段永远不会出错”。

### 第 7 页｜按内容载体处理图表、公式与文献关系

**核心结论**：统一流程之外，针对不同载体保留其已有结构，并补足语义关联。

**页面内容**

| 内容类型 | 处理方法 | 交付结果 |
| --- | --- | --- |
| 作者与机构 | 文首局部生成并校验人员、单位、通讯和 ORCID 关系 | 可识别的作者字段与正确关联 |
| 原生表格、文本排表、图像表格 | 读取合并网格；把原文片段分配到行列；保留图像载体 | 表对象、表题表注及相应网格或图像 |
| 图片与复合图 | 按出现位置归组，关联图号和图注，导出原始资源 | 图及子图关系、可解析的媒体路径 |
| 数学公式 | Word 原生公式（OMML）转 MathML；图像或复杂排版载体按其来源保留可读表示 | 行内、行间公式及编号、上下文 |
| 参考文献与正文引用 | 先识别条目边界，再并行提取字段；按编号或作者—年份关联引用 | 结构化或混合著录、可定位的正文链接 |

章节、摘要、关键词、列表与文末声明沿用原文范围和层级组织，构成整篇稿件的连续内容。

**画面建议**：主画面选择“表格＋公式＋文献链接”三个真实局部，各配一句处理方法；完整覆盖表可放备查页。展示 Word 与结果的对应关系，不仅摆转换后的漂亮截图。

**讲述重点**：说明对不同载体有明确处理方式，并且对象本身、上下文和关系一起保留。不要把图片公式一律说成可计算的 MathML，也不把混合著录说成参考文献丢失。

### 第 8 页｜按任务依赖切分和并行，减少整篇等待

**核心结论**：在有依赖的地方等待，在无依赖的地方并行；减少大模型调用对整篇处理时间的累积影响。

**页面内容**

1. **按职责拆分**：文首、正文、文献边界、正文引文可独立读取原稿清单并启动。
2. **按数据依赖衔接**：文献边界确认后立即并行处理各条文献字段；文首边界确认后并行处理元信息与摘要；文本表格在内容角色归并后恢复网格。
3. **长文分窗**：依据输入预算划分窗口，相邻窗口保留上下文，定位回原稿后统一归并。
4. **有界并发与异常处理**：进程内模型请求共用并发上限，实测配置为 32；完整接收后解析，失败作限次重试，避免无限增加等待和资源消耗。
5. **重复任务复用**：相同模型请求可复用完整回答；修改了输入的请求重新执行。复用与新调用分别记录，不混淆两种耗时。

**画面建议**：以任务依赖图为主体，突出“文献边界→各条文献并行”和“文首/正文/引文并行”两处。可补一条串行与并行的概念时间线，但不标未经实测的加速倍数。

**讲述重点**：解释如何组织工作，而不是只说“用了多线程”。下一页用质量数据确认结果，再用实测时间和成本说明运行代价。

### 第 10 页｜同一流程下比较两种模型配置

**核心结论**：除转换质量外，实测给出用户需要等待的时间和每篇稿件的模型调用成本。

**页面内容**

| 指标 | Qwen 配置 | DeepSeek 配置 |
| --- | ---: | ---: |
| 平均转换时间 | 135.90 秒 | 58.27 秒 |
| 转换时间中位数 | 92.31 秒 | 27.34 秒 |
