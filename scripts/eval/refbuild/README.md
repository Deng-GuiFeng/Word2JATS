# X01–X04 结构参考构建流程（可复现留痕）

这里是为四份外部投稿 X01–X04 建 `结构参考.xml` 的全套工具与中间产物，供审计复核。
10 例（01–05、S01–S05）的参考不由本流程产出，其历史工具见 [`../refxml.workflow.js`](../refxml.workflow.js)（已退役）。

## 设计要点：判断独立，取字机械

参考结构是「假设转换器 100% 准确、从这份 docx 转出来的 JATS」。它是评测的标尺，
所以构建过程必须与转换器的判断相互独立（否则拿转换器的输出评转换器），
同时必须杜绝模型在誊抄时改字。

做法是把两件事拆开：

- **判断**由模型做，但它只回答「哪个块 idx 归哪个 JATS 元素」，**一个正文字符都不许打**；
- **取字**由脚本做，按 idx 从 docx 原文取回，包括 run 级的上标/下标/斜体。

决策单里允许出现的短字段（姓名、日期、邮箱、参考文献各字段）一律做**子串校验**：
不是对应源块原文的连续片段就报错。编造在结构上不可能发生。

## 文件

| 文件 | 作用 |
|---|---|
| `blocks.py` | docx → 块清单。每块 idx + 逐字文本 + run 级格式 + 媒体/OMML/OLE 位置。确定性，无判断 |
| `view.py` | 块清单 → 判定用的可读视图（每行一块） |
| `X0N.decisions.json` | 判定产物：idx → JATS 元素的映射。**不含正文文字** |
| `refs.py` | 参考文献著录的确定性拆分（APA / 温哥华两种人名写法），拆不动的不硬拆 |
| `refs_unparsed.json` | 规则拆不动的 17 条原文 |
| `refs_manual.json` | 那 17 条的逐条拆分结果（体例特殊：书籍章节、学位论文等） |
| `assemble.py` | 按决策单取字装配 XML + 五道出口校验 |
| `build.py` | 主程序 |

## 复现

```bash
PYTHONPATH=scripts/eval/refbuild .venv/bin/python scripts/eval/refbuild/blocks.py X01 X02 X03 X04
PYTHONPATH=scripts/eval/refbuild .venv/bin/python scripts/eval/refbuild/build.py X01 X02 X03 X04
```

产物落在 `tmp/refbuild/out/<key>/`（XML + 外部化图片）。决策单已冻结在本目录，
所以除判定环节外全流程确定性可复现；重跑不会调用模型。

## 五道出口校验（全部必须通过）

1. **DTD**：JATS Journal Publishing 1.3，用项目内置 DTD 离线校验。
2. **块覆盖闭合**：docx 每个顶层块要么进了 XML，要么列入 `dropped` 并写明理由，不允许无交代的块。
   这道是防漏抄的关键——[`../fidelity.py`](../fidelity.py) 的 L1 主口径拿结构参考当「应保留内容」的仲裁，
   参考漏抄会把转换器同样的漏抄一并豁免掉，缺陷就此静默。
3. **图片**：每个 `<graphic xlink:href>` 指向的文件存在、可解码为真图、
   **字节 md5 与 docx 内嵌媒体逐字节相同**（原字节外部化、不重编码的硬证据）。
4. **媒体闭合**：docx 每个内嵌媒体要么被某个 `graphic` 以原字节引用，要么在决策单的
   `media_dropped` 里写明不用的理由。没有这道，"块里有图但该块被当成正文段"会让图静默消失
   ——`inline()` 从不渲染 `block["media"]`。X02 的图形摘要（104 KB）当初就是这样丢的。
5. **子串校验**：决策单与参考文献拆分里的每个字段值，都必须是对应源块原文的连续片段。

## 本批四例的口径决策

逐例完整记录在各自 `样例数据/X0N/scope.json` 的「构建口径」。共通的几条：

- **投稿件不产出 `article-id`**。DOI 是文章被接收后才分配的，投稿那一刻不存在；转换器同样
  拿不到（`--doi` 是外部入参，10 例的 DOI 由 `samples.py` 登记后喂入），参考里补了就是凭空
  造一个必然失分项，且属 C 档编辑加工。
- **参考文献 `<label>`：docx 里有编号就产出**。包括 Word 自动编号列表——X02（numId=2）与
  X04（numId=17）的参考区段落都带 `w:numPr`，`numbering.xml` 里是 `numFmt=decimal`、
  `lvlText="%1."`，文档渲染出来就是 "1." "2."。编号存在 numbering.xml 而非 run 文本里，
  但它确实是文档内容，按 numPr 机械推出、不含判断。X03 确无编号（无 numPr），故不产。
- **内联格式按目标元素定去留**（元素驱动）。格式若已被所指派的元素本身承载——
  `<article-title>`、`<sec><title>`、`<subject>`、`<kwd>` 这类标题槽天生按标题排版——
  则不产出 `<bold>`/`<italic>`；落进 `<p>`/`<td>`/`<th>`/`<caption>` 的，docx 上有的粗斜
  逐一保留，不论块内是否统一。参考文献字段只丢 `bold`、保留刊名的 `italic`。
  依据是 10 例实测：01 有 44 处占满父元素全文的 `bold`（父元素全是 `p`/`td`/`th`，无一在
  `title` 里）、S04 有 38 处；ref-list 内 `italic@source` 377 处、`bold` 恰好 0。
  JATS 的 DTD 对 `<bold>` 的定义是 "text that should appear in bold face type"，纯呈现性。
- **浮动体按块序落位**：图/表/独立公式按其在 docx 里的块序插入所属章节，不依赖决策单给锚点。
- **媒体闭合**：docx 每个内嵌媒体要么被 `graphic` 以原字节引用，要么在 `media_dropped`
  写明不用的理由（页眉图、SVG 矢量备份、已转 MathML 的公式图元等）。

## 审查

本批经历了与 10 例同等强度的审查（`样例数据/说明.md` 第 7 条）：**多路独立起草 + 逐疑点
三法官辩论**，共 35 个独立审查代理——

| 环节 | 做法 |
|---|---|
| 独立起草 | 每份 2 路独立结构判定，明令不得查看现行决策单与已生成的 XML |
| 结构辩论 | 每份 3 法官比对三路（现行 A + 独立 B/C），逐疑点裁决；并设 `unanimous_but_wrong` 通道专门找"三路一致但都错"的集体错误 |
| 文献复拆 | X02–X04 各 1 路独立拆分参考文献字段 |
| 文献辩论 | 每份 3 法官核字段边界，靶向子串校验的盲区（切错边界能完美通过校验） |
| 判据审议 | 3 法官独立论证上述口径判据是否成立 |

审查查出并已修正的实质错误：

- **判据被推翻两条**。原「整块统一格式=版式」被 3 票一致否决（所引 JATS 定义在规范里
  查无出处，且与 10 例成片冲突），改为上述元素驱动；原「docx 无编号不产 label」的事实
  前提对 X02/X04 不成立（它们是 Word 自动编号），已按 numbering.xml 还原。
- **图表位置全错**：题注块从不在 body 列表里，锚定 `pop` 永远命中不了，X01 的 12 图 3 表、
  X03 的 6 个浮动体、X04 的 9 图 1 表全被兜底逻辑堆到最后一节。已改为按块序落位。
- **X02 成片丢内容**：公式块里的引导句被整块吞掉（3 句）；ChemDraw 图元实为编号公式 (5)
  被当插图跳过，导致编号从 (4) 跳到 (6)；公式 (8) 的图与编号分处两块而整条丢失；图形摘要
  （104 KB）被当正文段渲染成空 `<p/>`；行内公式图 3 张只取 1 张；子图面板名（溶剂名）整批
  丢失。已逐一补回，`media_check` 现在会拦住同类问题。
- **参考文献拆分的系统性缺陷**：APA 分支刊名含逗号即被截断（`Mining, Metallurgy &
  Exploration` → `Mining`，后续字段整体错位）、`卷(期)` 写法丢卷号与期号（8 条）、
  尾部 DOI 未剥离（2 条）、文章编号被当卷号；Vancouver 分支篇名尾句点因 NBSP 剥不掉而
  残留 57 条、`Article N` 被截成裸数字、人名缩写尾点被无差别剥除、姓氏虚词白名单漏
  `aan het`。已改用 **docx 的刊名斜体 run 作边界事实**（比标点可靠），其余逐条修正。
- X03 的缩略语表改用 `<glossary>`（对齐 10 例的 02/04）。
