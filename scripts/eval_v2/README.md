# JATS 转换结果 V2 独立评测器

V2 与 `scripts/eval_v1` **平级，不分主次**：两套评测器判分逻辑完全独立、互不引用，同时评估同一批转换输出；只共用 `样例数据/样例登记.json` 这一份样例名单（名单是数据，不是判分规则）。两器数字不可相加也不可直接对照——V1 出缺陷清单条数，V2 出通过判定与按语义事实展开的问题数，量级天然不同。两者一致时结论更可信，不一致处最值得查，这正是同时养两把尺子的理由。一条命令跑完两器并出并排小结：`python -m scripts.evalsuite`。

V2 只读取已有候选输出、对应的 `结构参考.xml`、`figures.zip` 和 `初始文件.docx`，不调用转换器，不访问网络，也不改动任何被评测文件。

V2 回答一个严格问题：候选输出是否在合法性、完整语义、关系、媒体字节和输入来源方面达到当前金标准。它不把多个性质不同的指标加权成一个总分，因为“正文较多”不能抵消“作者错误”或“图片错误”。最终给出通过/不通过结论，并附八维质量向量供失败结果之间比较。

## 快速使用

在项目根目录运行：

```bash
python -m scripts.eval_v2 evaluate \
  --sample 01 \
  --candidate reports/outputs/latest/01 \
  --report-dir /path/to/eval-v2-report
```

`--candidate` 可以是主 XML 文件，也可以是候选输出目录：

- 传目录时，目录顶层必须恰有一份 XML；XML 引用的媒体必须位于该目录内；所有未引用文件都会报错。
- 直接传 XML 时，同目录文件只有被 XML 显式引用后才属于候选包；其他同级文件不参与“多余文件”判断。

批量评测时，候选根目录下应有 `01`、`02`、`S01`、`X01` 等子目录：

```bash
python -m scripts.eval_v2 batch \
  --candidate-root reports/outputs/latest \
  --samples all \
  --report-dir /path/to/eval-v2-report
```

`batch` 的两个路径参数都有默认值，日常直接 `python -m scripts.eval_v2 batch` 即可：候选默认 `reports/outputs/latest`（两套评测器共同的评测对象），报告默认落 `reports/eval_v2/latest`（与 V1 的 `reports/eval_v1/<tag>/` 对称）。

`--samples` 支持 `all`、`main`、`supp`、`external`，也支持 `01,03,X03`。退出码为：`0` 全部通过，`1` 候选质量不通过，`2` 金标准或评测器运行条件异常。

如只需机器结果：

```bash
python -m scripts.eval_v2 evaluate --sample X03 --candidate /path/to/X03 --json
```

## 通过条件

候选必须同时满足以下条件：

1. XML 能以禁用网络、禁用实体展开的方式安全解析。
2. XML 声明、JATS 1.3 DOCTYPE、命名空间和本地 JATS DTD 校验通过。
3. ID 唯一，所有 `xref/@rid` 闭合；图、表、陈列公式具有 ID；媒体引用有效。
4. 与金标准的完整语义树一致。所有元素、属性、非排版文本、层级、顺序、引用关系和媒体引用都参与比较。
5. 每个媒体文件可严格解码，扩展名与实际格式一致，且文件字节能在输入 docx 的 `word/media/` 中找到。
6. 候选目录不存在未引用的遗留文件或符号链接。
7. 覆盖登记没有任何未处理对象。

文本来源清单是旁证，不是豁免规则。docx 原稿与最终结构之间存在确定性模板内容、字段规范化和结构拆分，因此“候选中出现 docx 没有的词”本身不判错；候选与金标准的文本差异仍然严格判错。媒体则必须逐字节来自 docx。

## 明确允许的等价表示

默认规则是逐项严格比较，只允许以下差异：

- 内部 `id` 可以改名，但 ID 的有无必须与金标准一致，所有 `rid` 必须仍指向同一语义对象。
- 媒体文件可以改名或换目录，但文件字节必须相同，扩展名必须与真实格式一致，引用仍须留在候选目录内。
- XML 属性顺序和命名空间前缀的纯语法差异不影响语义；候选仍必须使用本地 JATS DTD 能识别的标准 `xlink`、`mml` 声明。
- 仅用于 XML 源码缩进、且含换行的纯空白不比较；混合文本中的普通空格仍逐字符比较。
- 数字形式的 `day`、`month` 允许前导零差异，例如 `8` 与 `08`。
- XML 注释忽略；处理指令、实体等其他非普通节点不忽略，而会使覆盖检查失败。

没有列入上表的“看起来差不多”一律不自动等同。例如作者次序、参考文献次序、`fpage` 与 `elocation-id`、表格跨度、MathML 属性、标点、大小写和空格都按金标准比较。V2 不通过 Crossref 或出版页补充 docx 中没有的信息。

## 报告内容

指定 `--report-dir` 后，每例生成：

- `<样例>-eval-v2.json`：完整机器结果；
- `<样例>-eval-v2.md`：可直接审阅的中文报告；
- 批量模式另有 `summary-eval-v2.json`。

报告记录候选、金标准、docx、figures.zip 和评测器源码清单的 SHA-256，可据此复现。问题包含稳定编码、严重级别、语义范畴、金标准路径、候选路径、期望值、实际值和必要证据。

八维质量向量包括：元素、属性、文本、尾文本、引用关系、媒体引用、父子层级、相邻顺序。每一维分别给出金标准事实数、候选事实数、正确配对数、精确率、召回率和 F1，不生成主观加权总分。

## 测试

在项目根目录运行：

```bash
python -m pytest -q scripts/eval_v2/tests
```

测试包含 14 例金标准固定点回放，以及无编号参考文献删除/换序、作者地址丢失、表格文字改变、闭合但指错对象的交叉引用、图片损坏、媒体来源错误、遗留文件、DOCTYPE 错误和允许等价表示等定向变异。

## 文件结构

```text
eval_v2/
├── artifacts.py      候选包、figures.zip、路径与媒体安全
├── canonical.py      完整语义投影和覆盖登记
├── compare.py        重复安全的对齐与逐项比较
├── engine.py         单例评测编排、质量向量和复现哈希
├── provenance.py     docx 段内拼合分词与媒体原字节核验
├── validity.py       XML、JATS DTD、ID、引用、公式等合法性
├── models.py         稳定问题和报告数据模型
├── policy.py         显式等价规则与问题归类
├── report.py         JSON、Markdown 报告
├── cli.py            单例和批量命令行
└── tests/            固定点与变异测试
```
