# V2 评测器设计说明

## 一、评测对象的本质

转换器的输入是一个确定的 docx 和少量确定的期刊参数，输出是一个 JATS XML 加一组外部媒体文件。评测对象不是一串标签数量，而是一个有约束的输出包：

- XML 树表达文章内容和结构；
- `id` 与 `rid` 构成对象关系；
- `xlink:href` 把 XML 与外部媒体连接起来；
- JATS DTD 规定结构是否合法；
- docx 是文本和媒体来源；
- 已定稿的 `结构参考.xml` 与 `figures.zip` 定义本轮目标答案。

因此，正确性必须同时覆盖包、语法、结构、文字、关系、文件字节和来源。只比标签数量会漏掉同量错位，只比全文文字会漏掉结构和关系，只做 DTD 校验则会把“合法但答案错误”的 XML 当成正确。

## 二、总体流程

一次评测按以下固定顺序执行：

1. 确定候选包边界，安全解析唯一主 XML。
2. 检查 XML 声明、DOCTYPE、命名空间、本地 JATS 1.3 DTD 和领域不变量。
3. 解析 XML 的所有本地媒体引用，拒绝 URL、绝对路径、路径越界、符号链接、缺失文件、超大文件和伪装格式。
4. 检查金标准 XML 与 figures.zip 的引用闭包，避免用损坏基准评分。
5. 分别把金标准和候选转成完整语义树，同时登记每个被处理对象。
6. 在不丢重复项的前提下逐层配对，比较值、层级、顺序和关系。
7. 从 docx 的正文、页眉页脚、脚注尾注和批注文本部件提取来源文字；每个 Word 段落先拼合全部 run，再分词。
8. 对候选媒体和 docx 内嵌媒体做 SHA-256 逐字节闭合。
9. 生成硬门槛结论、八维质量向量、完整问题和复现哈希。

整个流程只读。评测器不会运行转换器，不会调用模型，不会查 DOI，也不会依据网络信息改写答案。

## 三、完整语义树

### 3.1 为什么保留一棵通用树

JATS 元素很多，而且项目仍可能新增目前 14 例没有出现的合法元素。若只为已知标签各写一条评分规则，新元素在规则同步前可能静默漏评。V2 反过来做：通用树比较是保底真相，领域规则只负责把问题解释成人能理解的类别。

每个普通 XML 元素都投影为：

- 展开命名空间后的元素名；
- 全部属性；
- 元素直接文本；
- 元素结束后、父元素内的尾文本；
- 有序子元素；
- 原始可读路径；
- 用于配对的语义身份；
- 问题所属范畴。

元素名、属性、文本和子树均参与最终摘要。未知元素进入 `other` 范畴，仍逐项严格比较；报告的 `strict_fallback_tags` 会列出它们。

### 3.2 ID 与引用关系

内部 ID 的字面拼写没有出版语义，直接比较会把 `F1` 改成 `fig1` 误报为错误。但完全忽略 ID 又会漏掉指错对象。

V2 为每个带 ID 的对象建立由内容和类型产生的稳定语义锚点。例如参考文献优先使用编号、DOI、作者—年份—题名组合；没有这些信息时使用完整内容摘要。重复锚点按文档出现次序保留，不转成覆盖重复项的字典。随后把每个 `rid` 改写为目标锚点后比较。

结果是：统一改名且关系不变可以通过；`rid` 仍然存在、但从图 1 指到图 2，会明确报“交叉引用目标改变”。

### 3.3 媒体引用

媒体文件名也不是核心语义。V2 把 `graphic`、`inline-graphic` 和 `media` 的 `xlink:href` 替换为被引用文件的 SHA-256 后比较。这样同字节改名可以通过，不同字节即使同名也不能通过。

文件名仍受包规则约束：必须是候选目录内的安全相对 URI，不能经过符号链接；扩展名要与解码得到的真实格式一致。PNG、JPEG、TIFF、GIF、BMP 由 Pillow 完整校验；WMF、EMF 在 Pillow 无法解码时校验其完整格式签名。

### 3.4 空白

V2 不做全局 `strip()` 或空白压缩，因为正文中的空格、标点间隔和大小写属于内容。仅含换行的元素间缩进视为 XML 源码排版；普通空格保留。这个边界既允许合理重排 XML 源码，又不会把正文 `A B` 与 `AB` 当成相同。

## 四、重复安全的配对

V1 曾因参考文献只按 `<label>` 建字典，使 X03 的 35 条无编号参考文献塌缩为一条。V2 的配对不使用“键到单项”的字典：

1. 候选侧每个语义键对应一个有序索引列表；
2. 金标准按出现次序逐个消耗同键候选；
3. 内容已改变、无法精确同键的剩余元素，再按元素名和出现次序配对；
4. 未配对项才判为缺失或多出；
5. 精确身份在候选中的索引逆序时，单独报告顺序错误。

这同时处理有编号、无编号、编号重复、内容重复、内容修改和换序，不会因字典推导丢项。

## 五、合法性与安全边界

V2 使用项目随附的 JATS Publishing 1.3 MathML3 DTD，绝不从 DOCTYPE 的网址下载文件。XML 解析关闭网络、DTD 加载和实体展开，并限制超大树。内部 DTD 子集和自定义实体禁止使用。

DTD 之外还检查：

- XML 声明明确为 UTF-8；
- public/system DOCTYPE 与项目输出契约一致；
- `xlink` 和 MathML 命名空间正确；
- ID 不重复，`xref/@rid` 非空且全部闭合；
- 图、表、陈列公式具有 ID；
- 公式至少有 MathML、TeX 或输入原稿图像表达；
- ORCID 使用完整 HTTPS URL 且校验位正确；
- `license` 有许可链接。

候选目录会检查未引用文件，防止旧图片残留被误当成有效交付。直接传一份 XML 时不检查无关同级文件，因为调用者没有把整个父目录声明为候选包。为防止异常或恶意输出耗尽评测进程，主 XML 和单个媒体上限均为 256 MiB，候选媒体总量上限为 512 MiB；Pillow 的解压炸弹警告按错误处理。

## 六、docx 来源核验

### 6.1 文本

Word 经常把一个词拆成多个 `w:r/w:t`，例如 `statin` 与 `s`。V2 先在每个 `w:p` 内按实际顺序拼合 `w:t`、公式文字、制表和换行，再统一分词，不会制造 `statin + s` 这类假差。

来源清单分别列出：候选中 docx 没有的词项、候选出现次数超过 docx 的词项、docx 中未进入候选的词项。期刊元数据、许可证、文章标识和机械编号区域单独登记为允许生成区域。

这些清单是诊断证据，不直接改变通过结论。原因是 docx 不是 JATS 的逐字序列：字段可能被拆分，模板可能补入，参考文献可能结构化。真正的目标文字仍由已经定稿的金标准决定，来源清单不能反过来豁免候选错误。

### 6.2 媒体

媒体没有上述文字规范化空间。转换器能取得的是 docx 包内 `word/media/` 的原始字节，因此候选的每一次媒体引用都必须命中其中一个 SHA-256。复合图的多个原始面板可以各自引用；同一原图重复引用按引用次数登记。

## 七、结论和质量向量

只要存在 critical 或 error，或覆盖未完成，结论就是不通过。warning 和 info 用于不阻断但值得审阅的证据，目前核心规则不靠它们掩盖错误。

失败结果仍需要可比较。V2 对八类事实分别计算：

- 金标准事实数；
- 候选事实数；
- 正确配对事实数；
- 精确率、召回率、F1；
- 是否完全一致。

八类事实为元素、属性、文本、尾文本、引用关系、媒体引用、父子层级和相邻顺序。删除一个大子树时，分母包含子树内所有事实，不会只因报告一条“元素缺失”就把损失低估为一条。

V2 有意不提供合成总分。若评赛必须排序，应由上层先规定不可妥协的门槛，再依据公开业务优先级选择质量向量，而不是在评测器内部藏一组任意权重。

## 八、覆盖证明与局限

覆盖报告分别给出金标准侧和候选侧的元素、属性、文本节点、尾文本、关系、媒体引用、忽略注释、忽略排版空白和未处理对象数量。只有 `unhandled` 为空才算覆盖完成。

“覆盖完成”表示所有 XML 对象都进入了一条明确处理路径，不表示评测器能从数学上证明金标准没有人工错误。V2 以当前定稿金标准为目标答案，并额外用 docx 来源和金标准媒体闭包发现基准损坏。V1 与 V2 设计独立、同时使用，正是为了降低单一规则体系的盲区。
