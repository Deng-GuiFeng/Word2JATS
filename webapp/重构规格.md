## 一、产品语言与信息架构重构（有出版行业调研背书）

### 用户是谁
学术期刊的**生产编辑 / 排版员 / 小型 OA 期刊责任编辑 / XML 制作外包商**。行业共识（eXtyles、
Texture）：**这类用户绝大多数不想碰、也不需要懂 XML/DTD**。他们的心态是**校样审阅员**：最怕
"改坏原文/漏内容"，最终诉求是"这份能不能签字放行、拿去上线（被 PubMed/知网/CrossRef 收录）"。

### 组织概念：交付前自检报告（preflight）
**整个结果页应读起来像一份"交付前质检报告"**，按编辑依次要问的五个问题组织，以"能不能放行"
贯穿全页，终点是"放行/下载"——从**开发者视角的产出物目录**变成**编辑视角的交付前自检报告**。

### 结果页信息架构（自上而下，替换现在的 5 个平级 tab）
| 分区 | 命名 | 一句话 |
|---|---|---|
| 顶部横幅 | **总结论 + 下载** | 一句话说能不能放行（"可直接交付"/"有 N 处待确认"）；下载常驻 |
| 区块1 | **成品预览** | 按期刊排版样式显示，先整体看图表公式文献对不对（去掉"渲染/样式表"实现词）|
| 区块2 | **原文核对** | 逐字对照原稿，确认没改写、没漏掉正文（校样员头号问题，提到第2位）|
| 区块3 | **内容清单** | 分组列出作者/单位/图/表/公式/参考文献，核对齐不齐、认对没（替换裸计数网格）|
| 区块4 | **合规检查** | 能不能被出版平台接收；不通过逐条说清"哪里+什么问题+怎么办"（替换"DTD校验"）|
| 折叠 | **XML 源文件（技术核对）** | 供技术人员查看/下载源码，普通编辑无需打开（原"原始XML"降级）|

### 术语对照（全项目前端一律替换）
| 禁用（实现视角） | 改成（用户视角） |
|---|---|
| DTD 合法 / DTD 校验 | 符合出版标准(JATS) / 出版合规检查 |
| 渲染视图 / 按 NCBI 样式表渲染 | 成品预览 / 按期刊排版样式显示 |
| 内容忠实 / 词覆盖率99.4% / 多重集 / 内容守恒 | 原文核对 / 逐字对照 / 有没有改动或漏掉你的内容 |
| 结构摘要 / 交叉引用 94 | 内容清单 / 图表和文献的正文引用（都指对了）|
| 结构化著录 12 | 参考文献20条，其中12条已拆成可检索字段(作者/年份/期刊…) |
| 回填图片 / 出口校验 / 大模型判断结构 | 放回图片 / 交付前检查 / 识别文章结构 |
| 多出词 / 缺失词 | 系统按规范补的内容 / 转成图片带走的内容 |

### 关键文案（直接采用）
- **顶部总结论**：全通过→"转换完成，可以直接交付。符合出版标准，原文一字未改。"；有问题→
  "转换完成，有 N 处需要你确认后再交付。"（配结论徽标 `✓ 原文一致` `! 合规：N 处待处理`）
- **成品预览说明**："按期刊排版后的样子显示，先整体看一眼：图、表、公式、参考文献是不是都在、位置对不对。"
- **原文核对**：标题"有没有改动或漏掉你的内容"；结论先行"你的正文一字未改。多出的 N 个词是按
  出版规范补的刊名、ISSN、版权声明（可逐条核对）；少掉的 M 个词是做成图片的表格文字和图注，
  已随图片一起转走——都不是改动你的正文。"；两折叠列表改名"系统补充的出版信息(可核对)"/
  "转成图片的表格/图注文字"。
- **内容清单**：标题"该有的都齐了吗"；分三组（文章信息 / 正文 / 参考文献）+ 每组一句核对提示，
  不给裸计数网格。
- **合规检查**：标题"能不能直接交付"；通过→"符合通用出版标准(JATS)，可直接进入出版流程，
  PubMed、知网、CrossRef 等平台可接收。"；不通过→逐条"哪里+什么问题+怎么办"（如"参考文献
  第7条缺年份→补上年份即可"），不抛 DTD 报错原文。
- **下载**："下载文件包(XML + 图片，可直接提交)"；XML 降级为一行小字"查看/下载 XML 源文件(供技术人员核对)"。
- **转换步骤**：读取 Word 稿件 → 识别文章结构(作者/图表/公式/参考文献) → 生成 JATS XML、放回图片
  → 检查合规、核对原文。
- **首页副标题**："把 Word 稿件转成可直接交付的 JATS XML。图片、公式、表格、参考文献一并转好
  ——JATS 是学术期刊通用的出版用 XML 格式。"；页脚去掉 DTD 字样。

### 落地位置
`webapp/static/index.html`（tab 标签/区块说明/页脚/进度文字/IA 重排）、`webapp/static/app.js`
（状态条、校验分级、计数网格、内容忠实文案、tab 逻辑）、`webapp/static/style.css`（配合新 IA）。
原则：**按用户问题命名区块、结论先行不给裸指标、用编辑参照系下判断、术语分级、整页像自检报告**。

### 调研来源
Inera eXtyles（编辑留在 Word 一键出 XML）；Texture/JATS-Con（让手工写 XML 变得没必要）；
Scholastica《期刊生产四阶段》；PMC 校验两层合规（DTD合法≠被PMC接收）；Paperpal Preflight /
印前 FlightCheck（preflight 作为组织概念）；SciSpace（小型 OA 单人生产现实）。
