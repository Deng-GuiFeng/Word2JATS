# word2jats：面向编辑复核的 Word 智能结构化转换

学术期刊结构化技术创新大赛 · 选题一 · 决赛技术方案说明书

参赛团队：JiangLab
在线体验：https://word2jats.jianglab.work

## 一、项目概述

word2jats 将学术论文的 Word 投稿稿转换为 JATS 1.3 XML 与配套图片，并提供可视化校样、原稿定位核对和复核记录。项目面向期刊编辑的实际工作：自动完成能够确定的结构标注，把仍需判断的内容交接给编辑，形成从稿件输入到结果导出的完整流程。

方案的核心是“模型理解结构、程序取回原文、编辑确认结果”。正文与参考文献内容以原稿位置为依据，模型负责判断结构和提供定位线索；生成后分别检查原稿内容的去向与输出内容的来源。文首作者、机构等元信息使用受约束的局部 JATS 生成通道，并进行专门核对。系统不将全文重新生成，也不把图片识别出的猜测文字写入论文。

作品包含可运行转换器、网页校样工作台、命令行接口、14 例输入与实际输出、验证工具及运行文档。核心运行不依赖本地 GPU；模型响应可缓存复用，已生成的成果可离线预览。

## 二、任务理解与总体方案

### 2.1 从视觉排版恢复出版结构

Word 中的标题、作者信息、图表和参考文献往往依靠视觉排版表达，样式名并不可靠。JATS 则要求将这些内容组织为明确的语义元素和关联关系。转换不仅要生成合法标签，还要保留研究内容、数字、符号及图表，并避免把出版后的编辑加工误当成原稿事实。

单纯依赖模板会受制于稿件体例，直接生成全文则增加改写和遗漏风险。本方案将结构识别与内容取回分工，通过原稿位置连接两者。目标格式为 JATS Journal Publishing 1.3，结构定义依据 NLM 发布的标签库与 DTD。[1]

### 2.2 五个相连的处理环节

| 环节 | 处理内容 | 产生的结果 |
|---|---|---|
| 原稿解析 | 读取文字、格式、表格、自动编号、图片与公式出现位置 | 可寻址的源对象图 |
| 结构理解 | 判断文首、章节、文献边界与字段、引文、表格结构 | 带原文定位线索的结构判断 |
| 原文定位与组装 | 将摘抄映射回原稿，归并角色，处理冲突与不确定项 | 按来源组织的语义文档 |
| XML 生成与检查 | 组装 JATS、外部化媒体，检查结构、来源、覆盖及链接 | XML、媒体与检查结果 |
| 校样复核与导出 | 浏览成品、查看原稿摘录、记录结论，必要时修订原稿复验 | 可交接的成果包与复核记录 |

## 三、关键技术与工程设计

### 3.1 可追溯的内容取回

解析层为段落、表格、字符范围以及图片和公式的每次出现建立地址。结构理解采用这些地址与摘抄线索，程序再完成精确匹配、受控的空白与引号归一化以及上下文消歧。正文和文献字段最终取回的是原稿内容，不是模型重新写出的文字。

生成过程记录输出来源，检查过程反向寻找未覆盖的源内容。这样既能追问“这句话去了哪里”，也能追问“这个输出字段从哪里来”。图片与公式资源和出现位置分开管理，支持同一资源多处引用，不靠文件名猜图片身份。

文首的作者、机构、通讯关系采用局部 JATS 生成，以适应复杂的元信息表达；该通道通过格式校验、源外词处理与独立词级核对约束，并记录修正。它与正文的源地址通道区别明确，作者关系仍属于校样重点。

### 3.2 多体例参考文献与引用关联

参考文献先由两路不同问法识别条目边界，在有分歧时裁决，再逐条并行提取作者、题名、刊名、年份和卷期页。边界依据原稿中能够唯一定位的条目开头，文献完整内容与字段均从原稿取回。

字段级结构化需要同时核验实际输出范围。若存在未被字段承载的作者、年份等实义内容，系统退回整条 mixed-citation 保留原文，并提示核对，避免用结构化字段的外观掩盖内容缺失。常规著录分隔符单独处理，不将任意漏抽文字都视为标点。

数字制和作者—年份制引文分别与文末实体关联，Word 自动编号从编号定义恢复，图表提及也建立交叉引用。输出检查核对 ID 唯一性与目标闭合，语义不确定的引文另作复核提示。

### 3.3 表格、公式和原始媒体

原生 Word 表格按单元格与合并关系生成。以制表符或换行排出的表格由模型辅助判断列结构，机械校验未通过时保留文字并提示整理原稿。对于单行且仅一格有内容的嵌套排版小表，可将内容并入外层表头。

原生 OMML 公式通过样式表转换为 MathML，完整保留变换产生的各个节点；图像与旧式对象按其实际载体处理，不凭图片生成数学表达式。媒体按原始字节交付，并与 DOCX 内嵌资源核验。网页的 TIFF、可选 WMF 预览转换不改变下载文件。

### 3.4 按实际依赖并行推进

文首、正文、文献边界和引文识别同时启动。文献边界确认后即可提取字段，无须等待正文结束；正文归并后即可处理压平表格，无须等待所有文献字段结束。最终组装才汇合所需结果。

这项优化减少任务之间没有必要的等待，并保留原有内容约束与重问策略。长稿的引文识别、复杂表格及模型服务延迟仍可能成为主要耗时，系统据实显示运行阶段、耗时和缓存使用情况。

### 3.5 可检查、可复现的工程实现

转换器采用 Python，网页采用 FastAPI 与原生 JavaScript；命令行和网页共用同一转换入口。大文件上传支持分片、并发传输、失败重传和完整性校验。API 凭据保留在服务端，不随提交包分发。

候选结果先生成再检查，检查覆盖 XML 良构、JATS DTD、ID 与引用、媒体格式与字节、源内容覆盖、输出来源和理解状态等方面。存在未解决事项时保留候选与问题位置，供编辑处理，不把失败变成不可追查的空文件。

模型响应按请求缓存；同版代码、配置、输入及完整响应可以重放。全新模型调用和响应重放分开验证、分开计时。项目同时提供针对性单元测试、集成测试、结构对比工具与独立内容核对脚本。

## 四、编辑工作台与人机协作

编辑上传 Word 后，可在五个面板查看成品预览、原文核对、内容清单、合规检查和 XML 源文件。页面说明本次是重新识别、部分复用还是复用已有分析，使等待和结果来源可理解。

核对清单将具体问题关联到原稿摘录，并给出处理建议：文献未完全拆字段时核对完整著录；表格不能可靠分列时整理为 Word 原生表格；内容未覆盖时查看原段落的去向。正常完成的标题拆分不作为待办，减少无须处理的提示。

每项可记录“待核对”“已核对，保留当前结果”“需修改后重新转换”，填写复核人和备注。记录包含当前 XML 的文件哈希，随成果包导出，用于说明判断针对哪一版结果。人工记录不修改 XML，也不自动覆盖机器检查结论。需要修订时，在原稿 Word 中完成，再重新上传复验。

该设计将自动化难以确定的问题转为有位置、有原文、有处理结论的编辑工作，而不是要求编辑重新标注全文。当前尚未通过真实编辑用户实验量化人工耗时的节省比例。

## 五、验证结果与适用范围

本次对 14 份稿件进行了逐篇全新模型调用验证：14/14 通过 JATS DTD 检查，官方 10 例均通过系统联合自动检查；4 例初赛评委测试稿中，X03 自动通过，X01、X02、X04 保留候选供核对。

逐例核对共 692 条参考文献，条目数量均与原稿一致；27 个原生 OMML 公式的完整转换文本均已保留。原稿中的 ORCID 均在输出中找到，已输出图片与 DOCX 内嵌资源字节一致，XML 引用目标无断链。

单篇冷跑耗时 38.5–339.8 秒，中位数 72.1 秒。计时包含模型调用、转换与自动检查，不含上传和人工校样时间。

自动检查通过与无需编辑加工不是同一含义。复杂压平表格、旧式嵌入对象、手工排版公式及部分不确定引文仍需核对；部分候选中的内容覆盖问题会阻止自动通过。例如 X04 的两处文字排版公式未完整输出，需要整理原稿后复验，不属于原生 OMML 核对范围。现阶段的完整流程是自动转换加编辑复核。

## 六、运行与交付

提交包以 JiangLab 命名。包内 README 为上手入口，docs 提供系统设计、模块职责、实测结果与操作说明；样例数据提供 14 份原稿及对照材料，输出样例提供实际生成的 XML、图片压缩包、检查摘要与离线预览。文件清单记录来源版本及文件哈希。

运行需要 Python 3.10 以上，已在 Python 3.12 验证。安装 requirements.txt，在本地 .env 配置模型凭据，执行 python -m webapp 即可打开工作台。也可通过命令行转换单篇，便于与其他业务流程集成。

当前默认主流程模型为 qwen3.7-plus，文首为 qwen3.8-max，均经服务端接口调用。首次转换需要有效模型凭据与网络；离线预览展示随包的真实冻结成果，不等于离线重新推理。模型响应缓存不随提交包分发。

原型按单机服务设计，任务索引位于进程内存，重启后旧任务链接不再有效，重要结果应及时导出。面向生产部署时，需结合出版社要求配置身份认证、调用配额和稿件留存策略。

## 七、原创工作与使用资源

团队实现的主要工作包括源对象图与语义组织、模型任务编排、原文定位和内容取回、文献与引用处理、覆盖与来源检查，以及校样复核工作台。方案的创新体现为面向出版转换的整体约束与工作流程，而非将通用模型、标准或第三方解析库称为原创。

JATS DTD 来自 NLM 发布的规范资源；公式转换使用随项目保留的 OMML2MML.XSL 样式表；网页预览使用 NLM/NCBI JATS Preview Stylesheets，并保留来源说明。Python 文档与 XML 处理、图像读取和 Web 服务分别使用 python-docx、lxml、Pillow、FastAPI 等组件。项目源码许可见 LICENSE，第三方资源遵循各自来源与许可。

[1] NLM/NCBI, Journal Publishing Tag Library, NISO JATS Version 1.3 (June 2021)：https://jats.nlm.nih.gov/publishing/tag-library/1.3/
