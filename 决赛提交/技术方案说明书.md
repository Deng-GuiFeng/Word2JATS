# word2jats：从 Word 排版格式到 JATS XML 的智能结构化转换

**学术期刊结构化技术创新大赛 · 选题一 · 决赛技术方案说明书**

- 队伍：JiangLab（邓贵锋，指导老师：江海腾，浙江大学）
- 在线演示：<https://word2jats.jianglab.work>（校样工作台，上传 docx 即转换）
- 目标格式：JATS Journal Publishing DTD v1.3（2021-06-10），输出 100% 通过 DTD 校验

---

## 一、摘要

word2jats 把学术期刊的 Word 投稿稿自动转换为 JATS 1.3 标准 XML 与外部化图片包。方案的核心立场是：

> **大模型只判断结构，从不生成正文文字。** 正文的每个字符按源地址从 Word 原文机械取回——"内容守恒"是构造性保证（文字根本不流经模型输出口），不是事后比对补救。

决赛版在初赛方案基础上完成了一次系统性重构：层间契约从"字符串传递"升级为**源地址传递**（摘抄+落锚协议），建立**两本账**（源覆盖账+输出来源账）与**十一道出口交付门**，并针对初赛评委的四条反馈逐条实测改进。在赛题 10 个样例上，自建双评测器的缺陷合计从初赛方案的 281 降到 **164**；在赛题之外自采的 4 份真实投稿件上，参考文献从初赛方案的**整类丢失**恢复到 **30/32/35/70 条全数精确**；单篇转换实测 **101~125 秒**，比初赛的 2~3 分钟提速约一半。

## 二、赛题理解

选题一要求把 Word 投稿转成 JATS XML：结构上要"判断"（这段是摘要还是声明、这行是标题还是正文、这条文献的作者/年份/期刊各是哪几个字），内容上要"搬运"（一个字不许增删改，斜体上标照原样保留）。这两个要求天然互斥——判断要看懂内容，搬运不许碰内容。样式名不可靠（作者用 Normal 写标题是常态）、参考文献著录五花八门（编号制/作者-年份制/自动编号/手打编号）、公式载体多样（OMML/OLE/下划线排版），使纯规则方案脆弱；而纯生成方案会改写、丢失甚至编造文字，对学术出版是不可接受的风险。

## 三、技术路线：判断与搬运彻底分离

| 路线 | 结构判断 | 内容搬运 | 结论 |
|---|---|---|---|
| 纯规则+模板（官方基线） | 死规则枚举不完长尾，样式缺失即失效 | 可靠 | 结构判断太脆 |
| 纯大模型生成 | 强 | 会改写/丢字/编造，不可复现 | 内容风险不可接受 |
| **本方案：模型指路，程序搬运** | 大模型语义判断 | 按源地址机械取回，构造性守恒 | 两者兼得 |

实现为四层管线：

```
docx ──parse──► 源对象图 ──serialize──► 可寻址记录清单 ──understand──► 落锚后的结构判定
                （每个字符有稳定地址）      （模型所见）        （多路并发 LLM＋机械落锚）
     ◄──交付/隔离── 十一道出口门 ◄──render── JATS XML ◄──assemble── 类型化语义文档
```

1. **事实层（parse）**：直接读 OOXML 包建"源对象图"。正文/脚注/尾注/文本框逐部件读全；每个字符有稳定地址 `(节点, 起, 止)`；图片、公式、嵌入对象每次出现登记在册；格式按 Word 样式继承链算出实际生效值；**自动编号（numPr）按 numbering.xml 的封闭定义确定性还原**——印出的 "1." 是文档事实，不随切分位置漂移。
2. **理解层（understand）**：全项目唯一判语义的地方。模型回答一律是"原文摘抄＋位置"，程序拿摘抄回源文**落锚**成字符坐标：精确匹配→封闭归一（弯直引号/空白折叠）→上下文消歧，仍歧义一律拒绝（宁可不认，不许认错）。参考文献切条跑**两个问法不同的独立实例**（语义切分 + 对抗式边界审计），锚点一致才采纳，分歧交第三方裁决；每条文献单独一次调用析字段；正文引用按印出编号（或作者-年份身份）与文献实体机械匹配。多路任务分四批全并发。
3. **语义/渲染层（assemble/render）**：一切内容字段存源地址不存模型文字；渲染时按地址抄回、格式按 JATS 封闭内容模型投影（如 `person-group-type` 枚举外角色走标准 `custom` 通道）、ID 由文档级发号器统一分配、交叉引用只给原字符套标签；同时逐段登记输出来源。
4. **出口门（verify）**：十一道门全过才正式交付——DTD、ID 唯一、引用闭合、媒体逐字节一致、**源覆盖账**（原文每段字都有去向）、**输出来源账**（输出每段字都指得出来处）、独立词级守恒报警器（不读账本直接数词）。不过门的进 failed/ 隔离并附全量报告，绝不静默交付。

**确定性与可复现**：温度 0 + 磁盘缓存。实测云端 API 温度 0 并非位级确定（MoE 路由所致），逐字节复现靠响应缓存实现；同机重放可零成本、零网络复现全部结果。

## 四、决赛改进：对初赛评委反馈的逐条回应

| 初赛评委反馈 | 决赛实测改进 |
|---|---|
| ① 转换约需 2~3 分钟，建议提速 | 逐条析字段的首问契约修复使 LLM 调用量**精确砍半**（56 条文献从 112 次调用降到 56 次）；单篇实测 **101 秒（S01）/125 秒（03）**；配合响应缓存的复现模式，演示端到端 **3 秒** |
| ② 通讯作者识别不准、姓名里出现 * | 关系标记（*†#）与姓名分离：标记进 `xref` 元素，姓名内零杂质；通讯作者、共同一作标记在 10 例上与结构参考一致 |
| ③ 公式被识别为文本，应组装公式标签 | OMML 经微软官方 OMML2MML.XSL 转 **MathML**：03 例 16/16 全转（含 10 个行内公式），01 例图注内嵌公式也以行内 MathML 取回；转不出的以原图交付，公式不消失 |
| ④ 参考文献有时丢失，建议提升兼容性 | 切条改语义判断+对抗审计，与分隔记号无关：**14 例文献条数全部精确命中**（含无编号的作者-年份制 35 条、Word 自动编号 70 条、手工贴 JATS 标签的 30 条——这三种形态恰是初赛方案整类丢失的） |

为验证兼容性，我们在赛题 10 例之外**自采了 4 份真实投稿件（X01–X04）做盲区测试**，覆盖赛题样例没有的著录形态。初赛方案在其上参考文献输出为 0；决赛版 30/32/35/70 条全数恢复，X04 的语义元素 F1 从 0.33 升至 **0.96**。

## 五、质量评测体系与成绩

- **V1 三层缺陷清单**：L0 合法层（DTD+DOCTYPE+出版规范）/ L1 忠实层（词多重集守恒，抓丢字与编造）/ L2 对位层（语义键对齐逐项比对）。产出是问题清单不是加权分。

## 六、工程实现

- **代码**：Python 3.9+（3.12 验证），核心包约 1.4 万行、**516 项自动化测试**；依赖仅 python-docx/lxml/Pillow/PyYAML/openai/python-dotenv（网页另加 FastAPI）。JATS 1.3 DTD 全套内嵌，离线校验。
- **并发**：任务层（头部/正文/切条 A/B 四路）→ 条目层（逐条文献、逐表全并发）→ 进程级闸门（默认 32 在途），14 例整批转换总墙钟 851 秒。
- **资源消耗**：单篇 35~146 次调用、约 41~47 万 token（默认 qwen3.7-plus，文首任务 qwen3.8-max）。
- **可复现**：`--fresh-cache` 全新真实调用并留档；同机重放零成本零网络；ReplayLLM 只读快照支持无密钥离线演示。
- **运行**：
  ```bash
  PYTHONPATH=src .venv/bin/python -m word2jats convert \
      样例数据/03/初始文件.docx --journal JIN --doi 10.31083/JIN49347 -o output/
  # 评测（转换+打分一体）：
  .venv/bin/python -m scripts.eval_v1 --samples all --tag demo --fresh-cache
  .venv/bin/python -m scripts.evalsuite --tag demo --samples all
  ```

## 七、Web 校样工作台

面向期刊生产编辑的网页应用（FastAPI + 原生 JS，已上线）：拖入 docx → 分片上传（断点续传，绕 CDN 超时）→ 四阶段进度 → **校样单式结果页**：结论先行的"可交付/待确认"印章、期刊样式成品预览（XSLT）、**逐词"原文核对"**（输出来自原稿 / 原稿保留两个覆盖率与差异词清单——把内容守恒做成看得见的界面）、内容清单（作者/图表/公式/文献计数）、DTD 与结构合规明细、XML 源码。下载包=XML+外部化图片。

## 八、原创性与第三方资源

核心算法（源对象图、摘抄落锚协议、双实例对抗切条、两本账与交付门、双评测器）均为原创。第三方仅：JATS 1.3 DTD（NISO/NLM）、OMML2MML.XSL（微软开源样式表）、JATS 预览 XSLT/CSS（NCBI 公有领域）、OpenAI 兼容 SDK。大模型 API 为方法必需组件（理解层无规则降级档）。

## 九、已知边界（如实交代）

1. 嵌套表格（表中表）尚未展开（S03 一处表头 2 格）；
2. 制表符拼排的无线表格中，格网复原未过机械校验的按"一行一格"保全原文交付（05 例 14 张中 8 张，文字零丢失、结构降级）；
3. 参考文献内期刊名斜体的 run 级格式恢复不完整；
4. 手绘图形/OLE 预览缺失的对象以占位报告，不虚构内容；
5. 源稿未印的出版模板字（如编辑角色）不由模型补造——宁缺勿造，独立守恒器会点名任何越界。
