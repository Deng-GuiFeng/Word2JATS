# 新样例伪标签(优化目标)

这些是为"只有输入"的 5 篇新样例**严谨生成的参考标签(伪金标准)**,用作 Agent 管线的优化目标。

## 怎么产的(四路独立信号交叉验证 + 对照源裁决)
1. 两路独立候选(`scripts/gen_label.py`):DET=直接读原始 OOXML;LLM=本地 GPU 多模态模型分模块抽取。两者都不依赖被测的 word2jats 输出。
2. 多角色 Team 核验(2 个独立角色 A 细致抽取员 / B 对抗怀疑员,各自回到源 docx 逐字段重判、用本地模型看图核对):见 `核验AB/样例N.{A,B}.json`。
3. 对账(`scripts/reconcile_labels.py`):A==B 的字段高置信采纳;少数 cosmetic 冲突(日期格式/题注前缀)由人裁决。
4. 对照源 docx 裁决过分段(去掉 References=ref-list、正文节、段中嵌入标签)。

## 用法
`python scripts/eval_vs_label.py 样例N.json <output.xml>` 逐字段比对输出与标签,差异即优化目标。
当前 `word2jats --llm local --crossref --refine` 输出对 5 篇**逐字段 0 差异**。

## 第二轮:完全独立(零 word2jats)交叉验证(2026-06-26)
针对"标签经被测系统解析层=循环自证"的批评,重新用**零 word2jats 依赖**的工具
(`scripts/label/raw_docx.py` 纯 lxml 直解 OOXML;agent 用自身理解抽取)再产一套独立标签
(`独立核验XY/样例N.{X,Y}.json`),与当前标签做**三方对账**:
- 样例 1/2/4/5:独立X、独立Y、当前标签 **每个关键字段三方一致** → 确证正确。
- 样例 3:唯一分歧(back 小节数),回原始 OOXML 裁定:Trial registration(P30 独立成行)计入、
  Data Sharing(P29 段中嵌入"request. Data Sharing Statement:")不计 → **当前标签的 5 节正确**。
- 结论:伪标签经两条互相独立、且都独立于被测系统的路径交叉确认,可作可信优化目标。
- **标签生成不需要 GPU**:字段都是 docx 已有文本,代理(本身即模型)直接读原始 OOXML 即可;
  本地 GPU 模型是 word2jats 运行时引擎,与产标签无关。

## 第三轮:多角色 Team 肉眼手工核验(2026-06-26,零脚本提取/零GPU/零word2jats)
按要求把 5 篇 docx 渲染成逐页 PNG,派多角色子代理(每样例 2 独立审读员 + 1 对抗审核员,共 15 个)
**亲眼逐页 Read 图片、像人工审稿一样手工提取与互审**(`肉眼核验/样例N.json`)。
与当前标签逐字段比对,**所有分歧均由我回到权威源(docx 存储文本 / OOXML 表格 grid)亲自裁定**:
- 字符级(样例1 名 Xiaoze/ORCID 6068、样例3 Han ORCID 0009-… 、样例2 标题弯引号):
  肉眼读 130DPI 图**误读**(Xiaoze→Xiaoxi、6068→6868、0009→0000),存储文本为准 → 当前标签对。
- 参考文献数(样例2=50、样例3=22、样例5=46):肉眼跨页**目测误数**(样例2 按最大编号 53 高估、样例5 漏数),
  按 docx 实际条目/编号清点 → 当前标签对。
- 表格列数(样例3 表1=4、样例4 表2=12):肉眼把窄列/合并列**目测少数**;OOXML gridCols 为准 → 当前标签对。
- 样例3 Data Sharing:夹在段落中间("request. Data Sharing Statement:"),非独立小节 → 不计,当前 5 节对。
**结论**:三条互相独立的方法(脚本读OOXML / 独立读OOXML / 肉眼读渲染图)交叉验证,
每处分歧都回源裁定,**当前伪标签全部确证正确**。肉眼法擅长结构核验,但低分辨率下字符易误读、长表难目数,
故字符/计数类以存储文本为权威——这正是"多方法交叉 + 回源裁决"的价值。
