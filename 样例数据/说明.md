# 样例数据说明

本目录平铺存放 14 份样例：**01–05**（主样例）、**S01–S05**（补充样例）、**X01–X04**（外部投稿件）。

三组的文件层级现已统一：

```
样例目录/
├── 初始文件.docx     输入：投稿用 Word 稿件 —— 内容的唯一权威
├── 结构参考.xml      金标准（其一）：忠实结构化 docx 的 JATS 1.3 XML
├── figures.zip       金标准（其二）：外部化的图片，逐字节取自 docx 内嵌媒体
├── 上线版本.xml      出版方发表版 —— 仅 01–05 有
└── 附件.zip          补充材料 —— 仅 01 有
```

## 金标准是什么

> **假设转换器百分之百正确，它应从该 docx 生成怎样的 JATS。**

这里的"转换器"指所有面向本任务的转换器，不特指本项目的实现。

金标准 = `结构参考.xml` + `figures.zip`。转换器的输出是一个**目录**（XML 加外部化图片），不是单独一份 XML，所以图片包与 XML 同属标准的一部分。

判定任何一处只问两件事：

1. **docx 里有没有？**（事实，脚本可查）
2. **JATS 表达得了吗？**（规范，DTD 可验）

两问都成立就收，按 docx 的原文与归属落位；docx 里没有的，一个字都不补。

以下四类**不作判据**：

| 不作判据 | 原因 |
|---|---|
| 上线版本的**内容**取舍 | 那是编辑加工。docx 与它冲突，一律以 docx 为准 |
| 评测器的行为 | 评测器建立在标准之上；它对不上，改的是评测器 |
| 现有转换器有没有这个能力 | 标准定义正确输出，不迁就实现 |
| Crossref、DOI 注册库等外部数据 | docx 之外的信息 |

## 上线版本怎么用

`上线版本.xml` = 忠实结构化 **+** 出版方编辑加工，两层叠在一起，所以整份照搬会逼转换器去猜 docx 里没有的内容。但它不是不能看——要分开用：

- **内容层**（收哪些字）：不跟随。它删的、改的、补的，一律以 docx 为准。
- **结构层**（同样的内容用哪个元素、什么形态）：**这就是目标形态的实物**，是最权威的参照。

S01–S05 虽无 `上线版本.xml`，但五篇均已在 IMR Press 发表（CEOG 53(6) / RCM 27(6)，2026-06），官网只提供 PDF 与 HTML 全文、不提供 XML。HTML 全文可作**渲染层**旁证（比 XML 弱一档：能看出显示成什么样，看不出用了哪个元素）。X01–X04 是未发表的投稿件，无此参照。

## 现行口径

| # | 口径 | 依据 |
|---|---|---|
| 1 | **locator**：字面判不出的按著录位置标 `fpage`；只有 docx 明写 `Article N` 这类才用 `elocation-id` | 纯数字判定文章号必须查外部注册库；四份上线版全刊 `elocation-id` 计数为 0 |
| 2 | **范围引文**展开成逐项 `xref`，逗号分隔 | 01/02/03 上线版一致；S01 官方发表版正文即 `[13,14,15,16]` |
| 3 | **内联格式元素驱动**：格式已被目标元素承载的（标题槽）不产 `bold`/`italic`；落进 `p`/`td`/`th`/`caption` 的逐一保留 | 10 例实测：01 有 44 处占满父元素的 `bold`，无一在 `title` 里 |
| 4 | **图表 xref 只包编号数字**，`Fig. `/`Table ` 前缀与面板标识留在 xref 外 | 01/03/S04/S05 一致形态 |
| 5 | **作者联系地址**：docx 有就收，落 `contrib/address`（`corresp` 内放 `address` 经 DTD 实测不合法） | docx 明写即属内容；出版社删它是编辑加工 |
| 6 | **图文摘要**用 `abstract-type="graphical"`；docx 有标题文字才产 `title` | X02 块 187 明写 `Graphical Abstract`（产 title）；S05 没有（不产） |
| 7 | **相邻同格式元素合并**——run 边界是 Word 的存储细节，不是内容 | |
| 8 | **表格 `vMerge` → `rowspan`**，continuation 空单元格不产出 | |
| 9 | **公式一律转 MathML**，包括 OMML、OLE（MathType/ChemDraw）、以及用下划线加换行**模拟的分式**；每个字符逐字取自 docx（减号是 `-` 还是 `–` 各留各的） | 公式就是公式，退化成图片等于没解决问题 |
| 10 | **标签词由元素承载则不产出**：`Abstract:`→`<abstract>`、`Keywords:`→`<kwd-group>`、`Postal code:`→`<postal-code>`。只含孤立标点、不含任何词的块，与空段落同类，不产出 | 这是结构化本身，不是删内容 |
| 11 | **编号可由文档结构机械推出时补 `label`**：Word 自动编号（`w:numPr` + `numbering.xml`）、ref-list 里作者漏写的序号 | 不含判断，非外部信息 |

## 构建与审查

**01–05、S01–S05**：本队基于 docx 独立构建（01–05 用上线版本作结构形态参照，内容以 docx 为准）。
**X01–X04**：脚本化构建，全套工具与决策单在 [`../scripts/eval_v1/refbuild/`](../scripts/eval_v1/refbuild/)——判断由模型做（只回答"哪个块归哪个元素"，一个正文字符都不许打），取字由脚本按块索引从 docx 取回。哪些块没进 XML、哪些媒体不用及其理由，逐条记在各自的 `X0N.decisions.json` 的 `dropped` / `media_dropped` 里。

**审查经过两轮**：

1. **内部**：多路独立起草 + 每疑点三法官辩论 + 口径判据独立审议，共 35 个独立审查代理。
2. **外部**（2026-08）：由 Codex 对 14 例逐例独立重审，本队再逐条回 docx 核实、逐条裁决。查出并已修正的实质问题包括——01 的作者联系地址与复合图、02 的出版月日与 4 张重编码图、03 的四处 MathML 结构错误（原参考照搬了上线版的畸形转换结果）与 5 张被转码的 TIFF、04 的两张被替换的图、05 的表格列模型与 back 顺序、S02 的 48 个 DOI 尾点、S03 的 24 处图表引用与作者学位、S05 的图文摘要遗漏、X01 与 X04 的公式遗漏、X02 的 11 处引用错绑。同时驳回了 118 条依据外部注册库的 `fpage→elocation-id` 改标。

## 出口校验

每一例定稿前均通过：

1. **DTD**：JATS Journal Publishing 1.3，用项目内置 DTD 离线校验。
2. **图片**：每个 `graphic` 指向的文件存在、可解码，且**字节与 docx 内嵌媒体逐字节相同**；图片包内无冗余成员。
3. **引用闭合**：所有 `xref/@rid` 均有落点。
4. **词多重集守恒**：docx 与参考逐词比对，差异逐条归因（切词假差、标签词、表示法差异）。
5. **公式载体闭合**：docx 的每个 OMML / OLE 公式对象都有对应产出或写明理由。
