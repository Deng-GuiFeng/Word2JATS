# 评测产物

本目录留存**"结构参考"的核定与审查留痕**——即"评测对照物是怎么做扎实、凭什么可信"的可审计过程记录。
评测本身的运行产物(逐样例逐类缺陷清单)由现行三层评测落到 `../reports/eval/<tag>/`(可再生、不入库);
评测体系的权威设计见 [`../docs/03-评测/评测体系设计.md`](../docs/03-评测/评测体系设计.md)。

## 为什么保留这些留痕

评测的唯一对照物是冻结的 `样例数据/<key>/结构参考.xml`(A+B、不含 C 档编辑加工)。参考若不可信,评测就无从谈起。
因此参考不是随手写的:它经"多代理起草 → 逐疑点独立法官辩论 → 主进程逐项终审 → 人工冻结"这套流程建成,
本目录就是这套流程的证据链,便于任何人回头核查每个标签为什么这么打。

## 目录内容

- **`参考审查留痕/`** —— 对 10 例 `结构参考.xml` 的逐个独立全覆盖审查 + 每条疑点 3 名法官(含反方)据 docx 辩论定论的记录。
  核心是 [`参考审查留痕/审查辩论修复记录.md`](参考审查留痕/审查辩论修复记录.md):列出辩论确认的真错(已修)与判为误报(未动参考)各是哪些、依据什么。
- **`结构参考留痕/`** —— 01–05 参考的多代理构建与终审记录:每例含 3 份独立候选草稿(`gen_1/2/3.xml`)+ `定稿候选.xml`,
  外加 `主进程终审记录.md`,佐证定稿参考"逐字忠实 docx + 补 B 档 + 过 DTD + 计数对账"。

> 每份样例的 A/B/C 逐档结论与已知编辑加工,另以机读形式冻结在 `样例数据/<key>/scope.json`,由评测加载时交叉核对。
