# 84 处残余缺陷逐条 7 点留痕审查

> 迭代2(198→80)后剩余 84 处的逐条审查。每处按 7 点:输出/参考/不一致/是否真缺陷/该不该修/怎么修/可泛化。
> 四类归属:通用真bug(该修) / 度量伪差(评测分词口径产物,输出已忠实) / gold不一致(金标准自身逐例矛盾,追=硬编码噪声) / 难例(语义歧义或需视觉/外部知识,无稳健判据)。
> 由 8 个 subagent 中立审查产出,主进程逐个复核。**已实装的通用真bug见文末『实装/不实装裁决』。**


## 四类归属计数
- gold不一致: 33
- 通用真bug: 17
- 度量伪差: 10
- 难例: 8


## 样例 01

### L1-lost-ph-n3  【通用真bug】
- **输出**: 作者块 <contrib> 无 <degrees>；三位作者都缺学位
- **参考**: 金标准三处 <degrees>M.D., Ph.D.</degrees>（每位作者一处）
- **不一致**: docx 作者行 'Yinze Ji1,2, M.D., Ph.D., Aimin Dang1,*, M.D., Ph.D. , Naqiang Lv1,*, M.D., Ph.D.' 每位作者尾随学位 'M.D., Ph.D.'；金标准存为 <degrees>，输出整体丢弃。token 'ph' 来自 'Ph.D.'→['ph','d']，docx=3 out=0 ref=3
- **是否真缺陷**: 真缺陷。证据：Author dataclass(model.py:34-44) 无 degrees 字段，understand/prompts 无 degree/Ph.D 提示词，front.py _contrib 不产出 degrees；整条链路无学位概念，docx 明确有学位文本被丢
- **该不该修**: 该修。学位是标准 JATS <degrees> 字段，医学/学术论文普遍存在，丢弃=丢内容
- **怎么修**: 三层：(1)understand 提示词让作者抽取识别姓名后紧随的学位串(M.D./Ph.D./MPH 等)；(2)semantic model.Author 加 degrees 字段；(3)render/front.py _contrib 在 name 后 emit <degrees>
- **可泛化/过拟合**: 可泛化。'姓名, 学位,' 是稳定模式，学位词表(M.D./Ph.D./MSc/MPH/RN...)有限可枚举；误伤低——学位串紧跟姓名且格式固定

- **输出**: validation 表 thead 只有2行(11 th)，第3表头行 'Calibration intercept (95% CI)/P value/...' 落入 tbody 作 6个 td；形状(8,11,64,0) scope={col:11}

- **是否真缺陷**: 真缺陷。docx 用 w:tblHeader 明确标了3行表头，转换器忽略该原生信号
- **该不该修**: 该修。多行复杂表头在学术表格常见

### L2-公式-missing  【难例】
- **输出**: 缺 'p = exp(β0+β1*gender+β2*ldl-c+β3*egfr)/(1+exp(...))' 这条模型公式（输出10式=docx全部10个 oMath）
- **参考**: 金标准 11 个 inline-formula，多这条 logistic 模型式的 MathML
- **不一致**: 该公式在 docx 中不是 oMath，而是段落 '...logit transform (e.g., [两个 w:drawing 图片], where p stands for...' 里两个内联图片(equation image)。金标准把公式图片转录成 MathML，输出未转录
- **是否真缺陷**: 非通用可修缺陷。公式以内联图片嵌入，转成 MathML 需视觉/OCR 生成文字
- **该不该修**: 不该修。项目已明令删 OCR 造字路径(LLM 只判结构不生成文字)；从图片重建 MathML 恰是被排除的造字行为，且无稳健判据
- **怎么修**: 无稳健修法。可选保守改进：把被丢的内联公式图片保留为 <inline-graphic> 免得静默消失——但仍不满足评测(要 MathML token)，且属额外工程
- **可泛化/过拟合**: 难例：需视觉转录，无确定性判据

### L2-参考文献-[17]-title/source  【gold不一致】
- **输出**: ref b17 用 <source>MESA Risk Score and Coronary Age Calculator</source>
- **参考**: 金标准 ref[17] 用 <article-title>MESA Risk Score and Coronary Age Calculator</article-title>（无 source）
- **不一致**: docx '[17] McClelland RLJN BMBM, MESA Risk Score and Coronary Age Calculator, 2015.' 只有'作者,标题,年'无期刊；金标准归 article-title，输出归 source（两个 field 缺陷：title 参考有输出空 + source 参考空输出有）
- **是否真缺陷**: 度量惩罚但字段归属本身歧义。无容器(期刊/书)的单标题，article-title 与 source 在 JATS 都成立；且金标准自身不一致——ref[25] 同样'作者,标题,年'却归 <source>

- **可泛化/过拟合**: 过拟合风险高；金标准内部矛盾

### L2-参考文献-[25]-source  【难例】
- **输出**: ref b25 退化为 <mixed-citation>（整段原文），无 <source>
- **参考**: 金标准 <collab>SAS Institute Inc</collab> + <source><italic>Usage Note 32471...</italic></source>
- **不一致**: docx '[25] SAS Institute Inc, Usage Note 32471: Testing assumptions..., 2008.' 团体作者+文档标题；输出识别不出作者模式(非 Surname Initial)故整条回退 mixed-citation，source 空

- **该不该修**: 不宜为本例硬修。区分团体作者名与标题极易误伤（把标题当机构名或反之）
- **怎么修**: 可探索团体作者词典/后缀(Inc/Institute/Organization/Association)识别 collab，但误伤面大；本例安全做法是保持 mixed-citation 兜底
- **可泛化/过拟合**: 难例：collab 作者识别无稳健通用判据

**01 小结**: 样例01共17处缺陷(L1=6, L2=11)。分类：通用真bug 4处（作者学位丢失 ph×3；ref[22]漏作者 Revow=L1 revow+L2 surname；图例段未入caption 图missing+extra；表多行表头被忽略 表shape+scope）；度量伪差 3处（Word拆词 ge→age、author+s→authors 的重组，输出实为更忠实）；gold不一致 2处（续表标记'Continued'金标准硬留版式噪声；ref[17] title/source 无容器单标题字段归属歧义且金标准自身[17]/[25]矛盾）；难例 8个字段（公式为内联图片需视觉转录、项目已禁OCR造字；ref[25]团体作者 collab 识别无稳健判据，连带 source/year/unstructured）。强可泛化修法4条见 general_bug_candidates，其中'表 w:tblHeader 多行表头'误伤最低、最该优先实装；'作者 degrees 字段'次之；'参考逐条内容守恒守门'与'图例入caption'可泛化但需边界从严防误伤。严守纪律：未提任何硬编码本例值的修法；continued/[17]/[25] 归入 gold不一致/难例并说明追平即过拟合。


## 样例 02

### L1-fab-bioprostheses  【通用真bug】
- **输出**: 参考文献[62] article-title 输出 '...degenerated surgical aortic and mitral bioprostheses: Current state...'(复数),导致 L1 编造词 'bioprostheses' n=1
- **参考**: docx 原文与金标准均为单数 'bioprosthesis'(docx: 'degenerated surgical aortic and mitral bioprosthesis: Current state and future perspectives'; gold 结构参考.xml:5148 单数)
- **不一致**: 输出把源里的单数 bioprosthesis 改成复数 bioprostheses;该词在 docx 中不存在于此处 → fidelity 判为编造(输出有·docx无·参考也无)
- **是否真缺陷**: 真缺陷。铁证:LLM 缓存 5990ef/7f959a 等文件里 PAYLOAD(喂给LLM的参考原文)恒为 'bioprosthesis'(单数),而 RESPONSE(LLM返回)在 7f959a/2d43cb/dfec17 三份里被改成 'bioprostheses'(复数)。是 LLM 参考解析 pass 自作主张改词,非分词伪差。
- **该不该修**: 该修。违反'只加结构、不改内容'红线,且属可泛化的内容篡改类。
- **怎么修**: understand 参考解析层(assemble.py 组装 article_title 时)不要直接采信 LLM 自由文本:把 LLM 返回的 title/各字符串字段的 token 与该条参考的源文本(payload)对齐,凡输出 token 不是源 token 的(大小写无关)子集就判篡改,回退到源子串。或在 verify 层加同样的 token-subset 守卫。
- **可泛化/过拟合**: 可泛化。根因是 LLM 重打字参考字段时静默做语法/拼写'纠正',对任意论文的任意参考字段都可能发生;token-subset 守卫是通用防线。

### L2-参考文献-[62]-title  【通用真bug】
- **输出**: <article-title>Transcatheter valve-in-valve implantation in degenerated surgical aortic and mitral bioprostheses: Current state and future perspectives</article-title>
- **参考**: <article-title>...degenerated surgical aortic and mitral bioprosthesis: Current state...</article-title>(单数)
- **不一致**: title 字段 bioprostheses(输出) vs bioprosthesis(参考/docx),仅差一个 e/s
- **是否真缺陷**: 真缺陷。与 L1-fab-bioprostheses 同一根因(LLM 参考解析把单数改复数),docx 原文为单数已证。
- **该不该修**: 该修,同上。
- **怎么修**: 同 L1-fab-bioprostheses:参考字段回锚源子串 / token-subset 守卫。修一处即同时消掉 L1 与本 L2 缺陷。
- **可泛化/过拟合**: 可泛化,同上根因。

### L2-章节-imaging-evaluation-L1  【通用真bug】
- **输出**: 把 'Imaging Evaluation and Intraoperative Operational Strategies' 当作正文粗体段落 <p id="S4.2.p9"><bold>...</bold></p>,嵌在 4.2 节里;其后整节内容(表4-8)被错挂到 4.2 之下
- **参考**: gold 作为顶层第5节 <sec id="S5"><title>Imaging Evaluation and Intraoperative Operational Strategies</title>...
- **不一致**: 参考有·输出无 该顶层章节标题(title,level=1);实为漏识一个顶层 section,连带其下内容层级归属错误
- **是否真缺陷**: 真缺陷。docx 里该段 pStyle=None 但 numId=3/ilvl=0(自动编号,渲染出'5.'),且 numId=3 全文仅此一段使用——是作者用编号列表代替 Heading1 做的节标题;它夹在 pStyle=1 的第4节与字面'6.'的结论之间,是真顶层节。L1 lost 为空说明文字没丢,丢的是结构。
- **该不该修**: 该修。真结构漏识,影响下游层级归属。
- **怎么修**: understand 层(serialize._para_flags 已把 numPr 标为 'list' flag、并有 bold):在 prompts.py 章节判定处提示——顶层出现的 bold+list(numPr)且文本为短标题式(无句末标点)、其后跟成段正文的段落,应判为编号节标题而非列表项。或在 serialize 把'单独 numId 的编号段'与普通列表项区分标注,给 LLM 更强信号。
- **可泛化/过拟合**: 可泛化但需谨慎。判据(真 numPr + bold + 短标题式 + 顶层 + 后接正文)是源里真实存在的信号;且与本例 Key Points(无 numPr)天然可区分。但对'粗体短编号列表项'有一定误升级风险。
